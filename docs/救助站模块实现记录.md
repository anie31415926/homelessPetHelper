# 救助站模块实现记录

日期：2026-11-17。状态：ST-01 独立基础规则已完成；本轮新增 ST-02 站内独立试玩及 ST-03 局部清洁试做，入口和验证见本文后续记录。未接入 Main，不代表完整救助站已完成。

## 授权与范围

用户确认按设计开始、持续做记录；易调整的细节可边做边验证，关键后果仍先确认。设计依据为[游戏设计总纲](游戏设计总纲.md)中的救助站、行动时间、照护、领养与容量规则。

本轮 ST-01 只建立独立规则底座：

- 接收上游已经确认救助成功的动物，按站内会话、外出身份和动物身份校验，拒绝重复与超容量接收。
- 保存不可变的入站情况和回站总结快照，供后续总结与站内界面分别读取；总结不包含照护操作。
- 有限临时安置容量及已获批准的容量扩展应用，不实现建设费用或解锁条件。
- 独立行动世界时钟：只接受显式推进，保留前后快照，以会话和时间版本拒绝重复、过期提交；不读现实时间、不做挂机/离线补算。
- EditMode 单测及既有底座回归。

不做正式 UI、图片、清洁手势、健康诊断/治疗、患病判定、领养模拟、快进计算、长期陪伴变更、设施经济或存档；不修改 Main、不伪造救助成功连接现有 `RescueFlow`，也不重复实现选项管理。

## 实现边界与暂定表示

- `Modules/Station` 与 `Modules/WorldTime` 使用普通 C# 和独立 asmdef，无 UnityEngine 或跨模块反向依赖，不引入事件总线、DI 框架。
- 入站数据仅承接上游事实，不自行认证救助成功、检查骨折或把动物自动判为健康；上游仍须核对当前外出身份与真实完成条件。
- 入站健康评估只区分未检查、无紧急处理需求、有紧急处理需求，不是具体疾病分类；已知情况用结构化标识承接，显示文案由未来表现层提供。不另建一套医疗计算。
- 脏污暂用 0 至 100 的整数表示，仅为数据范围，不代表患病阈值或已实现增长、清洁、感染规则。初始容量与每次时间推进量由调用方明确提供，本轮不写入正式平衡值。
- 世界时间使用整数游戏分钟，一天长度由构造参数提供；不确定三张背景的分段、不启用昼夜遭遇差异。推进结果可供后续装配层发布通知，本轮不派发事件或自动更新脏污、康复。
- 会话身份、防重和暂停目前均为内存级；未接入场景生命周期、持久化恢复或跨模块事务，不声称具备这些能力。

## 调用契约与下一步接入

- `RescueStation.TryReceive` 只接受已获上游认证的 `StationAnimalIntake`，成功返回冻结的 `StationReturnSummary`；拒绝返回明确 `StationFailure`、空总结且不占位。它校验站内会话和重复身份，不检查上游当前外出是否仍有效，后者须在会话装配层补齐。
- `Animals`、`TryGetAnimal` 当前只返回入站事实，不能误当成会随照护变化的当前健康档案。医疗规则确定后需明确单一状态归属，再将当前状态与历史总结分开，不在此处另造治疗系统。
- `TryExpandTemporaryCapacity` 应用已获批准的绝对容量，重复提交不会再次加位；不负责解锁、扣费或发奖，禁止直接绑定正式 UI 作为免费扩建入口。
- `ActionWorldClock.TryAdvance` 接受调用方在完整行动开始时保存的时间版本及正整数游戏分钟，拒绝同一版本重复推进。重试必须沿用原版本，不能重读最新版本伪装新行动；版本不是救助成功或照护完成凭证。未来装配层须一起处理动作效果和时间提交，避免只完成其中一项。
- 暂停、关闭由未来会话所有者调用；当前无 MonoBehaviour、订阅、Update 或后台计时。快进至领养机会仍需领养事件计划和健康结算规则，不直接把大额 `TryAdvance` 当作完整快进实现。

## ST-02 / ST-03：站内白板与局部清洁

2026-11-17 用户授权“继续下一步，UI 可以搭一个简易能玩的”。本轮先提供独立 Editor 试玩，不等待真实外出结果契约，不将样例入站接入 Main 冒充救助闭环。以上 ST-01 的“未新增 UI”是当时范围，以下为新增状态。

### 试玩入口

Unity 菜单 `Homeless Pet Helper > Preview > Open Station Whiteboard`，再 Play。
场景为 `Assets/EditorScenes/SC_StationWhiteboard.unity`；打开前会询问保存当前已修改场景，不直接覆盖。面板为 `Assets/Prefabs/Panels/Panel_StationWhiteboard.prefab`，后续修改保存的 Prefab，不反复创建。

路径：回站总结 -> 进入救助站 -> 选择动物 -> 查看健康 -> 清洁护理 -> 在动物身上点击、按住或拖动擦洗 -> 完成护理。也可抚摸、返回站内、重看回站记录、暂停或重新体验。

- 三只固定样例：两只脏污、一只初始干净；容量 4。样例身份与站内时钟均由 Editor 会话创建，不是上游救助成功的认证。总结只报告最后一只样例到站，不能在总结直接照护。
- 健康查看当前只揭示“暂无紧急情况（样例）”，不计算骨折、疾病或治疗。清洁按钮在查看前禁用，抚摸不受这一检查限制；不把这个样例门槛当正式医疗方案。
- 总览显示多只动物，进入近景后清洁；清洁效果也会反映回总览。当前是固定样例布局，不是生产动态动物列表，未引入第二套对象池。
- 只试做洗净局部污渍，不包含修毛、剪指甲、康复、关系成长、领养、扩建、发奖或存档。清洁后的效果不回写不可变入站事实，历史记录仍显示原来的入站脏污。

### 技术与资源边界

- 普通 C# `Modules/Station/Cleaning/DirtField` 持有自己的有界样本副本，遮罩外永不生成脏污；验证非法/非有限坐标、尺寸与强度，局部圆形笔刷只能减少污渍。没有 UnityEngine 依赖。
- `Modules/Station/UI` 仅做展示和输入。全部界面层级预先保存在静态 Prefab，字段显式绑定；没有运行时手拼 UI、名字路径查找或 Resources 加载。统一 1080×1920 CanvasScaler，复用已有 `SafeAreaView`。
- Editor-only `Scripts/Editor/StationPreview` 独立程序集负责样例装配、噪声生成、进度和行动时间提交；关闭/重载时对称解绑，关闭会话并释放字体。界面持有自己创建的污渍 Texture2D，禁用/销毁释放，重开从样本恢复。
- 两张动物 PNG 从仓库 `src/Pet.jsx` 的既有静态绘图栅格化，未移植 Web 玩法。工具为 `tools/station-art.mjs`，使用 esbuild、React 与 sharp；sharp 从 `CODEX_NODE_MODULES` 指定的可用依赖位置解析。临时艺术资源位于 `Assets/EditorScenes/StationArt/`，不是正式美术选型或批量图片制作。
- 遮罩是 128×128 的 TextAsset 二进制数据，和动物图使用一致的归一化坐标，排除透明边缘、阴影和眼鼻。噪声限制在遮罩内；静态图关闭 Read/Write、MipMap，最大 1024、单 Sprite、FullRect，当前 Editor 样例不压缩。没有提交字体文件，没有启用生产资源加载框架。
- 首次创建通过 `StationAssets -Isolated`；导入修正通过 `StationArt -Isolated`，仅修改本轮自己的 Prefab/导入设置，并保留 GUID。两者拒绝在交互编辑器直接执行；创建命令拒绝覆盖已有资产。已有选项/停车棚 Prefab、Main 与构建场景列表不改。

### 暂定试做参数

- 清洁笔刷半径为归一化图片宽高的 0.12；128×128 噪声，固定样例种子。点击/拖动每采样消减 24，按住约每秒消减 320，单帧时长封顶 0.05 秒。它们均可调，不是正式平衡值。
- 初始污渍质量消除至少 97% 后可按“完成护理”，提交成功才清除最后细小残留。中途返回保留局部擦除进度，不推进时间；重新体验才重建样例。干净动物不会被重新加脏，仍能选择一次护理并确认完成。
- 一次完成暂用 20 游戏分钟，开始时保留时间版本，重复完成、未达阈值、暂停和过期提交不多推进。查看、抚摸、打开记录、闲置以及逐个擦拭不推进时钟。可重新发起新的护理，这是新行动，不会自动给奖励。
- 手动暂停、焦点丢失、后台和根面板禁用取消当前按住输入；恢复后必须重新按下，无挂机补算。不同触点不能接管同一次笔刷。
- **尚未实现**随游戏时间积累脏污、感染/患病、日夜背景或快进领养结算，不能将显式时钟存在误认为这些系统已经接通。部分清洁的最终时间语义也仍可根据试玩调整。

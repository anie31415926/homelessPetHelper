# 毛茸茸救助站：游戏设计总纲

更新：2026-11-18。用途：记录共识、控制首版范围、按模块逐项讨论。

本文是迭代中的设计底稿，不是所有系统均已定案。标记含义：
- **已确定**：来自当前讨论的明确共识。
- **原型暂定**：为了可试玩而采用，可随验证结果修改。
- **待讨论**：尚未确认，不应据此直接扩充开发范围。

## 1. 产品定位

**已确定**
- 2D、竖屏、休闲动物救助站，目标平台为微信小游戏。
- 前期动物以猫狗为主，动物种类可按实际制作情况调整。
- 两个重点：外出救助的操作乐趣，以及救助后互动的可爱、暖心反馈。
- 经营、任务等外围系统尽量简化，不让养成负担盖过救助和互动。
- 不采用给动物排价值高低的随机品质机制。
- 玩家串门暂不做。

### 2026-11-17：状态与失败边界

**已确定**：动物采用可组合状态，涵盖需求、伤病等健康状态、正负精神/情绪及当前行为，各类用枚举或类管理；具体类别边界和转换尚待设计。救助可失败，处理不当可引起应激、情绪极端化，部分情况需要合理处理才可能挽回。

**2026-11-18，健康状态来源已确认**：动物首次出现时即确定初始健康状态，之后在同一个体的最新状态上持续演变。现场与站内检查读取、揭示当前情况，不在首次检查时才生成，也不因重复检查、回站或再遇重新抽取；情绪缓和不代表伤病消失。具体初始伤病范围、生成方式、处置和康复变化仍待细化，本次不批准新的随机患病或自动恶化规则。确认及实现边界见[照护文档 6.9](站内照护措施与交互.md#health-state-source)。

**死亡边界已确定**：用户选择允许极少数、反复忽略明确警告才可能触发的死亡；正常认真救助不通过随机死亡制造风险，普通失误或本次失败不等于死亡。

**手册与应激容错方向已确定**：开局获得一本救助手册，记录各类情况的应对方法，选项可来自手册。应激时正确处理可挽回；方法正确但顺序不合适，至少不再恶化；选错仍保留呼叫救援的机会。顺序按关键前提判定，允许多条合理路径，不设置唯一正确操作串。

**行动组织方向已确定**：每回合从选项池抽取行动供选择，类似卡牌；动物也需主动回应，提供周旋和对抗的乐趣，而非完全被动。用户确认应提前透露动物的大致意图，避免完全碰运气，但不直接标出最优选项。并未因此确认组牌、稀有度、升级、能量或完整卡牌战斗系统。

**回应结算方向已确定**：首轮由状态、现场条件、相关历史、预告倾向与玩家行动决定动物回应，不额外判定隐藏接受/成功概率。相同相关条件得到一致规则结果；玩家改变条件后，回应可有原因地改变，不把意图当作无视操作的固定脚本。具体意图清单、优先级、行动前提与效果仍待细化。

**基础行动分工已确定**：退开解除距离压力；等候满足恢复前提后逐步稳定情绪，前提不足时稳住不推进；放食提供取食机会，不直接等于信任或情绪达标；接近依据动物是否接受当前距离推进，明确抗拒时继续逼近可引起退缩/警告。允许先退开再放食或先放食再退开等合理路径，具体状态转换、数值和失败幅度仍待细化；完整行动池未定。

**主动靠近与接近许可已确定**：动物不再感到玩家威胁、条件合适时可以主动靠近，作为安全感建立后的正向反馈，不只显示数值下降。接近许可与愿意接受救助分开，主动靠近不直接等于愿意被带走；已满足接近条件不强迫再用接近选项，也不要求每只动物都必须主动走来。具体触发条件与回应表现待细化。

**误处理与进展承接已确定**：普通失误以退缩、警告、影响当前接近机会为主，不将全部进展清零；进入应激后先满足恢复前提，再逐步恢复。已进食、已清除干扰等事实保留，不要求重复整套流程；恢复不自动等于完全信任或健康恢复。具体触发、损失/恢复程度与失败边界未定，不将高容错扩大为任意失误均可挽回。

**分层逃离与再遇方向已确定**：反应结合逃跑倾向程度与当前状态；倾向非常强烈、达到应激程度时可以迅速离开视野，不要求所有动物走完同一退缩流程。逃离的同一动物可再次出现在原处或其他地点，继续救助，不等于死亡或永久失去。具体触发、预告、离场结算、再遇时机和跨相遇状态更新细则仍待讨论；不新增隐藏随机判定，也不将全部应激或失败等同于逃离。详见[确认记录](回合交涉与组合流程.md#已确认分层逃离与再次相遇)。

**个体持续经历已确定**：每只出现的动物都有连续的状态、一定记忆与变化，可跨多次相遇继续救助；需求与情绪随间隔和经历更新，不因再遇重新初始化。允许非常棘手的动物通过多次接触逐步获得救助机会；具体记忆、变化与救助条件未定，不默认累计次数必成功。送出后清除详细个体数据，仅保留名字与形象纪念，具体归档边界见 G 节；当前均未实现跨相遇保存。详见[确认记录](回合交涉与组合流程.md#已确认个体记忆多次救助与送出归档)。

**玩法主次已确定**：动物自主性和玩家应对策略是普通救助的核心，不能仅高难个体有主动行为；多次才能救助的棘手动物要做，但属于额外挑战，不是主要循环。优先验证常规相遇的意图线索、多种合理应对与主动回应，再复用到高难个体，不以扩建挑战系统代替主玩法改进。文字推演方向已获认可，具体细节仍待确认，见[主次与推演记录](回合交涉与组合流程.md#已确认主玩法与挑战玩法的优先级)。

**真实参考方向已提出**：用户认可普通相遇的推演方向，并建议参考真实救助来丰富动物反应与应对策略。首批[个案与行为参考](真实救助案例与行为参考.md)已整理；报道事实、一般指南和游戏改编分开，不将成功故事当作概率依据或现实处置教程。具体行动、行为组合与供给规则仍需讨论，本轮未改代码。

**2026-11-18，选项归并与交流分工已确认，画面/局面效果讨论中**：先细化选项设计，再实现正式距离与画面承接；用户最新要求同步讨论选项的实际画面与情形影响。首批真实参考候选按用户认可的建议收敛：侧身/避免直视与猫适用的慢眨眼归低压交流；可控噪声与围观者归降低干扰；了解情况为情境对话、调整安置归已有准备入口，不另设唯一必抽牌。低压交流改变玩家姿态压力，轻声回应接续动物已主动发起的关注/交流，二者不等于同一安抚加分。十类方法的可见动作、局面后果、连续退开与分支推演见[效果草案](现场救助选项候选清单.md#画面与局面效果草案待确认)，新增细节仍待认可；熟悉垫物与食物引导仍是待选情境用途。不将画面讨论扩大为条件、耗时、供给完整性、Unity 开工或正式美术获批，也不扩成一次确认全部 16 项。

**2026-11-18，重复后果与幽默干扰选项进入讨论**：用户认为长回合选项仍少，明确要求设计重复动作的实际变化，并加入秒回女友消息、拍照发抖音等生活干扰，文案可以幽默抽象。十类真实方法不是全部可选内容的上限；[新提案](重复行动与趣味选项设计.md)区分方法随条件延续、轻松包装与有短后续的插曲，不按第三次必烦或隐藏概率处理重复。新增候选、效果、每手插曲限额及供给例外尚未确定；“无直接救助收益但有趣”的主动选择不能与写着有效却不发生变化的故障混同，也不靠笑话或换名填补真实方法覆盖缺口。仍保留每回合稳定选择、常驻查阅/求援及独立收尾，本次不批准实现、角色设定、恋爱/涨粉系统或真实平台发布。

**选项锁定、消耗与刷新已确定**：玩家可自行锁定/解锁未使用选项，保留到下回合或更后的回合；选项使用后正常消耗，锁定项也不例外；随回合自动刷新，只替换未锁定项，不自动让保留项过期。首轮按三个选项、使用一个、最多锁两个试做，不作为最终平衡。

**扩展要求已确定**：按项目规范，为更多行动内容、更多可选位置和未来每回合多选保留边界；不把首轮 3/1/2 写死在结构或流程中。当前只开放单选，多选的执行顺序与动物回应时机未定，不因此预建完整卡牌框架。具体约束见[选项扩展与多选边界](回合救助最小试做草案.md#选项扩展与多选边界)。

**抽取容错已确定**：查手册/求援常驻、不参与抽取；每回合至少有一种能稳住局面的选择，但不保证推进救助或抽到最优方法；可抽到暂缺前提的方法并由玩家锁定留待后用。

**重复处理已确定（2026-11-18）**：本次已无意义的方法不再新发；同手牌含锁定项去重，不禁止后续仍有作用的重复，保留准备价值与安全兜底。无意义锁定项仍保留并说明原因，当前不可执行、不消耗，玩家自行解锁后按正常回合刷新。不得用无效重复凑足三个位置，也不擅自减位置或解除锁定；已在 Editor 停车棚案例小范围接入，其他个体候选不足的补足方案仍待讨论，不代表正式动物系统已经覆盖。详见[处理规则](普通相遇推演-食物与接触边界.md#选项供给与重复处理)与[实现记录](停车棚救助案例试做.md#最新执行检查点选项适用性与安置回应)。

**救助收尾已确定**：愿意接受救助后不再等抽牌，提供独立完成操作；按钮可暂用“救助成功”，后续按动物类型调整文案，不强制所有动物使用“邀请进箱”的流程。用户进一步确认玩耍、抚摸是可选策略，不是普通救助前置条件；适宜安置条件和动物明确接受成立即可收尾，不要求先完成亲密互动。此项不将取食、接近或玩耍直接等同于接受转运，也不跳过必要现场医护；具体接受判定与表现仍待细化，见[案例确认记录](普通相遇推演-食物与接触边界.md#已确认与下一步)。

**接近与安置反馈已确定（2026-11-18）**：允许接近、试探安置、明确接受要有可读区别，不作为每只动物必走的固定阶段。适宜条件与明确接受回应共同支持收尾，本例用自行进入并放松安顿表达；不以僵住不动或停止挣扎当成接受。现有 Unity 样本已接入实际试探与接受状态，触发仅为该健康样本的暂定条件，不等于全部动物的正式判定或美术方案。详见[反馈记录](普通相遇推演-食物与接触边界.md#接近与安置反馈)与[实现记录](停车棚救助案例试做.md#最新执行检查点选项适用性与安置回应)。

**现场简易医护已确定**：成功接近、可救助时发现明显伤病，可打开简易医疗包扎窗口；与站内医护同源，只限制现场可用范围，不做两套系统。按安全转运需求决定必要性：轻微且不影响转运可回站处理，影响转运且现场能处理则先完成必要处理再结算成功；超出现场能力保留求援出口。用户选择动手包扎，不采用选完方法后自动播放作为主要操作。

**待讨论**：具体可处理范围、医护工具与手势、完成判定和中断/失败规则；具体行动/前提/动物反应和接受条件、安全保底、资源成本、双方结算、未来多选规则、手册查阅、救援结算；具体死亡条件与警告；累计 Game Over 的口径/阈值、是否为停业结局及存档影响。下一步细化具体行动、动物回应与安全保底，不自行实现这些规则。

详细确认记录见[回合救助玩法更新](回合交涉与组合流程.md#正式规则讨论更新2026-11-17)。旧 HTML 原型保证恢复的行为不再代表正式约束；本文后面的迷宫/网兜细节保留为历史探索，当前救助方向以解谜或清理开路接回合救助为准。

## 2. 总流程

**已确定**

2026-11-16 本轮进一步收敛：外出阶段随机在“场景解谜 / 清理开路”中二选一，到达动物处统一接回合交涉救助，之后回站。单轮目标几分钟，避免过度烧脑。新组合原型详见《回合交涉与组合流程》。正式数值、关卡生成量和内容寿命尚未确定。

```text
救助站
  -> 外出
  -> 探索 / 走迷宫
  -> 抵达动物救助地点
  -> 移动站位 / 等待时机 / 可选投食 / 网兜救助
  -> 回救助站
  -> 照顾与互动
  -> 再次外出，或决定动物最终去向
  -> 回到救助站，继续循环
```

放归、领养是动物可能的最终去向。具体适用条件待定，不把猫狗放归作为默认行为；后续需结合物种、健康、原生活环境及救助目标确定。

## 3. 分模块清单

### A. 救助站

**已确定**：出发与归来的中心，承接动物照顾、互动和最终去向。

2026-11-17 主界面与单只照护补充确认：

- 主界面同时展示多只已救助的动物，不采用始终只显示一只、左右切换为主的形式。
- 点击其中一只动物，进入该动物的近景进行检查、清洁和互动；主界面负责整体呈现，近景集中承载单只动物的照护操作。
- 此项为玩法与交互方向确认，不代表 UI 已实现，也不自动确定动物自由走动、寻路或逐帧动画；仍遵循静态图片资源约束。

**已确定，救助站成长**：需要扩建照护空间、新增设施及升级已有设施，不仅是建筑等级数字变化。具体边界与待定项见 H 节的[照护空间与设施成长](#station-growth)。

**后续推进约定（2026-11-17）**：用户同意救助站细节边做边考虑，不要求现在逐项确认完所有待定项。在已确认方向内，初始容量、行动耗时、报名数量等易调整细节可先作为明确标注的原型假设小范围验证，再按试玩反馈调整，不将试做数值记为正式定案。会新增玩法负担、改变健康安全后果或强制送养等关键规则，仍在实现对应部分前简短说明并确认；此约定不代表立即实现完整救助站、正式 UI 或未选定的资源框架，也不改变当前核心玩法的执行顺序。

**待讨论**：
- 临时安置的初始容量、每次扩建增量与同时照顾数量；有限容量及逐步扩建方向见 H 节，长期陪伴名额边界见 G 节，不将其直接当作救助站总容量。
- 多只动物在主画面中的摆放、活动范围、同屏数量及近景返回方式。
- 扩建照护空间具体增加哪些容量或功能；新增与升级设施的效果，以及是否影响外出救助能力。

**当前实现边界**：既有简易回站画面与旧养宠原型仍独立保留，不接存档。2026-11-17 ST-01 已新增独立入站、总结快照、容量及行动世界时钟；用户随后允许简易可玩 UI，本轮 ST-02/ST-03 新增独立 Editor 救助站试玩，串起总结、多只动物总览、近景及局部擦洗。样例、20 分钟护理、97% 完成阈值等均为试做表示，不是正式定案；健康仅揭示固定样例，无脏污增长、患病或治疗。未接主场景和真实外出结果，详情与实际验证见[救助站模块实现记录](救助站模块实现记录.md)。不代表新救助站系统已经完成。

#### 2026-11-17：昼夜与行动推进的世界时间

- **已确定，时间方向**：游戏世界时间由玩家进行的动作推动，不随现实时间自然流逝；在线挂机、切后台、离线等待均不推进世界时间，恢复游戏不补算现实经过时间。按行动而不是操作点击计时；清洁与梳理分别按有效护理量、轻伤基础处理按有效步骤结算，详见下方 2026-11-18 确认；其他行动的具体推进量及取消、中断结算仍待讨论。
- **已确定，完整行动与自由操作**：一次外出、一次完整照护作为可推进时间的行动；一次洗澡中的多次点击、长按与拖动合起来仍是一次护理，不逐次推进世界时间。查看总结、翻手册、切换面板、观察动物和随手抚摸等自由操作不耗时，玩家可放心停留和陪伴。不同耗时行动可有不同推进量，不按背景图片数量决定一天内只能进行几次行动；具体数值未定。
- **2026-11-18 已确认，外出无发现与提前返回**：查看地图和出发前取消不耗时；实际外出探索即使没有发现动物，也推进少量游戏时间。中途返回按已经进行的阶段结算，不一律按完整外出耗时，也不按现实操作时长计时。暂停、切后台不算结束外出。阶段划分、各段分钟数和防重复结算方式待试做，不因本条新增逐次点击计时。
- **2026-11-18 已确认，部分清洁结算；续谈确认梳理沿用**：清洁成果保留，主动结束、返回站内或切换动物时按本段有效护理量结算游戏耗时；不按现实操作时长或点击次数计时。暂停、切后台不算结束、不结算。相同有效清洁量分次做与一次做完总耗时一致，只结算尚未结算的成果，不重复扣时、不因反复退出免掉耗时。此规则细化前条的清洁行动边界，不把普通切面板本身变成耗时操作。梳理已另行明确确认沿用该规则，但进度独立、耗时单独调整。完整清洁 20 分钟仅作示例，正式数值与折算精度未定；尚未实现，不扩至医疗步骤计时。详见[清洁规则 7.4](站内照护措施与交互.md#74-部分清洁的成果与时间结算2026-11-18-已确认尚未实现)及[梳理规则 8.4](站内照护措施与交互.md#grooming-care-rules)。
- **2026-11-18 已确认，轻伤基础处理结算**：按有效步骤计时，完成一步只结算该步骤耗时，不按现实操作时长、点击次数或擦除比例。退出保留进度，但未完成的必要处理仍待处理，不能仅退出放行；转交助手只处理并结算剩余部分，同一方案亲手做与委托的总游戏耗时一致，不重算、不等现实倒计时。暂停、切后台不推进时间，不补算离线时间；完成基础处理只进入恢复，不是痊愈。具体分钟数、材料和费用未定，未实现步骤计时或存档，详见[医疗步骤计时规则](站内照护措施与交互.md#medical-step-time)。
- **已确定，主动快进**：临时安置满员时，玩家可以主动跳到有领养机会的游戏时间，再进行送养，具体流程与边界见 G 节。这是玩家主动推进世界时间，不是现实倒计时或挂机补算；通用休息功能仍待讨论。
- **已确定，昼夜与夜间外出**：保留昼夜变化，夜晚也可以外出救助，不设置夜间禁止外出的限制。用户以猫等动物夜间活动为考虑依据；这不自动确定昼夜遭遇表、物种出现时段或夜间难度差异。
- **表现候选，尚未最终定案**：可能用三张静态背景图表达不同时间段；具体分段、图片数量及切换表现未定，不直接扩大为实时光照或复杂天气系统。
- **技术讨论候选，尚未实施**：通过动作完成等事实衔接时间推进，保留模块间的松耦合。建议统一判定并提交时间变化，再发出时间变化通知供背景等表现读取；需要确定顺序与结果的推进操作保留明确入口，不依赖多个事件监听者的执行顺序，也不因该讨论直接引入通用事件总线。
- **技术边界**：一次有效行动只结算一次时间；清洁与梳理分别按主动结束的有效片段结算，轻伤基础处理按已完成有效步骤结算，同一成果或步骤不能重复计入。具体防重复及恢复机制待实现时确定。世界时间与操作手势、动画等局部计时分开，不以禁止世界时间自然流逝为由取消交互所需计时。
- **待讨论**：其他耗时行动、各类行动的推进量与取消/中断规则、一天的节奏、是否主动休息进入次日及其他夜间差异；昼夜是否影响动物遭遇或行为，以及具体影响方式；脏污、康复等状态如何使用世界时间、何时检查风险。不能据此默认所有状态随每次行动增长或立即触发患病。

- 临时安置的具体容量、满员腾位的可选方式及领养快进的边界情况；先腾位再出发的方向已确认。
- 玩家与动物告别时的表现与后续消息。
- 简单候选资料、报名出现节奏与随机规则，以及选择后的确认送养流程。

### H. 目标、奖励与救助站成长

**已确定**：希望有目标清单，完成后获得奖励；救助站需要扩建照护空间、新增与升级设施。称号仍为候选奖励。

2026-11-17 补充确认：救助等级提升可逐步解锁长期陪伴名额，上限及初期范围见 G 节。救助等级的获取方式、数值及其他作用未定，不将其与救助站设施等级自动等同。

<a id="outing-resources"></a>

#### 2026-11-17：外出补给与建设支持

- **已确定，途中补给**：补给作为外出救助过程中的顺带收获，可融入清理通道玩法，不以专程采集作为本轮选定的补给方向。具体可获得物品、出现方式、数量和用途仍待讨论。
- **已确定，外部支持**：完成救助记录、照护或领养后，可获得用于救助站建设的支持。表现来源可以是社区、政府或个人，也可以简化为系统发放；不据此增加政府审批、捐赠者经营或独立社交系统，具体包装尚未定案。
- **确认边界**：本轮确认收益来源与建设支持方向，不自动确定两种货币、物资合成、完整经济系统或具体发奖触发；不将救助等级、支持资源与设施等级合并为一个数值。
- **待讨论**：途中物资与建设支持的用途是否分开、是否需要货币及兑换；支持按单次有效成果还是阶段目标发放、重复照护的收益边界；清理中如何获得补给、是否自动收取、解谜分支的收益安排，以及外出失败/退出时已获得物资如何处理。
- **已有约束继续有效**：清理开路已有安全通道即可完成，不要求全清；新增资源规则不能未经确认就把全清改成救助前置条件。世界时间仍按完整行动推进，不因一次掉落或拾取就默认多推进一次时间。
- **实现状态**：仅记录设计共识，尚未实现掉落、库存、支持结算、设施升级或相应 UI，不因本轮讨论直接扩展开发范围。

<a id="station-growth"></a>

#### 2026-11-17：照护空间与设施成长

- **已确定，成长方向**：外部支持用于救助站建设，建设包含扩建照护空间、新增照护设施及升级已有设施，不仅表现为建筑等级数字提高。
- **已确定，临时安置容量**：等待康复、等待领养等临时安置采用有限容量，随救助站扩建逐步增加，不采用无限收容。初始数量、每次扩建增量及最终上限未定。
- **已确定，满员应对**：出发前提醒容量，允许通过主动快进到领养机会、确认送养来释放位置，流程与未定边界见 G 节；不依赖现实时间等待腾位。
- **确认边界**：扩建可增加临时安置容量，但具体数值、设施提供哪些照护能力或升级效果仍待讨论；不将扩建直接等同于解锁长期陪伴名额，长期陪伴名额仍按 G 节的救助等级规则处理。
- **待讨论**：初始空间与设施、首批可扩建区域和设施清单、具体容量与功能效果、满员提醒与腾位方式、升级条件与消耗、外观变化，以及是否影响外出救助能力。需要入站或去向不确定的救助/探索先腾位，明确不入站寻宠的例外按 G 节执行；不默认加入自由摆放、施工等待、自动照护、临时超额收容或其他尚未选定的安置系统。
- **实现状态**：仅记录设计确认，尚未实现扩建、设施或升级流程。

**待讨论**：救助等级的获取与解锁节奏、目标类型、其他奖励与是否需要货币；空间与设施的具体规则见上述小节。

**边界建议**：先用少量固定目标，不先做日常 / 周常 / 成就 / 通行证多套体系。不以动物品质或售价驱动救助。

### I. 动物个体差异

**已确定**：不做随机品质。

**补充已确定**：每只出现的动物都有持续经历与一定记忆，可有需要多次接触才能救助的棘手个体；不以“品质高低”划分价值，也不要求所有动物同样复杂。个体记忆与变化的具体规则见[确认记录](回合交涉与组合流程.md#已确认个体记忆多次救助与送出归档)。

**主次已确定**：高难、多次接触是要做的额外挑战；常规动物的自主行为及玩家的应对策略先做扎实，不将个体差异只用于增加救助次数。

**待讨论**：品种、花色、性格、习惯、经历与名字哪些先出现，哪些只影响表现。尚未承诺收集图鉴或繁育玩法。

## 4. 按顺序验证

### 2026-11-16：新增玩法比较分支

首次迷宫 / 网兜原型的反馈是“太简单”。当前先不把它确定为正式核心，新增场景解谜、连续清理、动物引导三个独立原型供实际比较。详见《三种救助玩法试玩》。三种均未定案，原循环与动物互动重点不变，后续顺序表中的救助手感阶段先完成玩法选择。

| 顺序 | 本阶段只确定什么 | 下一阶段的进入条件 |
| --- | --- | --- |
| 1，当前 | 迷宫接救助；移动、摆角、出网、投食 | 玩家能自然完成一轮，愿意再救一次 |
| 2 | 迭代救助手感、视角与难度 | 不依赖说明也能判断距离、空网原因和时机 |
| 3 | 一种高反馈的照顾 / 抚摸互动 | 玩家明确感到动物回应了自己的动作 |
| 4 | 救助站承接与轻量照顾 | 多轮救助仍顺畅，不被重复照护打断 |
| 5 | 领养 / 放归 / 留站条件 | 有情感闭环，容量逻辑不制造强迫感 |
| 6 | 最少量目标、奖励与升级 | 服务已有循环，不靠清任务掩盖玩法不足 |

## 5. 目前不做

多人串门、动物品质分级、可自由移动的开放大地图、完整跳跃平台系统、复杂医疗小游戏、离线惩罚、繁育、交易、排行榜、多套货币和完整经济平衡。城市地图点位选择的设计方向见 B 节，不代表已纳入当前最小试做。

## 6. 当前试玩反馈记录

2026-11-17，Unity 回合救助案例已收到实际试玩反馈：整体“还不错”，但行动重复、等待所需选项造成空转，正式版需要更鲜活的动物个体差异。用户随后确认逃离分层、逃离后可在原地或别处再次遇见并继续救助的方向；先吸引停留的具体方法、少量亲人顺利相遇的分布与选项改进规则仍待讨论。详情与下一问题组集中记录在[选项与动物差异反馈](回合交涉与组合流程.md#unity-试玩反馈选项与动物差异)，不据此自动扩展实现。

以下保留为较早迷宫/网兜探索的观察问题，不把自动化测试通过等同于“好玩”：
- 迷宫是否太长、太绕或没有必要。
- 到救助区后是否知道需要靠近。
- 摆动速度、出网速度和动物移动速度是否舒服。
- 食物是可选帮助，还是变成每次必按的流程。
- 一次成功耗时、空网次数，以及是否主动再玩。

# UI 排版与可读性规范

版本：v1.2 · 2026-11-24。适用于本项目地图、清障、回合救助、救助站及其弹窗、指引、提示。**后续 UI 设计、布局修改及 Review 前必读**；涉及实现时同时遵守 [UI 工程专题](conventions/topics/ui.md)。

目标是让玩家在手机上看清场景、读懂状态、点准操作。紧凑来自信息取舍、分组和对齐，不以缩小字号、压缩热区或遮住动物换取空间。

**同时必读[UI视觉样式规范](UI视觉样式规范.md)**：本文负责排版和可读性，样式规范负责当前手绘画风、颜色语义、组件外观与交互状态。设计、换肤、UI素材制作/替换、实现和Review按两份检查，存量是否完成整改另有证据。

## 1. 效力与当前边界

- **必须**是验收底线；**默认**是统一起点，确有理由可在任务记录中写清替代参数、适用界面及验证证据；**建议**可按场景选用。例外记录沿用既有协作流程，不新增逐次审批。
- 参数是针对本项目选择的设计目标，外部规范提供依据；它们不是 Apple、Android 或微信共同规定的数值。
- 当前采用 uGUI、静态 Prefab、1080×1920 基准及统一安全区。新规范不等于更换框架或自动迁移已有界面。
- **存量迁移状态（2026-11-22更新）**：发布时救助底部为狭窄横排、26设计字号及BestFit；用户随后授权检查整改，已增量修改13个UI Prefab，统一字号/热区、费用图标、底栏和长内容滚动。实际范围、最终800/800与90/90及截图见[整改记录](现有UI规范检查与整改.md)。编辑器通过不代表手机物理触控或可读性已验收。
- 规范发布本身不自动改变界面。当前费用图形已使用原生uGUI Graphic接入并与HUD“资源”图例一致，保留手绘素材；不改变扣费时机、手牌数量、动作规则或资源含义。

## 3. 信息层级与屏幕分区

1. **现场操作优先**：动物、通路、落点、可交互物件构成主画面。优先在场景上操作，底部保留当前需要的工具/手牌与主动作。
2. **即时决策信息可获取**：正在操作的玩法页面按需要展示当前资源、费用、必要进度及行动结果预览；地图浏览不常驻这些面板。相同信息只保留一个主要位置，余额与“本次行动后剩余”属于不同语义；放入详情弹窗时须在提交动作前可读，不能误删。
3. **详细规则按需展开**：大量提示和长说明不得直接堆在常驻界面，使用弹窗、气泡或Toast；完整目标清单、首次教学归各自系统；暂停菜单保持暂停/设置职责，不能作为杂项说明抽屉。
4. **同组靠近、异组分开**：卡名紧邻卡图，费用属于对应卡片；资源余额属于状态组；执行/撤销属于计划组。每个操作组只突出一个主动作，避免整排都用强色、粗边和呼吸效果。

背景铺满屏幕，交互和关键信息进入安全区。顶部左右角安放短状态与暂停/目标入口，**顶部中央不安排关键状态、主动作或引导文字**；即使模拟安全区认为可用，也要考虑挖孔与渠道覆盖。底部操作组锚定安全区下缘，再保留内容边距，不能压在手势条上。

现场可用矩形须依据HUD和底栏的实际占用更新，关卡布局消费这一边界；按地点配置路线，不为每张地图复制一套UI。增高底栏后，要回归动物、落点与路线是否仍可见、可点，不能仅确认按钮不重叠。

**关卡主画面必须占最大连续区域**：先计算状态区、手牌/主动作及必要上下文的实际预算，再布置可玩范围；不能用包含大块装饰空白的全图缩略图代替战场。选卡、选择路线等常规输入不应推动或缩小正在操作的场地；路线入口贴合配置坐标。可以紧凑组合状态、缩小装饰并把说明放进目标弹窗，不能缩减价格字号或触控底线。短屏/平板另验兼容预算，不把单一百分比当所有比例的通用达标线。

### 3.1 全屏地图与提示收纳（2026-11-24用户明确）

- 页面级常驻返回统一放在安全区左下角，和安全区左边、下边各留内容边距；弹窗关闭仍留在弹窗内。
- 地图浏览占满根Canvas，覆盖安全区之外的纯画面；常驻导航只保留左下小返回按钮，视觉紧凑但热区仍按本规范。不能再用固定顶部状态栏、底部详情/操作栏挤小地图。
- 场景只保留必要的短地点名；不得直接堆放大段规则、引导、出发耗时、容量说明或“有/暂无求助”等整排状态牌。点地点后用气泡或独立详情弹窗承接，再显示进入动作；不默认自动弹出推荐地点。
- 大量提示只能通过弹窗、气泡或Toast显示：决策信息/阻断原因使用可持续阅读的详情或弹窗，短时结果用Toast，首次操作用独立指引气泡；不能只靠会消失的Toast承载唯一出发限制。
- 地图拖动不改变业务；弹窗打开时拦截底层地图与点位，关闭恢复拖动。返回顺序先关详情，再返回上一级；关闭/主动作保持安全区内且在正文Mask外，正文长时独立滚动。
- 本条优先于旧地图固定摘要/常显状态的布局；历史截图和整改数字只证明当时版本。其他玩法页面按其决策需要保留操作控件，不据此自动删掉必需的工具/手牌。

### 3.2 所有UI通用的制作流程与提示归位

**新界面及改版必须先定主体、再放操作、最后安排提示**，不能先铺满按钮和说明，再把场景塞进剩余空间。设计与实现前在当前任务或设计说明中列清：页面主任务、主体画面/内容、必要常驻信息与操作、各类提示的入口和承载方式。

- **主体优先、按内容收口**：地图、探索和关卡等场景页背景铺满屏幕，主体保留最大连续可视/操作区域，必要控件叠放在安全区；列表、设置和弹窗依内容紧凑排布，不用大块空纸板或固定说明栏填空间。地图的单返回要求按§3.1执行，其他玩法保留实际需要的工具、手牌和主动作。
- **优先就地交互**：能直接点击、拖动或选择场景对象时，优先就地完成；二级动作在点选后按需展开，避免每个交互点再对应一排常驻按钮。入口仍须可发现，陌生图标给可读含义，不能依赖hover。
- **大量提示禁止直接常驻**：规则、教程、目标清单、地点详情和长限制说明按下表归位；操作所需的短状态、价格与必要进度保留清晰获取途径，提交前可读。暂停只承担暂停与设置，不作为帮助、目标和错误的统一入口。

| 信息用途 | 承载方式 | 验收要求 |
| --- | --- | --- |
| 当前操作必需的短状态、费用、进度与主动作 | 精简常驻操作区或当前上下文操作层 | 与主体不互挡，不重复铺面板；不能为减少控件删掉必要操作或决策数字 |
| 完整规则、目标、地点详情、出发限制、需处理的错误或确认后果 | 对应的详情/目标/错误/确认弹窗 | 入口可发现，需要时能再次查看；关键条件在操作前持续可读，确认后果紧邻对应动作 |
| 首次教学、与当前对象/步骤相关的说明 | 独立引导或轻量气泡 | 避让目标与合法输入；强指引沿用逐步输入限制，重复游玩有既定的简要说明入口 |
| 无需处理的短时操作结果 | Toast或场景飘字 | 短暂、不拦操作、不额外遮暗；不能承载唯一的关键错误、限制或恢复入口 |

落稿与实现均检查普通浏览/操作、点选展开、模态弹窗、锁定/空态/错误等实际相关状态。先看未展开任何说明的普通画面是否干净、主体是否充分，再检查详情能否找回、主动作前信息是否齐全。弹窗栈、引导、Toast复用现有组件，文字与控件按[视觉样式规范](UI视觉样式规范.md)统一；不在每个界面再造一套提示系统或字样式。

## 4. 单位与统一尺寸

### 4.1 设计单位和设备单位分开

- 规范以**设计逻辑格 L**标注，基准稿为360×640 L；对应当前1080×1920 Unity基准，**基准换算1 L = 3 U**，U为Canvas设计单位。
- L是设计标尺，**不是设备dp、pt或物理像素**。下面的U数值只用于基准落稿，不保证在所有机型上获得相同实际尺寸。
- 实现时记录CanvasScaler、实际Canvas尺寸、安全区和最终输出尺寸。均匀缩放且无额外父级缩放时，输出像素约为 `U × Canvas.scaleFactor`；再结合设备像素密度/渠道逻辑视口核对可读与触控大小。不能只把屏幕截图的物理像素当作dp。
- 容量示例的320/360/390 L表示保持字体与热区目标的不同可用宽度方案。实际断点按容器可用空间和测量结果判断，**不能把所有机型都除以3后假设天然完成了适配**。当前不同入口的Match值也需逐一核对。
- 通用专题以前的“建议88设计单位”不作为本项目触控达标线。此处的144 U也只是基准稿起点，后续还需目标机触控核验。

### 4.2 字号角色

默认使用当前可用的中文字体和常规/中等字重，正文不改成细线手写字体。手绘感由控件边缘、插画和纹理表达。下表字号均为设计字号，不是字形实际墨迹高度。

| 角色 | 默认 L / 基准 U | 用法与边界 |
| --- | --- | --- |
| 页面/弹窗标题 | 22 / 66 | 默认一层标题；不要重复写场景名、模块名和“温馨提示” |
| 小节/重要结果 | 18 / 54 | 与正文形成层级，不能每行都加粗放大 |
| 正文、主/次按钮、关键状态 | 16 / 48 | 指引、确认后果、主动作、资源余额等 |
| 卡名、费用数字、短次级状态 | 14 / 42 | 底部紧凑标签的默认下限；不能用12档放关键价格 |
| 非关键辅助文字 | 12 / 36 | 仅补充说明；不得承载唯一的规则、按钮含义或禁用原因 |

同屏同角色保持一致。多行正文默认行高约1.4–1.5倍，短卡名可约1.2–1.3倍并检查中文上下沿；具体uGUI字体指标需实测。长文左对齐，短按钮文字居中，费用数字与图标垂直居中；不要让整篇目标说明居中排列。

**禁止**为塞满布局而将关键文字缩到角色下限以下，或依赖无限制BestFit。优先改写重复文案、加宽、换行、增高或重排；可省略的名称须有明确完整查看入口，价格、后果与主动作不可截断。已有Text组件可继续使用，不以排版任务顺带迁移字体框架。

### 4.3 间距、图形与触控

| 项 | 默认 L / 基准 U | 规则 |
| --- | --- | --- |
| 间距阶梯 | 4、8、12、16、24 / 12、24、36、48、72 | 优先从这些值选；4用于图标/数值内部，8用于同组，16或24区分大组 |
| 安全区内左右/底部内容边距 | 16 / 48 | 在系统安全区之外另留；不能把安全区本身当作内容padding |
| 卡片内边距 | 8 / 24 | 需避开九宫格边框与透明留边，按真正可放内容的区域计算 |
| 弹窗内边距 | 16 / 48 | 标题、正文、按钮共用左右基线；按内容高度收口 |
| 标准点击目标 | 至少48×48 / 144×144 | 所有独立按钮、关闭、目标入口与滑块操作区；视觉图案可小于热区 |
| 相邻独立点击目标间隙 | 8 / 24 | 以热区边缘计算；透明扩区不能互相重叠或侵入场景交互 |
| 普通按钮高度 | 48；主操作可56 / 144；168 | 宽度由文字、图标和内边距决定，至少满足触控目标 |
| 图标视觉大小 | 20–24 / 60–72 | 独立入口仍拥有完整热区；不能按透明PNG画布估算可见大小 |
| 费用图标视觉大小 | 16–20 / 48–60 | 放在卡片内部，不单独增加一个小按钮 |

48 L热区与8 L间隙是项目选择的默认底线，不意味着静态截图完成物理尺寸验收。若在目标设备上仍小或难点，应放大或重排。滑块的轨道和手柄要对齐，整条约定操作区可交互，不能只有细线可拖；值域、填充与手柄位置一起验证。

## 5. 常用组件排版

### 5.1 按钮

- 一个按钮表达一个动作，动词明确；同一组高度、字重、圆角/纸边与内容基线一致。按钮宽度至少为内容测量宽度加左右内边距，禁止用固定窄宽度强行截字。
- 图标加文字时，图标在文字前、间距4–8 L；整个组合居中，不各占一半造成虚假留白。图标不得压过动作文字。
- 主动作位置在同一玩法内保持稳定；状态变化可换文字/可用态，不让按钮随手牌减少左右跳动。次动作使用低一级强调，危险确认明确写出后果。
- 正常、按下、选中、禁用、进行中分别定义；选中不能只靠浅绿，需边框/标记等第二信号。禁用仍能辨认含义，必要原因在说明区可见，不能靠变透明隐藏。
- hover只增强桌面反馈；触屏按下与选中必须独立成立。视觉动画沿用统一动效预设，命中根和强指引目标不随缩放漂移，见[动效记录](关卡表现与轻动效.md)。

### 5.2 费用：资源图标加数字

**卡片内的重复“费用 N”默认改成「资源图标 + N」**，按以下契约设计后续实现：

1. 数字保留动态文本；不把价格、单位、名称或按钮文字烘进图片。图标和数值作为一个整体排版，间距4 L，位数变化不推挤卡名。
2. 图标表示**现有规则实际扣除的资源**，与余额HUD采用同一资源标识和图形。当前只明确称“资源”，本规范不新增金币/补给等经济语义。已有爪印用于动物蓄力、播放/行动符号用于玩家蓄力，不能借来代指费用。
3. 余额HUD常显资源名称、图标与数值；卡片借这个常显图例省略重复文字。新图标含义尚未建立时保留短标签，并用首次引导/目标说明解释；不能只在hover或长按后才知道是什么。
4. 费用区是卡片内容，整卡负责选择/拖拽；不新增微小可点击角标。详情另有入口时须明确可发现，也要兼容当前拖拽操作。
5. 0费用仍显示图标与0；资源不足同时提供可辨识状态及“资源不足”等文字说明，不只变红。已计划、已选择和不可用属于不同状态，不得共用一个灰色外观。
6. 费用上角标或独立小行均可，同组统一位置；至少验证0、一位、两位、三位数。超过已验容量时扩大/重排，不能裁价或用含糊缩写替代决策数字。
7. 计划总费用/行动后余额用紧邻计划组的简短汇总呈现，不能把每张卡费用、当前余额、预计余额混在同一数值里；展示变化不能改变业务实际扣费时机。

### 5.3 状态、进度、提示与弹窗

- 短状态在同一底板对齐，标签与数字相邻；高频变化的数字预留位宽，避免整组抖动。进度条有可辨识的含义，不能只靠两条不同颜色猜测。
- 场景上短提示就近显示，避开动物、落点与手指遮挡；时限内需要读取的关键信息不能只闪一下。长说明移入目标/指引，不能用底部小字把所有规则常驻。
- 强指引气泡按当前正文收口，使用轻量底板；必须避让本步所有允许点击/拖拽的目标、同屏可用控件及顶部中央挖孔区域。目标移动、分辨率/安全区变化、步骤推进后重新定位，气泡本身不截获合法输入。验收逐步覆盖选卡、路口、执行和清障操作，确认说明仍可见、可读，不能仅靠把气泡隐藏来通过遮挡断言。强指引遮暗与暂停等模态遮暗分别配置，均沿用全屏遮罩管理。
- 弹窗默认宽度为安全区内可用宽度减两侧16 L；大屏建议最大360 L，过长正文在内容区滚动，标题、关闭和确认操作仍可达。高度随内容收口，不做固定大纸板留下大片空洞。
- 同层操作先主后次，左右顺序全项目保持一致；默认主操作在右，取消/返回在左。放不下时改纵排且主操作在上，不能缩字。多层返回、确认保留现有弹窗栈职责，不复制遮罩和暂停逻辑。
- 沿用[全屏遮罩约定](conventions/topics/ui.md#s-6-3)：遮罩覆盖完整Canvas，交互卡片留在安全区，多层弹窗共享一层遮暗；不因缩紧卡片而只遮卡片背后。

## 6. 底部操作区：本次问题的标准模板

### 6.1 内容结构

默认将底部拆为相邻的「进度/计划摘要」「手牌组」「主操作」，职责清楚、彼此对齐。摘要无内容时收起其占位；主动作与撤销只在既有规则允许时出现，不新增动作。

手牌默认采用**物件展示区 + 名称区 + 费用角标/小行**。同排卡名底边对齐，卡图等比例居中；不要继续在约80 L宽的卡内左右硬分“图片 + 四字名称 + 第二行费用”。

| 模板参数 | 默认 L / 基准 U | 容量要求 |
| --- | --- | --- |
| 卡宽 | 至少80 / 240 | 以文字、图标和状态共同测量；不是一张卡必须永远固定80 |
| 卡高 | 起点128 / 384 | 可增高；默认含8内边距、20费用区、40图形区、36名称区及分隔间距 |
| 名称 | 14 / 42，最多两行 | 例如四字名称可单行，长名可两行；超过两行用改写/更宽版式等处理 |
| 费用 | 14 / 42，图标16–20 | 与卡图、名称、选中标记各有独立空间，不能互相叠住 |
| 主操作 | 起点64×56 / 192×168 | 仅适用于“执行”等短文案；更长动作按内容加宽并重新算容量 |

模板为起点，字体实测和内容变化可能要求更宽/更高。卡片选中边框不改变布局尺寸；剩余少量卡片保持尺寸与槽位规则，不为填满空间突然拉成巨卡。

### 6.2 容量公式与重排

以下W是安全区容器的可用设计逻辑宽，尚未扣内容边距。M为单侧边距，B为主按钮宽，G为卡组/主动作间隙，g为卡间隙，N为当前需展示卡数：

```text
主动作同排：cardWidth = (W - 2M - B - G - (N - 1)g) / N
主动作另排：cardWidth = (W - 2M - (N - 1)g) / N
```

示例取M=16、B=64、G=8、g=8；80 L为本模板最小卡宽：

| 可用宽W / 卡数N | 主动作同排卡宽 | 布局决定 |
| --- | --- | --- |
| 390 / 3 | 90 | 可同排；仍需核对内容和场景高度 |
| 360 / 3 | 80 | 同排容量边界；主动作变长就必须重算 |
| 320 / 3 | 66.67 | 不满足80；主动作另排后每卡90.67 |
| 360 / 4 | 58 | 不满足80；另排后每卡76，仍需更宽容器或额外卡行/手牌抽屉方案 |

**三张是当前布局例子，不是业务或数据结构上限。** N=0时显示明确空态，不参与除法；N=1/2时不自动填满整行拉伸。容器宽度、文案或N变化后重新选择版式，按事件更新，不能每帧计算布局。

空间不足时按顺序处理：去掉重复标签和空占位 → 分离主动作与卡组 → 卡片换行/增加展开区。关键信息、主操作与即时可选项保持可达；若使用滚动/抽屉必须有明确更多提示，并处理其与卡片拖拽的手势冲突。回合中的可选卡不能无提示藏到屏外。具体超大手牌交互在出现真实需求时单独设计，不由本规范定玩法。

底栏加高影响场景空间时，先检查现场可用矩形和路线；不能反过来把字号降低。短屏可减少辅助常驻说明、调整分组或采用展开区，但必须保留价格、关键状态和主动作。

## 7. 画风与工程落地

- 沿用当前清新手绘版：轻纸纹、柔和底色、细线边缘、克制的小装饰。**文字/数字区域保持干净**，不要把浅灰字放在浅黄纹理和高亮背景上，也不要每块纸板都加大花边。
- 项目默认所有有意义文字对比度至少4.5:1；必要图标、控件边界/状态至少3:1。此处对文字统一取4.5:1，不借“大字”例外降低关键文字要求。WCAG对不可用控件有例外，但本项目仍要求禁用含义与原因可读。
- 对比检查针对实际合成背景：半透明纸板叠在最亮/最暗场景区域后复核，不能只量原始PNG底色。必要时提高内容底板不透明度，而不是让文字描边越来越粗。
- 颜色不是唯一信息：选中加标记/边框，不足加说明，完成加形状/文字。装饰hover、阴影无需当成每个状态都必须单独满足3:1的规则；关键识别信号必须满足。
- 静态Prefab保存结构、锚点、布局约束、初始状态和Inspector引用；Prefab Mode局部修改，不重跑创建工具覆盖素材绑定。运行时只绑定数据/状态，Cell复用沿用既有机制。
- 字号、间距、尺寸采用有语义的共享样式/布局参数，优先复用已有配置入口；本规范不授权新建全局框架。玩家文案继续本地化Key，资源图标走显式引用；禁止为每个面板散落一组硬编码数值与中文。
- 九宫格的border只定义可拉伸边界，**不自动等于内容padding**；核对透明边、可见边与实际内容区。图片按比例展示，不能拉扁动物或把物件撑满卡片。
- 稳定的点击/拖拽根与动画视觉子层分离。指引孔、焦点、遮罩及命中目标跟随实际布局，复用/关闭清理状态；不能为布局示例绕过既有弹窗、引导和动效管理。
- **Mask 下的动效必须验收裁切范围**：在任何 `Mask` / `RectMask2D` 列表或容器中新增按钮动效或其他动效时，检查完整动画轨迹，包括最大放大、缩小后回弹、位移、旋转及曲线超调；文字、描边、阴影、装饰和特效都计入可见范围。布局需为运动范围预留内边距/间距，稳定热区保持不变；不能只检查静止矩形，也不能通过关闭 Mask 或随意设置 `maskable=false` 绕过列表裁切。验收覆盖首项/末项、滚动到两端、完全可见条目、长短屏和实际交互状态；设计上允许的滚动边缘部分露出须明确，完全可见条目的有效动效不得意外被截断。

## 8. 每次 UI 任务的检查清单

### 设计与实现前

- [ ] 任务记录注明已读排版/视觉规范及版本，按§3.2写清主任务、主体画面、必要常驻信息/操作、各类提示的入口和承载方式。
- [ ] 普通浏览/操作态先完成主体预算；长规则、教程、目标与详细限制已经归入弹窗/气泡/Toast，不用固定说明栏或多排按钮挤占主体。
- [ ] 列出内容容量：最长已支持名称/文案、数值位数、卡片数量变化和空态；未知上限注明，不能写死当前样例数。
- [ ] 标注L与基准U、字号角色、热区、间距、安全区和场景可用矩形；主操作放不下时有明确重排方案。
- [ ] 费用图标与实际资源语义、余额图例一致；缺图时保留可读的文字占位，不临时借用有其他含义的图标。

### 交付前

- [ ] 分别查看普通浏览/操作、点选展开和弹窗状态：主体充分、无大段常驻提示，详情入口可发现，操作前决策信息完整；Toast不承担唯一限制/关键错误。
- [ ] 同比例查看实际手机尺寸的画面；分别记录“看得下、看得清、点得准”，不以无裁字断言替代其余两项。
- [ ] 模拟至少320/360/390逻辑宽，并覆盖16:9、18:9、19.5:9、20:9与4:3兼容布局；注明模拟视口、CanvasScaler、安全区和输出像素，不能把这些截图称为目标设备dp验证。
- [ ] 检查顶部挖孔/渠道覆盖、四边安全区与底部手势区。动物、场景交互点、路线和主操作不互挡，底栏重排后也成立。
- [ ] 覆盖长名、费用0/一位/两位/三位、余额增长、手牌0/1/2/当前满手/超出单行容量，以及正常/选中/已计划/不足/禁用/恢复状态。
- [ ] 有 Mask 的列表/容器逐项检查动效完整轨迹的最大可见范围，覆盖 hover、按下、选中、回弹、位移/旋转及曲线超调，包含文字/阴影/特效；检查首尾条目和滚动两端，确认完全可见条目的动效不被裁切，热区稳定且列表裁切仍有效。
- [ ] 点击与拖拽热区不重叠；滑块首尾、填充、显示值一致；hover缺席时仍可用；多层弹窗返回和强指引定位正确。
- [ ] 实际合成画面对比度通过，禁用含义可读；长文换行与价格完整，按支持的最长文案验证。若调整文字大小，另查放大后的重排。
- [ ] 保存对应截图、实际验证范围和未验项目；界面实现改动运行必要的Unity回归，纯文档不冒用历史测试。目标手机手感、微信渠道覆盖及物理尺寸未验时明确记录。
- [ ] 例外有参数、原因及证据，更新对应模块记录/协作任务；未实现的方案不写成已落地。

推荐后续迁移顺序：**救助底部手牌与费用 → 清障底部工具/主操作 → 共同状态区 → 其余弹窗和地图/救助站**。按真实使用反馈逐处迁移，不在一次布局修改中重做所有界面。

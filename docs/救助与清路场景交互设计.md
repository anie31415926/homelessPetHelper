# 救助与清路的场景与直接操作设计

2026-11-21。根据用户对运行截图的反馈整理：救助三路要融入地点，按钮减少，主要操作直接在场景中完成，并与之前清路联动。

**状态：设计提案，供确认。** 已有三路、玩家决策暂停、手牌费用、场上自然/付费合体和改道继续沿用。下述场景布局、输入方式和清路联动尚未改入Unity。可点示意在[现场界面示意](prototypes/field-ui-20261121/index.html)，用现有小院图和程序形状说明空间关系，不是最终美术或新的战斗实现。

## 1. 建议的整体方向

把开路与救助做成**同一个现场的两个阶段**。同一相机、同一入口、同一只动物、同一套箱子/花坛/地面；清理后只切换操作工具和行动界面，镜头可轻推近，但现场不能突然换方向、搬动物或恢复已清掉的杂物。

社区地图仍负责选地点；这里的三路属于地点内部，不能把六地点社区插画上的道路直接当三路战场。每个地点有自己的现场布局，结构允许共用，路径位置与场景物件必须逐个对齐。

当前问题根源是：开路是7×8格，战斗是360×360的通用三路，两者各自投影在一张768×1024插画上；动物、障碍、三路没有共同空间定义。单纯隐藏路线或缩小按钮无法解决穿屋顶、路线漂浮及清路前后不一致。

## 2. 救助主屏：场景为主，底部一排手牌

建议以约390×844手机内容区检查布局，比例是设计目标，实际由锚点/布局与安全区决定：

| 区域 | 常驻内容 | 排版目标 |
| --- | --- | --- |
| 顶部约12–14% | 地点、救助进展、剩余时间、我方/动物行动条，暂停入口 | 两条紧凑信息行，不放种子、测试阵地、全量日志 |
| 中部约68–74% | 地面、入口、动物、单位、机关、可读的招式预告 | 场景一直在场，状态说明不挤成大段文字；短屏仍保留可点对象与路线间距 |
| 底部约14–18% | 三张手牌、资源点、一个“行动/等待”按钮 | 不再常驻上/中/下、合体、改道、落点、材料、清空等多排按钮 |

这里仍需要少量界面。手牌解决“用什么”，场景解决“放哪/对谁”，行动按钮解决“何时结束思考”。玩家回合全场冻结的既有规则保留；拖放只生成可撤销的计划影像，按行动后才实际扣费和继续战斗。避免一松手就意外结束整个回合。

动物情绪/救助进展放顶部简明显示，不包装成动物受伤的生命条；单位耐久与机关信息只在选中或变化时显示，强招预告必须始终可见。

## 3. 三路怎样长在场景里

### 3.1 用地形分出路线

同一个出发集结点在左下、动物活动区在右上，沿用既有方向。一条中线、两条侧线绕过真实障碍汇入动物前沿。常态看见的是石板、土路、花坛、棚柱与地面边界，不是三根覆盖在插画上的宽色条。

以小院为例：左侧沿墙石板路，中间穿院的通行带，右侧绕花坛的通道。两个不规则花坛/杂物岛划出三条走廊。单车棚则是沿车架外侧、棚前空地、沿立柱外侧；自行车和棚柱是实在的边界，单位不能走到屋顶或穿过停放车辆。门廊可用台阶前沿、院心与矮墙小径，不能让所有地点机械套同一张三角形。

现有小院/车棚图是环境气氛底图，**还没有为完整三路画好地形**。小院可沿现有地面补少量花坛/铺地；车棚需要调整俯视角度与屋顶占比、保证后场可见。先定灰盒路径与活动范围，再局部改图/分层制作，不能为迁就已生成插画让判定穿过墙和屋顶。

### 3.2 只有操作时提示路线

- 未选手牌：不显示全路线高亮，入口是小型地面标识，单位自己的移动帮助读路。
- 选牌/拖牌：可部署入口扩大热区并出现图形+名称提示；当前候选路线用低透明脚印或短虚线预览，放开/取消即收回。预览只在地面上，不压住动物和单位。
- 选机关：只显示该机关实际射程和说明；取消选择收回。强招危险区与自身预览用颜色之外的形状/纹样区别。
- 路线若被封：真实障碍加不可用标记及原因，不能只灰一条看不见的线。

逻辑路线仍是固定路径，第一版不变成自由画路、任意落兵或全场寻路。路线长度、速度、跨路射程和技能锁区都受几何影响；重新摆路径属于需要回归/平衡的内容，不是只改Sprite位置。

## 4. 主要操作映射

| 玩家想做什么 | 建议操作 | 必须保留的反馈/边界 |
| --- | --- | --- |
| 出一个道具 | 拖底部手牌到对应道路入口；也可先点牌再点入口 | 跟手影像放在手指上方；合法入口吸附，非法区域弹回，不扣费。只规划出兵，不允许任意放到动物脸前 |
| 提交回合 | 一次“行动”；无计划时显示“等待” | 显示费用预览及预计剩余资源；提交时沿用实际规则重检，不因拖拽成功绕过费用/阶段限制 |
| 撤销未提交计划 | 点计划影像的撤销标记，或点空地取消当前选择 | 取消选择与清空全部计划分开，避免误点把已选合体都清掉；底部状态行可展开“撤销计划” |
| 主动合体 | 先点主体→就近浮出“合体”→场内同类候选亮起→再点两份材料 | 主体即结果落点，三份编号/轮廓及费用可见；材料可跨路，不要求靠近，也不把远处材料拖过来重定位；取消不消耗 |
| 带本回合新兵合体 | 出兵计划影像可作为一份材料，在其入口位置做主体或材料 | 保留既有新出兵参与能力与付费总价预检；不只支持“三个已经在场”而丢掉旧能力 |
| 改道 | 点有改道能力的单位→“改道”→点可选目标道路预览 | 新路对应落点/过程显示清楚；按住、叼取、转线状态等沿用现有拒绝规则；不能把所有单位都拖成自由移动 |
| 材料重叠难点中 | 连点重叠区域轮换；选中单位附近出现最多三项可滚动缩略列表 | 确保小屏可选，局部面板可收回，不恢复整屏常驻名单；热区扩大但不改变真实射程/合体半径 |
| 换掉选牌 | 选牌后在底部该牌旁展开“换掉” | 明确这会独占当前回合，单次确认后执行；拖回手牌仅取消，不能误触换牌 |
| 看详情 | 点机关/单位，卡片有明确详情入口 | 长按可快捷看，但不能作为唯一入口；信息在手指上方或底部短面板，不遮目标/危险区 |
| 回站/暂停 | 右上暂停菜单 | 主屏不常驻巨大回站按钮；暂停中必须有继续、回站和已确认的退出存档说明 |

合体和改道属于选中某对象后出现的少量上下文动作，不围着每个单位常驻一圈按钮。不自动选出“最划算的两份材料”；可以预选可用组合，但主体与材料必须能看清、能修改，不能静默吞掉玩家要保留的单位。

## 5. 清理与挪箱：看场景物件，隐藏调试格

### 清理杂物

仍保留手动选择三种工具，底部三枚有图形和短名称的工具卡即可；目前用户并未要求把工具匹配规则删掉，不改成点哪里自动换工具。

垃圾、草丛、泥斑各用独立物件与地面贴花。选工具后直接按住并拖动清理，工具头跟随，进度只出现在正在处理的物件旁；不在每块杂物上常驻“100%”。清除后露出同一张干净底面，边角未清的杂物继续留下。

从入口可达的清理前沿用柔和边缘/物件微动提示；远处不可达障碍不亮。错误工具给物件抖动和短提示，不扣工作量；不能隔花坛、隔墙远程清理。泥斑保持现有不挡路性质，不能因看上去铺满路就偷偷变成必须清掉的路障。

只要安全通路连通就出现一次“开始救助”；不要求清完所有角落，不每清一块就弹确认，不自动跨阶段，玩家仍能看清最终现场。

### 挪箱搭桥

点箱子出现合法移动方向/落点，沿原规则同一行列滑动或点落点；显示可取消的拖动影像，不为贴图改成任意拖动。点允许桥位时露出搭桥操作，放下木板成为现场持久物件；不永久占两枚“挪箱/搭桥”大按钮。撤回一步放工具区小按钮，保留原撤回上限/规则。

方格仍可作为隐藏的规则结构；平时不画整块墙/水沟文字方块。选中时按需显示合法格点/轮廓，素材必须对应格子占位和真实通行边界。不能只把现有方块隐藏而失去哪里可走、哪里不可走的信息。

## 6. 清路与三路联动：推荐先做哪一层

| 方案 | 玩家经历 | 规则影响与取舍 |
| --- | --- | --- |
| **A：同场景、共同入口（建议第一版）** | 清掉入口到前沿公共通道的瓶颈；进入救助后保留箱子/桥/杂物状态，三条已设计好的通道可选 | 开路关键阻挡只放在三路必经的公共段，最小完成后全部三路都真正可走。边角杂物可留，但不能落在战斗路线内。不新增按路开放、战斗中清理和额外资源规则；更容易先验证直接操作 |
| **B：清哪条，开哪条（后续可选）** | 清出一条就可开始救助；多清的侧路带来更多进攻选择，未通道路入口不可部署 | 清路选择实际改变战斗路权；需要新的路权/状态传递、单路可完成性与费用/供给平衡。不能按清理比例猜开路，也不能开始战斗时突然开全图 |

**本轮推荐先用A把两个小游戏真正做成同一现场，同时把数据边界留给B。** 用户当前明确要求联动，但没有确认关闭道路、额外清理成本或战斗中继续清理。B不应随UI改版默默加上。

A不是“清掉任意一条后无条件全开”。关卡必须从布局上保证：当前阶段完成条件要求经过共享瓶颈，瓶颈之外三路早已畅通；搭好的桥若必经，必须真实覆盖该公共段；清理保留物不能与任何战斗路线/机关落点冲突。现有两个通用样例不满足这一场景契约，需要重做一个地点模板并验证，不能只加转场动画就声称联动完成。

B若后续采用，建议仍用固定三路，清路结束时按完整通行空间检查每条路径和单位净空；一条断点仍在就封整路。先只允许救助前追加清理，不在同次战斗加入清路/救助来回切换；一条路是否有解、抽牌是否会软锁必须单独验证。不能因为少开两路就按比例降低救助目标等，任何补偿另议。

### 一轮具体例子（A）

小院入口的一堆纸箱/杂物挡住共同通行带 → 玩家选工具并向里清理（解谜分支则挪箱/搭桥）→ 真正连通后出现“开始救助”→ 原物件位置保持，工具收起、手牌从底部出现 → 选毛线球，三个道路入口短暂提示 → 拖到沿墙入口，出现出兵影像/费用 → 点行动后推进 → 动物预告横扫时区域落在同一块地面上 → 下一玩家窗口点场上主体，选另两份合体 → 完成救助后沿既有回站链路结算。

选错工具、拖到花坛上、费用不足、材料被按住导致不允许改道时均给明确原因，保持原状态；切后台释放拖拽/清理接触并暂停，回前台显示继续，未提交计划不会误变成已扣费操作。退出仍沿最后站内检查点，不新增局中存档或跨次地点清理成果。

## 7. 工程落点与资源制作

以下是实现建议，未创建类或改数据。

- 给一个地点模板定义共享现场坐标、背景内容矩形、入口、动物活动区、可走轮廓/网格、三路与塔位、可移动箱/桥/清理物ID、遮挡层。开路与救助通过同一投影显示，禁用按控件尺寸各自拉满的两套坐标。
- 规则仍各自负责连通/战斗；Game装配层持有本次地点与场地状态，将只读的清路结果传入下一阶段。UI不根据图片颜色猜哪里可走，也不把贴图移走当成规则完成。
- 现场状态至少能描述箱子最终位置、桥是否搭好、已移除的杂物ID及未清工作量。第一版只在本次外出内延续，状态关闭/回站时释放；不扩存档schema。换地图/下次出发不能继承上一局残留。
- 现有Siege基础数值来自`src/siege/definitions.json`、内容来自`src/siege/content.json`并生成Unity配置；不得直接手改生成的`SiegeTrialData.json`。地点布局如何注入Siege地图、旧独立试玩如何保留，实施前明确契约；路径变化后同步检查速度/时长/射程/技能范围。
- 静态Prefab与显式绑定继续沿用。场景中的可交互物件用固定节点或既有池化Cell，uGUI射线/屏幕→现场坐标转换统一；前景不能遮关键落点，热区不能互相抢选。
- 文案、工具名称/反馈均走本地化表。原型里的文案也集中在独立JSON，设计色彩/坐标只属于示意数据，不复制成运行代码硬编码。
- 先做一处小院验证同场景和操作，再做车棚的布局/局部改图；猫狗两种外观和两种开路都能用该布局，不能按物种锁定某个小游戏。
- 背景、可清障物、单位、机关和选择/预告分层。清理前/后不各画一张全屏背景，也不做每条路线各一张大图；共用干净底面和独立物件。新增图制作前按唯一资源台账登记，继续按实际静态依赖计算首批成本，不能把美术分层当成按需加载已实现。

## 8. 建议落地顺序及验收

1. **先审这份布局/操作稿**：确认救助常驻信息、拖放/点选与单次行动、A或B联动深度。
2. **一处地点做灰盒**：固定共同坐标与同一相机，重排入口/动物/三路/障碍，清理与挪箱各一个可解模板。先检查屏幕净空，后画水彩路径；不批量重生六地点。
3. **接直接操作**：卡片拖放/点选替代、场上主体和材料、能力限定改道、撤销、信息查看及暂停菜单，保留原规则入口预检。
4. **同场景转阶段**：清理/箱子/桥的最终状态保留，验证关键路径无穿墙、可见路线与逻辑一致、原玩法均可完成。原三路默认试玩保留用于对照。
5. **再做精细资源与动画**：根据灰盒改一处背景/障碍和道具表现，确认后复制制作流程到其他地点，最后测微信资源/触控成本。

验收重点：390×844与375×667能不打开常驻单位名单完成出兵/合体/改道；20:9到4:3含安全区不裁入口/动物/强招预告；判定热区至少88设计像素并处理拥挤，不用改逻辑半径补外观；卡片拖出屏、pointercancel、多指、切后台不误扣费/重复提交；自然与付费合体、新出兵参与、跨路材料、按住/叼取互斥不退化；清理只需连通、保留边角杂物、错工具不变、桥/箱位置前后一致；两地点连续外出不串状态；原回站/护理/存档继续回归。

HTML只演示布局、局部按钮显隐及共享物件前后变化，不运行真正清路连通、Siege费用/合体/AI或存档规则。它不能证明玩法平衡、所有手牌组合可通或最终美术质量；本轮也未运行Unity/微信真机验证。

# 回合救助行为基线与待定项

日期：2026-11-17。对应任务：P2-01 基础整理。
状态：本页记录 HTML 实验与后续共识，不将原型假设当 Unity 定案；P2-00 讨论尚未全部完成。已授权的独立选项管理已实现，进度见[实现记录](选项管理模块实现记录.md)，不代表整个回合规则完成。

## 已有共识与原型假设

**已有方向**：先开路，再通过观察动物、选择行动和动物回应建立信任，成功救助后回站。体验轻量、可爱，不做动物价值分级；救助可以失败，不再保证每种误处理都能恢复。
**2026-11-17 新确认**：采用可组合状态，涵盖需求、伤病等健康状态、正负精神/情绪及当前行为；各类用明确枚举或类管理。处理不当可引起应激、情绪极端化，可能需要合理应对才挽回，也可能救助失败。
**死亡边界已确认**：只作为极少数、反复忽略明确警告才可能触发的极端后果；正常认真救助不通过随机死亡制造风险，普通失败不等于死亡。
**手册与容错方向已确认**：玩家开局获得救助手册，记录应对情况的方法，选项可来自手册。应激时正确方法与顺序可挽回；方法正确但顺序不合适，至少不继续恶化；选错后仍有呼叫救援机会。用户认可顺序按关键前提判定、允许多条合理路径，不做唯一操作串；具体动作/前提、手册查阅和救援结算的细节未定。
**行动组织新方向**：每回合从选项池抽取行动，类似卡牌，动物也应主动回应，产生周旋乐趣。用户已确认意图应提前透露大致倾向，避免纯碰运气；具体意图、线索、回合顺序和抽取实现细节尚未确认，不据此默认建设完整卡牌系统。
**回应结算方向已确认**：首轮按状态、现场条件、相关历史、预告倾向与玩家行动决定回应，不另加隐藏成功率；相同相关条件得到一致规则结果。意图是可被玩家改变条件影响的倾向，回应变化需有原因；具体阶段、意图优先级、行动前提与效果仍未定。
**四种基础行动分工已确认**：退开解除距离压力；等候在恢复前提满足后逐步稳定情绪、前提不足时稳住不推进；放食创造取食机会而非直接降低警惕；接近依据接受程度推进，明确抗拒时继续逼近可退缩/警告。允许先退开再放食、先放食再退开等合理路径；具体转换、数值、资源与失败幅度未定，完整行动池仍待扩充。
**接近许可与主动靠近已确认**：允许靠近不等于愿意接受救助；动物不再感到玩家威胁、条件合适时可以主动靠近，作为可见的正向回应。已满足接近条件不必再抽接近选项走形式，主动来取食或靠近不自动算接受转运；不要求所有动物都主动走来。具体触发与意愿判定仍待细化，不将其当作已实现结果。
**误处理与进展承接已确认**：普通失误影响当前接近机会，不清空全部进展；进入应激后满足相应恢复前提，保留已进食、已清除干扰等事实，不要求从头重复流程。具体应激触发、接近许可损失/恢复程度与失败边界仍待细化，不保证所有误处理都可恢复；下一步拟在已有隔离案例中用正常与应激两个测试起点验证，新增范围待确认。
**锁定、使用与刷新已确认**：玩家自主锁定/解锁未使用选项，可跨多个回合持续保留；使用后选项正常消耗，锁定项也不例外；随回合自动刷新，只替换未锁定项，不自动解锁保留项。首轮按三个选项、每回合使用一个、最多锁两个试做，不作为最终平衡；资源成本和重复抽取细节仍待确定。
**扩展边界已确认**：须方便新增行动内容、扩大选项数量及后续多选，不把首轮 3/1/2 写死。具体设计约束见[选项扩展与多选边界](回合救助最小试做草案.md#选项扩展与多选边界)；当前仍只开放单选，多选顺序与动物回应时机未定，不据此建设通用卡牌框架。
**抽取容错已确认**：查手册/求援常驻、不进入随机池；每回合至少有一种可稳住局面的选择，但不保证推进或最优方法；暂缺前提的方法可抽到并锁定留待后用。具体保底算法、锁定冲突处理和查阅/救援成本未定。
**收尾方向已确认**：动物愿意接受救助后不再等待抽牌，提供独立完成操作；按钮可暂用“救助成功”或后续按动物类型调整，不把“邀请进箱”写成所有动物的固定流程。具体接受条件与转运表现未定。
**现场医护方向已确认**：成功接近、可救助时，发现明显伤病可打开简易包扎窗口，复用后续站内医护，不做两套系统。按安全转运需求判断必要性：不影响转运的轻微伤可回站处理，影响转运且现场能处理时先完成必要处理再结算成功，超出现场能力保留求援。用户选择动手包扎，不以选方法后自动播放代替主要操作；具体伤势、工具与手势、物资、失败与中断规则未定。
**尚未定案**：具体行动集合、状态类别边界与组合/转换规则、数值展示、距离机制、意图优先级与具体回应效果、资源用量、回合长度及未来多选结算。极端死亡的具体条件，以及累计 Game Over、停业结局、存档影响仍待确认，详见[正式规则讨论更新](回合交涉与组合流程.md#正式规则讨论更新2026-11-17)。

当前原型暂用食物、等待、玩具、接近/邀请四个行动位置；警惕、距离和行为状态影响结果。
三种起点为饥饿猫、谨慎狗、好奇猫。这只是测试样本，不能据此固定物种和行为的对应关系。
警惕阈值、三份食物、约 1.15 秒反应锁定等参数见[组合原型记录](回合交涉与组合流程.md)，本页不另维护数值表。

## 移植前发现的设计缝隙

### 需求与即时反应混在同一个状态中

原型用同一个 `mood` 表达饥饿、谨慎、进食和玩耍。过早靠近会把状态直接换成谨慎，再等待又换成观察。
这意味着饥饿线索可能因为受惊而消失，并不需要实际吃过东西。技术上可运行，但不一定符合正式动物行为设计。

**方向已确认，细节待讨论**：需求、健康、精神/情绪与当前行为需能独立表达，再按明确约束组合，不能受惊后就自动消除饥饿或伤病。
这样能表现“很饿但因受伤和害怕不敢吃”“吃饱了仍不愿靠近”；是否展示数值、食物是否必需、状态如何变化及应激如何处理仍须讨论，不能直接实现。

### 文案与内部状态有不一致

原型中进食时再次放食，文字说“停下进食”，但该分支没有退出进食状态。
正式规则需先决定真实行为，再让文案、动画与状态对应；本轮只记录，不擅自修补原型或把这一细节固化到 Unity。

### 技术原型行为不等于玩法决定

原型在接受行动时立即改变规则值，再锁定输入约 1.15 秒；这不表示最终一定要“立刻结算再播动画”。
持续时间的帧截断、可无限增长的回合日志等也是实验实现，不应直接搬成正式时钟或存档结构。
正式实现须分别处理规则时序、表现完成、中断和有界记录，但先确认玩家实际体验，不先叠通用框架。

## 接下来按顺序讨论

1. **失败的边界，方向已确认**：允许本次救助失败；死亡仅限极少数、反复忽略明确警告的极端情形，不作为正常认真救助的随机风险。具体死亡条件与整局结局未定，不先定累计阈值。
2. **手册与顺序，原则已确认**：手册与三档容错、选错后可呼叫救援、按关键前提允许多条路径已确认。具体提示、查阅成本、恢复窗口和救援结算仍待讨论；结束外出、不带回站、不计责任等仍是建议，未获确认。组合流程文档中的文字示例不是已执行测试。
3. **动物意图与行动，方向已确认**：选项池抽取、动物主动回应与意图提前可读已确认；具体如何改变距离/关注对象/机会、与玩家行动的结算关系，以及具体方法和前提仍待细化。
4. **首轮规格与扩展方向已确认，细化具体回应**：现场简易包扎、站内同源、按转运需求先处理再结算和动手操作已确认；具体工具、手势和反馈留待小范围试做细化。首轮三个选项、用一个、最多锁两个已获认可，并要求保留更多选项与未来多选的扩展边界。接下来通过[最小试做草案](回合救助最小试做草案.md)细化行动、动物意图/回应与安全保底；资源、重复抽取、中断与反应时长仍待讨论，不能让锁定或卡手违背容错与极端后果边界。

确认结果回写[玩法记录](回合交涉与组合流程.md)，与“原型暂定”明确区分，再更新执行计划和正式测试。

# 完整清理解谜与战场重设计

2026-11-25。用户确认清理和解谜要各自成为完整关卡；清理时动物藏在可清物下，同一现场、同一动物、清出来的路继续用于逆塔防；回访只恢复部分障碍。战场按地点换障碍主题，出战单位和防守机关放大、造型更圆，资源移到手边，进度有直观画面。以下首张图、达标条件和数值是落地样稿，尚未进 Unity。

## 第一张验证图：精灵树屋

用户已把首张样板从小院改到现有地图的精灵树屋。地图 Prefab 里的 `Treehouse` 当前是视觉地标，正式地图配置还没有对应地点 ID、求助及内场绑定；实现时加独立地点，旧小院和原存档仍保留。场景底图、可清物与战斗道具见[树屋美术批次](../art-source/treehouse-field-20261125/README.md)。单位的圆润轮廓直接画进 Sprite，继续复用现有绘制与图集。树屋先按真实空间排布：底层、贴墙木楼梯和上层平台，不强行画三条平行路线。楼梯版美术已获认可。首题见[精灵树屋关卡设计](精灵树屋关卡设计.md)：提议清理上楼找猫、逆塔防在底层送达楼梯脚。下文小院题面是历史草案，通路、遮藏与同场接战的原则沿用于树屋；以藤篮盖毯替代草窝，书堆、木凳、卷轴杂物替代户外障碍。

## 前序题面草案：杂草小院

取 `playlab.html` 中三个已有要素：对应工具连续清理、从可达处向内推进、清掉覆盖物后才可见动物；解谜继承直线挪箱、可选桥位、撤回。旧网页里引诱动物自行跟回入口的结局由同场逆塔防接替；也不照搬旧样本的双动物要求，一次求助延续一个已记录的身份。

纵向由下至上分三段。下方从入口清出第一片落脚区，中段绕过两条低矮花坛，各支路各有主要清理对象，上方从两侧汇到藏身角。此图只示意通路骨架，正式关卡的清理摆放和解谜题面分别配置：

```text
       藏身角（当前动物；草窝完全遮住）
      ┌─────────汇合小径─────────┐
      左草径  低花坛  正门路  低花坛  右碎石径
      杂草群          废纸堆          草团
      └─────────入口空地─────────┘
```

- 清理从空地开始。先清杂物，再沿可达边缘用对工具处理草团、杂物或泥斑。泥斑可提供额外清理反馈，只有配置为挡路的物件才影响通行。草窝未清完时不显示动物本体、不允许点到；可用草叶动一下提示。清完草窝并能到达藏身格后，播放掉叶和探头。仍有支路可清时允许继续操作，达标后由玩家轻点开始救助，不自动跳转。错工具不扣进度，未够到时标出最近的可清边缘。
- 同一个小院的解谜版本用不同起始物件和断口，做“先腾出箱子停放位，再滑出交叉口，最后选桥位接到深处”的依赖关系；候选题须有可解步骤、错误布置可撤回。解谜可从一开始看见动物。清理和解谜共用最终道路、地景坐标和动物锚点，避免每套玩法各摆一次地形。
- 首版建议保留现有三条指定路径全部可走才进入战斗的规则。清完整关有明确的形状变化和终点揭露，但边角装饰性杂物不用刷到 100%。当前 `OutingFieldLayout.ValidateBattleClear` 会检查三条路径每一格，`CreateBattleCatalog` 也直接基于它们生成路线；“只开一条就打”会影响部署、换路、教学及回放，应另议。三条路可用性和动物揭露分别显示，解释“已经看见它，哪条路还没接通”。
- 进入战斗只换工具栏和表现状态。沿用已经清出的格、桥和挪过的箱子；战斗路线从同一份已校验的现场生成，剩余侧边障碍继续可见。相机在原地，动物身份和脏污沿用。下兵、合体和换路仍按原规则；改变绘制尺寸不改变站位、选取优先级、射程或部署范围。

## 地点主题与战斗比例

| 地点 | 需要玩家处理的物件 | 安静的分路地景 |
| --- | --- | --- |
| 小院 | 成撮杂草、散纸、抱团枝叶 | 低花坛、碎石边 |
| 单车棚 | 纸箱、掉落布袋、散落修车用品 | 停车线、低挡车墩 |
| 仓库或矿区（后续主题候选） | 木箱、破袋、碎石堆 | 旧轨道、矮木栏 |

用关卡主题把共享物件定义映射到本地 Sprite，并分别配置工作量、是否挡路、是否遮盖动物、是否可在回访恢复。逻辑只认稳定的物件与格子 ID，换贴图不会改变通行。把可操作物件、静态分隔和纯装饰分开：静态分隔低矮低对比，不盖住道具、塔或下兵范围；揭露前的遮盖物是例外，要能读出目标又确实盖住动物。两阶段复用同一套地点贴图和场地状态，不烘焙两张“清前/清后”背景。

单位与塔先用现有图做尺寸白板对照：普通单位视觉轮廓约 **1.3×**，重型、合体与防守机关约 **1.4×**，实战按遮挡微调。正式图调圆轮廓、加宽主形、减少小碎件，让羽毛、毛线球、重车在战场尺寸仍有不同剪影。单位不靠全图同比放大来做 Q；根节点依脚底或轮底对齐。1 费小单位也要清楚可读，不能缩成点。密集同格时用前后排序、限量生命条和区分选中描边处理，不抬高普遍特效数量。场景里的真实猫狗保持可辨比例，战斗道具走 Q 版造型。

左上把文本式进度换成爪印到爱心的小条，保留简短“救助”语义，终点亮起。只有单位实际抵达并产生进度时更新；数字在目标详情可看。战斗资源靠近手牌并用格、短数字和恢复动画表达；卡面费用贴着卡画，买不起时降饱和并用图形状态区分。底部留在安全区内，下一张只在五卡模式有意义时出现。守方不重复放一行余额，塔位继续用占位和施工表现提示。目标说明进原目标面板，普通战斗中不新增执行按钮。清理阶段底部同一位置放工具；发现动物前显示找寻线索，出现后以动物状态和通行目标图标提示还有什么没做。

## 回访与接续

已确认以游戏时间后的轻度恢复为方向。建议定义为：同一次外出中断恢复使用原检查点；结束外出后再次抵达，若游戏时间达到配置间隔且有可恢复物件，才在进场结算补回少量已清物件。首测候选为每次符合条件时补一处入口或中段的轻量物件，保留大部分清理成果；不能补到一两次就堆回初见状态。打开面板、重载、暂停、现实挂机都不重掷。已揭露的同一动物不重新被盖住；新求助是否掩藏按新事件配置。固定墙、已搬好的箱子、已搭好的桥和已保存的撤回历史不拿来做自动恢复对象；解谜主题可为回访配置轻量支路杂物，再确认其操作方式，避免重做整套谜题。

当前存档已有箱桥位置、每块剩余工作量、事件与动物身份；正式实现需增加可恢复物 ID 和地点上次结算标识，避免重进重复补物。恢复在新一次外出、创建战斗回放前结算；已有战斗中断只重放原场地快照。清理进度和救助进度保持分开。旧保存的清理状态照原实例恢复，换图或新增地点变体不改写旧事件。

## 实现先后和试玩验收

1. 用树屋做一张完整的两阶段样板。先定底层与楼梯的可操作范围、盖毯藤篮揭露和一张多步解谜题，用分层候选素材验证。对比现状：开局看不到动物，清出可达区域后仍有内容可玩；战斗前后没有挪路、换动物或重置剩余杂物。
2. 调现有战斗 Prefab 的资源、手牌、进度位置和单位比例，复用底板、费用图标和显示池。检查 320×568、390×844、长屏安全区及多单位拥挤时的字、轮廓、拖放与进度可读性；资源不够时手牌和补牌队列不动。
3. 接回访结算和存档迁移。回站后在间隔前/后各进一次；部分清理、动物刚揭露、已经进入战斗分别中断重进，核对身份、物件、路线、回放及幂等。确认树屋成立后再扩到其它地点，不先批量铺开。

树屋不要求固定三路，救助前应清通哪些通道按题面确定。当前 Unity 场地模型仍要求三条路线，如试做选用其它数量，需要把沿用的路数校验与部署规则拆成关卡配置。回访仍只恢复部分轻杂物。回访间隔、数量及尺寸仍是试玩可调参数。树屋批次是美术候选；Unity 内场和玩法实装尚未验证。

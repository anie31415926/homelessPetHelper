## 本地检查入口

在仓库根执行：

```powershell
powershell.exe -NoProfile -File tools/wechat.ps1 -Task Check
powershell.exe -NoProfile -File tools/wechat.ps1 -Task Probe
powershell.exe -NoProfile -File tools/wechat.ps1 -Task Probe -BuildWebGL
powershell.exe -NoProfile -File tools/wechat.ps1 -Task BuildGameWebGL
```

`Check` 只读显示当前精确编辑器、模块目录、开发者工具位置及项目依赖。`Probe` 在 `test-results/wechat-environment/probe-<id>/` 复制已保存的 Assets/Packages/ProjectSettings，再加入仅该副本使用的 `tools/wechat/WeChatEnvironmentProbe.cs`：检查 SDK 程序集及 WebGL 能力，输出 `ProbeReports/installation.json`。`-BuildWebGL` 在副本以 WebGL 活动平台创建最小摄像机场景并构建开发包，输出 `ProbeReports/webgl-build.json` 和 `ProbeBuild/WebGL/`；不修改正式场景或平台、不进行微信转换。

Git 下载慢时可复用本轮官方干净检出：

```powershell
powershell.exe -NoProfile -File tools/wechat.ps1 -Task Probe -BuildWebGL -SdkCachePath test-results/toolchain/setup-2026-11-18/wechat-sdk
```

`BuildGameWebGL` 使用同样的隔离流程和可选 `-SdkCachePath`，按 Editor Build Settings 的顺序构建已启用的游戏场景（现为 `SC_Loading → Main`），不再生成最小摄像机场景。它输出不压缩、关闭多线程的普通 WebGL 开发包，检查当前游戏代码能否走完 IL2CPP → WASM；不读取账号凭证，不运行微信转换。普通浏览器没有 `wx` API，不能用这份包验证微信存档。

该选项检查 origin、HEAD 和工作区是否干净，只在子进程环境中将官方 Git 获取映射到本地检出，UPM manifest/lock 仍保留官方固定 URL；不改全局 Git 设置。缓存不在其他机器上时省略该参数，由 UPM 正常下载。构建进程清除继承的 `NODE_OPTIONS` 以避免外部 agent 注入影响 Emscripten/Bee；结束后恢复本进程环境。超时限制为 20 分钟，不用其他正在运行的 Unity 作为验证副本。

## 2026-11-25 脚本化导出与上传

用户提供真实小游戏 AppID 后，把原先在 Unity 菜单里手工点的转换固化成脚本，避免每个新会话重新摸索：

```powershell
$env:HPH_WECHAT_APP_ID = "wx..."          # 只放进程环境变量，不写仓库或报告
tools/wechat.ps1 -Task ExportGame         # 隔离副本内跑 IL2CPP + 转换
tools/wechat.ps1 -Task Upload             # 取最新产物，调开发者工具 CLI 上传
```

- `ExportGame` 产出在 `test-results/wechat-environment/probe-*/WeChatCandidate/minigame/`，含 `project.config.json`，不污染工作树。
- `Upload` 取写入时间最新的 `probe-*` 产物，`--version` 省略时按 `0.MMddHHmm` 生成；它需要 AppID 与已登录的开发者工具，但不要求 WebGL 模块，因此单独跳过该检查。
- 开发者工具路径依次尝试 `WECHAT_DEVTOOLS_PATH` → `%ProgramFiles(x86)%\Tencent\微信web开发者工具` → `%ProgramFiles%\Tencent\…` → `C:`/`D:`/`E:` 盘根目录。**本机实际装在 `D:\微信web开发者工具`**，早先写死 C 盘的检测会误报「未安装」。
- 最近一次成功上传：开发版本 `0.11.251424`，主包 1,187,373 B、首资源 13,331,611 B、WASM 5,113,668 B，详见[上传任务](协作任务/20261125-微信开发版本上传-01a20c2d.md)。

**脚本编码约束（踩过）**：`tools/wechat.ps1` 无 BOM，PowerShell 5.1 按 ANSI/GBK 解码，任何中文字面量（含注释）都会与三字节 UTF-8 错位、吃坏后续代码，表现为变量莫名变空（本次 `$devtoolsFolder` 变空导致 `Check` 误报未安装）。中文一律用 `char[]` 码点构造，注释写英文。

### 上传命令

在开发者工具目录执行，参数只保留 ASCII 路径，避免 Windows 控制台中文编码问题。**先 `cd` 到 `cli.bat` 所在目录再调相对名**，这样含中文的工具目录不会出现在参数里：

```bash
# 本机（D 盘）：cd "D:/微信web开发者工具"
# 另一台机器若用默认安装位置：cd "C:/Program Files (x86)/Tencent/微信web开发者工具"
cmd //c 'cli.bat upload --project D:\PetHelper\homelessPetHelper\test-results\wechat-transform-20261124\minigame -v 0.1.0 -d First playable build'
```

CLI 自动拉起工具、复用当前登录态，先打印分包体积表再返回 `√ upload`。首次上传耗时约 20 秒（21.5 MB）。`-d` 描述建议纯 ASCII，避免 Windows 控制台编码问题。

**版本号**：项目惯例是 `0.MMddHHmm`（如 `0.11.251959`），`tools/wechat.ps1 -Task Upload` 会自动生成。本次手工上传用了 `0.1.0`，未按惯例，后台无法从版本号看出导出时间；后续正式对比应以脚本上传为准。

注意：**上传通过不等于没有包体告警**。真机上曾出现包体过大提示，见[真机反馈与复测](#2026-11-25-真机反馈与复测)；硬上限与提示阈值不是一回事，不能用本表证明告警消失。

`project.config.json` 的 `packOptions.ignore` 已排除 `*.symbols.unityweb` 与 `*.symbols.unityweb.br`，合计约 8 MB。**这项必须保留**，删掉会让调试符号进入包体。

### 体验版自动跟进（与旧流程文档不同）

以实际后台为准，实测结论：

- `upload` 完成后，后台「版本管理 → 开发版本」卡片**直接带「体验版」标签**，右侧下拉为「取消体验」，**不需要手动点「选为体验版本」**。
- 同一开发者账号后续上传，体验版自动指向最新开发版本；手机端已保存的入口与旧二维码继续进入新包，不会停在旧版本。
- 开发版本身只能通过扫码获得，且每个开发者本地只有一个；非开发者扫不到开发版。给外部人员仍需在「成员管理 → 体验成员」添加微信号（个人主体上限 15 人）。
- 新版上传后旧二维码与旧入口不作废，与“重新生成码才生效”的旧说法不同。

### 二维码有效期

体验版二维码有 **7 天**有效期，后台明写「该二维码 YYYY-MM-DD 前有效」（例：11-25 生成标注 12-02 前有效）：

- 只约束**首次扫码**的人。已进入过的人入口常驻，并自动更新到最新体验版。
- 过期后回后台重新生成即可，版本与包本身不受影响。

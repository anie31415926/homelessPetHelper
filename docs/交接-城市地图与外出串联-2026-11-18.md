- 一张抽象城市底图 + 少量固定点位；区域是点位分组标签，不是可进入的节点层。
- 首版点位全部可见可用；"按等级/建设解锁"暂不做成系统，只在点位定义里保留"开放条件"字段。

- 求助点与无事件点用明显视觉差异区分。
- 一轮验证例子：3 个点位中 1 个带求助标记，点它出发进现场；另外 2 个无事件点位的点击行为属 B 组"主动发现"，本组未定。

### 3.3 M1 规则层（2026-11-17 落地）

- 新增 `Assets/Scripts/Modules/Outing/`（`HomelessPetHelper.Modules.Outing` 程序集，纯 C#、`noEngineReferences: true`，无 Unity/UI/时钟/随机依赖）。
- 四层：静态只读定义（`CityMapDefinition`/`MapPointDefinition`/`HelpRequestTemplate`）、单局可变态（`OutingSession`/`RequestPoolState`/`PointUnlockState`/`HelpRequest`）、只读快照（`MapViewSnapshot`/`MapPointView`/`OutingSummary`）、规则协调器（`CityMapRules`），另有失败枚举与阶段/信号枚举。
- 事件状态机只实现已确认迁移 `Available -Accept-> Accepted -Resolve-> Resolved`（单一入口 `TryTransition`，Resolved 唯一终态）；会话固定 seed 与时间版本、出发/结算各防重一次；选点校验"点位开放 + 有可接求助"，无事件点位只返回"无求助"这一事实。

### 3.4 M2 会话串联（2026-11-18 落地）

- **阶段链路**：`RescueStage`/`RescueSignal` 插入 `Map`/`Depart`（值为 1），后续顺延。`Station -(LeaveStation)-> Map -(Depart)-> Approach -(ApproachCompleted)-> Negotiation -(NegotiationCompleted)-> Rescued -(ReturnToStation)-> Care -(CareCompleted)-> Station`。保留"阶段 i 的合法离开信号是信号 i"的对应关系；`RescueFlowTests` 循环边界 5→6、CompleteLoop 加 Depart、越界值与 Suspension 用例同步。
- **装配协调器** `Bootstrap/OutingCoordinator.cs`（纯 C#，无 Unity 依赖）+ `OutingAssemblyFailure.cs`，构造注入 Flow/Station/Clock/MapRules/RequestPool 与三个会话 Id，持有唯一活跃会话。四个入口：
  - `TryBeginOuting`：无活跃会话 + seed + Station 阶段 + 站点未满 + 未挂起 → 建会话、捕时间版本、`LeaveStation`。满员只拒绝，不写默认后果。
  - `TrySelectAndDepart`：`CityMapRules.TrySelectPoint` 只读校验 → `Accept` → `session.TryDepart` → `Depart`。
  - `TryAdvanceField`：只注入已验证的现场信号（`ApproachCompleted`/`NegotiationCompleted`），校验会话身份与阶段后转发；协调器不自造成功信号，两条开路分支在此汇合。
  - `TryReturnAndSettle`：全量前置校验 → `session.TrySettle` 闸门 → `Resolve` → `station.TryReceive` → `clock.TryAdvance`（用出发时保存的版本，一次）→ `ReturnToStation` + `CareCompleted` → 只读 `OutingSummary`。
- 跨模块提交靠"校验段只读、提交段前置已保证"避免中途失败；重复结算在会话闸门被拒。

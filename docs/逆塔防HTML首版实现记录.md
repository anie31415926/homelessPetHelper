## 守方加强：当前版本

2026-11-19，用户认可先试持续守门与威胁选防区，并要求大范围招式真正造成范围伤害，允许修补防御塔与扩大塔射程。现已在原 `siege.html` 实现，入口不变；本节及下方当前参数/验证优先于历史记录。

- **持续守门**：最多驻守 8 秒，每 1.1 秒拍击该路终段一个最前排单位，2 点损耗/16 距离击退；后来进入防区的单位也会受击。横扫会提前结束驻守，其他路不被同一爪封死。选下一防区按可见部队距终点的威胁加权，不按整路人数等权计数。
- **真实大范围横扫**：以选定路线的 84% 路程位置为中心，半径 82，预告时冻结实际空间范围；范围内所有存活单位受 4 点损耗和 42 距离击退，包括邻路与改道途中的单位，不再只按 laneId 筛选。护盾仍抵挡一次损耗、重装仍抵挡一次击退，并非无敌。判定与预警圆直接共用同一份区域数据，预告后不追踪改目标；至少经过一次玩家窗口才落招，之后留 1.8 秒明确收招空档。
- **远程炮台**：射程从 52 增至 85，耐久从 12 增至 14；损耗 1/射击周期 1.4 秒不变。单位自身攻击距离仍为 26～32，因此会先进入火力圈再接近塔。范围按真实空间距离计算，可以覆盖邻路；点击塔显示射程圈和耐久，不再用详情弹窗遮住地图。
- **有限修补**：损坏的存活塔低于/等于 60% 耐久可被选中，先锁定塔位预告并等待实际玩家应对，动物动作开始后施工 1.8 秒，完成补 8 点且不超过上限。全局最多两次，启动即扣次数，冷却 10 秒，施工中拆毁目标会中断；已拆塔不复活，不借修补无限重建。修补和建塔占动物主动动作，不免费附送额外出手。菜单显示剩余次数。

玩家供给、出兵费用、回合额度、进度目标、时限、三路开放、Unity/正式救助与旧入口均未改；不新增图片或完整爪尾动画。精确数值仍是本次试调值。

**本版对照结果**：8 种子×3状态×9策略共216局有界结束。普通状态固定上/中/下路盲投合计从旧版24/24降为5/24；读防区分路、轮流分路、轮流分路带合体、中路选材合体各8/8，说明没有强制单路必败，也没有强制必须合体。高警戒固定三路盲投0/24，几种简单战术仅0～4/8；疲倦仍明显宽松。**机械轮流分路在普通组也能8/8，因此不能宣称长期同质化已解决**，合体并非每个状态/时机都更赚，高警戒可能偏难，后续继续收手感而不是把通关率当正式平衡。

本版25/25规则测试、8视口浏览器/真实控件通关、射程圈、7个锁定范围、4个修补预告快照、炮台射击及逐回合耐久/位置/塔状态与纯引擎对照通过；旧Web/duel回归与构建通过。详见下方验证。下一步试玩驻守压迫、横扫读区、修补打断与高警戒难度，不再重复等待此次能力试调确认。

## 最新试玩反馈：单路盲投过强

以下为此次加强前的诊断历史，已由上节获准实施，不代表当前仍未改。

2026-11-19 用户反馈“我方有点太强了，一直往一条路出兵就行了”。已核对规则并做只读模拟：8 种子 × 3 动物状态 × 3 固定路线，共 72 局；每回合直接出手里第一张牌，不主动合体、不改道、不读预告，全部通关，各组平均用时 46～65 秒，远小于 120 秒。自然合体仍会自动发生，其中高警戒下路组总计一次，其余组没有。这不是玩家理解不足，而是防线不足以要求战术应对；此前 48 局全通只说明规则能结束，不能当平衡验收。

实现原因：守门只在动作触发瞬间拍一次，后来的单位不会再被拍；驻守只有 2.4 秒，随后长期空窗。炮台拆除永久有效，补塔全局仅一次，打穿一条路线后持续出兵越来越稳。招式按全路单位数量与路程选路，可能把火力投向仍在远处的部队，而不是即将抵达的威胁。

**待确认的最小调整建议，尚未实现**：先不削补牌/回费、不强制三路达标，也不无限复活塔。让已有守门成为有持续时间与明确拍击节拍的驻守，阻挡并消耗这一路前排；动物优先依据终段可见威胁选择防区，横扫衔接该防区积压的单位。预告锁定后不追踪玩家应对，强招保留实际玩家窗口及收招空档，其他路线不同时封死。由此比较集中合体/护送硬破、佯攻分路、升级改道，而非强制每两回合换路。具体持续时间、拍击、选招与横扫衔接须先确认，再在现有独立试玩中试调。

后续验证应对照固定上/中/下路盲投、读招分路不合体、单路有意识合体/护送及改道策略；目标是观察忽略防守的代价与战术收益，不要求单路必败或合体成为唯一解。本轮仅诊断、记录和讨论，没有修改运行规则或数值，没有新增浏览器/Unity验证。

## 规则与临时数值

已认可的结构：双行动条、动物速度关联状态；玩家决策窗口全场冻结，开始时补牌/回费一次；提交后继续，动物条不清零；每窗口最多一张出兵，附带最多一次付费合体，两者各自扣费；允许只合体或蓄势。三个同类材料必须在场上，付费合体不限距离、保留所选主体位置；附近自然合体免费。不同合体分别拥有硬突破、改道、护送能力。

以下是可调试验值，不是永久数值或长期平衡结论：

| 项目 | 当前数据 |
| --- | --- |
| 战斗时钟 | 固定步长 50 ms；局内 120 秒；我方周期 4 秒 |
| 动物周期 | 观察 6 秒、高警戒 3 秒、疲倦 8 秒；高警戒达到一半目标后缓和，保留既有充能 |
| 供给 | 手牌上限 3、开局填满；每回合补一个空位；三种基础单位各三张组成短袋，同手允许重复，未用牌留存 |
| 点数 | 开局 4、上限 6，每回合 +2；出兵 2、主动合体 1 |
| 自然合体 | 同路三个基础同类，两两空间距离不超过 26；前进距离至少 65，避开出生区安全堆叠 |
| 主动合体 | 消耗三个基础同类，主体原地升级；可原子提交“出第三只 + 合体”，新单位可作材料或主体；按三材料剩余耐久比例继承，不凭合体满血 |
| 改道 | 跳跳球一次机会；转到目标路线的最近投影点，700 ms 真实空间过渡，不直接按路程比例传送；与本窗口合体互斥，可搭配一次出兵 |
| 换牌 | 弃掉选中一张，消耗本次玩家窗口，不同时出兵/合体；不立即补牌，下一回合补空位 |
| 目标 | 累计 70 进度；基础单位抵达 +8 / +10，合体单位 +24 / +30，记一次后离场 |

三种基础单位为补给小车、引导球、遮蔽小队，升级为重装小车、跳跳球、护送伞阵。重装抵挡一次击退但仍会损耗；护送提供一层不叠加护盾。耐久/射程/速度/攻击节拍都在配置中。

猫的主动动作采用持续守门、空间群体横扫、有限建塔及修补；塔和单位沿战斗时钟自行交战。横扫锁定空间区域、补塔/修补锁定塔位，均必须经过至少一次真实玩家决策窗口才生效。玩家与动物同刻满条，先进入玩家窗口；动物保持充满等待。普通暂停、失焦和后台同样冻结，恢复不追赶现实离线时间。

## 模块边界

| 文件 | 所有权 |
| --- | --- |
| `definitions.json` | 带 schemaVersion 的单位、能力、动物状态、数值、折线路线与稳定塔位 ID；不存运行时耐久或牌实例 |
| `text.zh-CN.json` | 独立中文文案键，配置只引用键 |
| `catalog.js` | 启动校验、引用与几何检查、只读目录、查询入口 |
| `session.js` | 会话创建、固定步模拟、阶段/暂停/终态、双条时序；外部显式输入经过的毫秒数 |
| `orders.js` | 同源预览与原子提交；校验会话 ID、回合、材料、费用与互斥；拒绝不修改原状态或随机数 |
| `supply.js` | 会话内确定性 RNG、短袋、实例 ID、有限日志 |
| `entities.js` / `geometry.js` | 生成、受击、自然/付费合体、改道及折线路径计算 |
| `combat.js` / `animal.js` | 自动交战、持续拍击、修补施工/中断、一次抵达，以及威胁选区、预告、主动动作和状态速度变化 |
| `useBattle.js` | 浏览器 rAF 与失焦生命周期适配，不拥有费用或战斗规则 |
| `SiegeApp.jsx` / `Battlefield.jsx` | 计划输入与展示；不直接改战斗状态。合体可点场上单位或使用材料列表，列表避免单位重叠时无法选中；出兵路线与改道目的地分开 |

扩展现有能力的单位只改定义与文案；新增能力须同时补校验枚举、规则处理和测试，不靠 UI 回调实现效果。改变地图用稳定 lane/pad ID 与折线点，不按三个按钮的数组下标驱动战斗。没有为后续 Unity 迁移预造大型框架，纯 JS 规则可独立测试，未来 C# 实现仍须重验契约。

预览会对状态副本计算，不消耗真实资源。牌实例与单位使用会话内唯一 ID，命令还携带会话/回合标识；旧计划、重复点击、无效材料和不足费用不产生部分部署、吞牌或扣费。

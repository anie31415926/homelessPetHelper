# 救助闭环与动物数据接入

2026-11-19。用户认可先串联已有模块、把可能大改的现场玩法隔离，并允许开始实现。本轮是独立 Editor 可玩闭环，不是正式主场景或完整经营系统。

## 试玩入口

Unity 菜单 `Homeless Pet Helper > Preview > Open Rescue Loop`，打开后 Play。

1. 救助站从空站开始，点击“外出救助”。
2. 地图默认选择单车棚，确认“前往这里”，进入已有停车棚回合救助。原长按行动、保留、手册与动物回应继续使用。
3. 真正完成安置和救助后回站，显示同一只猫的入站总结，不生成替代动物。
4. 进入站内，选择动物，查看健康。当前明确健康样本检查后即可再次外出，不要求洗净、梳完或抚摸。
5. 可选清洁、梳理及接触沿用既有样例边界；局部清洁更新当前个体，主动结束或返回站内才结算有效工作时间。暂停、失焦不结算。

独立地图、正常/应激救助案例、原三动物站内白板仍保留。它们不是这个共享会话，不能把几个独立入口分别 Play 当作连续游戏。

固定求助用完后不会自动补单。当前普通样例只供一次真实救助；后续外出可以查看地图、取消或走尚未接入现场的明确返回路径。停 Play 再 Play 会重建临时会话，不保留存档。

## 状态归属

| 对象 | 职责与寿命 |
| --- | --- |
| `Bootstrap/GameLoopSession` | 持有一套救助站、世界时钟、流程、地图、请求池、协调器和当前现场活动；离开/重开面板不关闭它，整体结束才统一释放 |
| `OutingCoordinator` / `OutingSession` | 延用外出身份、出发/返回预检、容量、请求占用、实际阶段与一次计时；实际回站总结从成功入站结果取得 |
| `AnimalIndividual` | 动物当前状态的唯一可变所有者，救助与站内持有同一个实例；稳定动物 ID 不随换面板改变 |
| `AnimalSnapshot` | 不可变当前快照；按类别替换，不用 UI 字段保存第二份饥饿/情绪/脏污档案 |
| `StationAnimalIntake` / `StationReturnSummary` | 冻结入站事实和历史快照，后续护理不得回写 |
| `StationCoatCare` | 每只入站动物的局部脏污/浮毛场、累计成果、有效工作计时与数据效果；不依赖具体救助玩法或 UI |
| Editor Presenter / Host | 装配既有静态 Prefab 和样本、处理输入与页面切换；不自行创建救助成功或重做通用规则 |

`StationPreviewSession` 以动物 ID 管理 `StationResidentPresentation`，不是三个固定数据槽。总览索引只用于找到当前名册中的 ID。新增入站不会重建已有动物的脏污场和工作记录；多动物各自独立。

## 可替换的现场

`Modules/Rescue/IRescueActivity` 继承已有 `IRescueAnimalSource`，只暴露会话身份、同一个体、真实完成/求援状态、暂停、关闭和释放。不暴露卡牌、回合、选项、分数或具体谜题类型。

当前 Editor `RescueCaseTrial` 是适配实现，以 `standaloneStation:false` 注入外出会话中的同一个体，不再创建第二个私有救助站。原独立案例路径仍可使用其原私有样本。传入已有个体时，正常/应激样本起点不能重置其数据。

玩法替换通常只需：新的活动实现相同契约，对同一个体提交它负责的效果，并在装配处更换现场入口/Presenter。地图、名册与护理不应引用新玩法内部类型。纯规则测试已使用一个没有卡牌/回合类型的替代活动验证入站和再次外出。

这不表示任何新机制都只加字段即可：新伤情、接手方式、退出结果或时间规则仍须确认对应业务契约，不能把流程状态全塞进动物档案。

## 动物数据

在原有身份、`Disposition`（需求/情绪/应激/行为）和明确的 `Health` 之上，本轮增加两个类型化分区：

| 分区 | 本轮字段 | 缺失与更新 |
| --- | --- | --- |
| `AnimalCarePermissions` | 分别接受接触、清洗、梳理 | 旧调用不提供时全部为 false；接受救助不自动推出接受护理 |
| `AnimalCoatCondition` | 脏污、浮毛，均为 0–100 | null 表示未提供，不是干净；数值越界直接拒绝构造 |

`TryApplyDisposition`、`TryApplyCarePermissions`、`TryApplyCoatCondition` 都要求调用者持有当前最新快照；旧快照写入拒绝且不覆盖其他分区。站内效果经救助站校验会话、暂停、关闭及真实入站身份后提交。当前是单游戏线程内存契约，不是持久化事务或多线程同步方案。

局部护理图场不是另一份永久动物状态：它表示本次可擦位置及已完成区域，按剩余比例更新共享 `Coat` 总量。界面切换不重新散布污渍；若其他规则已替换同一 `Coat`，旧护理会话拒绝继续覆盖，需要后续规则显式重建对应现场。情绪等其他分区变化不应被护理抹去。

健康仍在首次创建时明确，检查读取已有健康，不重新抽取。尚无通用健康更新、诊断、伤病随机分布、康复、恶化或存档版本迁移。本轮样猫初始脏污 65、浮毛 50、三个护理许可为 true，都是显式样本事实；护理仍另验基础检查、当前健康、情绪和应激，不能当全部动物默认值。

## 诚实的流程边界

当前真实入口明确是“不需要清路的已有停车棚样例”。它跳过不存在的清路活动，**不登记 `HasOpenedRoute`**，不能冒充完成清路、发现算法或关卡成果。样例救助返回按配置结算 25 游戏分钟（探索 5 + 交涉 15 + 交接 5），不是额外收取清路时间，正式时长仍待调试。

小院探索与门廊寻宠仍只有原出发及明确未完成返回，不替换成停车棚猫，不捏造发现、给主人交付或谢礼。求援只记录请求并提供明确返回，不宣称专业方已接手或成功收容。出发前取消不计时，已到地点/交涉等路径按现有阶段一次结算。

满员仍能看地图，有安全接收计划的寻宠出发例外沿用既有规则；普通收容出发重验容量，不弹强制送出、不挤掉已有动物。本轮没有领养、转站、寻宠实际交接等长期腾位出口，因此容量达到上限后不能靠本闭环无限收容；这是当前试做边界，不是假定正式方案会如此停住。

尚未接入：Main/正式 Player 闭环、存档及恢复、普通求助自动补充/到期/他人救助调度、场外饥饿与地点变化、真实清路、寻宠核验和交接、设施升级、经济奖励、医疗、领养或正式运行时资源框架。同期 HTML 玩法和动物分层动作实验保持独立。

## 规范 Review 修复（2026-11-19）

本次仅修复 Review 确认的四项，不新增玩法或重建静态 Prefab。

- 共享护理资格统一归 `StationCoatCare`，清洗、梳理分别提供资格和类型化拒绝原因；Presenter 不再复制健康、情绪与护理许可规则。原独立三动物样例保留自己的接触规则，不混用共享个体判断。
- 站内时钟使用 `WorldTimeSnapshot.DayIndex` / `MinuteOfDay`，不再固定按 1440 分钟切天；一天 30 分钟、累计 35 分钟显示第 2 天 00:05。一基天数展示也覆盖 `long.MaxValue` 边界。
- 开地图、接现场、成功/未完成返回、完成首次照护都消费失败结果并显示本地化反馈；拒绝后保留动物、现场成果和未结算状态。临时阻塞解除后沿原会话重试，不重复入站或计时；时间版本过期不能偷偷改用当前版本，也未新增自动恢复/强制结算入口。

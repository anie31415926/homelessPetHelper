### 玩法确认与试做

2026-11-17 用户明确要求：大方向已确定，具体玩法细节须多讨论，避免先快速做完整模块再大规模返工。

- **先讨论再实现**：进入回合救助、解谜、清理、照护互动等模块前，先确认影响玩家选择、操作和反馈的关键规则，不把阶段计划获认可当作模块细节也已获认可。
- **一次讨论一个问题组**：列出尚未确定的问题，给出少量可行选项、体验取舍、推荐理由及对代码/美术的影响；不一次抛出所有远期问题。
- **先走一轮具体例子**：用正常操作、选错后的反应、资源耗尽和中断恢复检验方案，确认玩家看到什么、可以做什么、为何成功或拒绝。
- **区分决定状态**：玩法文档标明“已确认 / 原型假设 / 待讨论 / 暂不做”。HTML 的按钮、阈值、回合数、反应时间和关卡布局均不能自动升级为正式决定。
- **确认到适当粒度**：先确定行动机制、状态关系、成功/恢复规则与操作方式；易调整的数值可在用户认可的范围内试调，不要求每个常量都单独审批，也不靠堆可配置框架代替设计。
- **不确定就小范围验证**：需要手感验证时，先约定本次只验证什么，再做隔离的小原型；玩法得到反馈前不扩成完整系统、不批量制作依赖它的图片或动画。
- **记录后再执行**：确认结果回写对应玩法文档，注明日期、仍待定项和下一步验证；关键规则变更同步调整验收与测试，不能用配对测试锁死尚未确认的假设。
- **技术工作不必停摆**：工具链核对、编译、独立测试设施等无玩法影响的工作可继续；若技术取舍会限制玩法、资源成本或操作形式，也应先说明并讨论。

这套流程用于减少高成本返工，不承诺完全消除试玩后的迭代，也不要求先写完全部详细设计才开始验证。

## 2. 阶段目标与范围

### 第一目标：可试玩的完整外出闭环

```text
救助站出发
  -> 本轮选择解谜或清理开路
  -> 路径实际连通，抵达动物
  -> 观察状态，回合行动，动物回应
  -> 愿意接受救助，进入独立收尾，不再等待抽牌
  -> 必要时简易医护，满足安全转运条件后完成救助
  -> 返回救助站
  -> 一种有明确动物回应的轻量互动
  -> 再次外出
```

这一目标不是可发布版本。领养/适宜物种放归属于完整产品循环，但条件尚未确定，不用临时按钮冒充已完成的系统。
单轮以几分钟为体验目标，时长、趣味和重复度须真人试玩，不能由自动化通关推断。
上图只展示成功路径。用户已确认救助可失败、状态可组合并包含健康与情绪；死亡仅限极少数、反复忽略明确警告的极端情形，不作为正常认真救助的随机风险。失败分支、应激挽回、具体死亡条件和整局结局须在 P2-00 讨论后再实现，不能由原型的保证恢复规则代替。
用户进一步确认可接近/可救助后针对明显伤病提供同源简易医护包扎窗口，并以安全转运需求决定是否先处理再结算成功；不影响转运的轻微伤可留到站内，超出现场能力时保留求援出口。操作采用动手包扎，具体分类、工具与手势、完成判定和求援结算待定。当前白板 UI 授权只覆盖已实现选项功能，不把完整站内医疗直接加入 P2。

| 纳入第一目标 | 暂不纳入 |
| --- | --- |
| 一轮一只动物，前期猫狗，初始行为可组合扩展 | 动物品质、交易、繁育、排行榜、玩家串门 |
| 解谜与清理各一个完整模板，再加少量受约束变体 | 大地图、无限随机解谜、持续手工供给大量关卡 |
| 可组合状态与回合救助；失败及极端死亡的具体规则先讨论，原型四个位置/三种起点仅供参考 | 回合战斗成长树、行动点、概率捕获；累计 Game Over 与整局结局范围尚待确认 |
| 回站承接和一种轻量互动，具体动作在制作前确认 | 多套照护小游戏、长期经营、多货币、任务经济 |
| 本地运行、暂停恢复、基础测试和早期微信技术验证 | 账号、云存档、社交、广告、内购、资源远程更新、代码热更 |

用户最新允许白板 UI 验证已完成的功能，范围与资源评估见[白板 UI 与资源管理](白板UI与资源管理.md)；正式图片表现仍待资源确认。图片不等于整屏切图：面板用静态 Prefab、显式绑定、独立文案及可适配布局。
不提前移植旧原型画面，不以运行时拼装面板或复杂占位美术代替玩法规则验证。

### 第二目标：首版候选

在第一目标试玩成立后，再确定最低限度的存档、站内照护、动物去向和目标奖励。
这些系统不因写入计划就视为已定案。微信真机、资源预算、数据恢复与发布检查通过后，才可称为首版候选。

## 3. 模块边界与状态归属

以下为后续实现边界，不要求立即建立全部目录、接口、事件或程序集。

| 部分 | 持有/负责 | 不应负责 |
| --- | --- | --- |
| 启动装配 | 创建服务、显式传依赖、连接平台生命周期 | 救助数值、UI 动态造树、隐式全局服务查找 |
| 一轮救助会话 | 轮次身份、阶段、开路分支、动物身份、合法流程顺序 | 复制开路或交涉的内部规则、替 UI 保管第二份状态 |
| 开路规则 | 模板、障碍、工具、操作历史、路径连通与完成结果 | 自动捕获动物、扣交涉食物、修改站内动物档案 |
| 回合救助规则 | 可组合状态、行动及反应、应激与恢复、单次救助结果；字段与规则待确认 | 展示字符串、动画对象、文件读写、平台 SDK、擅自决定整局结局 |
| 救助站与互动 | 接收已救动物、站内状态、互动完成与动物回应结果 | 绕过救助条件创建重复动物、实现尚未定案的经营系统 |
| 表现与输入 | 读取快照、提交意图、文字/图片/动画/音效反馈 | 直接写规则字段、以动画结束当作唯一业务成功凭证 |
| 基础设施 | 资源、存档、平台能力的适配和生命周期 | 决定动物价值、行动收益或关卡是否完成 |

采用普通对象、枚举和明确方法即可；不默认引入通用状态机、事件总线、DI 容器、行为树或 ECS。
医护复用为已确认设计约束：现场简易范围与站内医护共用规则及同一动物健康/处理结果，不复制两套系统；模块结构、处理操作、适用条件与排期需确认后再定，不提前创建完整框架。
当前 `RescueFlow` 只是阶段骨架。接真实模块时由会话装配层调用，完成信号来自规则校验，不直接暴露为 UI 的“跳过关卡”命令。
若新增模块成为独立程序集，依赖从装配/展示指向规则，规则不得反向引用展示、Editor 或平台 SDK。

### 模块交接契约

1. 出发时创建独立会话，固定本轮种子、模板版本、分支和动物定义；取消/重开后不得误用上一轮结果。
2. 开路完成结果包含所属会话和关卡身份；会话核对当前阶段、身份及实际完成条件后，才启动交涉。
3. 交涉按输入和经过时间推进，产生可供表现读取的状态及结构化反应标识；文案和美术不进入核心规则。
4. 救助成功只提交一次；回站接收同一动物身份，重复调用不能新增第二只动物或重复结算。
5. 暂停、失焦和切后台冻结玩法时间及输入；回前台不补算隐藏时间。规则先决定结果，表现不能反向改变结果。
6. 未来引入延迟/异步时同时检查会话版本和对象生命周期；旧回调不得推进新会话。实现到该边界时补测试，不提前堆异步框架。

静态定义、单局可变态和未来存档 DTO 分开。只读配置不能被当作动物实例状态修改。
随机数和时间在规则边界可控；不承诺 JS 与 C# 的默认随机序列一致，同输入配对测试应显式固定初始状态和行动序列。

**交付物**：纯 C# 回合规则、EditMode 测试、行为对照数据及差异记录。

**讨论材料**：[最小试做草案](回合救助最小试做草案.md)仅为候选行动与文字示例，不代表可执行原型、正式预期或 P2-00 已完成。

**验收重点**：已确认的状态组合和转换正确；成功、拒绝、恢复与失败结果可解释且互不混淆；收尾不依赖抽牌且不固化进箱；有转运前必要处理时不能提前走成功路径，同源医护的处理结果应承接；资源耗尽有明确后续而非卡死；动作锁定不重复消耗；单次救助终态不再接受行动；非法输入不留下部分修改。具体失败后果、警告和挽回条件以 P2-00 确认为准，不再要求所有误处理都可恢复。

### P3：再移植开路，先模板后变化

实现前分别讨论解谜与清理的操作方式、工具限制、完成判定、重试/撤销及变化范围；原型模板是比较材料，不是正式关卡设计。每次先确认一个分支，再实现和验证该分支。

- [ ] P3-01：先做解谜固定模板，验证箱子合法移动、桥位、真实路径和撤销；选用并记录适合当前规模、Unity/目标平台可用的路径查询实现。
- [ ] P3-02：再做清理固定模板，验证工具匹配、持续接触时间、可达前沿和通路完成；不要求全清，也不自动完成交涉。
- [ ] P3-03：固定模板通过后再加入左右变体及受约束清理变化，固定种子和模板版本，保留失败种子以便复现。
- [ ] P3-04：生成约束包含可解性、可达目标、至少需要的有效操作与路径长度范围；具体上下限先从模板和试玩测量，不假装已有平衡结论。
- [ ] P3-05：覆盖已知模板和种子样本；不沿用 HTML 的“160 个种子已通过”作为 Unity 证据，重新执行并记录实际数量。

**交付物**：两种开路规则、模板/变体定义、求解或可达性验证及测试。

**验收重点**：不能穿墙、隔障清理或以点击次数代替持续时间；路未通不能交涉；可撤销/重试避免不可逆困局；同版本同种子可复现。

### P4：模块串联，不提前做正式 UI

- [ ] P4-01：在装配入口接入单轮会话，核对阶段、身份与结果；不让多个组件各自维护一份阶段状态。
- [ ] P4-02：用自动化驱动实际模块完成“出发 -> 开路 -> 交涉 -> 回站”，两条开路分支都覆盖，不用伪造成功信号冒充端到端通关。
- [ ] P4-03：覆盖暂停/恢复、重复完成、过期结果、场景重载及连续多轮，明确会话结束和清理路径。
- [ ] P4-04：确认重试、主动退出外出及回站容量的最小规则后实现；暂未确定的动作不添加隐式默认行为。

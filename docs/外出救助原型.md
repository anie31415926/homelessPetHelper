# 外出救助原型 01

状态：可操作的 HTML / React 原型。日期：2026-11-16。

## 1. 验证问题

先走一段迷宫，再通过“移动站位 + 判断距离 + 等待角度 + 出网”救助动物，是否构成有意思的一轮体验？可选投食是否降低操作压力，而没有取代观察与出手？

本次不验证完整经营、照护深度、长期成长、社交或微信运行性能。

## 2. 试玩入口

- Vite 开发环境：`/rescue.html`。
- 原有养宠原型：`/`，不覆盖、不接入它的本地存档。
- 本原型所有状态仅在当前页面内存中，刷新重新开始。

## 3. 操作

### 寻路
- 手机：按住下方方向键移动。也可点击同一条直走廊中的可达格子走过去，不会自动绕弯解迷宫。
- 电脑：方向键或 WASD；同样可以鼠标点击方向键。
- 进入另一端的动物标记即抵达救助现场。

### 救助
- 方向键：在前景安全步道内上下左右调整站位。
- 网兜瞄准线自动左右摆动；虚线末端表示最大伸出位置。
- 点击“出网”，或电脑按空格，锁定当前角度伸出网兜。
- 网兜长度固定，不会自动延长，距离不足时需向前移动。
- 点击“投食”，或电脑按 F，在当前方向前方落食。
- 动物先走向食物，再停留进食约 4.5 秒，并非立即定身。
- 每轮食物 3 份，出网不限次数；用完食物仍能直接救助。
- 出网期间暂不能移动或再次投食，收网后恢复。
- 出网路径碰到动物即可成功，不叠加随机捕获失败概率。

### 结束
- 接住后先完成安全收网，再显示成功。
- “带它回站”进入简易回站画面，点击画面有简单爱心回应。
- “再去救助”开始下一轮，并切换猫狗。
- 右上设置可选南门 / 北门、小猫 / 小狗，开始新一轮生效。
- 暂停会同时停止动物、摆角、收网与计时；切换到后台也停止推进。

## 4. 暂定参数

场景逻辑尺寸 390 × 580。竖屏保持场景比例，横屏用中央竖屏试玩区。

| 项目 | 数值 | 意图 |
| --- | --- | --- |
| 迷宫 | 固定 11 × 11 | 先验证穿行节奏，不做生成器 |
| 迷宫移动间隔 | 0.135 秒 / 格 | 能短按、能连走 |
| 救助员移动速度 | 128 单位 / 秒 | 站位明显影响覆盖范围 |
| 网兜最大长度 | 210 单位，界面为 2.1 m | 不足以从任意初始位置轻松接住 |
| 摆角范围 | 约左右 58 度 | 保留等候时机 |
| 出网速度 | 420 单位 / 秒 | 需要少量提前量 |
| 空网收回速度 | 390 单位 / 秒 | 降低空网等待成本 |
| 成功收回速度 | 165 单位 / 秒 | 留出“稳稳接住”的反馈时间 |
| 接触半径 | 27 单位 | 比像素级命中更宽容 |
| 动物巡游速度上限 | 猫 48 / 狗 58 单位 / 秒 | 初步区分节奏，不代表品质差异 |
| 食物数量 | 3 | 有策略选择但不会卡关 |
| 进食窗口 | 4.5 秒 | 容纳一次摆角和出手 |

参数仅为本轮假设，优先根据真实试玩修改，不是正式平衡数值。

## 5. 实现边界

- 使用项目已有 React + Vite 与绘本动物素材，Lucide 控件图标。
- 简单正交迷宫的寻路查询使用 `pathfinding` A*，点击仅接受直走廊，输入与碰撞仍逐格执行。
- 自定义救援机制不是黄金矿工规则的完整复刻；没有重物计分、出售动物或受伤表现。
- 网兜使用线段与圆的扫掠碰撞，避免较快投射物跨过动物漏判。
- 自动化测试覆盖玩法约束和流程，不代替用户体验验证。
- 减少动态效果时取消装饰性走路摇晃；必要的瞄准、动物与网兜移动保留。
- 当前没有音效、概率捕获、惊吓值、任务奖励、正式入站登记和持久化。

## 6. 试玩后优先讨论

1. 俯视走迷宫是否符合预期，还是应改成侧视平台？
2. 自动摆角的节奏是否合适，是否改手动拖动？
3. 救助阶段上下站位是否有必要，还是只左右移动？
4. 食物落点是否足够可预判，是否需要独立选点？
5. 是否减少迷宫长度，把时间更多给动物救助？

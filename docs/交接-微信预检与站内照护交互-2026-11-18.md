# 交接：微信接入预检与站内照护交互设计

日期：2026-11-18（承接 2026-11-17 晚）。用途：记录本轮会话两项成果——微信小游戏兼容性探针（P1 风险排除）与站内照护玩家亲手操作交互的草案设计。本轮**全部是文档工作**，未改任何代码、Prefab 或场景。

## 1. 接续结论

- 工程 `unity/HomelessPetHelper`，Unity **2022.3.62f3 LTS**；uGUI、静态 Prefab、显式绑定，基准 1080×1920。正式 `Main.unity` 仍是工程底座，四个 Editor 白板（选项、停车棚两起点、救助站）可试玩但不进 Player。
- 阶段仍是玩法验证期：P0 底座 + P2/P3 部分规则有代码，P4 会话串联未打通。上一份验证结论（**EditMode 177/177、PlayMode 14/14、Windows Mono 构建成功**）本轮未重跑，本轮无代码改动不影响它。
- 用户本轮明确：广告暂不接入；继续推 P2/P3 站内照护交互；照护交互要现实严谨（玩家可能照搬，不能教错）。
- 项目红线不变：玩法先讨论后实现、不重复造轮子、不伪造成功、不跨模块越权、自动化 ≠ 好玩。

## 2. 本轮成果 A：微信兼容性探针（P1 风险排除）

用户问"WebGL 工具链 / 开发者工具 / AppID 现在要不要先接"，判断为**分层接入**：只提前排除引擎级硬阻塞，完整链路后放。探针已执行，结论见[微信小游戏技术预检 · 兼容性探针执行记录](微信小游戏技术预检.md#2026-11-17-兼容性探针执行记录p1-风险排除)。

- **探针 A 通过**：已在 `D:\program files\Unity 2022.3.62f3` 静默装入 WebGL Build Support；隔离工程最小 WebGL 构建 Succeeded，产出约 4.49MB 完整包（`.wasm.br` / `.data.br` / `loader.js` / `index.html`）。**证明官方版本表未覆盖的 62f3 补丁版构建链路可用，不需换引擎版本**。
- **探针 B 未通过（有价值的真实差异）**：固定提交 SDK 在标准 Unity 隔离编译失败，根因是 `WXBase.cs:884` 用 `AssetBundle` 但程序集定义未引用 `UnityEngine.AssetBundleModule`（团结引擎默认可用、标准 Unity 需显式引用）；另有 `Unity.InstantGame.Editor` 硬引用为潜在第二处。按"不手改第三方代码绕过依赖"约束，**未改 SDK**，适配决策留到真正接渠道时。
- **环境坑已记**：Unity 官方包被 CN/HK 出口重定向到 unitychina.cn 后 404（改用美国出口 12002）；隔离进程授权失败（复用当前编辑器的 Hub 授权参数）；`NODE_OPTIONS` 注入的 shim 让老 Node 报语法错（启动探针时清空）。均为探针环境问题，非兼容性缺陷。
- **未做**：AppID、微信开发者工具、真机预览、SDK 适配、广告接入——按既定顺序后放，不因此视为渠道验证通过。

## 3. 本轮成果 B：站内照护交互草案（五项全部出齐）

从"救助一只动物回来要做哪些措施"的现实查证出发（来源：国内收容技术规范、执业兽医急救指南、收容机构手册），定了三层模型与五项亲手操作交互草案，全部写入[站内照护措施与交互](站内照护措施与交互.md)，总纲 E 节挂了[指引](游戏设计总纲.md)。

**三层处理模型**（贯穿护栏，防止玩家照搬出错）：玩家亲手做 / 状态提示带过 / 专业机构完成。三条护栏：医疗动作零操作、提示必带"由专业机构/兽医完成"、不做错误示范。

五项草案（均为设计方向，细节待确认，**无一已实现**）：

| 交互 | 文档节 | 已定要点 |
| --- | --- | --- |
| 站内检查 | 第 6 节 | 静态叠加伤病效果、热区点选、医疗助手执行测温与送医、读数按实际状态线性更新、四路结果分支 |
| 清洁去污 | 第 7 节 | 保留白板擦除手感、97% 阈值沿用、泡泡为纯表现层（笔刷即时冒 + 停手渐消）、数量/性能按实测取舍 |
| 毛发梳理 | 第 8 节 | 凌乱杂毛覆盖层简单消除、在脏污下一层、不做真实毛发模拟与打结分层、**确认不做剪甲** |
| 分工与安置 | 第 9 节 | 基础投喂/补给/打扫由助手包办只给说明，玩家只做零食加餐等正向互动；保留笼养/放养（笼位=已有观察位）；避免衰减槽打卡 |
| 安抚互动 | 第 10 节 | 轻量版持续抚摸 + 即时叫声文字反馈 + 停手「似乎还想摸」提示；零食并入；**废弃四档信任阶梯**（救助阶段已放下戒备，回站仅轻互动） |

关键取舍记录：
- 助手设定是核心解法——医疗由助手执行（解决护栏 + 世界观，不必定死高科技），基础维持也归助手（避开"反复补充衰减槽"红线）。
- 测体温做成"助手执行 + 示意图 + 正确方法讲解 + 给读数让玩家判读"，不做成玩家亲手插体温计（侵入操作是错误示范风险）；正常肛温 38.0–39.2℃、39.5℃ 发热分界等数据已查证。
- 安抚互动原设计的四档信任推进被用户指出与救助流程重复，核对[交接-连续状态](交接-回合救助连续状态-2026-11-17.md)第 46 行"回站轻互动"后废弃，改轻量版。

## 3. 用户最新确认与实现边界

用户明确：动物状态应是连续演变的，变化后保留，后续在最新状态上不断更新；救助失败后，本次动物状态可以丢弃。

- “线性”指时间上的连续演变，不是固定正确动作串，也不是状态只能变好。动物仍可受惊、退缩、恢复。
- 已进食等事实不因受惊或恢复而消失；情绪、应激、行为分开。恢复不自动等于完全信任，更不代表健康问题治愈。
- 只有显式重新开始或切换测试起点才初始化新会话和新动物；普通阶段变化不能重新加载预设。
- 失败后可丢弃是生命周期方向，不是新增失败机制的授权。本案例没有正式失败/死亡判定，也没有把求援当作失败或成功入站。
- 当前连续性只覆盖一次运行中的会话。退出场景、停止 Play 或重启应用后的恢复未实现，不能称为已完成存档。
- 正式动物仍需可组合的需求、健康、精神/情绪等类别。本例是无明显伤病样本，没有实现完整健康状态、伤病和医疗系统，不为凑类型创建空框架。

## 4. 试玩入口与观察重点

Unity 菜单 `Homeless Pet Helper > Preview`：

| 菜单 | 起始状态 |
| --- | --- |
| `Open Rescue Case` | 饥饿、紧张、无应激 |
| `Open Stress Recovery Case` | 已进食、受惊、应激中 |

打开后 Play。两者共用 `Assets/EditorScenes/SC_RescueCase.unity` 与同一面板；Play 中可用菜单显式切换并重开。原有 `Open Option Whiteboard` 保持不变。

应激样本可验证：前提不足时等候不恶化 -> 退开留空间但不立刻清除应激 -> 合适等候缓和 -> 继续建立安全感并得到主动靠近。过程中不需要重新喂食，食物库存不因恢复而减少。具体恢复步数只是样本参数。

样本后续是允许接近 -> 准备安置并观察接受回应 -> 独立完成救助 -> 只读总结 -> 回站轻互动。允许接近不直接等于愿意被带走；回站仍沿用同一动物，并非接入 ST-01/ST-02。

优先收集：意图是否读得懂、保留选项是否有用、等候是否拖沓、退缩后是否知道怎么调整、主动靠近是否带来暖心反馈。自动化只能证明行为，不判断好玩。

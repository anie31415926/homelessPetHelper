# 正式关卡首批与策略操作

2026-11-22。依据[已认可方案](正式关卡设计与重复游玩方案.md)及用户本轮补充实施：手牌拖向实际路线自动设置分路，设置提供回合暂停选择。本批为统一开路完成契约、逆塔防实际输入/UI和三地点×两种模式的小样本；完整重玩调度与外出持久化仍在后续阶段。

## 操作与节奏

手牌拖到场景内独立路段，沿当前布局的折线路径计算最近路线；预览亮起对应路线，松手进入部署计划。沿用“执行”确认，确认前不扣牌、不扣资源，合体/改道仍使用同一订单校验。选择手牌后也能点击实际独立路段；大排路线按钮已移除可见图形和射线接收，保存的路口锚点保留给教学和旧兼容回调，不承担物理落点判断。

实际投影考虑横纵缩放差异与 Canvas 相机；只接受场景视口范围，拖到路外或多路共享/相近歧义处则退回并提示。切后台、打开弹窗或取消会撤销拖动，旧手指回调不能重新选牌。不可见/收缩为零的场地拒绝命中。落点半径与歧义容差为序列化表现参数，路径、完成目标和规则不写在 View 的地点分支里。

暂停菜单→游戏设置→“回合开始时暂停”，默认开启。关闭后战斗在 Decision 等待期间继续计时、移动、攻击与动物技能及其前摇/持续/恢复；蓄力满只发放一次本回合补牌/资源，玩家仍每回合提交一次操作，执行后重新蓄力。不是额外无限出牌模式。暂停菜单、目标弹窗、后台独立暂停；首次教学在等待操作时仍暂停，完成教学后采用玩家所选节奏。

玩法设置草稿只在显式保存成功后生效；取消与关闭不修改偏好，恢复默认也要保存。声音沿用即时试听与取消恢复。玩法偏好独立保存于 `play-preferences`，微信原生键为 `homeless-pet.play.v1`，不修改玩法旧档；坏档保留，失败可重新读取后重试。若声音已保存而玩法保存失败，会明确提示部分结果，取消不倒回已经成功保存的声音。

## 三地点六样本

| 地点/配置 | 解谜关系及真实规则最短解 | 清障必需顺序 | 可选工作 |
| --- | --- | --- | --- |
| 车棚 `parking.pockets` | 桥38、箱46→47、箱45→46；3步，右侧箱先让出停车袋 | 45杂物→38杂草 | 47角落杂物、46泥斑 |
| 小院 `yard.staging` | 桥33、箱45→38、箱47→46→39；4步，第二箱需经临时位置转入侧袋 | 45杂物→40杂草→33杂草 | 39角落杂物、38泥斑 |
| 门廊 `porch.plank` | 桥38、箱45→31、桥33；3步，先借桥搬箱再把同一块桥移到主通道 | 45杂物→40杂草→33杂物 | 31泥斑 |

数字是用于审核的格索引；游戏指引指向场景热点，不显示这些实现编号。桥先后顺序存在等价解，最短步数只用于防止一步绕过，不替代乐趣评估。必要清障从入口可达区按顺序开放，未要求清光侧袋或泥斑。Undo、错工具、不可达、错误位置仍走既有规则。

四个场地配置由 GameContent 显式绑定。小院旧 `yard.main` 标为 introductory：第一次尚未完成对应操作教学时使用旧教学布局，掌握后选正式 `yard.staging`；教学重播有新布局自己的热点，不套用旧格子。车棚直接接实际 Main 请求。门廊正式入口仍是主人重聚，本批没有将该请求改成普通收容。

六样本均有 Unity 菜单 `Homeless Pet Helper → Field Samples → 地点 - Puzzle/Cleanup`。菜单使用 Main 的现有面板、Presenter 和完整清路→救助链，临时克隆配置并注入内存进度/偏好。门廊仅在该 Editor 试玩中换成普通狗救助，退出 Play 不写玩家存档、不改原配置。未改成正式产品入口，也没有另建一套玩法原型。

## 完成判定与表现

场地配置把全部拟用战斗路径的格子集合交给 ApproachTemplate。完成条件统一为“动物可达，且三条战斗路径不再有箱子、未搭桥的水格或阻路杂物”；UI 的继续按钮与进入救助的验证遵守同一契约。单独到达动物、把箱子移到另一条路线的错误局面不能继续。

清路与救助共用同一坐标、动物状态及已清成果快照；移动后的箱、桥和可选残留保持。三地点路线来自数据，未通过拉长清理进度条伪造决策。保留现有临时场景/物件资源，没有把 ComfyUI 概念图上的错误字或路线烘进正式背景。

逆塔防沿用满屏背景、可玩范围放大、角落状态/按钮、紧凑手牌和费用图标，选牌时不缩小场地。本批进一步取消可见路口纸片按钮，提示只留短句，详细说明在目标弹窗。设置选项在共享手绘弹窗静态绑定，身体内容可滚动；弹窗在渲染前重新核对安全区，防止安全区改变一帧后才收缩。原有 Mask 内动效留边保留。

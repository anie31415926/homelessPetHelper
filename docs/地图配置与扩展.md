# 地图配置与扩展

更新：2026-11-21。用户要求地点数量可扩展，并继续完善地图。本页是当前有图地图的配置/绑定及出发体验说明，接续[地图实施 14.6](城市地图与求助事件实现方案.md#extensible-map)。

## 数据分工

| 文件 / 类型 | 管理什么 | 不管理什么 |
| --- | --- | --- |
| `Assets/Settings/Game/CityMapConfig.json` | 地点集合、开放默认值、现场模板 ID、求助模板/初始事件、初选点、容量、种子和阶段耗时 | 图片位置、运行时动物、正式事件调度、升级门槛 |
| `Assets/Settings/Game/CityMapText.json` | 地点名称、中性地点说明、独立求助说明、状态及出发提示 | 数值和可变状态 |
| `Panel_CityMap.prefab` | 底图、地点 Sprite、位置/比例、名称与状态文字、出发摘要、按钮及 Point Bindings | 事件供给、容量判断、时间扣除 |
| `CityMapPreviewConfig` | 本地 JSON 解析/校验，生成不可变地图定义和每次独立的请求池 | 远程加载、存档或正式配置框架 |
| `CityMapView` / `CityMapPointBinding` | 以 `PointId` 接收点击、更新各节点文字和高亮 | 固定地点名称、数量或数组下标含义 |
| `CityMapPresenter` | 将已验证配置与现有外出业务连接；读取地图快照显示开放状态和当前求助说明 | 新的业务状态源、伪造现场结果 |

以上 Asset 路径相对 `unity/HomelessPetHelper/`。Main 经 `GameContent` 显式引用同一本地配置、文案和静态地图，旧 Editor Host 保留独立预览；不表示已选定 Luban、远程覆盖或生产资源加载框架。换一个地图预览配置可注入同一 Presenter，不表示已经实现多城市选择。

## 新增或删除地点

1. 在 `CityMapConfig.json` 的 `points` 增加一条，给唯一且稳定的 `id`，例如 `riverside`。数量不再固定为三个；地点顺序和 UI 数组顺序互不依赖。
2. 在文案表添加该点的 `nameKey`、`detailKey`。Key 不需要等于 ID，也不要求用 `id + .detail` 命名。
3. 在 Prefab Mode 复制一个现有地点节点到 `MapArt` 下，修改位置和 Image 的 `Source Image`；保留其 Button、Nameplate Image、名称 Text 和 State Text。不同地点可复用同张图，不用重复资源。
4. 在根节点 `CityMapView > Point Bindings` 增加一项：`Point Id` 填同一 ID，`Button` 绑定地点根节点按钮，`Highlight` 绑定名称牌 Image，`Label` 绑定名称 Text，`State Label` 绑定独立状态 Text。图片由 Button 的 Image 引用，名称和状态分别刷新。
5. 有初始求助时再添加 `requestTemplates` / `initialRequests`，普通救助在 Main 还需有效 `rescueEncounters` 映射；没有求助的开放点在规则层仍可规划探索，不编造请求 ID。Main 的探索发现尚未开放，会保留详情并禁用出发；旧地图预览允许抵达后直接返回。启动 Play 验证配置和绑定是否一致，再检查各屏幕比例、名称与点击范围。

删除地点需同时删定义、Point Bindings、对应可交互节点，以及引用它的初始求助/模板限制。若删除初选点，改 `initialPointId`。装饰节点不需要登记为地点；救助站当前仍是展示，不因可替图就变成第四个入口。

**新增普通地点不再修改 C#**，但仍需完成静态 Prefab 美术摆放与明确绑定。不是输入配置后运行时自动铺图，也不保证任意数量都能挤进当前画面。不存在业务上的“三点上限”，实际可见密度、交互尺寸、图片预算和性能仍需复核。

## 配置字段

当前手写 JSON schemaVersion 为 `1`；解析入口只有 `CityMapPreviewConfig`，不由各业务类分别读文件。

| 字段 | 约束 / 默认 |
| --- | --- |
| `schemaVersion` | 必须为 1；其他版本明确拒绝，不猜兼容 |
| `backgroundId` | 必填、非空、去首尾空白；必须与 View 的 Background Id 一致；实际 Sprite 仍在 Prefab 绑定 |
| `regionIds` | 非空且唯一的区域 ID 集合，仅分组标签，不是额外一层可移动地图 |
| `initialPointId` | 必须存在且默认开放，是同级默认选点的优先项；实际开图结合当前请求、容量与流程限制选择，运行态可被显式关闭 |
| `initialCapacity` | 非负整数，可为 0 以验证满员；不等于真实救助站存档 |
| `minutesPerDay` / `seed` | 前者为正整数游戏分钟，后者为非负复现种子；不读取现实时间 |
| `timePolicy` | `explorationMinutes` / `openingMinutes` / `negotiationMinutes` / `handoverMinutes` 均为正 long；累计溢出拒绝 |
| `points` | 非空；每项 `id` 唯一，`nameKey` / `detailKey` 必填并存在于文案表，`regionId` 必须在区域集合内 |
| `points[].openByDefault` | 默认 false；已有 PointUnlockState 支持外部显式开放/关闭，但本轮不增加救助数门槛或调试解锁按钮 |
| `points[].sceneTemplateIds` | 非空、唯一模板 ID 集合，仍是候选现场定义，不是自动加载场景路径或新增现场玩法 |
| `requestTemplates` | 可省略/null/空数组，表示没有求助模板；每项 id 唯一、textKey/animalDefinitionId 必填 |
| `requestTemplates[].allowedPointIds` | 空集合表示适用于所有地点；非空需唯一且引用已定义地点；建议明确填写数组 |
| `initialRequests` | 可省略/null/空数组，表示无初始求助。每项 templateId/pointId 必须有效且相互适用，templateVersion 为正整数 |
| `initialRequests[].hasDirectReception` | 默认 false；只有明确 true 且 reunion 的 ownerId/receivingArrangementId 均有效，才创建原有直接团聚安排 |

`reunion` 是本地样例对“出发前已经确认安全接收”的声明，不证明正式主人核验和真实交接已完成。填写 reunion 却未声明 `hasDirectReception` 会报错，不能因模板名字叫 reunion 或填写文案就绕过容量。普通求助和无求助探索仍需空位。初始事件池按配置顺序建立；具体调度/优先级不在本轮扩展。

启动时拒绝重复 ID/按钮、空引用、名称与状态文字混用、图片与名称牌混用、配置与 UI 点位缺失/多余、未知外键、无效数值和缺失地点/请求文案，不静默跳过坏点位。所有点击提交稳定 ID，不使用节点名称或数组下标推断身份。

## 地图信息与出发体验（2026-11-20）

- 每个点位独立显示“有求助 / 暂无求助 / 尚未开放”，高亮只作用于名称牌。锁定点不可选，有无求助也有文字区分，不依赖单一颜色。
- `points[].detailKey` 只写地点本身；求助放在模板 `textKey`，如 `parking.rescue`、`porch.reunion`。选择时组合地点与当前可用求助；请求结束后显示地点与“暂无待处理求助”，不残留原猫狗线索。
- 出发前读取 `CityMapRules.TryPlanDeparture`，不接受请求、不扣时间、不占位置；按钮禁用与限制原因同时显示。实际点击再次预检，再由原 `OutingCoordinator` 校验并提交，旧的可点击画面不能绕过变化后的请求状态。
- Main 通过显式只读限制回调开放已有猫狗救助流程，寻宠交接和探索发现显示暂未开放并拒绝出发。这是当前接入范围，不改变规则层的满员直接团聚能力，也不把“禁止探索”定为正式玩法。
- 耗时来自同一 `OutingTimePolicy`。当前 Main 样例完整救助并回站预计 35 分钟；未接开路的旧救助预览为 25 分钟；旧地图预览、未接交接的寻宠预览抵达后直接回站为 5 分钟，改配置会同步变化。仅查看、选点、暂停和未出发取消仍不消耗时间；提前返回按实际到达阶段结算。
- 当前空位及累计用时继续显示在顶部，出发摘要注明是否需要安置位。已暂停、禁用或隐藏面板的输入不会触发出发；多种暂停原因叠加，重新显示时复位手动暂停，仍保留后台/失焦限制。

`MapInfoAssets -Isolated` 仅对保存的旧 Prefab 增量补齐文字与绑定，保留原图片、地标位置、音效和 GUID；已补齐时不重复创建。日常继续在 Prefab Mode 编辑，不重建地图。

试玩入口：打开 `Assets/Scenes/Main.unity` → 站内外出 → 点击三个地点。先观察猫狗救助的预计耗时与寻宠未开放提示；完成猫救助、检查护理后再次外出，应默认选中居民小院的狗求助，仍可点击单车棚查看“暂无求助”。旧独立预览入口为 `Homeless Pet Helper/Preview/Open City Map`。

## 默认选点与加载校验（2026-11-21）

每次打开地图或独立预览开始新一轮时，优先选中当前真正可出发的求助：先检查 `initialPointId`，再按配置顺序检查其他地点，同时复用容量和宿主流程预检。没有可出发求助时，保留仍开放的初始点，否则显示首个开放点；全部锁定时展示初始点及锁定原因。只推荐选点，不自动接受请求、扣时或创建动物；之后的刷新、暂停及限制提示保留玩家手动选点。它不改变请求池顺序、事件调度或正式探索规则。

独立预览支持直接接回，因此满员时可能优先显示该求助；Main 尚未接入寻宠交接，会跳过该推荐并继续显示对应未开放提示。Main 两条救助完成后仍可开图查看地点，但不会自动进入未实现的流程。

地图装配前统一检查通用文案、地点名称/说明和所有请求模板文案。缺键报准确 key，格式损坏报准确 key 并保留原始 `FormatException`；不仅检查初次开图会显示的分支。`GameContent.Validate()` 在 Main 创建/恢复玩法会话前调用相同校验，独立地图也在订阅输入和创建外出状态前校验。玩家文案继续保存在 `CityMapText.json`，未新增代码内提示字符串。

| 格式 key | 实际格式参数 |
| --- | --- |
| `status` | 空余安置位 int、累计分钟 long |
| `arrived` | 地点名称 string |
| `returned` / `returned.exploring` | 外出分钟 long |
| `detail.noRequest` | 地点说明 string |
| `detail.request` | 地点说明 string、求助说明 string |
| `departure.rescue` / `departure.preview` | 分钟 long、安置需求 string |

其余通用文案、地点/模板文字不接收格式参数。可按语言重排占位符，数字使用相应整数格式，字面量花括号使用 `{{` / `}}`；多余参数索引、未闭合括号及无效数字格式会在加载阶段拒绝。扩点仍使用稳定 ID，不依赖节点名称、UI 数组位置或当前三点样例。

## 保留边界

- 位置、图层尺寸、图片与高亮颜色属于可编辑 Prefab；稳定流程枚举和容量/团聚规则保留在业务代码，不能为了“全部配表”绕过校验。
- 旧独立预览每次创建新的请求实例、救助站、世界时钟和外出会话，不修改共享配置；Main 复用现有真实会话及站内检查点存档，本轮不修改存档 schema。
- 地点点击监听在启用/禁用时成对注册/移除；初始化校验失败不注册部分监听。Presenter 构造校验完成后才订阅界面，Dispose 取消订阅。
- 删除了已完成的一次性三点创建/布局及分层迁移工具，不再保留会写回旧结构的 MapAssets/MapLayout/MapLayers 命令。现有场景、图片、GUID 和 Prefab 内容保留。新地点在保存的 Prefab 上编辑，不重建地图。
- 两轮均未增加事件供给/他人接手调度、探索发现、寻宠交接、动物世界变化、设施升级或通用配置平台。最新交付见[选点与校验任务](协作任务/20261121-地图选点与校验-01a1f74d.md)，前轮地图验证仅适用于其原快照。

### 参考及纠正

- [Unity 2022.3 SpriteAtlas属性](https://docs.unity3d.com/2022.3/Documentation/Manual/class-SpriteAtlas.html)：Canvas UI 禁旋转，Padding默认4；Read/Write会增加副本。本文沿用已验证的无Mipmap/RGBA32基线，不把其他案例的压缩格式照搬到微信。
- [Unity UI优化案例](https://unity.com/how-to/unity-ui-optimization-tips)：按同时更新/显示的UI组织Canvas，关注实际批次、材质、纹理与层级；合图只是降低纹理切换的手段。
- [Unity SpriteAtlas常见使用场景](https://docs.unity3d.com/2022.3/Documentation/Manual/SpriteAtlasScenarios.html)，Scenario 2：保留packables却只关闭Include in Build，可能使源纹理也不入包、运行时不可见。因此停用不是只改开关。

`UiAtlasGroups.json` 的 `includeInBuild:false` 表示目前选散图。Sync在**保持原atlas GUID**的前提下重置候选atlas的旧打包缓存，清空packables/packed sprites并关闭Include in Build；候选路径清单保留在JSON用于今后评估。门禁同时拒绝“停用但仍有旧packed Sprite缓存”。一次实际构建检查发现仅Remove packables仍会保留旧缓存；现在已补回归和真实玩家构建检查，确认依赖的Texture2D像素数据均入包。未改原Sprite身份、Prefab或Importer。

新增资源时先按显示/释放边界分组，比较散图、按用途拆组、多个小页与大页；检查原生页大小/利用率、实际构建纹理负载、缩小后的边缘与遮罩。只有可重复的批次/帧耗时或内存/包体收益足以覆盖成本时才启用。正式美术或微信压缩策略变化后重新测量，不能把当前散图决策称作所有设备和后续内容的永久全局最优。

## 两条流程

| 用途 | 来源与产物 | 关键约束 |
| --- | --- | --- |
| 动物蒙皮 | public 原图 → `tools/pet-motion-atlas.mjs` → `art-source/pet-motion/atlas.json`、`Assets/Art/PetMotion/T_Pet_Atlas.png` → motion Unity export/fixtures | 不旋转、不缩放、不有损量化；保留源尺寸、offset、SHA256；仅重映射 UV/裁掉无用几何 |
| 普通 uGUI | `Assets/Settings/Atlas/UiAtlasGroups.json` → `UiAtlasTools` → `Assets/Art/Atlases/Atlas_UI_*.spriteatlas` | 显式纹理与生命周期组，不收整个文件夹；原生 Sprite 子资产引用，保留 GUID/local ID、切片、pivot、九宫格 Border |

两者不互相替代。蒙皮 Shader 使用 UV2 作为局部区域裁切，不能只合 PNG 不更新网格。uGUI Image 不改成 RawImage，也不重写原 TextureImporter 或已有 Prefab 绑定。

普通 UI 候选清单为 CityMap 的四动物角标与四建筑，当前不启用打包；排除独立地图底图、站内护理 RawImage 及交互遮罩。真实使用范围按上节与当前Main依赖核对，不把候选清单当实际共同显示，也不因为面板隐藏就算按需卸载。

## 依赖与生成

根目录 Node >=20.9，Sharp 固定 `0.35.5` 并写入 lock；不再依赖 Codex 外部模块目录。

```powershell
npm ci
npm run test:atlas
npm run atlas:generate
npm run atlas:check
```

`atlas:generate` 依次生成 PNG/坐标、动作导出及夹具，再运行两个生成器的只读重算检查，最后生成 `Assets/Settings/Atlas/PetAtlasManifest.json`。单独刷新清单不会跳过生成检查。现有八图已有透明余量，本轮接入完整补边后图集仍为 876×924、518906 bytes，像素/坐标/UV 未改变，因此不重烘现有网格、动画、骨骼或覆盖 rig。

后续源图/规则导致 UV 改变时，还须运行既有 `tools/unity.ps1 -Task PetMotionBake -Isolated`，在输出快照检查网格/材质/rig 后只同步该任务拥有的派生资产及 `.meta`；不能把隔离输出当作已自动回写。保留外部 GUID，并重新跑下方 Unity 校验和动作回归。

`prepareAtlasImage` 默认按 alpha 包围盒加完整 2px 透明间隔；内容贴原图边界时允许负 offset，避免旧逻辑夹到原尺寸而漏补边。保留区域 RGBA，包括透明 RGB；可显式选 `edge:'extrude'`，当前动物不启用。2px 只适用于无 Mipmap、无块压缩、Bilinear、不缩放的当前导入基线，不承诺任意缩小/压缩级别都不串色。

## Unity 入口

菜单 `Homeless Pet Helper/Atlas/`：

- `Sync UI Atlases`：按当前选择原位同步并保留GUID。启用组禁旋转/紧密打包，4px native padding、alpha dilation、无Mipmap/ReadWrite；停用组清空成员及旧打包缓存。
- `Pack UI Preview`：仅试打包启用组；当前无启用UI组时明确报告散图选择。启用时导出原生页数、尺寸、基础像素量、占用率和非空PNG到当前工程`Library/AtlasAudit/`。
- `Evaluate UI Grouping`：仅隔离batch运行，按八图大页/小页、建筑与动物分组分别试打包，报告真实Prefab Image和Main依赖；不回写临时资产。
- `Validate All`：只读检查 UI 配置、成员/平台设置、跨主图集重复，及下面的动物生成一致性。

不占用打开工程的命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/atlas-unity.ps1 -Action Sync
powershell -NoProfile -ExecutionPolicy Bypass -File tools/atlas-unity.ps1 -Action Pack -Graphics
powershell -NoProfile -ExecutionPolicy Bypass -File tools/atlas-unity.ps1 -Action Validate
powershell -NoProfile -ExecutionPolicy Bypass -File tools/atlas-unity.ps1 -Action Evaluate -Graphics
powershell -NoProfile -ExecutionPolicy Bypass -File tools/atlas-unity.ps1 -Action BuildProbe -Graphics
```

该辅助脚本总是新建隔离快照，不自动复制回源工程。第一次 Sync 后检查输出，只合并 `Assets/Art/Atlases/`、`Assets/Settings/Atlas/` 及对应 `.meta`；不要整份覆盖 Assets。新增原生图集成员仍须评估共同显示/释放边界，不能扩成全局大图集。

## 构建门禁

独立 `AtlasBuildGuard : IPreprocessBuildWithReport` 自动参与 Unity BuildPipeline，不编辑 Main 的 DesktopBuild 或 unity.ps1，也不在构建时启动外部 Node 进程。

- 对照已由生成器验证的清单，检查 35 个源/生成文件的 SHA256，包括工具、实际依赖源码、原图、atlas PNG/坐标、导出、夹具、Shader 与 package/lock。源文件变动后不重新生成会拒绝构建。
- 对照清单检查 Unity 实际载入的八个网格：位置、UV、UV2、三角索引，统一 length-prefixed little-endian float32/int32 SHA256；不只检查一个“已经生成”的回执。
- 检查 atlas 无缩放/压缩/Mipmap、alpha 和采样设置，材质纹理/Shader，以及 rig 各 Renderer 的网格/材质绑定。
- 检查原生 UI 图集设置、成员及跨主图集重复。配置非法、丢文件、UV 过期、错误绑定均抛 `BuildFailedException`。

隔离快照的 `Assets/` 项取自当前快照本身，不拿源工程图片替其验收；仓库外独立 Assets-only 工程缺少工具/原图时明确失败。普通 GUI Build、批处理及 SDK 经 Unity BuildPipeline 的构建都适用；未调用该管线的第三方自定义导出仍需显式执行 Validate All。

# 普通相遇选项覆盖核对

日期：2026-11-18。本页保留**实施前**源码只读核对及候选集合的组合可填性检查，不是正式玩法覆盖率或试玩结论。用户随后明确“可以开工”，最小范围已落地；当前实现、实际样本条件与 Unity 验证从[案例最新检查点](停车棚救助案例试做.md#最新执行检查点选项适用性与安置回应)恢复。以下未实现描述均指核对时，不代表当前代码仍有同样缺口。

## 结论

**本例可以先复用现有五种方法，不必为凑三个位置立即增加牌名。** 当前真正的缺口是投喂适用性、锁定项的执行与表现，以及接近后实际区分试探安置和接受安置。不能把这次核对扩大为所有个体偏好、伤病、环境和未来状态组合均已覆盖。

玩法依据：[已确认反馈与供给规则](普通相遇推演-食物与接触边界.md#接近与安置反馈)。本次只核对，下一轮对既有 Editor 案例的改动范围见下文，尚未实施。

## 三个位置与锁定的组合核对

### 方法

在内存中用 JavaScript 枚举集合，不修改文件：按源码人工整理候选，枚举五种方法的零、一、两个锁定组合，共 `1 + 5 + 10 = 16` 组。对每组检查能否保留锁定项、从其余合适方法中补齐三个位置，并至少包含一个可执行的退开或等候。

锁定组合包含跨状态保留下来的方法，是保守的组合包络，不声称全部组合都在每个状态真实可达。无意义锁定项仍占位置，但不计作可执行安全方法。计数验证的是**至少存在一组合法供给**，不是随机分布、实际 C# 执行、全部行为序列或性能测试。

### 与现有码对应的候选集合

以下应用的是本例已确认的新供给方向，尚未接入当前供给代码。暂时不能推进但仍有准备价值的方法保留；其中玩具在本例恢复后可以有用，不代表所有动物都有这种偏好。

| 局面 | 可新发的不同方法 | 有合法供给的锁定组合 |
| --- | --- | --- |
| 正常开局，有食物、尚未放食 | 退开、等候、放食、玩具、接近 | 16/16 |
| 已有食物在地上，尚未吃到 | 退开、等候、玩具、接近；不重复放同一份食物 | 16/16 |
| 已进食、仍在观察 | 退开、等候、玩具、接近 | 16/16 |
| 已进食的应激恢复起点 | 退开、等候、玩具、接近；玩具/接近可作为恢复后的准备 | 16/16 |
| 已进食后因过早接近而退缩 | 退开、等候、玩具、接近；保留取食事实 | 16/16 |
| 食物耗尽且仍饥饿 | 退开、等候、玩具、接近 | 16/16；仅证明可稳住，不保证无食物也能完成救助 |

这六组人工候选条件下，共 96 个锁定组合有合法供给。当前案例无对应的状态过滤，也没有执行这些新行为断言，所以不能写成“96 项 Unity 测试通过”。

### 尚未实现的试探安置

对本例继续保持玩具兴趣、且退开/等候仍有实际稳定或探索意义的假设，去掉已无用途的放食和形式接近后，候选为退开、等候、玩具。相同集合检查为 16/16 可填。

**这只是下一轮试做的候选覆盖，不是现有码的状态覆盖。** 若玩具正在妨碍探索且没有准备价值，不应为了三个位置强发玩具；需要先根据实际回应检查其是否仍有用。现在既没有试探安置状态，也没有这一阶段的真实适用性评估，不能据计数宣称安置玩法已验证。

### 不应扩大结论的反例

若未来某只动物已不需要食物、也不喜欢玩具，且已允许接近但还未接受安置，现场又没有其他合理方法，此时假设只剩退开与等候。16 组锁定包络中有 4 组无法填满：无锁定、仅锁退开、仅锁等候、同时锁退开和等候。最直接的反例就是没有锁定时两种方法无法填三个不同位置。

这不是当前案例一定会出现的运行错误，而是说明五种牌名不能证明所有个体都适用。遇到真实缺口时应补足有意义的方法或另行确认边界，不添加无效牌、隐藏解锁、强制亲人或擅自减位置。本轮不为尚未进入试做的所有未来组合扩充动作池。

## 建议的最小试做范围

**下一轮开工提案，尚未执行；不重新征求已确认规则。** 只改现有停车棚 Editor 案例，保留正常接近与应激恢复两个起点及同一动物连续状态。

1. 复用现有五种方法和供给去重；地上已有足够食物或已经进食、且本次没有其他用途时，不再新发投喂。库存不足与当前无意义分开说明，提交在消耗前作同样校验。
2. 无意义锁定项保留实例、锁定与原因，不消耗；禁用使用但允许玩家解锁。只扩展现有表现接口所需的最小能力，保持原选项白板默认行为，不重建 Prefab 或覆盖图片绑定。
3. 将允许接近与接受安置落实为不同的实际条件和回应；不再让准备安置无条件成功。本例展示试探与自行安顿，收尾独立、不加隐藏接受率、不改成固定点击次数；具体触发在试做时明确标注为本例假设。
4. 安全判断、当前可执行、未来有准备价值和当前无意义保持区别；刷新与提交读取同一份最新动物状态。核对锁定与缺货组合，不用不可执行项冒充安全保底。
5. 复用既有手册、求援、暂停与连续状态；不加入正式动物系统、地图、再遇存档、伤病、失败阈值、奖励或主场景接入。

既有数据只支持单只健康样本，不在本轮添加完整性格系统。若实际试做中本例也出现不足三种合理方法的局面，明确记录并讨论，不默默用无意义玩具补位。

## 实施时应验证

- 地上已有食物、已吃饱、库存耗尽分别正确过滤与拒绝；拒绝后动物、手牌、回合、锁定和物资不变。
- 通过自然可达的过期保留项验证不可使用且仍能解锁；新发与锁定合并后同方法不重复，数量和安全兜底同时成立。实施时采用锁定接近后动物主动靠近的路径；当前去重与使用即消耗意味着没有另一张锁定投喂可在放食后自然过期，不为测试添加旁路。
- 接近许可、试探安置、接受安置反馈确有不同规则结果，不是仅修改文案；普通退缩保留已进食事实。
- 正常与应激两个起点、无玩具互动路径、手册/求援、暂停和旧输入拒绝仍可用。
- 对共享选项视图补交互回归，确认禁用使用没有连带禁止解锁；原选项白板及已有图片绑定不退化。

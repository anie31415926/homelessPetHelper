## 本轮执行检查点：连续状态与两个起点

2026-11-17 用户确认正常接近与应激恢复两个起点可以开工，并强调动物状态应连续演变：后续操作始终更新最新状态，不在回合、恢复或回站时重新初始化。明确救助失败后可以丢弃本次动物状态；这不代表已经确定失败触发规则，也不要求此试做加入自动失败。显式重新开始/切换测试起点创建新会话，不等同普通状态转换；未接存档，连续保留指本次运行期间，不承诺退出/重启应用恢复。

- 沿用已有 `CaseAnimal` 单一状态所有者与不可变 `CaseAnimalSnapshot`；本轮不复制正式动物系统，也不将状态“线性”误解成只能按固定动作串进行或不能退缩。
- 新增独立的 `CaseStress`（无应激/应激中），不把应激混入饥饿或行为枚举；普通受惊与应激区分。正式多类状态扩展仍待细化。
- `CaseStart.Normal`：饥饿、紧张、无明显伤病；`CaseStart.StressRecovery`：已经进食、受惊、应激中。仅在会话创建时应用一次预设；普通行动不能重新加载预设。
- 本案例应激恢复暂用“退开留空间 -> 合适等候缓和 -> 继续建立安全感”验证：前提不足的等候不恶化，退开不直接清除应激，恢复后已进食事实保留，不必再消耗食物。具体恢复速度仅为试做参数，不反推正式应激触发与伤病处理。
- 保留同一个动物身份经过回应、刷新、独立收尾、总结、回站与轻量互动；回站不按起点重建动物。求援仅结束试做且禁止继续提交，不冒充救助失败、成功入站或正式交接。

## 范围与假设

- 复用已有选项管理与静态白板 Prefab，单独保存 Editor 验证场景，不修改旧选项白板、主场景或正式构建列表。
- 从已经抵达停车棚开始，一只饥饿、紧张、没有明显伤病的小猫；本轮不做地图、开路、医护、建设、存档、奖励或正式领养。
- 按同期已确认方向：由状态、前提与行动确定回应，不额外判隐藏成功率。需求、情绪、行为分开，受惊不会消除饥饿；具体状态转换、物资和回应步骤仍只是本案例假设。
- 三个选项、用一个、最多保留两个。使用后先展示一次主要回应，玩家继续观察后进入下一回合；收尾独立于抽取。
- 行动暂用退开、等候、放食、玩具与接近。带两份食物作为试做参数；重复放食不叠加进食效果，已落地食物保留。物资不足时拒绝使用，不消耗选项或推进回合。
- 本案例的安全前提暂为留出空间、吃过东西、情绪放松；退开和合适等候能稳住，等候不保证自动成功。玩具和等候提供不同的放松路径，不要求唯一动作串；不将这组前提泛化到所有动物。
- 同期确认了区分允许接近与救助意愿、动物可主动靠近。因此样本放松后，合适等候时可主动来到身边，不强迫再等接近选项；玩家也可先用合适接近进入可接近状态。再用独立“准备安置，观察回应”确认本样本接受，才开放完成救助。这次准备操作总会接受是该健康样本的试做假设，不代表正式动物必然接受或全部动物都需额外点击准备。
- 过早接近会受惊、退缩，并重置接近机会，但保留饥饿、地上食物及求援入口。此样本不含死亡、不可恢复失败或整局结局，不能推断正式玩法保证恢复。
- 每轮先评估真实可执行且不恶化的行动，再供给三个选项；考虑保留项与食物库存，必要时将一个刷新位置留给安全行动。有种子的抽取仅用于比较此样本，不代表正式概率、去重或保底规则已定案。
- 手册是自由查看，不推进本案例回合；求援只结束本次试做并明确标为交接待细化，不发奖、不算普通救助成功，也不把动物送入站内。
- 成功后先展示只读总结，再进入单只动物的站内近景；提供一次轻量互动回应，不假装已完成正式照护系统。回站承接同一身份及状态，不重复创建动物。
- 暂停或失焦拒绝输入，不推进；重新开始创建新会话，旧回合输入不能作用于新会话。退出场景结束本次试做，不提供存档恢复承诺。

## 参考走法

正常路径：留出空间 -> 放下食物 -> 等候进食 -> 等候或玩具使其放松并主动靠近 -> 准备安置，观察到接受回应 -> 独立完成救助 -> 查看总结 -> 回站互动。

替代路径：在其他回合先放食再退开，或先等候稳住后再提供食物。发牌与保留会改变实际行动顺序，不以完整输入串匹配判断成功。

误处理：紧张时接近 -> 显示退缩和原因 -> 退开恢复安全空间 -> 继续尝试，或随时呼叫求援结束试做。

资源耗尽：两份食物均放出后，食物选项不可再执行；地上已有食物仍可在合适前提下进食。安全行动与求援不能因食物耗尽而消失。

# 地点回访与进度保存

2026-11-23；用户授权实现地点回访、现场保存和中断接续。沿用现有 Main、纯规则与双槽存档，不新增玩法框架或场景。任务与最终验证见[本轮记录](协作任务/20261123-地点回访与进度保存-01a1f74d.md)。

## 玩家行为与保存边界

- 首次到一个普通救助事件时固定地点布局、模板/模式、内容指纹、随机种子及动物身份；再次进入同一请求使用这份实例，不因教学完成、地图重开或外出种子变化而换题、换动物。
- 保存箱子的索引对应位置、桥的位置、每块杂物的剩余工作量和有界撤回历史。清到一半退出可以继续；同一事件回站再访仍保留现场与同一动物。
- 地点独立保留最新现场成果及来源事件。新事件使用已保留的通路和侧边物件，已经安全时直接进入救助，不额外收取未执行的开路耗时。若另一事件在同地点操作过，回访优先使用地点的最新成果，不把旧事件的箱子摆回去；跨事件不继承撤回历史。
- 外出中断后恢复同一次外出及请求保护。战斗恢复后先打开现有暂停菜单，玩家继续后按当前已保存的节奏设置推进；未提交的拖牌计划、手指接触和设置草稿不恢复。
- 箱/桥移动、撤回、清理接触结束、单块障碍清完、部署提交、阶段变化、胜利确认、回站与站内既有检查点即时保存。持续清理/战斗另外每5秒合并一次，后台或失焦时补保存。正常关闭做补充保存，不依赖退出回调；直接杀进程可能回到最近成功检查点，持续变化的周期窗口最多约5秒（前台正常调度条件下）。
- 地图只选点而未出发时仍保留站内检查点；本批没有新增地图选择存档。站内护理保持既有“结束本次”结算边界。

## 数据归属与兼容

`main.station` 分区从版本1提升到版本2，原分区ID和桌面/微信存储键不改。v1在副本上增加空现场记录，读取不落盘；首次成功保存才提交迁移结果。旧档原有动物、容量、请求ID、已结算时间和护理成果保留。

`MainProgressData`同时保存站内状态与`WorldFieldData`：

| 数据 | 内容 |
| --- | --- |
| 事件 | 请求ID、地点、固定布局/模板/模式/种子、动物、现场进度 |
| 地点 | 最新物件/工作量、布局与模板契约、来源请求、最近变化时的已提交游戏分钟 |
| 当前外出 | 外出ID、请求、外出种子、实际开路标志、开路/战斗/已确认救助阶段和战斗记录 |

地点/事件数据由`FieldProgressSession`维护；`MainProgressSession`在构造时恢复完整外出业务，包括请求保护、开路、战斗及已确认救助，界面随后绑定，不由Presenter补做业务恢复。脱离界面单独读档后也能再次保存。`MainProgressCodec`保存整个业务聚合，站内和外出结果不分成两次磁盘提交。请求池允许保存同一已配置定义的多个真实实例，不再要求请求条数等于开局条数；仍校验配置版本、地点约束与重聚接收安排。本批没有自动生成这些实例。

布局及开路/战斗配置生成SHA-256内容指纹；事件另存动物定义、遭遇、战斗profile、成功情绪/压力/行为及各阶段外出耗时的规则指纹，避免途中换规则。动物初始值由保存的个体状态延续。进行中的模板按保存的ID与模式恢复，不重新挑选候选。不存在或不兼容的内容拒绝读取，保留原档，不静默换题。当前没有把历史配置版本打包成资源库；正式改版时应显式迁移或保留旧版本，不能仅改ID绕过校验。

开路模块只接收脱离场景的只读状态，校验位置、格数、桥位、工作量及撤回上限后写入新会话。恢复完成路线仍需经过真实完成校验；已有通路走原有无开路救助入口，保留预检与耗时语义。

## 战斗恢复

`SiegeSession`记录实际执行的固定步长数与成功订单，将相同节奏/教学等待条件的连续步长合并，拒绝的订单不入记录。存档使用显式DTO，不反序列化规则私有实体，不保存Unity对象或运行时类型名。

恢复在新建的临时规则会话中按同一种子和配置重演有效输入，校验订单、会话/回合身份、阶段、步数总量及不足一个固定步长的余量，成功后一次替换状态。手牌袋/RNG、能量、单位、蓄力、技能前摇/持续/恢复都由原规则推导，不复制一套战斗计算。输入量受配置的战斗时限和固定步长约束；记录有独立模拟版本，后续修改模拟语义须同步处理旧记录。

暂停/后台不记录推进步数，不使用现实经过时间补算。UI动效在新场景重新绑定当前业务状态；未承诺恢复到同一个动画像素帧。

## 结算与失败处理

恢复外出通过原有出发、请求接受、真实开路和动物绑定入口，不直接改`RescueFlow`的阶段。已确认胜利从保存的胜利记录恢复，确认回站后由原结算校验一次性提交请求解决、入站身份、游戏时间和清空当前外出。回站写入前失败时停止操作，旧检查点仍是待回站的同一动物；重新读取后可以再次确认，不叠加未持久化的那次时间或动物。若写入已发生但回读失败，结果暂不确定，重进后由双槽中最新有效的完整记录决定恢复到待回站还是已入站，不把失败提示当作肯定未提交。

保留双槽校验、坏槽恢复及原始记录。读取失败不创建可写的新档；保存失败显示既有失败提示并停止业务操作。收尾先结束现场占用，再关闭弹窗，避免弹窗释放暂停时把已结束外出重新保存；关闭后的现场不再刷新派生快照。

## 试玩步骤

1. 打开`Assets/Scenes/Main.unity`，从站内地图进入单车棚或小院。挪动箱子/搭桥，或清理一部分杂物后停止Play，再进入：仍是同一动物、布局和现场进度；解谜可继续撤回。
2. 在开路或救助中主动回站，再从地图进入同一个求助：现场成果与动物保留；这是新一次外出，战斗重新开始。
3. 开通三路后进入救助，部署并推进战斗，再停止Play、重新进入：先显示暂停菜单，继续后接上原战斗。也可在胜利后、回站前重进，确认同一动物只入站一次。
4. 正常存储下检查原站内动物、护理与时间仍可续接。存储失败、旧档迁移、新事件继承安全通路由自动化注入存储和真实请求测试覆盖；普通Main尚无自动生成新事件的玩家入口，不用清档或篡改本机存档来模拟。

以上是待人工执行的步骤，不能当作真人试玩已通过。测试中的重进使用同一存储重新加载Main，并另行断言离散操作在销毁前已经落盘。

## 已确认与本轮授权

- 用户批准首轮三个选项、每回合使用一个、最多锁两个；要求方便新增选项、增加展示数量及未来多选，随后授权按规范动工并及时记录。
- 锁定项跨回合保留，使用后仍消耗；刷新随回合进行，只刷新未锁定项，不提供回合内无限重抽。
- 选择前可读动物倾向，每回合有安全稳定选择；手册/求援不参与随机池。此处不能把“安全”理解为必然推进。
- 当前只授权已确认的选项管理部分，不猜定动物状态、具体效果/资源、抽取概率/重复策略、医护、死亡或结局，也不制作 UI。

## 实现边界

已在现有 `Modules/Rescue` 程序集内新增 `Options` 子目录，使用普通 C# 类型，不新增运行时包或通用框架。

- 行动定义、本轮选项实例、只读数量规则分开；选项集合不固定为三个字段。实例有会话内独立身份，锁定和消耗不依赖列表位置。
- 选择提交使用实例 ID 集合。当前规则只支持每回合使用一个；大于一的使用上限在规则构造时明确拒绝，防止误以为只改参数就已获得完整多选玩法。多选的动物回应、先后和资源规则仍待讨论。
- 选项容器仅管理发牌结果、锁定、选项消耗与换轮，不执行动物行为、不扣实际物资、不判救助成功。外层将来必须先校验完整行动，再调用选项消耗入口。
- 刷新入口接收外部已经抽出的选项定义，以及本回合经规则评估可稳定局面的行动 ID；校验保留项与新选项合并后确实包含稳定选择，否则拒绝整次刷新。不实现抽取分布，也不把调用方提供的分类冒充真实动物安全判定。
- 初始供给与使用后换轮可进入刷新；选择期间拒绝刷新，不让此入口变成手动重抽。后续由会话编排在动物回应结束后调用，不从 UI 直接调用。
- 每次输入核对会话、回合和阶段；失败不改选项、锁定、回合或实例计数。暂停时拒绝操作，关闭后拒绝继续使用；只读快照不泄露内部可变集合。
- 同种行动可由不同实例引用，容器不决定随机源是否允许重复抽取；锁定上限必须小于展示数量以保留刷新位置。后续若放开全锁需另行设计。

## 接口与接入顺序

生产实现位于 `unity/HomelessPetHelper/Assets/Scripts/Modules/Rescue/Options/`，仍属于原有无引擎引用的程序集：

| 类型 | 职责 |
| --- | --- |
| `RescueActionDefinition` | 只读行动 ID，未提前塞入动作效果、文案或医疗字段 |
| `RescueOptionRules` | 显式传入展示数/使用上限/锁定上限；校验范围并拒绝未启用的多选 |
| `RescueOption` | 不可变选项快照，包含实例 ID、定义和锁定状态 |
| `OptionTurnId` | 会话 ID + 回合编号，防止旧回合或其他会话误用相同实例编号 |
| `OptionHandPhase` / `OptionFailure` | 明确阶段与可识别拒绝原因 |
| `RescueOptionHand` | 唯一持有选项流转；只读快照、锁定、选项消耗、换轮、暂停和关闭 |

外层未来的接入顺序如下，不是目前已存在的完整玩法实现：

1. 会话装配提供本轮唯一 ID 与集中规则参数（首轮 3/1/2），创建选项容器；未接配置生成器，不存在生产默认常量或自动启动。
2. 动物规则确定下一回合意图，结合前提与物资评估稳定行动；抽取模块提供待填充的新选项，调用 `TryRefresh`。初始目标回合为 1，后续严格递增；无安全选择或数量不符时拒绝，不偷偷解锁/重抽。
3. 选择阶段用本回合标识调用 `TrySetLocked`；展示读取不可变快照。锁定不执行行动，选择期间不允许刷新。
4. 玩家提交实例 ID 集合，外层完整校验行动/资源，随后调用 `TryConsumeSelection`；当前恰好使用一个。成功只消耗选项并进入等待动物回应阶段，不修改健康、食物或救助结果。
5. 外层执行已确认的行动与动物回应，若还需交涉再供给下一回合；若收尾、退出或失败则 `Close`，不为收尾强制刷新。

行动/资源的全流程一致性必须在后续所属规则中完成；本容器的局部拒绝无副作用，不等于已经实现跨模块事务。`TryRefresh` 在等待回应阶段可供会话调用，但容器不能认证动物回应已结束，禁止直接绑定为 UI 重抽按钮。

数量扩大时算法仍遍历集合，已有测试覆盖 1、3、6、12 个选项，生产规则未固定为三个字段。重复定义的实例独立，当前不决定抽取分布。所有快照替换发生在低频命令入口，没有 Update/计时轮询；未做真机内存或性能测量，不声称零分配。

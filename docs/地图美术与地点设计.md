- 首张社区地图规划六处探索地点，优先细化单车棚、居民小院、临街门廊三处。救助站不计入六处外出地点。

## 首图构图建议：林缘社区

采用稍俯视的插画地图，同时看见屋顶、立面和地面。中下部是有人生活的社区，上部逐渐过渡到疏林和较密的森林，让玩家从首图就能感到社区与森林相邻。

| 画面位置 | 内容建议 | 画面作用 |
| --- | --- | --- |
| 上沿约四分之一至三分之一 | 成片树冠、近处可见树干、林中光斑与出画的小路 | 森林有实际面积和纵深；此占比仅为首版构图起点 |
| 上部左侧 | 林缘公园，草地从社区延入树林 | 从人工环境到自然环境的过渡地点 |
| 上部至右侧 | 小溪、木桥、河岸步道，沿溪生长的芦苇 | 与森林图共享的视觉地标，兼顾岸边地点辨识 |
| 中部左侧 / 右侧 | 居民小院 / 市场后院 | 用矮墙与屋棚形成不同的生活空间 |
| 下部左侧 / 右侧 | 单车棚 / 临街门廊 | 首批地点轮廓清楚，方便寻找和点击 |
| 靠近下方主路 | 救助站建筑 | 表达外出的起点和回家的方向；本轮不将建筑新增为按钮 |

道路把地点组织成一个街区，溪流偏右侧纵向延伸，避免道路和水面切碎所有点击区。住宅、街巷、林缘仅作视觉分组，不新增“先点区域、再点地点”的中间界面。六处地标应有各自轮廓及名称空间；具体距离在手机尺寸预览后调整，不承诺任意数量都能挤进同一屏。

地图插画绘制在内容区，顶部状态和底部详情面板单独排版。底图不烘焙地点建筑、文字、动物、求助标记、按钮和选中光圈；沿用现有地面与独立地点图分层方式。森林、路和溪流可进入地面底图，需要遮挡建筑的近景树冠再评估独立层，不预先扩大分层数量。

## 两张地图怎样承接

建议保持同一方向感：首图由社区向画面上方的森林走，森林图从画面下方接入。共享三组线索：

1. **林间路**：首图上沿出画，森林图下沿接入，宽度、路面颜色和弯曲方向连续。
2. **小溪与木桥**：溪水在两图同侧延伸，桥的木色、栏杆和邻近树形一致；可在森林图入口再次看到同一座桥，不画成两座无关桥。
3. **林缘植被**：沿用同一组浅黄绿阔叶树、灌木和花，森林深处逐渐增加树冠密度、光影层次，避免突然换季或换色板。

首图的林缘通路先作为环境线索，不额外算第七处探索地点。森林图应向更深处展开，有新的空间层次和地标，而非把首图树丛简单放大。上述是画面连续性要求，不代表无缝大地图、地图切换、相机移动或资源按需加载已实现。

## 六处地点：外观、点击和进入后的现场

下表是内容设计，不是新增运行模板清单。现场里的障碍和工具仅作美术搭配建议，实际可操作物必须匹配已有规则；需要新增规则的内容先确认。

| 地点 / 优先级 | 地图外观与点击对象 | 进入后的局部现场 | 可复用的细节建议 |
| --- | --- | --- | --- |
| 单车棚 / 首批 | 暖木或浅色棚顶、两三辆单车、少量纸箱；以整个棚体和附近地面作点击范围 | 棚下略窄的通道，侧面是车架与支柱，动物区域在遮蔽处；棚顶、箱子颜色与地图一致 | 轻箱、木板、落叶；保持通路边界清楚，不把装饰车架误画成可移动物 |
| 居民小院 / 首批 | 矮墙、木门、晾衣绳、花盆，院口明显；点击院落整体 | 门口到院内的短路径，角落有花架、空盆和落叶堆，前中后景清楚 | 可移动箱和落叶/杂物；保留院墙和主花盆作为内外识别物 |
| 临街门廊 / 首批 | 奶油色墙、浅木门、淡色雨棚、两级台阶及盆栽；点击雨棚和台阶一带 | 近景是台阶与门前空地，屋内有柔和暖光，动物或接收区域放在有遮蔽的门边 | 花盆、垫子、少量轻杂物；可为后续团聚交接留空间，但当前 Main 交接尚未接入 |
| 林缘公园 / 后续 | 原“社区公园”细化；草坪、长椅、低木栅栏和伸入树林的小路，树冠不遮住入口 | 林缘空地、长椅侧面、灌木边缘，能看见林中光线，兼具社区与森林特征 | 落叶、轻枝、木箱；局部树形与首图森林衔接处一致 |
| 市场后院 / 后续 | 低矮遮棚、手推车、整齐叠放的周转箱，与门廊的住宅轮廓区分 | 收摊后的后院通道，墙边有箱堆和小推车，中央留可读的操作空间 | 箱子与轻杂物；避免把场地画得拥堵阴暗，不固定某一类开路玩法 |
| 河岸步道 / 后续 | 木桥、栏杆、溪水和芦苇，步道与林间路相接 | 安全岸边的平台或步道，水面作边界，操作区在岸上，远处可见同款桥栏 | 岸上落叶、轻箱、浅沟木板；不把进入深水或危险追逐设为默认操作 |

三个首批现场先共用现有开路与逆塔防结构，以场景色彩、边界和摆设建立差异。不要为每处地点复制一套业务流程。两种开路方式均可使用符合地点环境的素材，不用美术规划改变当前随机选择规则。

## 点进去的体验

建议保留当前选点→下方详情→确认出发的结构，地点本体使用宽松且不互相重叠的点击区，名称牌与求助角标单独叠加。选中使用柔和光圈或名称牌高亮；同时保留文字，不能只靠颜色区分“有求助 / 暂无求助 / 尚未开放”。装饰树、普通房屋和森林延伸方向不要长得像已开放的按钮。

详情依次说明地点环境、当前线索或求助、预计耗时、安置名额需求和出发限制。地点说明不固定写某只猫狗，求助结束后可回到中性环境描述。“暂无求助”仅代表当前没有待处理请求，不代表地点永远不会出现动物。

确认出发后，局部现场先让玩家辨认环境与目标，再操作开路；真实连通后接现有逆塔防，结束回站。地图地标与现场共用至少两项辨识元素，例如棚顶和支柱、院墙和花架、雨棚和台阶。**开路几何继续影响逆塔防路线**只是可讨论的后续提案，本轮不新增该规则。

## 制作顺序与交付边界

1. 先做首图整体构图候选：六处地点位置、上部森林、小溪/木桥/林间路、UI留白一起检查；候选仅供看图调整。
2. 构图认可后，再分别制作地面底图和地点透明图。先完成现有三处及救助站外观，后续三处沿用同一比例和光向；不把一张合成图直接覆盖当前运行底图。
3. 先以单车棚做一处局部现场，核对地图外观、开路操作区、动物焦点及逆塔防视角能否统一，再扩到小院和门廊。
4. 首图色板和共享地标稳定后，再做森林图构图；森林地点和切图规则确认后另建实现任务。

源图规格沿用[项目图片规格](图片资源规格与首包预算.md)：背景先比较约720×1280 / 768×1344，源文件计划200 KiB起；独立地点按实际显示从256档比较，确有需要再到512长边。母图留在 Unity 外，尺寸和字节是规划起点，不能用低清参考放大冒充高清成品。新增六处现场也不等于启动时把六套图片全部常驻；实际加载边界在资源接入时评估。

候选评审应检查：森林是否有真实空间、两图共享地标是否一致、六处缩小后是否可辨、名称与状态是否有位置、树冠/屋顶是否遮住点击区、现场是否匹配开路可操作范围。生成/派生信息、图片归属及审核状态按[台账流程](../art-source/README.md)留档。

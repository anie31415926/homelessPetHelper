## 必须先解决的问题

### 1. P2：阻断后没有可读的错误说明

前轮已实测保存失败后Toast透明度为0；本轮重核源码与对应输入未变化，问题仍在。[前轮完整复现](救助站UI规范复核.md)与失败报告保留，没有重新标为通过。

`StationPreviewSession.ReportPersistenceFailure()`设置阻断后进入`Refresh()`，先停用界面并冻结Toast，随后显示新消息；`ToastView.Show()`将alpha清零，冻结的Update无法再淡入。玩家看到操作失效，却看不到保存失败原因。这违反样式规范§5、§6、§7中的阻断提示可持续读取要求。

本轮还检查到[MainLoopPresenter](../unity/HomelessPetHelper/Assets/Scripts/Game/MainLoopPresenter.cs)的`!Progress.CanContinue`读档失败分支，同样先`SetSuspended(true)`后`SetStatus(...save.loadFailed)`；静态调用链具有相同风险。**该读档分支本轮未另跑运行夹具**，不冒称已新增实测。

建议使用独立、持续可见的阻断错误区域/弹窗，与普通Toast分工；保留业务停用保护。内容写清实际原因与已有可执行后续，不增加未经实现的“修复存档”按钮，也不自动覆盖坏档。验收同时覆盖加载失败、保存失败、恢复和关闭重开，检查真实透明度与可读内容。

### 2. P2：清洁与梳理缺少各自的禁用说明

当前`StationCareAvailability`只有两个bool，详情正文仅解释健康、脏污和轻触意愿。“允许抚摸/梳理，但暂不接受清洗”的合法组合下，清洁灰掉而正文仍写“愿意接受轻触”，玩家无从判断原因。首次短Toast不足以代替稳定说明。

沿用已有护理失败原因，具体到清洁/梳理显示一行原因或清晰的按需入口；不新定护理规则，不扩大常驻UI。[前轮权限夹具与截图](救助站UI规范复核.md)仍适用。

## 本轮新确认的样式问题

### 3. P3：彩色菜单图标被深绿乘色，细节糊成一团

实际[站内Prefab](../unity/HomelessPetHelper/Assets/Prefabs/Panels/Panel_StationLoop.prefab:537)的`StationMenu/MotionVisual/SharedIcon`引用共享`Settings`切片，但Image颜色是`#2A3D30`。它是彩色手绘图标，并非单色符号；深色乘色把浅杏底、中心孔与轮廓一起压暗。运行图右上看起来像一块深色小花，违反样式规范§4的彩色图标白tint约定。

![原图、离线乘色示意、实际运行图裁切](../test-results/station-style-review/menu-icon-comparison.png)

左为原始56×56切片放大，中为离线按当前tint相乘的说明图，右为运行图裁切；中图不是修复后截图。应先修正静态Prefab引用上的tint；[StationUiSkin](../unity/HomelessPetHelper/Assets/Scripts/Editor/StationHabitat/StationUiSkin.cs)的旧默认也有相同赋色，后续实现时需防止作者工具再次引入问题，不能重跑整站重建覆盖绑定。源图本身也较接近花朵，复原色彩后仍需按手机实际大小检查辨识度，不能只看放大图宣称已解决。

### 4. P3：设置图标与复合菜单含义不符

入口只有图标，原文字Label已隐藏；点开却是容量、时间、记录和暂停，没有声音设置。触屏无法靠hover知道里面是什么。按样式规范§4，若继续使用齿轮，需有可发现的菜单含义说明；单纯恢复原色仍不解决这个语义问题。

建议保持一个紧凑入口，提供“菜单”文字标识或换成同体系、含义明确的菜单入口；容量、时间继续放其中。后续给站内接声音设置时，复用已有设置/确认控件与返回层级，不复制一套站内专用设置系统。

## 后续精修建议

这些是画面完善建议，不能与上面的确定缺陷混为一谈：

- **观察位与选中框**：当前[动物控件](../unity/HomelessPetHelper/Assets/Prefabs/Widgets/Widget_StationHabitatResident.prefab)仍用无sprite的直线Image组成方框/栏杆；功能状态明确，但和柔和房间、手绘纸板不够协调。可将观察位表现为贴合场景的小围栏/垫子加标签，选中保留轻轮廓或标记；必须保持观察/选中含义和动物比例，不靠装饰隐藏必要状态。涉及新图片时另走台账流程。
- **暂停Toggle**：当前浅杏底、空方框/实心内方块，有独立状态图形；不能误报成“完全无开启标记”。可改为同体系勾选或开关，更易理解。其hover/pressed仍用旧灰色参数，与附近纸按钮不同；后续统一共享状态参数时一起核对，不能只改默认态。
- **关闭与按钮层级**：当前详情/菜单统一`X`与浅杏底，热区144U；主操作依页面分别为外出、清洁、结束、进入救助站，没有发现同组多个强绿主按钮。先保留，避免为追求统一而抹掉主次。`X`不是本轮确定违规项。

建议实施顺序：**错误可见性和护理说明 → 菜单图标与含义 → Toggle与状态标记 → 站内接共享设置/确认 → 观察位等场景精修**。顺序是后续建议，本次没有实施这些修改。

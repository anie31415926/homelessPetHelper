# 图片规格与首包预算（按需读取）

日期：2026-11-18。适用：微信小游戏目标的图片制作、导入与交付评审。当前重点是下载/首包，不新增玩法、资源框架或自动改图流程。

## 1. 先明确计量口径

| 指标 | 怎么取得 | 用来判断什么 |
| --- | --- | --- |
| 源文件字节 | 仓库中的 PNG/JPEG 文件实际长度 | 制作交付与存储；作为早期预警，不是最终包体 |
| 转换后交付字节 | 微信转换后的代码包、首资源、纹理/Bundle 等实际输出 | 渠道包大小；不能直接相加 PNG 文件冒充结果 |
| 首次可玩下载量 | 清空缓存后，从启动到目标首个可玩画面必需的全部请求 | 玩家等待；包括首包外的必需资源，不能通过挪到 CDN 隐藏 |
| 纹理像素/内存 | 导入格式及目标设备上的实际分配 | 运行成本；与 PNG 文件大小、网络流量分开 |

256×256 RGBA32 的基础像素量是 `256 × 256 × 4 = 262144 bytes = 256 KiB`。这不是“一张 PNG 下载 256 KiB”；无 Mipmap/额外副本时的基础像素量也不等于完整运行内存。KiB/MiB 分别是 1024/1048576 bytes，本文不混用 kb（千比特）。

## 2. 尺寸根据实际显示分档

先测目标截图中图片主体占多少**实际渲染像素**，包含允许的最大缩放，再取接近的尺寸；已按实际像素计算时不能再乘一次 DPR。1080×1920 是布局基准，不代表所有图片都要 1080 或所有手机都要按原生屏分辨率制作。

目标是正常玩法尺寸下观感不明显变差，不承诺有损压缩在任意放大下“零损失”。保留高质量母图；运行资产只保留需要的档位，不把母图全部放进 Unity Assets。不要把现有 256 图放大成 768 假充高清。

| 模块 / 用途 | 常见主体显示范围，需实测 | 首选交付分辨率 | 源文件目标 / 超出复核线 |
| --- | --- | --- | --- |
| 公共 UI：小图标、工具/状态图标 | 长边 48–96 px | 128 长边，简单图可 64 | ≤ 15 KiB / > 30 KiB |
| 地图：动物/求助角标 | 长边 80–160 px | 128 起比；细节或放大需要时 256 | 128 图 ≤ 20 KiB / > 35 KiB；256 图 ≤ 60 KiB / > 100 KiB |
| 选项/工具卡：独立插图，不含底板与文案 | 长边约 144–256 px | 256 长边；更小可 128 | ≤ 60 KiB / > 100 KiB |
| 档案、列表、纪念：头像/缩略形象 | 长边约 96–256 px | 128 或 256，优先复用已有图 | 同上；不为每只个体/每条记录新增完整 PNG |
| 救助现场/站内照护：主要动物 | 长边约 400–700 px | 512 起比；近景允许 768 长边 | 512 图 ≤ 150 KiB / > 250 KiB；768 图 ≤ 250 KiB / > 400 KiB |
| 特写/精细互动 | 长边超过 768 px | 1024 上限需说明实际需要 | ≤ 300 KiB / > 500 KiB；仅当前互动加载 |
| 城市/现场/站内：不透明背景 | 跟随画面裁切，需评估缩放 | 先比较约 720×1280 / 768×1344；细节不足时再比较短边 1024、长边随构图比例 | JPEG/同链路适用格式 ≤ 200 KiB / > 350 KiB；保留构图比例，禁止强拉正方形 |
| 面板、按钮、边框 | 随布局延展 | 64–256 九宫格或小块平铺 | 通常 ≤ 20 KiB / > 40 KiB；不用整面板大图 |
| 清洁/伤口等动态遮罩 | 按交互精度，不按彩色插图尺寸 | 当前清洁样例 128×128；需要时比较 256 | 原始单通道分别约 16 / 64 KiB；不能当普通彩色图随意压缩 |

表中是**起步规格与源文件复核线**，不是官方限制或最终下载量保证。超过复核线先检查用途、透明留白、细节及输出方式，并提供画面对比；确需超额可记录例外，不为达标损坏画面。非正方形按主体宽高比保留矩形，不为凑 2 次幂强制拉伸/补满方形。

现有选项样例的 Artwork 首选宽为 144 布局单位，256 图已有余量；站内主动物是自适应的大展示区，不能与角标一起降到 128。以上读取的是保存的布局/代码，最终像素范围仍待微信渲染与缩放实测。

## 3. 按模块预留总量，不只卡单图

以下是本项目的**暂行评审预算 v0.1**，用于先限制生产规模；待首个微信导出和真机首启后校准，不声称用户已确认渠道硬配额。超过先评审拆分/复用/规格，而非自动降低画质或静默放宽上限。

持续维护入口为[图片台账流程](../art-source/README.md)；预算数值以同目录 `resource-catalog.json` 为单一维护源，下表为当前说明快照，调整时同步本页。制作状态、内容开放说明和 `first-play/on-demand/preview-only/unassigned` 加载计划分开记录，不因容量示例确定新等级解锁或正式动物数量。

| 分组 | 早期源文件总量复核线 | 预留方式 |
| --- | --- | --- |
| CommonUI | 256 KiB | 少量通用图标/九宫格；字体、音频另计，不塞全局巨图集 |
| CityMap | 768 KiB | 1 张约 200 KiB 地图底图 + 约 8 个 60 KiB 的 256 档角标，约 680 KiB；更多种类优先按需，不一律常驻 |
| Rescue | 1 MiB | 当前场景底图 + 当前动物 + 本轮会用到的工具/表现，不加载全部动物图库 |
| Station | 1.5 MiB | 当前站内场景 + 可见缩略图 + 当前查看动物的大图；不预载全部大图 |
| Archive / Handbook | 512 KiB | 复用动物/工具视觉定义；列表虚拟化，不为每份记录烘焙新图 |

分组按唯一资源归属计算，共享图只计一次；源图总量仅是预警，Atlas/平台变体/压缩/构建重复仍可使最终结果不同。动物总数、肤色/动作/成长阶段数量尚未定案，表中“约 8 个”仅用于容量估算，不是玩法数量承诺。

**首个可玩画面的图片资源首次下载暂以 ≤ 2 MiB 为内部目标，预估使用不超过 1.5 MiB、保留约 25% 余量。** 此目标按转换后的真实必需图片请求/包内图片统计，不只看启动第一张空白屏，也不把“必需资源改到第二个请求”算优化。源码阶段用源文件清单作预警，但不能据其宣称目标通过。

这 2 MiB 不包含 JS/WASM/引擎、字体、音频和其他数据，**不是小游戏总包目标**。完整包和总首次下载预算，必须在渠道身份/SDK 链路可用后根据代码与基础资源基线分配；当前不引用旧版文档的 4/20/30 MB 数字充当本项目已确认限制。

预估示例：1 张 200 KiB 底图 + 12 张 60 KiB 动物角标 + 20 张 12 KiB 图标，源文件约 1160 KiB；100 张 60 KiB 图约 5.86 MiB，应按可见/当前内容加载，不能全进第一轮资源。两者都不是最终网络实测。

## 4. 控制成本而不先牺牲效果

1. **复用画面，而非为状态复制整图。** 动物基础形象、工具、场景、脏污/提示分层；干净/脏、选中/未选中尽量叠加或材质变化。个体与纪念优先记录已有视觉定义 ID、名字及必要外观参数；具体外观/动作仍待玩法美术确认，不能先生成大量组合图。
2. **先去浪费，再调压缩。** 移除无意义透明留白、重复背景、烘焙文字；多处同图共用引用，母图置于 Assets 外。已有交互图的裁边会改变 pivot、碰撞/清洁遮罩对齐，不能自动裁切覆盖现有 PNG。
3. **按内容选源格式。** 不透明连续色背景可比较 JPEG 质量约 75–85；动物/图标保留透明 PNG，平涂可试调色板但要检查渐变和半透明边缘。先可逆优化，保留母图；不要把所有资源统一转成 JPEG/WebP 或引入运行时解码器。
4. **源格式压小不等于 Unity 交付压小。** Unity 通常先解码再按目标纹理格式导出，PNG 优化/JPEG 改名不能保证最终纹理更小，也不会自动减少 GPU 像素占用。微信转换插件的压缩纹理/按需路径可能再改变交付形式，必须以目标链路输出验证。
5. **目标纹理压缩单独验证。** 评估微信 SDK 支持的 ASTC/ETC2 或适用回退；清晰线条从较高质量档开始，检查白边、毛发、眼睛/细线和色带。256² 无 Mipmap 的 ASTC 4×4 数据约 64 KiB，6×6 约 28.9 KiB，但这些仍不是 HTTP 下载量，且不支持的设备回退可能更大；不能无条件强制 ASTC。
6. **图集解决批次与生命周期，不是图片压缩魔法。** Common/Map/Rescue/Station 按共同使用时机分组，先 1024 页，确需时评审 2048；结合利用率/页数/打包结果，不为少数小图固定开一整页。RGBA32 1024² 基础页为 4 MiB，2048² 为 16 MiB；填充、空白、重复收集都可能增加成本。
7. **先资源边界，后按需下载。** Editor 静态引用当前允许；正式启动链若把全部动物/背景放进一个 Prefab 的直接引用，会把依赖一起拉入。首批正式图前接统一加载入口并测真实分组；不为解决当前 6 张图立即装完整资源框架/CDN，CDN 也不能消除首次可玩必需下载。
8. **禁止序列帧无预算扩张。** 若正式设计需要动作，先评估少量关键帧/部件变化/已有动画方案；帧数 × 外观 × 阶段 × 尺寸一起预算，不能只审单张图。新增骨骼/动画框架另行评审，不由本规格直接授权。

## 5. 从现在开始的入库检查

- 临时 ComfyUI 图也从生成前登记到[唯一图片台账](../art-source/resource-catalog.json)，记录工作流/母图与候选或运行图，不等正式入库再补历史。每批运行 `npm run assets:check`，检查漏登记、缺失、审核后变化及源文件规划线；1.4 MiB 估算和未确认的首批不能当已验收计划。
- 每批正式图提交用途/分组、唯一资源 ID、最大显示像素、数量/状态变体、交付尺寸/文件字节、来源/许可；同批给出分组累计和首启使用范围。临时图标明不进入发布用途。
- 尺寸或字节超过第 2 节复核线、分组超过第 3 节、单图超过 1024 长边（背景按比例评估）、图集页超过 2048 时先评审；例外有用途、视觉依据和替代方案。不凭文件名自动判断用途，也不把母图体积当运行资产体积。
- 验收先比较原图与候选在**相同实际显示尺寸**的画面：小/大屏、最大允许缩放、深浅底、透明边缘和交互热点；模糊/白边/明显色带/遮罩错位则不接受。离线桌面截图只是初筛，不替代微信目标机。
- 运行已有 `Homeless Pet Helper > Tools > Check Image Resources`，或隔离命令 `powershell.exe -NoProfile -File tools/unity.ps1 -Task ResourceAudit -Isolated -ReportSuffix ImageSpecsV2`。v2 报告明确区分源文件字节和 RGBA32 参考量，不自动压缩、改绑定或强制阻断构建；不把未分组的试做图自动归入正式模块预算。
- 微信导出可用后记录代码包/首资源/纹理实际字节、去重后的冷缓存首次下载、可交互时间与设备回退；同图可能有多种平台产物，按一次真实设备路径计下载，按渠道实际归属计包体。超额回到分组/复用/压缩比较，不先承诺任何图“压到固定 KB 一定不丢效果”。

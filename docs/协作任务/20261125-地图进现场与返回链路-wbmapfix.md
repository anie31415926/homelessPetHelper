## 当前事实与下一步

根因（已用源码与 Prefab 核对）：
1. `MainLoopPresenter.EnterApproach()` 的 Exploration 分支（约 319-325 行）只设 `_explorationLayout` + `RefreshArrival()` 就 return，从未进入现场；玩家须在详情里再点 Explore/Puzzle 才进，且玩法由玩家选。
2. `OutingFieldCatalog.Get(pointId)` 对 park/market/riverside 等无 FieldConfig 的地点返回 null，`_explorationLayout` 为 null 导致 `StartExplorationActivity` 早退，表现为"点进去还在地图外"。
3. 救助现场 `_returnRequested = ReturnFromApproach`、战斗 = ReturnFromSiege，均结算回站；只有探索现场 `CloseExplorationActivity` 回地图。
4. 弹窗栈两套不通：`CityMapView` 内嵌 `PopupStack<PopupKind>`、`LevelOverlaySession` 的 `PopupStack<LevelPopupKind>`；Left Bottom 返回键未接 `Back()`，`Back()` 只挂 Esc。

细案：
- A. 进现场与随机：EnterApproach 探索分支改为按 outing seed 确定性随机 Cleanup/Puzzle 并调用 StartExplorationActivity 真正进现场；有求助地点沿用 FieldProgressSession.Begin 的随机 opening 后接 EnterSiege。详情里去掉 Explore/Puzzle 玩家二选一（RenderExtraActions 只保留站况），玩法描述并入详情文本。
- B. 默认兜底：OutingFieldCatalog 在构造时以任一已配置布局为模板，为所有无配置地点派生 pointId 匹配的默认布局副本；OutingFieldLayout 增加可从 Data 构造与 ForPoint 复制能力。
- C. 统一返回（不改弹窗栈实现）：MainLoopPresenter 增统一 `HandleBack()`——若 `_overlays.Depth > 0` 则调 `_overlays.Back()` 关最上层弹窗（栈空不误开暂停）；无弹窗时按 现场→地图→救助站 层级导航。现场三处 `_returnRequested`（EnterApproach/StartExplorationActivity/EnterSiege）统一接到返回地图路径（保存进度 + 清弹窗 + 回地图、外出保留、不结算），重建被 dispose 的 mapPresenter；地图左下角 Cancel 保持回站结算；RescueResult 确认仍结算入站。
- D. arrived 状态提供"继续现场"入口（按 seed 随机一致，重进读到同一进度），使外出保留后可恢复。

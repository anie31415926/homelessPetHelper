# 协作任务

共同目标、更新规则及信息归属见[当前协作状态](../当前协作状态.md)。本目录每个任务一份文件，各负责人独立更新，避免所有 agent 同时争写一张状态表。

开始或续接任务时读取目录中的未结束记录；“状态待核实”也仍须核对占用。未结束状态包括进行中、待验证、阻塞、待协调、交接中。超过 60 分钟未更新的进行中记录不得自动当成已释放。任务结束后保留原记录，不新增一份相互冲突的状态摘要。

文件名：`YYYYMMDD-任务短名-会话短ID.md`。填写实际值，不写凭据、内部推理或无关聊天全文。

写入任务还需以下结构化 `collaboration` 块；字段是机器可读的负责人和写入范围，范围以该块为准，正文说明依赖与协调。路径相对仓库根目录，列精确文件或以 `/` 结尾的目录，不使用通配符或 `..`。包含自己的任务文件及对应执行记录目录；已有任务下次接续时由负责人补齐，历史完成任务不批量补签。按[执行记录说明](../协作执行记录/README.md)运行 read → ack → check。

````markdown
# 任务名称

- 任务 ID：与文件名一致。
- 负责人：工具/会话标识；不能仅写“本聊天”。
- 最近更新：YYYY-MM-DDTHH:mm:ss+08:00。
- 状态：进行中 / 待验证 / 阻塞 / 待协调 / 交接中 / 完成 / 已取消。
- 用户授权：具体目标；待讨论范围另列，不将建议自动视为获批。

## 写入范围

```collaboration
{
  "sessionId": "实际会话ID",
  "writePaths": [
    "docs/协作任务/YYYYMMDD-任务短名-会话短ID.md",
    "docs/协作执行记录/YYYYMMDD-任务短名-会话短ID/",
    "精确的仓库相对文件路径"
  ]
}
```

替换所有示例值；补全脚本、测试、生成物、文档及资源移动的源/目标和 .meta。Unity 路径也从仓库根目录写起，如 unity/HomelessPetHelper/Assets/…。

## 不负责与依赖

明确避开的工作、共享文件及需要协调的其他任务；独立工作可继续。

## 当前事实与下一步

已实现、在做、未做和下一步分清；提出的方案注明待讨论。

## 验证与交付

实际命令/结果、报告与源码快照；未运行、失败、跳过、人工/渠道未验均如实记录。
未提交的工作区内容不等于已验证。完成时说明是否提交以及遗留事项。

## 占用与交接

未释放的路径、接手人及条件；结束后明确释放。未知的其他会话状态不能代其修改。
````

# 抚摸反馈网页试做

2026-11-27。用户从《蓝色星源》的体验提炼出这轮方向：先验证动物在抚摸时是否会让人觉得“它真的开心了”，不把制作重点放在自主走来走去。以下保留网页迭代记录。

## Unity：第三种动物豆豆

- 打开 `Main` 并进入 Play Mode：地图选公园，完成求助，回站后点豆豆，揉头或身子。先微笑，持续揉会大笑、冒彩虹花并摇尾，松手约 1.8 秒后恢复普通表情。固定短根毛与独立卷尾沿用第七轮做法。
- 豆豆是独立动物定义 `dog.doudou`。保留原有猫、小麦及它们的请求和表现；新档公园已有求助，旧档由既有机制派发。初始收容名额仍为 2，不更换已有住户或更改存档格式。
- 现场和站内概览用静态站姿；近景使用拆层图集和 Unity UI 网格，不依赖 Cubism。洗护复用原流程，不包含独立的实时梳毛试做。[资产派生记录](../art-source/pet-affection-20261127/unity-derivation.json) / [实现与验证](协作任务/20261127-Unity第三种豆豆-01a21bfc.md)。

## 第七轮：卷尾离背

- 只在红线靠臀部的一端固定短根毛。红框内的卷尾下缘纳入活动层，不再有一长条固定毛压住它；整个卷尾仍是刚体贴片。
- 前后翻转的试做上限由约 28° 提至 36°。接近两侧摆动极值时，绕同一固定接点略抬起，背和卷尾之间有短暂空隙，接点不离身。静止姿势、抚摸与表情不变。[连续运行帧](../test-results/pet-affection-v7/tail-frames.png)。

## 第六轮：根部毛边固定

- 红线仍是旋转轴。贴着臀部的根毛从活动尾片拆出来，作为固定前景盖住接口；卷尾在它后面翻动，红线下方只保留短重叠以避免裂缝。
- 仍是一张同尺寸图集，原图和表情不改。[运行帧对照](../test-results/pet-affection-v6/tail-frames.png)与像素回归验证卷尾在动、根毛采样区和脚底不动。

## 第五轮：沿红线向内外翻

- 根据截图把从卷尾底部斜向臀部的红线作为固定铰轴，512 像素底图端点约为 (360, 231)、(409, 265)。轴在画面平面内，整片尾巴绕它向镜头内外翻，不再叠加屏幕内的转动。
- 静止时仍投影到原图位置。用同一张图集，笑容、头耳、脚底与热区不改。[尾巴运行帧](../test-results/pet-affection-v5/tail-frames.png)。

## 第四轮：卷尾拆层，整片摆动

- 移除微动档的整图尾部蒙皮。按原图描出卷尾，保留整块透明纹理；身体底图删除原尾，用邻近原毛色补回原先被挡住的臀部。拆分产物为一张 656×512 无损 WebP 图集，含 512×512 身体格与 144×148 尾片。
- 尾片是独立平面，尾根锚点固定。整片在空间绕根摆动，允许投影宽度随角度变化，但不再用局部权重拉扯卷尾或臀部。头耳仍用原网格；表情和约 1.8 秒微笑退场不变。原图、单换表情以及减少动态效果仍用原来的整张图。
- [卷尾连续运行截图](../test-results/pet-affection-v4/tail-frames.png) / [资产来源和锚点](../art-source/pet-affection-20261127/tail-derivation.json)。第三轮及以下作为历史。

## 第三轮：左右摇尾，笑容退场

- 尾根和卷尾改为绕身体竖轴左右摆，尾卷网格带少量深度，避免上一版绕画面法线打转。固定足底，头耳动作不变，松手后仍逐渐停摆。
- 不再永久保留微笑：停止抚摸后先微笑约 1.8 秒，再淡回初始表情。按钮或键盘预览也会退场；光再按住不动不会延长。头和身子均可重新抚摸触发。
- [松手余韵](../test-results/pet-affection-v3/after-390x844.png) / [恢复原脸](../test-results/pet-affection-v3/settled-390x844.png)。后面的第二轮说明保留作为历史。

## 第二轮：微笑、大笑、余韵

用户试玩后认可方向，要求头和身子都能摸、先微笑再大笑，松手保持微笑，并给柴犬加骨骼摇尾。以下为第二轮历史实现。

- 按住不动不会升级。连续揉约 0.16 秒并达到最短移动量，先微笑；达到约 0.54 秒、累计移动量且微笑已展示至少 0.26 秒，再闭眼大笑并冒彩虹花。头、胸腹和背部共用同一手势累计，可不松手跨区；移出有效区域不计位移。手势不足则不硬播完整反馈。
- 松手从大笑回到微笑，保持到点「复位」、切换对照档或重开页面；摇尾从当前幅度收住，不永久摇。继续揉可再触发大笑。点击底部「摸摸」或键盘触发同样的微笑、大笑、微笑序列。
- 三档仍便于比较：原图可单看花，换表情是纯贴片，表情＋微动加头耳网格和尾巴骨骼。同一张纹理不拆图；身体锚点固定，尾根和卷尾两节骨骼带网格，尾根到臀部小范围羽化过渡。未新增图片、全身骨骼或 SDK。
- [笑开时](../test-results/pet-affection-v2/happy-390x844.png)和[松手后](../test-results/pet-affection-v2/after-390x844.png)是本轮浏览器运行截图。

## 试玩

入口 [摸摸小屋](../pet-affection.html)，从仓库根运行 `npm run dev -- --port 5197`，打开 `http://127.0.0.1:5197/pet-affection.html`。在柴犬豆豆的额头按住左右揉；点「摸摸」或用键盘也能触发一次完整反馈。不加数值、任务或奖励。

| 对照 | 显示 | 想验证什么 |
| --- | --- | --- |
| 原图 | 固定完整底图，彩虹小花仍可用 | 只有特效时，会不会像是在点一个特效按钮？ |
| 换表情 | 同底图 + 眯眼、闭眼笑局部贴片 | 眼睛、嘴和反馈时机能不能独立成立？ |
| 表情＋微动 | 同一套表情 + 向手的方向微贴近、耳朵有余量 | 微动是否像真的在回应，值得额外的每个形象标定？ |

右上角独立关闭花，方便分开判断表情和特效。第一轮的行为是按下先放松、揉动后闭眼笑、松手约 0.8 秒再恢复原脸；最新行为以上面的第二轮为准。

## 静态图如何变成交互图

1. **固定姿态**：从用户指定的「宠物  场景」里选现有柴犬 `(26)` 平静脸、`(33)` 眯眼、`(34)` 闭眼笑，用仓库内已整理的同源临时参考。先以相同相机、视角、体型和脚底为基准；只将平静图抠成一张 512×512 透明底图。影子和房间单独画，不把背景烘进角色。
2. **只换会变的像素**：保留同一张头身底图；眼、嘴和颊一起取 181×133 面部区域，蒙版羽化后把两个表情排进一张 362×133 小图集。在同一坐标上合成，短过渡，不对两张整图做交叉淡入，不让轮廓和脚底跟着跳。两份网页图共 198,764 字节，复用的房间图另计 35,490 字节；并非正式包体或微信下载量。
3. **贴完脸才做小形变**：参照 Live2D 的 [网格编辑](https://docs.live2d.com/en/cubism-editor-manual/mesh-edit/)和[变形器](https://docs.live2d.com/en/cubism-editor-manual/deformer/)思路，沿用项目 Three.js 渲染。第一轮仅用 24×24 分段网格推动头耳；第二轮加密至 32×32 并加独立尾巴蒙皮，下身和脚仍在动态权重外。不直接复用猫的骨点或权重，不需要拆腿、补颈后或接 Cubism SDK。关闭 WebGL 时降级为换脸；减少动态效果时去掉网格运动及粒子位移。
4. **只有一张图时**：在原图上用窄面部遮罩生成增量表情，锁住原鼻位、头宽、下颌与视角；看鼻梁、眼距和脸颊色差是否会在切换时跳变。用本机 ComfyUI/Qwen Image 2.1 实际做了[微吐舌闭眼笑候选](../art-source/pet-affection-20261127/comfy-alternate.png)，明确只改眼、嘴和脸颊、不画手或特效。候选脸颊和鼻口笔触偏重，本轮留作对照，试玩使用对齐更好的现成同源表情。[工作流](../art-source/pet-affection-20261127/workflow.json)和[裁图来源与哈希](../art-source/pet-affection-20261127/derivation.json)保留。

不建议把单图网格当成自动拆层或自动生成全部表情。小幅度头耳反馈适合变形；闭眼、露舌、大张嘴需要实际画出新的像素，大角度转头才考虑正式拆层与遮挡补绘。

# 回合交涉与组合流程原型

日期：2026-11-16。状态：可试玩，参数与规则待反馈后调整。

## 正式规则讨论更新：2026-11-17

本节记录后续讨论，优先于下文的 HTML 原型假设；原型代码和历史验证结果未随讨论改变。

**已确认方向**：
- 动物状态可组合，不固定为饥饿、谨慎、好奇三种相遇类型，也不把物种与状态绑定。
- 状态至少涵盖需求、健康（包括伤病）、精神/情绪（包括害怕、紧张、放松等正负情绪），并区分当前行为。具体类别边界和组合约束仍待细化。
- 各类状态使用明确的枚举或类管理，不继续用一个 `mood` 混装需求、情绪与行为；具体类型、字段及转换规则尚未设计。
- 救助不保证成功。处理不当可能引起应激、情绪极端化；部分情况需要合适处理才可能挽回，也可能直接救助失败。
- 用户进一步选择：允许死亡，但仅作为极少数、反复忽略明确警告才可能触发的极端后果。正常认真救助不通过随机死亡制造风险，普通失误和本次救助失败不等于死亡。
- 玩家开局获得救助手册，记录应对各种情况的方法；救助选项可来自手册。应激时，正确方法按正确顺序使用可挽回；方法正确但顺序不合适，至少避免进一步恶化；选错后仍保留呼叫救援的机会，以高容错为目标。
- 用户认可顺序判定采用关键前提约束，允许多条合理处理路径，不为每种情况设置唯一正确操作串。具体动作、前提和恢复效果另行确认。
- 行动组织方向改为选项池，每回合从池中抽取行动供选择，体验类似卡牌；不采用先前建议的固定常用行动配场景行动作为默认方案。用户希望动物能主动回应，带来周旋和对抗的乐趣，不只是被动承受玩家行动。
- 用户确认动物应提前透露下一步的大致倾向，给玩家判断依据，避免完全碰运气；不直接标出最优选项。具体线索和结算方式仍待细化。
- 用户确认首轮回应由动物状态、现场条件、相关历史、已预告倾向和玩家行动决定，不额外掷隐藏接受/成功概率；相同相关条件产生一致规则结果。玩家改变条件后，实际回应可有原因地偏离原倾向；具体意图优先级、行动前提与效果仍待细化。
- 用户确认四种基础行动的分工：退开解除距离压力，等候在恢复前提满足后逐步稳定情绪、前提不足时稳住不推进，放食提供取食机会而非直接降低警惕，接近依据动物是否接受当前距离推进、明确抗拒时继续逼近可引起退缩/警告。先退开再放食、先放食再退开均可继续；取食、情绪与接近许可相互独立，具体条件、数值与失败幅度未定。详见[基础行动确认记录](回合救助最小试做草案.md#已确认四种基础行动的职责)。
- 用户认可接近许可与救助意愿的区分；动物感到玩家没有威胁、条件合适时可以主动靠近，作为建立安全感的可见反馈。主动接近不直接等于愿意被带走，已满足接近条件不必再使用接近选项走形式；不要求所有动物都必须主动走来。具体触发、线索与意愿判定未定，详见[确认记录](回合救助最小试做草案.md#已确认允许接近与愿意接受救助)。
- 用户认可误处理后不将全部进展清零：普通失误主要影响当前接近机会，表现为退缩、紧张或警告；进入应激后先处理刺激与恢复前提，不从头重复所有喂食/互动。已进食、已清除干扰等事实保留，恢复不自动等于完全信任或伤病治愈。具体触发、损失与恢复程度、失败边界未定，不保证任意误处理均可挽回，详见[确认记录](回合救助最小试做草案.md#已确认误处理后的退缩与挽回)。
- 用户明确状态连续演变：每次变化保留在同一动物的最新状态上，后续继续按因果更新；回合刷新、应激恢复和回站不能重新套用初始预设。“线性”不指固定动作串或状态只能变好；救助失败后可丢弃本次动物状态，失败触发与再次相遇仍待讨论。当前案例仅在运行期间保留，不代表已实现存档。
- 用户认可选项锁定：玩家自行决定锁定或解锁，锁定的未使用选项可保留到下回合甚至更后的回合；刷新只替换未锁定选项，不因经过一回合自动解锁。
- 用户确认选项使用后正常消耗，锁定项也不例外；刷新随回合自动进行，不采用回合内反复手动重抽作为当前机制。
- 用户确认抽取容错：查手册和呼叫救援为常驻入口，不进入随机池；每回合至少有一种可稳住局面的选择，但不保证推进或抽到最优方法。暂时缺少前提的方法仍可出现，供玩家锁定后续使用，不能只抽当前最合适的答案。
- 用户认可首轮按三个选项、每回合使用一个、最多锁定两个试做，不作为最终平衡；要求按项目规范为新增行动、更多选项位置和未来多选保留扩展边界，不把 3/1/2 写死在固定字段或流程中。当前不开放多选，具体多选顺序和动物回应时机仍待讨论。
- 用户确认动物愿意接受救助后不再等待抽牌，提供独立收尾操作；不把“邀请进箱”绑定为所有动物的固定流程。按钮可暂用“救助成功”，后续按动物类型调整文案即可，实际接受条件与转运表现仍待细化。
- 用户确认现场简易医护：成功接近、进入可救助状态后，若发现明显伤病，可打开简易医疗包扎窗口进行简单处理。现场与后续救助站医护同源，不做两套系统；现场只开放简易范围，不把包扎加进交涉抽取池。
- 用户确认以安全转运需求决定现场处理是否必做：不影响转运的轻微伤可回站处理；影响安全转运且简易医护可处理的伤势，先完成必要处理再结算救助成功；超出现场能力时保留求援出口。具体伤势分类与操作尚待确定。
- 用户选择动手包扎的医护操作方向，不采用选完方法后自动播放作为主要操作；具体工具、手势、完成判定和误操作反馈仍待试做细化。

**待讨论，不作为已批准规则**：
- 极端死亡的具体前置条件、警告内容与次数、挽回窗口尚未确定；不能直接用应激数值超过某阈值就判死亡。
- 累计一定数量后 Game Over 是用户提出的候选；是否采用累计、计数口径、阈值、是否表现为救助站停业及存档影响均未定案。
- 区分本次救助失败、动物后续去向和整局结局；是否能再次遇见、主动撤离、救援的具体时机与挽回窗口、失败后的存档处理均待确认。
- 普通失误的退缩/警告与保留已完成事实方向已确认；具体接近机会损失、应激触发、逃离或本次失败边界，以及技术中断如何处理，仍待设计。
- 呼叫救援的存在已确认，但是否结束外出、动物是否由其他机构接收、成功/责任记录、费用与奖励均待讨论，不能沿用先前建议擅自定案。

### 救助手册与应激容错

本节记录用户本轮提出的具体方向，不表示已批准行动清单、处理流程或数值。

| 输入情况 | 已确认的容错方向 | 尚需明确 |
| --- | --- | --- |
| 方法与顺序都正确 | 可挽回应激，而非必然失败 | 恢复判定、是否分阶段，以及与健康/信任/救助成功的关系 |
| 方法正确但顺序不合适 | 至少阻止情况进一步恶化 | 是否有部分恢复、如何提示先后关系、是否消耗物资或回合 |
| 选择错误方法 | 仍保留呼叫救援的机会，不因一次选错立即剥夺兜底 | 恶化幅度、警告、还能尝试多少次、救援如何结算 |

**顺序原则已确认**：用处理前提而非唯一操作串判定，允许不同的合理先后；不因与预设整段输入历史不同就判错。具体前提、方法和效果仍需讨论，不能把下面的示例当作已确认行动清单。

**文字验证示例，动作尚未定案**：在虚构的持续噪声情境中，暂用“噪声已消除”和“已留出空间”作为恢复前提，验证同一组原则：

| 示例输入 | 按已确认原则应有的区别 |
| --- | --- |
| 消除噪声 -> 退开 -> 等待 | 前提满足后进入恢复 |
| 退开 -> 消除噪声 -> 等待 | 同样有效，不因合理先后不同而判错 |
| 等待 -> 消除噪声 -> 退开 -> 等待 | 首次等待稳住但不满足恢复前提；后续可以调整，不锁死失败 |
| 消除噪声 -> 等待 | 尚缺空间这一前提，提示原因，不把正确方法但时机不合适当作危险误处理 |
| 选择不适合该情况的方法 | 反馈不合适的原因，仍保留呼叫救援机会；恶化程度未定 |

这是用于核对玩法逻辑的游戏示例，不是实际救助建议、正式关卡或已执行的测试。恢复应激与伤病治愈、重新建立信任、完成救助的关系仍待确认。

其他待讨论项：手册是完整步骤还是处理原则、可否随时查阅、查阅是否占用回合、手册与选项池的关系。查手册不耗回合且不推进危险仍为建议，未将对顺序原则的认可扩大到全部建议。不先设计手册 UI，也不默认所有手册方法对任意动物都安全有效。

### 选项池与动物主动回合

**用户已表达的方向**：每回合从选项池抽取行动供玩家选择，类似卡牌；动物也需要主动反应，让玩家与它周旋。选项可由玩家主动锁定、跨多个回合保留。并未据此确认组牌、卡牌稀有度、升级、付费抽卡、能量或完整弃牌循环等额外系统。

**意图预告已确认**：在玩家选择前透露动物的大致倾向，而不是行动后才第一次揭晓意图。具体姿态、文案、预告粒度及意图何时形成未定；不据此开始制作 UI 或美术。

**回应结算方向已确认**：状态、前提与玩家行动决定回应，不另加隐藏成功率；相同相关条件不因额外掷骰产生不同接受结果。意图是倾向而不是无视玩家操作的强制动作，回应变化应有可解释的原因。这不代表每只动物有唯一固定动作串，也不确认具体动作收益、资源或成功条件。确认记录与下一组提案见[可解释的状态回应](回合救助最小试做草案.md#已确认采用可解释的状态回应)。

**以下为细化建议或既有约束，未定细节仍待确认**：
- 以“动物表现出倾向 -> 本回合抽取行动 -> 玩家选择 -> 根据新状态结算动物行动 -> 下一回合”作为讨论模型。动物预示的倾向可因玩家操作改变，不是无视状态的固定脚本。
- 动物根据需求、健康、情绪和环境选择意图，例如准备躲藏、试探食物、注意玩具、主动靠近或警告回避；主动改变距离、关注对象和行动机会，而不只加减警惕数值。
- 预告可用姿态和简短线索，例如看向掩体、盯住食物或主动探头；玩家据此决定争取进展、稳住或等待机会，不必给出精确结算数值。提前可读是共识，这些具体线索仍是示例。
- 意图变化需有可解释的原因，不在玩家合理应对后无缘由地换成另一种危险反应。具体变更规则待定，不能通过这种变化绕过已确认的极端死亡警告边界。
- 同一意图允许多个合理应对，分别偏向进展、稳定或创造后续机会，不把卡牌玩法变成每回合只有一张正确答案的选择题。
- 抽取保底原则已确认，具体如何保证每回合安全应对仍待设计；不能以抽不到关键方法为理由迫使玩家承担极端后果。锁定项因环境变化不再安全、全锁且无安全选项等边界，需在确认抽取方案时明确，不能默默解除玩家锁定来满足保底。
- 动物回合不能绕过已确认的容错：若方法正确但前提不足应至少不恶化，就不能仅在玩家步骤保持不变、紧接着又由动物步骤强制恶化；具体整回合判定需在实现前明确。

**文字体验示例，未定案**：动物又饿又紧张，一边盯食物一边往掩体挪动；抽到放远处食物、退开等待、尝试接近。放食可争取它停下来试探，退开偏向稳定情绪但未必拉近距离，过早接近则可能使它藏得更深。后续动物还可以叼走食物退开或在安心后主动靠近，具体反应必须由可观察条件解释。这不是实际救助建议、固定牌组或已执行测试。

### 选项锁定与刷新

**已确认原则**：玩家决定保留哪个未使用选项及保留多久；锁定状态跨回合持续，不只限于紧接着的下回合；刷新仅作用于未锁定选项，不自动丢失仍锁定的选项。锁定是保留一个可用方法，而不是已经对动物执行该方法。

**使用与刷新已确认**：选项使用后移除，原本是否锁定不影响消耗；随回合自动刷新，其他锁定的未使用项继续保留。锁定不赋予无限使用能力，也不代表同一方法以后不能再次抽到；是否回到池中及重复抽取规则尚待确定。

首轮手牌流转为：选择并使用一个选项 -> 消耗该选项 -> 动物回应 -> 未达收尾条件时保留其他锁定项、刷新未锁定项并补充空位；动物愿意接受救助后不再等待抽牌。确切的动物结算步骤与收尾转换细节仍需定义，此处不扩展为完整回合实现，也不据此将未来多选固定为逐项回应。

**首轮规格已确认**：三个可选行动、每回合使用一个、最多锁定两个，至少留一个刷新位置；不作为最终平衡，也不沿用更早的“最多留一个”。用户要求为更多选项和多选留余地：行动内容、数量参数与本轮选项实例分开，使用集合及明确实例身份，选择与执行分离，集中校验数量与副作用。具体最小设计与待验证项见[选项扩展与多选边界](回合救助最小试做草案.md#选项扩展与多选边界)。多选玩法尚未启用，不能只改上限就默认多动作结算已成立。

**建议边界，待确认**：
- 锁定/解锁不消耗救助行动；自动刷新不另收资源。具体操作窗口、暂停/回应期间是否可修改锁定尚待确定。
- 选项消耗与实际物资消耗分开；使用前检查物资及可执行条件，非法提交不消耗选项或留下部分修改。正确方法但前提不足属于稳住局面、暂未推进，不能默认当作不可执行输入；具体分类另行设计。
- 锁定不冻结动物、环境或物资。若局面变化使该方法暂时不适用，应提示原因，而不是默默换牌或保证仍能按原收益生效。首轮上限排除全锁，但仍需保证可刷新位置提供必要安全选择；未来调整数量或放开全锁时，必须重新验证安全兜底，不能自动解除玩家锁定。

### 抽取容错

**已确认**：查手册、呼叫救援常驻且不参与抽取；每回合至少有一种安全稳住局面的选择，不保证每回合推进救助或抽到最优方法；可提前抽到暂缺前提但之后有用的方法，交由玩家决定锁定。

**仍待确定**：安全应对保底如何与锁定、物资耗尽和动物主动行为相容；查手册的回合/时间成本、救援结算、抽取来源及重复规则。首轮以 3/1/2 排除全锁，未来若允许全锁仍需另定安全出口；更多选项与多选仅确认扩展要求，不代表最终容量及多选结算已定。常驻入口不等于已确认免费或具体救援结果。

### 救助收尾与物种扩展

**已确认**：动物愿意接受救助后不再依赖抽到某个收尾选项，提供独立完成操作。按钮暂可写“救助成功”，也可后续按动物类型提供不同文案；不为改文案提前扩展本地化系统，也不让所有动物必须进同一种运输箱。

具体“愿意接受”的判定、哪些伤势影响安全转运，以及收尾表现仍待确认。按转运需求判断现场处理必要性的原则已确认；不能只因出现医护入口就认定动物已回站。规则结果不由按钮文字决定，已有的成功只结算一次约束继续有效。

### 现场简易医护与站内复用

**已确认**：现场医护在成功接近、可救助时提供；有明显伤病时可打开简易包扎窗口。它是与站内同源医护的受限使用范围，不另建一套现场治疗系统，也不提前制作正式 UI。

共用医护意味着同一只动物的伤病与处理记录需要承接，现场已处理的结果不能因回站丢失或另复制一份；具体健康类型、处理动作与记录结构尚未设计。不把情绪恢复当作伤病治愈，也不把所有疾病都当作包扎可以解决。

**转运与结算边界已确认**：不影响转运的轻微伤可留到回站处理；影响安全转运且现场能处理时，必要处理完成后再结算救助成功；超出现场能力时提供求援出口。不要求所有明显小伤都强制包扎，也不将现场处理当作伤病完全治愈。

**操作方向已确认**：玩家亲手完成包扎，不以选完处理方法后自动播放代替主要操作。现场与站内仍共用同一套医护规则；这不代表已确认具体拖动手势、工具或失败规则。

**待讨论**：具体伤势及可处理范围、工具与手势、完成判定、取消窗口/操作中断的结果、物资、处理失败与求援结算。选择工具后在目标区域短拖动、以可见包扎和动物回应反馈、偏离只算未完成而不造成新伤，仍为试做建议，不能扩大为已确认规则。这里是游戏操作讨论，不是现实医疗指导；不开始 UI 或完整医疗实现。

**下一步建议**：[正常接近与应激恢复两个起点](回合救助最小试做草案.md#已试做正常接近与应激恢复)已获授权并接入既有停车棚隔离案例，状态连续性与 UI 操作有自动化验证，入口和报告见[案例记录](停车棚救助案例试做.md)。先收集试玩反馈，再讨论正式应激触发、恢复程度和失败边界；未自行确定触发次数或失败阈值，医护精细手感留在对应试做中验证，不先扩展完整站内系统。

**实现进展**：已完成独立选项容器与测试，见[实现记录](选项管理模块实现记录.md)。案例另外实现 Editor-only 的样本供给与动物回应，但正式运行时仍未接入主场景、抽取、动物效果或真实安全评估。P2-00 其余规则继续讨论，完整状态、医疗、死亡、失败累计与结局不据此自行实现。

## 本轮共识

- 一次外出先随机遇到“场景解谜”或“清理开路”，不是每次都做两种。
- 打通路径后抵达动物处，再进行回合救助。
- 交涉时读取动物的状态与反应，选合适的行动降低警惕、拉近距离。
- 成功救助后回站，后续仍以照顾与暖心互动为重点。
- 一轮目标是几分钟内完成，既有变化，也不做成高难解谜或复杂战斗。

## 试玩入口

`/outing.html` 默认随机开路分支与动物初始状态。右上设置可指定分支、状态，并选择直接体验交涉。

保留旧入口：`/playlab.html` 为三个独立玩法，`/rescue.html` 为迷宫与网兜，`/` 为最初养宠原型。本轮不更改旧存档。

复测链接参数：

```text
/outing.html?seed=7&route=puzzle&profile=hungry
/outing.html?seed=5&route=cleanup&profile=shy
/outing.html?stage=talk&profile=curious
```

`seed` 是可重复的整数随机种子，`route` 为 puzzle / cleanup，`profile` 为 hungry / shy / curious。设置的“重玩同一次相遇”保留同一随机组合。

## 一轮流程

```text
随机开路方式
  -> 解谜：挪开木箱，选择搭桥位置
  或 清理：选择捡拾 / 修剪 / 冲洗，持续清理可达区域
  -> 通道实际连通，选择“走近它”
  -> 看动物的表现
  -> 选行动
  -> 动物回应，警惕 / 距离 / 状态发生变化
  -> 再观察，再行动
  -> 愿意靠近后邀请进箱
  -> 安全回站
  -> 简单抚摸反馈 / 再次外出
```

开路不是直接把动物“送到家”，不会自动跳过交涉。清理不要求全清，已有安全通道即可。解谜不再使用食物，避免开路与交涉反复消费同一种资源。

## HTML 原型回合规则（非正式定案）

### 主要状态

- **警惕 0–100**：本轮唯一显式主要数值。越低越安心。
- **距离**：远处 / 附近 / 身旁；不是第二条养成数值。
- **行为状态**：饥饿、谨慎、闻食、进食、好奇、玩耍、观察、安心。通过姿态、道具与文字描述表达，不增加一排进度条。

### 四个行动位置

| 行动 | 用途 | 不是总有效的原因 |
| --- | --- | --- |
| 放下食物 | 诱发闻食 / 进食反应，缓解饥饿 | 很紧张时不敢吃；正吃时再伸手会打断；吃饱后收益很小 |
| 退开 / 蹲下等待 | 给谨慎、进食、闻食中的动物空间 | 不会靠一直等就自动拉近距离，单纯等待有收益下限 |
| 轻晃玩具 | 回应好奇、观察状态，带来放松 | 饥饿、进食或高度警惕时不合适；连续使用效果变小 |
| 慢慢靠近 / 邀请进箱 | 在警惕适当降低后拉近距离 | 靠得太早或打扰进食会让它后退；满足条件后才变为邀请 |

每轮食物三份，等候与玩具不收费；食物耗尽仍存在恢复并完成救助的路径。当前没有行动点、回合上限、失败倒计时、死亡、伤害或随机捕获失败。

靠近的暂定阈值：从远处到附近需要警惕不高于 48，从附近到身旁不高于 28。身旁、警惕不高于 20 且不在进食时可邀请进箱。这些值是调试参数，不是最终平衡。

### 动物差异

| 初始状态 | 表现线索 | 倾向 |
| --- | --- | --- |
| 有些饿的小猫 | 盯食物袋、舔嘴 | 先处理饥饿，进食时保持空间 |
| 谨慎的小狗 | 缩身、耳朵向后、盯手 | 先退开，避免直接靠近或晃玩具 |
| 好奇的小猫 | 耳朵朝向玩具，视线跟随 | 玩具更有效，可更早建立接近机会 |

不把这些差异做成品质或价值分级。三个状态只用于本轮验证，并不表示未来猫狗只能有上述对应关系。

### 节奏与反馈

- 玩家选择后留约 1.15 秒给动物反应，期间锁定操作，防止双击消耗多次食物或行动。
- 不需要点“结束回合”，反应后自动恢复选择。
- 当前线索自动可见，不用每轮先点“观察”。
- 上一次反应不会一闪而过；下一轮仍保留，同时展示当前状态线索。
- 警惕条、数值变化、位置变化、缩身 / 低头进食 / 玩具 / 爱心等共同反馈行动结果。
- 暂停与切后台会冻结动物回应、回合计时和开路操作。

## 变化与生成的边界

当前实现的是受约束的原型变化，不是无限随机解谜：

- 解谜来自同一可解结构的左右布置变体，移动两只箱子与两个桥位形成不同路线。
- 清理的杂物类型、覆盖与动物位置由种子决定，维持明确的可达前沿。
- 回合状态从三种起点中组合，不随机改变行动规则，不把失败藏在概率里。
- 160 个种子已做规则级可通关验证。此检查不等于关卡有趣、多样性足够，或长期内容问题已解决。

如果组合循环的实际体验成立，下一步再增加模板与行为组合，并为生成关卡加入可解性、路径长度、最少操作、重复度等约束，不能只随机摆放障碍。

## 本轮未做

正式照护系统、领养与放归、长期经营、奖励经济、玩家串门、云存档、微信发布、完整关卡生成器、正式角色动画与音效。站内抚摸仅是流程结束后的轻量情感反馈。

## 实际试玩要回答

1. 开路是否让人进入情境，还是让人只想赶快跳过？
2. 能否从动物表现判断下一步，而不是猜策划设定？
3. 错误后是否能理解原因，并愿意调整，而不是觉得被惩罚？
4. 三种状态是否真的让你改了行动顺序？
5. 交涉是否过于固定，几次后就记成按钮公式？
6. 开路与交涉加起来是否在理想时长内？几分钟是目标，目前未取得用户实测时长。

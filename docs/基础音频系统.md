## 接入音频素材

1. 有素材后按规范命名 `BGM_*` / `SFX_*` 并核对来源、许可、实际渠道压缩和加载策略。
2. Unity `Create > Homeless Pet Helper > Audio Catalog` 创建目录资产，填写 Entries 中的稳定ID、通道、Clip、Gain和叠音策略。
3. 将目录显式绑定到Main所用GameContent的Audio Catalog字段。底座允许空目录；后续基础音效接入已将当前 Main 绑定为 `BasicAudioCatalog`。
4. 从装配入口把 `AudioService` 显式传给需要的表现层，不让模块到处FindObject或访问静态Instance。

ID区分大小写，非空、最长128字符；不把文件路径当ID。Music允许Loop，Effects只支持短音效、不允许Loop；后续环境循环声须按真实需求单独扩展，不偷用短音效池。

调用示例，`audio`由Main装配传入，以下ID只是示例，未成为已绑定资源：

```csharp
AudioPlayResult result = audio.PlayEffect("ui.confirm");
AudioPlayResult musicResult = audio.PlayMusic("station.music");
audio.StopMusic();
audio.StopEffects();
```

返回值区分 `Played`、`AlreadyPlaying`、`UnknownCue`、`WrongChannel`、`MissingClip`、`ClipNotReady`、`Suspended`、`Muted`、`Cooldown`、`VoiceLimit` 和 `Disposed`。表现层按需要处理，普通冷却/静音不应逐次刷错误日志。没有加载完成的Clip明确拒绝，底层不会暗中加载大文件。

同一首仍在播放的音乐再次调用不会从头重启；自然结束的非循环音乐可以再播。错误ID不会停止现有音乐。暂停期间的新播放请求直接拒绝，不保留待播队列；调用方要在适当恢复点重新决定当前音乐。静音音乐可按0音量启动/继续计时，解除静音不重新起播；短音效静音时直接丢弃。

单个音效默认最多2路、间隔0.05秒；全局8路上限。当前策略不抢占其他音效，不实现优先级淘汰/音乐交叉淡入淡出/3D定位，后续按听感和测量增加。数值必须有限并在合法范围，不能传NaN/Infinity后静默Clamp。

## 音量与存档

`MainGameRoot.Audio.Playback`是当前显式所有者暴露的播放服务，实际模块应通过构造或绑定取得，而不是全局查找。

```csharp
var preferences = new AudioPreferences(
    new AudioBusSettings(1),             // 总音量
    new AudioBusSettings(0.4f, false),   // 音乐音量、是否静音
    new AudioBusSettings(0.8f, false));  // 音效音量、是否静音
audio.ApplyPreferences(preferences);
```

有效输出是 `Master.Gain × 通道.Gain × 单Cue.Gain`。静音不丢掉原来音量。修改立即更新已播放源的音量，但**不自动写盘**。未来滑条拖动时只Apply，放手/明确确认设置时调用：

```csharp
if (!mainAudio.TrySavePreferences(out var error))
{
    // 当前音量继续生效，但要反馈“未保存”，不可声称跨重启已生效。
    // WriteUncertain/Conflict后先显式重读，不能盲目重复写入。
}
bool pending = mainAudio.HasUnsavedPreferences;
```

偏好保存的数据为纯DTO：三路音量、三路静音；固定分区 `audio.preferences` v1，Required字段及范围校验，DTO/构造器有Preserve，类型不接受任意多态。当前无需历史迁移，后续结构变化按[基础存档流程](基础存档系统.md#版本升级)提升版本和写迁移。

桌面目录是 `Application.persistentDataPath/audio-preferences/`；微信键前缀是 `homeless-pet.audio.v1`。不是关键进度存档位置；未来统一设置档时必须迁移，不直接改前缀导致偏好丢失。同值保存不重复落盘，启动读取和Dispose不写盘。

读失败时Main记录包含异常链的诊断，只以默认偏好供**本次会话**使用，并阻止默认覆盖原档。`PersistenceError`/`HasUnsavedPreferences`可供未来设置UI反馈；显式 `TryReloadPreferences` 成功才替换当前偏好，失败则保留当前会话设置。独立 `AudioPreferencesStore.RecoveryWarnings` 可查询坏槽回退的异常线索。没有清档按钮或自动清坏档。

**音频偏好接入不意味着动物/地图/战斗存档已接入Main。** 该业务边界继续按基础存档记录。

## 暂停与生命周期

AudioHost接Unity `OnApplicationPause`、`OnApplicationFocus`、`OnDisable/OnEnable`，每个原因独立置位/解除；重复通知不会重复Pause/UnPause。音乐记录暂停位置；Unity先停源再回调导致原生游标不可读时，使用已记录的播放意图和单调起点估算采样位置，恢复时尝试回到该位置，不能宣称所有渠道采样级无缝。无素材不启动任何播放。

外部SDK或玩法的适配层可显式设置原因：

```csharp
audio.SetSuspended(AudioPauseReason.ExternalInterruption, true);
// 广告等确实结束后：
audio.SetSuspended(AudioPauseReason.ExternalInterruption, false);
```

每种原因只能由一个上层协调者持有，位标志不是多调用者引用计数；多个广告/弹窗应由所属模块先聚合，不能互相提早清除。未接入广告SDK或业务暂停按钮，当前只有扩展入口，不宣称打断链路已完整验收。

销毁Main同时释放服务、停止并清空Clip引用、停用Listener/子对象；重载不会残留静态状态或重复源。服务、输出和Unity对象均只在游戏主线程使用；不支持后台线程调用。

## 微信与资源边界

本轮采用Unity AudioSource作为首个输出实现，没有引入微信专用内音频上下文或另一套播放器。WebGL Player的偏好后端选微信桥，普通浏览器无wx时明确拒绝存储，不把临时内存伪装成持久化。

微信SDK初始化、wx hide/show与Unity回调映射、首次手势解锁、设备静音开关、广告音频焦点、压缩格式/Streaming支持、后台强杀、恢复采样精度及性能，均须用真实AppID/转换包和目标机核验。不要套用原生移动端导入建议就宣称微信Streaming/音效延迟达标。

本轮没有新增素材字节，不修改图片台账。后续素材接入需要额外评估包体、解码内存、Clip驻留和下载时机；当前目录是静态引用，未实现远程按需加载。测试Clip仅在测试进程创建并销毁，不入正式包。

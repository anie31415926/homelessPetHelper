# 逆塔防：守方技能公共释放流程

2026-11-20。用户要求技能效果可以独立编写，但释放流程必须通用，防止每个技能重写行动条、预告、收招等逻辑。本批只整理已有五种动物动作，不追加狗叼取或新玩法，不改变数值、原HTML定义或Main路由。

## 边界

| 归属 | 职责 | 不负责 |
| --- | --- | --- |
| `SiegeAnimal` | 按原优先级评估前线、受损塔、空塔位及合法按住目标，选择下一招 | 不扣行动条、不推进施法时钟、不结算技能 |
| `SiegeAnimalCasting` | 唯一预告/释放/推进入口：玩家窗口、行动条、互斥占用、命中时刻、收招、冷却、锁定上下文、一次结算与合体目标映射 | 不判断猫爪射程、不决定横扫损耗、不修塔 |
| `SiegeAnimalSkill`与各技能类 | 声明是否等玩家窗口、是否停止守门、延后/收招/冷却参数，提供本招的目标校验、开始、命中、落空和结束效果 | 不另建Coroutine/计时器，不自己清行动条或再实现公共收招 |
| `SiegeState.Animal` | 拥有本局施法实例和按技能类型记录的冷却；向UI返回独立快照 | 不把技能对象或Unity组件写进状态，不在静态技能实例中存单局数据 |
| `SiegeSession` / `SiegeCombat` | 固定步进/全局暂停、统一调用施法与独立效果推进 | 不再分支检测“如果横扫到落地时间/如果按住到期”来释放技能 |

采用模块内小型、显式登记的技能集合和单层抽象类，不增加通用战斗框架、反射、全局事件总线或跨模块依赖。处理器均为无单局状态对象；一切执行状态仍由当前Session持有，不能跨局串冷却。

## 公共流程

1. `Plan`统一写入下一招、路线/塔位/单位ID，并根据声明设置需要经过的玩家回合。具体技能可补自己的地面锁区和预告事件。
2. `TryRelease`统一拒绝非Running、暂停、行动条未满、尚有占用/收招、冷却未到或未经过实际玩家窗口的请求。满足后保存独立的`SkillCast`，只消费一次行动条、增加一次行动计数。
3. 本次施法锁定自身的技能身份、目标、区域、开始时间、命中时刻与收招时长。它与“下一招预告”分开，动物提前考虑下一招不能覆盖仍在空中那一扑的真实落点。
4. `Advance`按 **Windup -> Active -> Recovery -> 空闲** 推进。同一步多次调用也不会重复命中；零延后可同次释放命中，狗飞扑仍等500ms落地。只有公共执行器更新施法阶段和动物收招截止时间。
5. 命中时由技能检查原目标是否合法，再执行效果或落空；不会由公共流程自动换目标。冷却写入同一张按技能类型索引的单局表，以出手时点起算；按住落空仍进冷却，失效修补不扣修补次数/冷却，保留既有规则。
6. 持续占用到期或技能报告目标已失效，由公共流程一次结束并进入收招。控制保护期、修补次数、塔耐久属于各自效果，不混成通用施法费用。

`End`是一次施法离开Active的收尾回调：零持续时长和落空也会经过它，因此必须能处理未取得目标的情况。`Miss`负责本招的落空反馈，不能在其中再次消费行动或另开收招。

所有时间均为模拟毫秒，统一由Session固定步进驱动。玩家窗口/手动暂停/失焦时不推进施法，UI动画只读模拟状态。结束/重开Session不存在仍在后台运行的技能协程。

## 五种已接入动作

| 动作 | 技能自身逻辑 | 公共执行器负责 |
| --- | --- | --- |
| 守门 `SiegeGuard` | 开启指定入口的节拍拍击；`AdvanceEffect`推进独立守门效果 | 守门开始时消耗动物行动；当前沿用无需额外窗口的普通动作声明 |
| 横扫/飞扑 `SiegeSweep` | 锁定地面区域、开始演出、对真实圆区内目标损耗/推退 | 等窗口、结束旧守门、延后命中、只结算一次、收招互斥；不再由Combat单独触发横扫 |
| 建造 `SiegeBuild` | 检查锁定塔位/次数，生成施工中的正确机关 | 等窗口、消耗行动、公共目标快照；施工交给机关生命周期 |
| 修补 `SiegeRepair` | 检查锁定塔、消耗修补次数，`AdvanceWork`处理完成/拆塔打断 | 等窗口、消耗行动和公共冷却；不为修补另开一套施法计时器 |
| 按住 `SiegeHold` | 近身目标规则、单位控制/保护、目标损失和松爪反馈 | 等窗口、停止旧守门、控制占用、提前结束后的收招、冷却及下一招释放门槛 |

**动物占用不等于所有效果的存续。** 守门展开后、建塔施工中、修补工作中，保留原来允许的重叠关系；按住/飞扑及收招则占用动物，不能同时再开另一近身动作。机关单体/减速/推退仍由已有`SiegeDefenses.Advance/Fire`公共发射流程驱动，不把每座机关塞进动物唯一行动条，也不把动物技能执行器说成已经覆盖所有塔机制。

## 目标与兼容

- `SkillTarget`为只读值，包含路线、塔位或单位ID；`SkillCast`另外保存锁区和阶段时刻。合体时公共入口映射待释放/执行中锁定的材料ID；按住仍独立继承剩余控制/保护，不因为换了ID免费逃脱。
- `Animal.Clone`复制施法对象和冷却表。UI持有的旧快照不会随实时战斗改变，更不会让第二个Session继承第一局时钟。
- 旧`NextHoldMs`、`NextRepairMs`成为公共冷却表的只读投影；旧`ImpactAtMs`成为本次横扫Windup的只读投影，避免一招维护两套可写时钟。旧枚举编号和已有对外读取名称保留。
- 不修改生成DTO、内容/文案源、Prefab序列化字段、动物动作或资源加载方式。当前技能状态尚未接正式存档，不声称这是已完成的跨版本技能存档迁移。

## 新增技能的做法

1. 在独立技能类实现目标合法性、具体效果及必要的提前结束条件，声明时序和占用策略；共享施法字段只由执行器写入。
2. 在`SiegeAnimalCasting`的显式集合登记该无状态处理器；在动物选择策略加入经确认的选招条件。纯换主题/参数先复用现有机制，不按猫狗名字复制代码。
3. 新效果需要的配置继续从生成源增加并校验；确需新的运行状态才加到本局状态和Clone。新技能不得用UI演出完成回调决定逻辑命中。
4. 经统一`Plan`/`TryRelease`/`Advance`接入，不给Session/Combat追加一份技能专属释放分支；补目标消失、落空、暂停、同拍优先级、合体和一次命中的回归。

这是当前五招真实复用的扩展点，不是承诺任意未来技能都能只配数据。狗叼取的搬运效果、目标免途中塔伤、替身脱壳等还要单独设计/实现，但不再重写公共释放流程。

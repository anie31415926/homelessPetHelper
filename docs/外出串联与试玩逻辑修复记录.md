# 外出串联与试玩逻辑修复

## 修复范围

| 问题 | 当前处理 |
| --- | --- |
| 回站拒绝留下半结算 | Station、Clock、RequestPool、OutingSession 提供只读 `Can*`，实际写入口复用相同校验；协调器先完成所有校验，再同步提交。覆盖重复动物/外出、真实会话身份、容量、暂停/关闭、请求合法迁移、旧时间版本与溢出 |
| 已结束外出 ID 可以再次开局 | 协调器记录本实例生命周期内已成功开始的 ID；即时及隔轮复用均拒绝，不清空旧总结或创建新会话；失败的开始不占用 ID |
| 地图显示与选择校验不同 | 两者共用有效求助解析：Available、同点位、模板存在且允许该点位；跳过无效前项，不遮蔽后面的有效请求 |
| 回站顺带自动完成护理 | 结算只推进到 `Care`；新增 `TryCompleteCare`，由调用方验证真实护理结果后显式调用。未完成前不能开始下一次外出，重复/过期/暂停输入被拒 |
| 重复退后仍宣称发生移动 | 已有空间时，同一方法标题改为“保持距离，不再靠近”，回应明确没有继续退后；应激状态单独反馈。不增加信任、物资成本或假移动 |
| 玩家靠近被写成动物主动靠近 | 新增 `PermittingApproach` 行为，文字明确玩家缓慢靠近、动物留在原处；合适等候后的 `Approaching` / `CameCloser` 仍表示动物主动行动 |

出发还校验地图返回的请求确实由装配层使用的请求池持有；同 ID 的另一请求对象不能被误接。安置试探后，在原有适宜状态下“保持距离”仍可以得到明确接受；它不是永远无效的选项，也不是重复刷进度。

## 一致性契约

- `Can*` 是只读判断，不预留位置、不封口、不推进时间；后续状态变动会使先前判断失效，写入口必须重验。
- 依赖当前纯 C#、单一游戏线程、校验到提交之间无回调/await/外部 I/O 的事实。不承诺跨线程事务、落盘恢复或崩溃原子性；若将来加入异步/通知/存档，必须重设计提交边界。
- 预期业务拒绝返回 `false`，所有参与者保持调用前状态。提交段违反已校验不变量时抛技术异常，不再假装是无副作用的普通拒绝；内存分配等技术异常不在本次恢复保证内。
- 会话 ID 防重与站点接收防重目前都是内存级，随其所有者生命周期结束；没有新增磁盘存档或永久身份注册表。
- 回站校验仍按一个连续的业务动作排列提前返回，具体规则归模块 `Can*`，不复制一份规则到装配层。方法超 40 有效行的评审点保留可见，没有用 `partial` 或万能事务框架隐藏复杂度；回归逐一核对拒绝后的参与者状态。

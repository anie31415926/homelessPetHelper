# 动物形象配置与制作流程

2026-11-24。用户授权将动物制作整理为每种形象独立配置，后续换图复用状态与播放代码。当前已落地侧面四足模板 `side-quadruped-v1`，使用原生蒙皮/骨骼与离线IK烘焙，没有新增SDK或动物业务状态。

## 已落地的边界

- 同轮廓换色/换花纹，且图集布局一致，可复用同一绑定和动作；换体型需要填写关节、蒙皮及动作配置并重烘焙。
- 一张任意完整图不能直接获得动画。素材仍需拆层、补遮挡、标关节和接地点，再检查变形与轮廓；新图不自动沿用原猫的像素坐标。
- 当前模板固定为侧面四足的36骨/15附件，前后腿拓扑和IK算法共享；关节限位可配置。正面耳眼嘴、多段软尾或不同身体结构需要独立模板/表现适配，不能仅改模板名绕过校验。
- `AnimalIndividual/AnimalSnapshot` 仍是唯一动物事实。形象配置只描述外观和动作；不包含AnimalId、饥饿/脏污/健康/奖励，不按视图复制业务情绪。

## 唯一数据归属

| 数据 | 位置与单位 |
| --- | --- |
| 原猫形象 | `src/pet-sit-chibi/appearances/cat-orange-side.json` |
| 技术验证样本 | 同目录`cat-compact-sample.json`；复用原图，修改单位比例/头支点/时长/层级/尾巴参数，非第二只正式美术 |
| 图集拆层矩形、UV、可见轮廓接地采样 | `art.atlasManifest`指向的atlas JSON；原图像素坐标，atlas矩形为图集像素 |
| `source` / `landmarks` | 原图坐标原点、pixelsPerUnit、髋/膝/跗/爪/肩/肘/腕/头支点；原图X向右、Y向下，转换后朝鼻方向为+X |
| `rig` | 骨长派生规则、脊柱段长、远侧偏移、关节限位与头颈角；距离为作者空间单位，`*Degrees`为度，`*Radians`为弧度 |
| `sit` / `walk` | 动作时长（秒）、0～1关键进度、髋轨迹/脊柱角、肩/前爪移动和步幅；起身仍遵守站内现有1.6秒后行走的节奏 |
| `skin` | 语义层→atlas层ID、像素蒙皮范围、尾根、软组织锚点、前后遮挡排序/色调、网格采样间距；世界距离与像素字段明确区分 |
| `contact` / `tail` | 接地边距和衔接区间、尾巴抬起角/摆幅/周期；轮廓不穿地须逐形象验证 |
| `framing` | 该形象的正交镜头大小/局部位置，保存到actor Camera；运行时不再写死原猫镜头 |
| `unity` / `export` | 独立actor/资源目录/命名前缀、显式atlas/shader/template引用、导出和fixture路径；路径相对仓库或Unity工程 |

`profile.js`集中校验后深冻结配置：缺字段、非有限数、无效时长、乱序关键帧、空层/重复层、出界atlas矩形、非法导出路径立即失败。关节与素材比例不合理仍可能产生坏形体，因此配置通过不能替代实际渲染验收。

`rig.js`、`skin.js`、`tail.js`和`bake.js`读取同一份profile；不在这些计算器里补另一只猫的专用像素分支。默认导出接口继续可用，旧原型/测试的入口保留。

## 新增或换图步骤

1. 准备已确认的侧面拆层素材：头、身体、尾巴、前腿、后腿大腿/小腿/爪及腿段补片，补足被遮挡区域。图层语义角色固定，实际layer ID可以通过`skin.layers`映射；不同结构先扩模板，不复制播放器。
2. 按[图片台账流程](../art-source/README.md)登记新图及来源、加载计划；生成自己的atlas manifest，保留每层原图位置、图集位置和轮廓support采样。绘图/打图集仍是资源作者工作，不由本轮profile自动完成。
3. 复制原profile为新文件，换唯一id、资源与输出路径，按新图填写关节/蒙皮/尾根；骨长从关节点派生，站立髋轨迹首点须对应原图髋点。调整坐下轨迹、关节限位、接地和镜头。profile文件不能只换id仍写到原猫目标。
4. 在仓库根运行：

   ```bash
   node tools/pet-sit-unity.mjs --profile src/pet-sit-chibi/appearances/<形象配置>.json
   node tools/pet-sit-unity.mjs --profile src/pet-sit-chibi/appearances/<形象配置>.json --check
   ```

   默认不传`--profile`生成当前正式橘猫使用的烘焙，见[本次接入记录](协作任务/20261124-橘猫坐下工程接入-01a2076c.md)。新形象仍使用独立 profile；橘猫 HTML 的像素坐标不自动套用。导出schema2含appearanceId、模板、目标路径、镜头、bones/meshes/curves/tailMotion。它是作者数据，须与本轮导入器成组更新，不是玩家存档schema；旧schema1不再作为新导入输入。
5. 将atlas/shader按profile显式路径导入Unity，保持meta；将bake JSON放隔离工程的`PetSitSource/<形象>.json`。在隔离batch Editor执行：

   ```text
   -executeMethod HomelessPetHelper.Editor.StationHabitat.StationAnimalAssets.ImportFromCommandLine
   -animalBake PetSitSource/<形象>.json
   ```

   importer只编辑profile指定的资源与actor。新actor从显式template复制，在Prefab Mode内替换该actor的rig；不重建站内面板。导入前校验目标、骨架、权重、曲线和必要引用；已有actor的非空appearanceId不同则拒绝覆盖。每种形象使用独立资源目录与命名前缀，不共享可写的生成mesh/clip/material目标；atlas/shader可显式共用。
6. 保留原猫窄入口`StationCatAssets.UpdateExpressionBindings/UpdateSitClip`，仅更新同形象的动作/绑定；不同绑定姿态或atlas必须完整导入。新asset/meta、actor及生成源同步入库，保持已有GUID。每次先比较导出与实际渲染，再接正式内容。
7. 站内展示数据`StationSceneResident`增加可选的`Appearance`（显式renderer Prefab引用）。同一视图实例化该actor，继续传同一Snapshot、姿势和受暂停控制的表现时间；未提供时沿用现有猫/狗默认表现。切换Appearance释放旧renderer、保留同ID的动作对象，实际生成的播放器类型仍沿用`StationCatPlayer/StationCatTail`兼容名称。

`Appearance`是展示输入，不写动物存档。正式动物定义→形象资源的内容清单需在具体新动物素材确认后显式装配；本轮没有在Main内新增动物或随机换皮。

## 验收和当前证据

- 关节/骨长不拉伸、IK可达；站立/坐下/起身/踏步中无折叠、穿地、尾根脱离或蒙皮突然跳变。清洁脏污仍读取同一快照；新轮廓对应的静态脏污mask也需资源制作验收。
- 状态→动作映射仍走既有AnimalExpression，尾巴周期从各自actor读取；暂停/详情/切后台冻结、关闭释放。实例进度不写回共享配置或素材。
- 同时核对小屏/长屏实际显示尺寸、镜头边缘、动物比例与交互区域；新贴图按台账运行`npm run assets:check`，新增图片预算和目标机验收另记。
- 已为原猫保留抽离前六个导出段SHA基线：bones、bindposes、meshes、takes、fixtures、tailMotion完全一致；不靠观感猜测“没变化”。测试还覆盖新坐标原点/重命名图层、第二套关节/时长/尾巴、输入拒绝及独立Unity导入。
- 当前技术样本已在隔离工程生成独立actor并实际渲染，未复制到正式Assets；不能把它当第二套美术完成。报告与当前结果见[任务](协作任务/20261124-救助站同骨架坐下-01a1f74d.md)及`test-results/station-cat-sit/appearance/`。

# 开放探索与地图信息

2026-11-25，用户确认。此方案优先于旧地图方案中「纯探索先腾床位」及「完成清障、解谜必然遇到动物」的约束。首版先验证停车棚，不批量制作场景。

## 地点与求助分开

- 已开放地点可前往，不以当前求助为准入条件。床位只限制需要入站的救助，不限制纯到访、清障或解谜。同点同时有求助与纯探索时，玩家明确选其中一种；纯探索不接单、不生成或收容动物。
- 到场按地点可用内容行动：清障、解谜、逆塔防救助各自独立，也可组合。只有内容明确配置为救助路线的阻碍，才要求先处理；不是每次必须清完整个地点。
- 清障工作量、已搬物件及解谜状态按地点保存；返回不清空，后续求助可读取有效的通路成果。求助本身及动物仍按请求保存，不能被另一次纯探索覆盖。
- 地图浏览、出发前取消不耗时；实际到访即使没有发现也耗时。同一趟只计一次到访，清障和解谜分别按已推进阶段计时，没开始的项目不扣。回站一次提交时间与地点进度，重试、暂停与切后台不得重复计费；具体分钟数留给首版试玩调节。

## 地图信息怎么放

| 玩家要知道什么 | 入口与内容 |
| --- | --- |
| 哪里正在求助 | 有求助的地标旁显示动物小图标＋「求助」。出现时轻弹提示，随后保留可读标记，不闪烁或自动弹窗；没有求助的地点不贴「无求助」。气泡跟随地标移动，不抢地图拖动；点地标打开相同地点详情。 |
| 这里有什么 | 地点卡片左侧复用地标图，右侧放地名和最多两三条短信息，例如「有求助」「清障进行中」「解谜已完成」。行动旁只预览本次耗时；站内人数、全局时间、床位统计不塞进这里。需要床位的救助若不能接，只在该操作旁说明原因。 |
| 站内现在怎样 | 安全区右侧只放一个小型「站况」入口，返回留左下。展开独立轻弹窗，左图标、右短句，例如「在站 3 只」「空床 1 位」；不常驻文字状态栏，也不和地点详情叠两层遮罩。 |

验收例：救助站已满，地图上停车棚仍提示求助。点它能看到简洁的当地情况并选择「前往探索」；到场只清一半杂物就回站，耗时入账，下次开同一个地点继续。求助仍可见且未被纯探索接走。站况入口能独立开关；有弹窗时不得穿透地图；停用动效时求助标记仍可辨认。

## 接入状态

先补独立地点出发入口，不改已有救助出发及存档恢复语义。地图昼夜、局内天气任务释放共享路径后，继续接地图卡片、气泡和站况，以及不依赖请求 ID 的停车棚现场、地点存档与分玩法结算。当前不把底层出发入口视为已上线的自由探索。

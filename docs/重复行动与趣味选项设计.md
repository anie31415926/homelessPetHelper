# 重复行动与趣味选项设计

日期：2026-11-18。状态：**趣味扩展方向与自然、克制的幽默包装风格已获用户认可；具体机制、供给与完整文案清单仍待细化，未实现。**

**最新执行状态**：轻量 JSON 与两项提示型趣味选项已获授权并接入原 Editor 案例，详见[实现记录](选项管理模块实现记录.md#2026-11-18-json-与提示型趣味项)。首版每项一次/相遇，不做下文的连续消息、拍摄画面或专属效果；此处“完整清单未实现”继续成立，不重复开工已有功能。

**首版规则已确认并进一步简化**：用户认可趣味项消耗本回合选择、每手至多一项（含锁定）且保留真实稳定选择、首版聚焦静音回复/拍照；随后明确目前选完只显示提示文案，额外效果以后有空间再做。因此下文的连续消息、成片和口播等仅保留为后续提案，不作为首版必做或已批准的专属动物效果。提示与普通回合动物回应分开，不凭一句文案新增信任、恢复或惩罚。数据与文案的存储建议见[代码提案第 8 节](现场选项代码设计提案.md#8-数据与文案存储建议)。

用户反馈：现有十类方法偏少，长回合会重复大量动作；需设计连续选择的后果，并加入幽默、抽象、经过包装的干扰选项。用户举例“收到女友微信消息，立马回复”“掏出手机拍照发抖音”。这不是要求全部选项都专业严肃，也不是批准新的惩罚、社交平台接入或立即编码。

**文案风格已确认**：用户先明确“包装不能整的太油腻，要幽默一点”，看过日常短句与现场反差的改写后认可“这些不错，就按这种感觉来包装”。后续沿用自然、简短、克制的幽默：选项正常说话，笑点可放在符合当时现场的短回应里，不堆网络梗、刻意卖萌，也不要求每个选项都带笑话。上一版油腻表达不作为定稿；本次确认的是包装尺度，不扩大为全部候选、重复后果、插曲限额或编码获批。

获认可的语气参照：“女友来消息了，先回一下”对应“你回消息，它继续吃饭”；“再拍一张”对应“还是背影”；“跟它商量一下”对应“要不跟我走？”后它继续吃饭。回应须符合当时实际行为，不为笑点强制动物转身、出画或吃饭；这些参照用于统一感觉，不要求每次逐字复读。

沿用[现场方法与画面草案](现场救助选项候选清单.md)，但十类方法不再被当作全部可选内容的上限。先前十类的具体效果尚未全部获认可，本页不替用户补批。

## 1. 让三种变化一起工作

| 层次 | 提案 | 不冒充什么 |
| --- | --- | --- |
| 真实救助行动 | 保留退开、等候、放食等不同用途，根据当前状态和历史改变回应 | 不统一加信任，也不要求十类全部做过 |
| 情境与连续回应 | 同一方法随位置、兴趣、正在做的事、真实目标变化；尚未结束的插曲可以有后续 | 不重置现场来制造用途，不设置第三次必烦 |
| 生活插曲与抽象选项 | 加入回消息、拍摄、一本正经说废话等自选行为；可以只是有趣地花掉一次行动 | 不把所有玩笑包装成有救助收益的正确答案，也不靠纯换文案声称增加了独立机制 |

玩法目标是既能认真救助，也能偶尔选个离谱选项，看角色与动物的反差；不是专业知识测验，也不把动物痛苦作为笑料。幽默主要来自生活打岔、人的打算与实际现场不一致，不靠持续自作多情、撒娇或过度表演。

## 2. 多次选择同一方法会怎样

**按方法分开设计，不套“第一次有效、第二次减半、第三次惩罚”的统一公式。** 连续历史可以改变情境；同样相关条件、历史与行动仍得到一致结果，不额外抽隐藏成功率。

| 重复对象 | 第一次的作用 | 继续选择时的变化提案 | 何时停止提供或转向 |
| --- | --- | --- | --- |
| 退开 / 接近 | 玩家发生真实位移 | 仍有需要且可安全移动，就从最新位置继续移动；动物是否跟随另算，不强制双方同步 | 已无位移用途或到安全边界，不假演再移动；合适空间由等候承接。接近仍受许可、安全限制 |
| 等候 | 给现有过程留机会 | 吃饭、观察、探索按实际条件延续，过程可能在一次回应内完成，不为长回合拆成逐帧点击 | 缺食物就不会凭等候吃饱；反复未推进时，持续表现真正阻碍和可用出口，不不断复读同一句 |
| 轻声回应 | 接续它主动发起的交流 | 它仍愿意交流时继续；它转去吃饭或探索就不必继续叫。若玩家明知回避仍持续呼唤，才成为不合时宜的声音干扰 | 不因第二次正常回应就扣关系；已没有交流对象时不假装又建立一层信任。持续呼唤的具体后果待确认 |
| 逗玩 | 提供自愿互动、改变关注 | 愿意继续就继续；兴趣或身体状态变化时，它可停下、转看别处。持续吸引可暂缓其他探索 | 不规定玩三次必腻；没兴趣后收起，不继续刷玩耍分，也不要求抽到“停止” |
| 短暂抚摸 | 发生已被接受的接触 | 当前仍愿意可以继续；它移开或不再邀请时停手，不把永久接触许可当收益 | 不因重复本身惩罚，也不按摸几次解锁抱起或转运；强行追摸不是同一个合理动作 |
| 放食 / 低压姿态 / 遮蔽 | 改变食物、姿态或环境事实 | 这些事实保留，不靠换回合回到缺食物、盯视或无遮蔽状态来制造重复收益 | 没有新用途就不新发，锁定失效项保留但不可用；食物引导与熟悉垫物仍待选择 |
| 降低干扰 | 处理一个实际来源 | 若仍有另一个可处理来源，能产生新变化；已处理来源不重生 | 不以多个同义名称同手牌占位；多目标选取方式仍待讨论 |
| 回消息等插曲 | 回复一条实际出现的消息 | 有新消息才接后续，例如“你到底在忙什么？”；话题结束后不无限生成追问 | 没有消息不凭空反复“秒回”；同一插曲可在任何节点不再选，不锁住救助 |
| 拍照 / 拍视频 | 一次真实拍摄与角色表现 | 后续可换成补拍、检查成片等有限段落；动物继续自己的事，成片由当时画面决定 | 完全没有新内容时不一直补发；不靠多拍必涨粉、动物必生气或第三次必逃来续命 |

“继续合理互动”与“无视拒绝继续纠缠”必须分开：后者在选前已有回避等线索，后果来自打扰，不是系统厌恶玩家重复点击。没有真实声音、移动或其他改变的行为，不凭手机亮屏、平台名或台词荒诞就扣信任。

长回合的变化也来自动物自主转移关注，而不全来自玩家指令；不能以“内容丰富”为由给本来可以完成的相遇强加回合或插曲。若合理行动长期没有新决策，只剩同一状态同一动画，仍是流程/供给缺口，不是多写几句笑话就算解决。

## 3. 认真选项也可以好玩

以下是替换上一版的包装示例，不是新增六个独立方法。按钮先把动作讲清楚，不必每张都写段子；笑点可以放在符合实际现场的短回应里，不把玩家理解操作变成猜谜。

| 文案候选 | 实际动作 | 对应方法与去重 |
| --- | --- | --- |
| 往后站一点 | 退开，留空间 | 退开变体，不与另一张退开同手牌重复 |
| 先别动，看看谁先动 | 原地安静等候 | 等候变体，不另算一种独立安全方案；不判输赢或限时 |
| 不盯着它看了 | 侧身、移开直视 | 低压交流变体，不给犬硬套猫的慢眨眼 |
| 放点吃的 | 放下适宜食物 | 投喂变体，已无用途仍不新发；无需硬加笑点 |
| 试着摸一下 | 仅提议当前适宜接触，回避即收手 | 可选接触变体，不是点击就一定摸到 |
| 请大家站远一点 | 请可沟通围观者退开 | 降低具体人群干扰，不假称周围正在直播 |

包装可随个体、现场与前次回应换，但不把不同名字当作同方法去重的漏洞，也不让幽默文案掩盖明显的声音/距离风险。

### 文案语气约束

- 不默认使用“大佬、贴贴、营业、求生欲拉满”等上一版表达，不把流行梗串成每个选项的固定腔调。
- 选项短而清楚，回应留一点反差即可；不用感叹号、夸张赞美或旁白解释“这很好笑”来强推笑点。
- 有时正常说话比硬改名更好；荒诞可以来自“认真跟它商量，它仍然吃饭”这样的局面，而不是把每个词都换成梗。
- 反馈必须符合当前画面：只有确实出画、背对或正在吃时才用对应笑话，不为了包袱强制动物配合或改动行为。

## 4. 趣味干扰选项候选

以下全部为游戏内虚构演出，不调用真实微信、抖音、相机或通讯录，不真的发布内容。分身角色的女友不是对现实用户身份的假设；女友台词可保留，通用版本另可用朋友/熟人，具体角色设定尚未确定。不是认定女友消息必然找麻烦或扣好感。

| 候选选项 | 画面与笑点提案 | 局面后果 / 可重复性 |
| --- | --- | --- |
| 女友来消息了，先回一下 | 原地静音回复“还在忙”；若动物正吃饭，可接“你们各忙各的” | 合适安全条件下相当于一段不干预的时间，不自动扣关系，也不自动解决距离；只有后续消息存在才再出现 |
| 发张照片，说明一下情况 | 接上前一插曲；若只拍到背影，消息可接“这是哪一面？” | 是条件性拍照后续，不是新投喂或接近；成片依据当前画面，不要求动物配合，也不必选来“修复恋爱关系” |
| 拍张照片发抖音 | 原地拍摄、编辑；若动物自主走出取景范围，可接“文案写好了，主角出画了” | 静音、不靠近时主要花行动而非激怒动物；发布为故事表现，无涨粉、打赏、围观者生成或平台奖励系统 |
| 再拍一张 | 若仍背对镜头，反馈“还是背影”；不额外解释包袱 | 可接检查成片的有限后续；不能每次强制动物转身制造笑点。没有新拍摄目的或演出后就退场，不无限发 |
| 录段视频，讲讲现在的情况 | 角色举手机说话；动物若在警惕声音，就朝声源看或暂停活动，不强加俏皮话 | 与静音拍照不同，新增可听见的声音；选前说明要出声。后果看当前敏感性，不固定一次失败或扣统一信任 |
| 跟它商量一下 | 低声说“要不跟我走？”；若它正在吃，可接“它继续吃饭” | 本质是说话，不因人类提出建议就判接受安置；低声且适宜时可无害，继续打断才是干扰 |
| 问问它叫什么 | 角色低声询问；反馈候选“暂时没有得到可登记的回答” | 动物回应只由声音、关注等条件决定，不理解问句；同属说话插曲，不开启命名/关系加成系统 |
| 打开相机，先看见了自己 | 切换前置镜头，角色停顿一下再切回，不加旁白替玩家解释 | 安全静止时近似不干预，主要变化是角色和插曲；不复制成多张等候来证明救助方法覆盖 |
| 在心里排练一下怎么开口 | 内心独白与角色小表情；短回应候选“排练很顺利，现场暂时没用上” | 动物不读心，不能仅因台词抽象而受惊；可作一次等候型趣味演出，演完不反复刷同样空话 |

更夸张的动作可以继续脑暴，但不默认加入闪光灯贴脸拍摄、追逐、吓唬或强行触碰作为刷笑点的常规手段。抽象程度主要放在台词与角色自我表演，后果保持可解释。

## 5. 同一插曲与重复选择的连续示例

样例前提：普通非紧急相遇，玩家已留出合适空间，食物适宜且动物正在取食；本例只推演，不固定回合数或耗时。

1. 选“女友来消息了，先回一下”：玩家原地静音打字，回复“还在忙”。动物继续吃；既有食物和位置不重置，不额外演出求饶或解释清白。
2. 有新消息“那发张照片看看”才可能有下一段。此时玩家可正常救助，也可选静音拍照；动物转身是它自己的当前行为，不是固定惩罚。
3. 若玩家选择补拍，拍到什么取决于此刻朝向；成片可以是背影，角色却认真挑封面。继续编辑只是角色花时间，不让手机里的点赞远程改变动物情绪。
4. 若转为口播，场内确实新增声音。对声音敏感且尚在戒备时，动物可暂停活动、朝声源看；停止说话后读最新情况，不清空吃过的事实，也不靠另一张唯一“关手机”牌才能继续。
5. 插曲可以到此结束；玩家不必拍齐、回复完或看完笑话才获准收尾。它已经明确接受且其他安全条件成立时，原有独立收尾仍可用，本轮不新增“玩手机错失接受倒计时”。

前两项不应被统一判成坏选择。好玩的地方是“你回消息，它继续吃饭”或“照片没拍好，它也不等你”，而不是硬演恋爱危机，或违反常识地让动物因为抖音或女友扣关系。

## 6. 抽取、保留与容错怎么接

其中每手插曲上限、回合消耗及真实稳定选择已获首版认可，其余细化仍需结合所选内容核对；**未改变已实现的三个选项、用一个、最多锁两个**：

- 一手至多一项趣味插曲，包括已锁定插曲；可以完全不出，不要求每回合固定塞一项。已有锁定插曲时不再用新插曲挤占刷新位置。
- 原有每回合至少一种真实稳定选择保留；抽不到插曲不缺少救助能力，锁住插曲也不能挤掉安全兜底。暂缺前提的方法与失效锁定项沿用原规则，不能悄悄解锁腾位。
- 有明确动物风险时不强推玩笑：不能只剩“大声口播 / 继续拍 / 讲冷笑话”，更不能把危险现场当专门整活的舞台。出现频率、排除情境及锁定组合覆盖需后续核对。
- 同一手牌按实际方法或插曲族去重。女友/工作消息不能只换发件人同时占两格；纯等候包装也不能被算成几种不同救助策略。
- 真实回复有消息后续、拍摄有新内容时可重复出现；话题结束则不继续新发。失效保留项只解释原因，不自动消耗或解除锁定；不增加无限重抽。
- 选择趣味行动也正常用掉本回合的一个选择，并让动物按当前条件回应；不暂停外界让玩家免费演完，也不按现实操作手机的时长扣游戏时间。具体游戏耗时仍待定，不额外双扣。

### 与此前“无意义选项不新发”的关系

用户此次明确想要非最优、甚至没有直接救助收益的干扰项，不能再把“没有救助加成”一律当成无意义。

建议区分：**故障式无效**是“写着退后却没退、已喂足却谎称继续喂有效”；**主动选的插曲**是“我知道角色要回消息/搞笑，它确实做了这件事，现场也继续演变”。后者允许作为可选内容，但纯换皮、同段空演或已结束事件不无限供给。这个例外及其边界是当前提案，不假称此前已批准；同样不能拿数张等候型插曲证明原先三位置方法覆盖缺口已解决。

## 7. 当前接续范围

按用户最新要求，首版先做提示型内容、回合消耗和供给边界，额外效果与连续插曲后补；无需为每条提示先建立完整剧情。当前先说明选项元数据、文案与运行状态如何分开保存，再按获准的最小范围落地；具体数据格式为技术建议，不代表已经创建配置或修改代码。

本轮仅做设计讨论与记录，未改 Unity 代码、Prefab、图片、距离系统、角色设定或抽取实现，未运行玩法测试，未提交推送。不将候选表视作全部采用，也不将新增提案标为用户已确认。

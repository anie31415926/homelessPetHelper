# 外部 Agent 派工与验收

2026-11-27 · 适用于本项目。与[项目协作规则](当前协作状态.md#开工与更新规则)及[验证与交付](conventions/topics/delivery.md)并行使用，不替代任务认领、玩法确认或交付门禁。

## 外派还是自己做

**用户没指定执行方式时，主 Agent 自主判断任务是否满足外派条件；满足就先派，不再为执行方式询问用户。** 用户点名外派、自行处理、指定平台或模型时，以用户要求为准；无法在既定授权或安全边界内执行时说明缺口，不静默绕过。

有实现或制作要求时，读完上下文、确认范围并认领后，在主 Agent 写实现前，挑出符合条件的完整交付单元并实际提交给豆包。完整交付单元可以是一个工具、模块或边界明确的原型，不必是整个需求。只建议外派、写任务单、测连通性，都不算已派；不为凑派工次数另造任务，也不把单纯咨询、排查或审查强行外派。

**实现和配套测试一起交给执行端。** 能独立交付实现，就不只派测试、示例或资料整理，自己包揽实现。比如抚摸反馈原型，可以让豆包按已定接口在隔离目录交付状态模块、状态转换测试和运行结果；主 Agent 保留体验方案、素材与主工程集成，独立检查实现并复跑验收，不在等待期间平行写同一模块。测试本身就是交付目标，或实现所需输入、工具权限、共享接口暂不适合外派时，可以只派测试等可独立验收的部分，但须写明具体限制。

| 情况 | 默认做法 |
| --- | --- |
| 有清楚的执行步骤，所需输入已获准外发，修改范围能隔离，产物能独立复测 | 优先把实际交付物连同配套测试或验证交给豆包，例如独立工具、状态模块或规格明确的素材候选。不因主 Agent 也能做而跳过。 |
| 需求尚未确认、需要多会话协调或决定跨模块契约 | 主 Agent 先梳理、协调并定验收口径；能拆出的低风险实现仍可外派。 |
| 只读核查、方案和任务单、最终审查，或无需单独交付和复测的几行机械改动 | 主 Agent 自行处理；不要把有独立验收的实现一概归为“小改动”。 |
| 缺少可用工具、合适的隔离环境，或涉及敏感资料、生产权限 | 不扩大资料和工具权限。能用缩小后的输入外派就先缩小；否则在原授权内本地处理。若用户明确要求外派或需要新增授权，先报告缺口。 |

主 Agent 对范围、方案、派工、复核和最终结论负责；执行 Agent 按任务单制作、测试并提供证据。执行端不可自行批准、扩权、再派工、合并、提交、推送或发布。是否需要外派与是否允许外发是两回事。

实现或制作任务在本轮任务记录写一行`执行方式：豆包（交付范围 / 请求模型 / 回执或待回执）`，或`执行方式：自行处理（具体例外）`。交付范围写明实际交给豆包的实现和测试；如缩成只派辅助项，同处说明原因，例如“模块依赖未获准外发的源码，只派合成契约测试”。执行方式变化后更新该行；交付时区分哪些由外部完成、哪些由主 Agent 自己完成。不为这条记录增建平行台账。

## 派工到验收

1. **认领与拆任务**：按[协作执行记录](协作执行记录/README.md)登记主会话与具体写入路径，核对未结束任务；主 Agent 对交付、返工和范围释放负责。
2. **准备候选**：优先用独立目录，或从明确的 Git 基线建立独立工作树，不把正在并行修改的主工作区交给执行端。工作树只隔离版本，不是权限沙箱。只发送已授权且完成任务所需的输入；能用数据摘要、脱敏样例就不外发原文件，不发送凭据、个人数据、未授权业务源码或整仓。任务单写明基线/输入指纹、可读写范围、禁止动作、交付件和复测方式。
3. **选平台并执行**：默认先试豆包官方 CLI，常规先用 DeepSeek V4.1 Flash。可用 AgentDispatch，也可直调官方 CLI；AgentDispatch 不在本机而 CLI 可用时，不因此跳过派工，不要求经过 DSH。用本机工具说明核实入口、可用模型和登录，给执行保留合理时间。模型能力或稳定性不够时，按任务与额度调整模型或平台，优先保留完整交付范围，不默认把实现拆成辅助项。权限不足不改开全权限。官方 CLI 与调度工具都无法安全执行时，记录实际失败或缺口，再由主 Agent 在原授权内接手。
4. **收件与返工**：记录平台、请求模型、实际会话/尝试标识（如已知）、退出状态、实际产物及指纹。只有落盘文件、只有成功回执，或执行端说“已完成”，都不足以宣布交付。超时或回执不明时保留已有产物，先核对执行是否结束和文件是否仍在变，不在同一候选目录盲目重派。返工只给具体问题和复验条件，保留上轮证据。
5. **独立验收**：主 Agent 对比实际文件/差异与任务范围，绑定基线和候选指纹，独立复跑适用检查；记录通过、失败和未验项。验收只对该候选和核验过的范围有效，不自动进入主工程；合入、提交或发布沿用原有授权和交付流程。

## 已跑通的例子

2026-11-26，豆包用 DeepSeek V4.1 Flash 在仓库外制作了占位 BGM 的只读包体检查脚本。派工仅发送规格和三条包体测量数字，不发送工程源码或音频。首轮文件落盘但没有成功回执，且作者测试有错误；同模型返工通过官方 CLI 获得成功回执，由主 Agent 独立核对脚本和复测。最终作者测试 8 项、独立测试 5 项均通过，读取既有 Windows 审计报告时通过本轮临时预算检查。候选未合入主工程；本次没有验证微信下载量或正式音频预算，也不据此推断所有任务都适合外派。

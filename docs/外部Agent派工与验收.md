# 外部 Agent 派工与验收

2026-11-26 · 适用于本项目。与[项目协作规则](当前协作状态.md#开工与更新规则)及[验证与交付](conventions/topics/delivery.md)并行使用，不替代任务认领、玩法确认或交付门禁。

## 外派还是自己做

**用户没指定执行方式时，由接手任务的主 Agent 判断，不需要为每项选择再询问。** 用户点名外派、自行处理、指定平台或模型时，以用户要求为准；无法在既定授权或安全边界内执行时说明缺口，不静默绕过。

| 情况 | 默认做法 |
| --- | --- |
| 任务能写成清楚的执行单，输入可外发，修改范围能隔离，产物能独立复测，派工和复核成本合理 | 优先交外部 Agent 实现。例如独立工具、窄范围回归测试或已明确规格的素材候选。 |
| 需求尚未确认、需要多会话协调或决定跨模块契约 | 主 Agent 先梳理、协调并定验收口径；能拆出的低风险实现仍可外派。 |
| 只读核查、方案和任务单、最终审查，或很小的本地改动，派工成本反而更高 | 主 Agent 自行处理。 |
| 缺少可用工具、合适的隔离环境，或涉及敏感资料、生产权限 | 不扩大资料和工具权限。能用缩小后的输入外派就先缩小；否则在原授权内本地处理。若用户明确要求外派或需要新增授权，先报告缺口。 |

主 Agent 对范围、方案、派工、复核和最终结论负责；执行 Agent 按任务单制作、测试并提供证据。执行端不可自行批准、扩权、再派工、合并、提交、推送或发布。是否需要外派与是否允许外发是两回事。

## 派工到验收

1. **认领与拆任务**：按[协作执行记录](协作执行记录/README.md)登记主会话与具体写入路径，核对未结束任务；主 Agent 对交付、返工和范围释放负责。
2. **准备候选**：优先用独立目录，或从明确的 Git 基线建立独立工作树，不把正在并行修改的主工作区交给执行端。工作树只隔离版本，不是权限沙箱。只发送已授权且完成任务所需的输入；能用数据摘要、脱敏样例就不外发原文件，不发送凭据、个人数据、未授权业务源码或整仓。任务单写明基线/输入指纹、可读写范围、禁止动作、交付件和复测方式。
3. **选平台并执行**：优先选已实测且适合任务的平台，默认先试豆包官方 CLI；按任务能力、稳定性和额度选模型，常规先用 DeepSeek V4.1 Flash。可以根据实际结果换模型或平台；明确区分权限、网络、回执与实现问题，不因权限不足改开全权限。可以直调官方接口，不要求经过 DSH。工具路径、参数和当前能力以本机 AgentDispatch 的 `USAGE.md` 为准；工具不在本机时照常执行本项目协作规则。
4. **收件与返工**：记录平台、请求模型、实际会话/尝试标识（如已知）、退出状态、实际产物及指纹。只有落盘文件、只有成功回执，或执行端说“已完成”，都不足以宣布交付。超时或回执不明时保留已有产物，先核对执行是否结束和文件是否仍在变，不在同一候选目录盲目重派。返工只给具体问题和复验条件，保留上轮证据。
5. **独立验收**：主 Agent 对比实际文件/差异与任务范围，绑定基线和候选指纹，独立复跑适用检查；记录通过、失败和未验项。验收只对该候选和核验过的范围有效，不自动进入主工程；合入、提交或发布沿用原有授权和交付流程。

## 已跑通的例子

2026-11-26，豆包用 DeepSeek V4.1 Flash 在仓库外制作了占位 BGM 的只读包体检查脚本。派工仅发送规格和三条包体测量数字，不发送工程源码或音频。首轮文件落盘但没有成功回执，且作者测试有错误；同模型返工通过官方 CLI 获得成功回执，由主 Agent 独立核对脚本和复测。最终作者测试 8 项、独立测试 5 项均通过，读取既有 Windows 审计报告时通过本轮临时预算检查。候选未合入主工程；本次没有验证微信下载量或正式音频预算，也不据此推断所有任务都适合外派。

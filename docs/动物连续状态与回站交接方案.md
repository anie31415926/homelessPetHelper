## 目标与已有事实

下一步建议只解决一件事：救助现场的动物到站后仍是同一个体，站内检查有明确的数据来源，不再靠独立样本冒充真实衔接。先用现有健康案例验证，不同时建设完整伤病系统。

已确认的约束见[健康状态来源](站内照护措施与交互.md#health-state-source)：首次出现即确定初始健康情况，之后持续演变，现场与站内共用；检查不生成或重抽状态，处理完成不等于康复。基础检查及放行沿用 6.7，轻伤处理及委托以 6.8 的最新确认执行。

实施前的代码事实（现状以 ST-06 为准）：

- `CaseAnimal` 是 Editor 停车棚案例内唯一可变动物，尚无正式通用健康状态；`CaseAnimalSnapshot` 供只读展示。现有回站只是案例阶段切换，不是接入救助站。
- `StationAnimalIntake` / `AnimalIntakeCondition` 是不可变入站事实，不应改成当前动物档案；`StationReturnSummary` 保持历史用途。
- ST-04 的 `StationCareSnapshot` 记录初次必要安排，不是实际健康状态。ST-05 已让站内健康样本使用该记录，但评估来源仍是明确标注的固定样本。
- `OutingCoordinator` 已校验外出身份、阶段、防重及容量，但当前接收上游提交的入站动物，并未绑定真实案例动物的来源。仅有相同外出 ID 不足以证明状态承接完成。

## 建议的数据边界

以下为实现提案，不是新的伤病、行为或康复规则。

| 部分 | 记录什么 | 不代表什么 |
| --- | --- | --- |
| 个体当前状态 | 稳定动物 ID、定义 ID；按类别分开的需求、情绪、应激及实际健康问题 | 不因换场景重新生成；不是一条健康总分或互斥的健康/患病枚举 |
| 检查信息 | 对哪只动物、在什么健康状态下做过哪类检查，得到哪些观察与安全处置提示 | 未检查不等于健康；基础安全评估不等于确诊所有疾病 |
| 处置记录 | 对应问题的处理步骤、已完成成果及安排/接手进展 | 已安排、初步处理和已康复不能互相替代 |
| 入站历史 | 本次入站时的情况及冻结总结 | 后续清洁、情绪或健康变化不回写历史 |

健康问题使用集合，允许同时存在多个；每项有稳定的问题实例标识及类型标识，处置记录关联具体问题，不能用病种名称作为整只动物唯一状态。同一种类型是否允许同时多处出现、具体伤势字段与治疗阶段，留到真实伤情样例再定，不提前构造疾病目录。

一次运行中的个体状态只有一个可变所有者，建议放在现场和站内均可依赖的普通 C# 规则层。外出/站内保存该动物的身份关联，UI 只读快照并提交操作，不各自复制一份可变健康档案；Editor 只负责创建固定样本与装配。具体目录及接口在开工时沿用现有依赖约束，不引入通用状态框架或全局事件总线。

检查结果应能追溯对应健康情况，避免旧结果覆盖新情况；不能将任何情绪/需求变化都视为必须重新检查，更不由本提案自动启用复查、患病或恶化。初次站内基础检查仍按已有确认执行，现场已知信息和处理成果不能因此被抹去。

现场上下文不混入永久个体状态：地上的食物、障碍、现场空间和安置器具属于本次现场；进食经历、应激等个体事实延续。回站可结束现场上下文，但不能把全部字段原样复制后就声称连续性，也不能顺手将饥饿、情绪和伤病重置。站内行为如何变化仍依据已确认规则，不自动播放一律放松。

## 建议的最小试做

1. 绑定现有停车棚健康样本的稳定动物身份与明确的初始健康数据；保留正常/应激两个起点，不将它们的情绪、动作和抽取参数直接升级为正式通用规则。
2. 救助实际完成后，由装配层关联当前外出、实际完成结果、动物身份及最新状态。通过既有入站预检后登记同一个体并冻结历史，不创建替代动物；被拒绝时不改状态、不占位、不重复推进时间。
3. 站内基础检查读取这只动物的健康数据，写入既有照护记录。此固定样本无紧急问题，故检查后可满足再次外出条件，即使还脏；不等同于所有动物都无问题，也不表示清洁/接触权限已全面判定。
4. 先做纯规则与装配集成验证，再小范围接既有白板；不为此重建 Prefab、制作新图片、扩地图 UI 或将完整样本搬进 Main。具体白板切换方式在规则接通后说明。

不在本轮实现轻伤小游戏、真实诊断、疾病随机分布、康复/恶化速度、脏污风险、存档、多次相遇调度或新情绪转换。已有 ST-04 必要问题仅实现专业交接路径，不能用于宣称轻伤亲手处理/助手委托也已接通；那些路径按照护文档另步实现。

## 验收例子

正常样本起初饥饿、紧张，健康数据已明确但站内尚未检查。现场实际吃过食物、缓和并接受安置后，完成救助，入站保持相同 ID 和最新个体事实。站内基础检查读取预先已有的健康数据，不再生成，显示该样本无紧急问题；不强迫再喂一次、清洁或抚摸才能外出。

应激起点验证已有进食事实不会因恢复、收尾或入站丢失；不是新增应激恢复规则。其他拒绝测试覆盖错误动物身份、旧会话、暂停、重复回站、满员及缺少可信评估来源，不允许缺项默认为健康。规则不依赖画面播放结束；历史总结保持原值。

实际医疗效果暂不实现。多问题可在契约测试中使用明确的非诊断测试数据验证身份和专业安排不被覆盖，不借测试虚构某种伤病的真实处理办法；实际现场处理成果、轻伤处理和委托路径尚未接入。具体测试数量与执行结果记录在 ST-06，不将历史验证当本轮结果。

## 开工与更新规则

1. **开工前认领**：读取本页、`协作任务/` 中全部非“完成/已取消”记录及目标路径的实际改动。每个独立写入任务新建一份 `日期-任务短名-会话短ID.md`，写清用户授权、负责人、状态、具体写入路径、依赖和不负责的范围。前序已有自己的任务则原地更新，不重复建单。日常认领无需编辑本页，集中查看任务目录即可；共同目标或接续关系变化时再补本页。
2. **认领后复读**：保存认领后重新读取其他未结束任务和目标路径；发现文件重叠先协调。未登记的工作树改动也是待核对信号，不能因无认领记录就覆盖。未取得协调结果时，可继续处理范围独立的文件，不开始有冲突的写入。
3. **按边界写入**：路径范围涵盖脚本、测试、配置源、生成物、文档与资源；移动同时登记源/目标路径及 `.meta`。修改共享程序集接口、`Packages/`、`ProjectSettings/`、场景/Prefab、`tools/unity.ps1`、`package.json` 或同一文档前，确认现有任务范围。不同功能修改同一文件也可能冲突。
4. **及时维护**：开工、范围/接口变更、验证结论变化、阻塞、停工交接及交付前都更新自己的任务记录，注明带时区时间。每次持续工作约 30 分钟至少刷新一次；超过 60 分钟未更新的“进行中”视为**状态待核实**，不能自动认定任务已结束或占用已释放。
5. **完成有证据**：分别记录实现、验证、人工试玩和渠道状态。写明本轮实际检查、报告及适用源码快照；没有统一指纹时如实注明。验证前后代码有变化，结果仅适用于已验快照。暂停/交接保留占用直到明确接手或释放；完成/取消后记录释放的路径及遗留事项。
6. **保留他人内容**：公共文档只改本轮相关段落；写前重读、局部合并、写后核验，不整文件覆盖或回退。只更新自己的状态，不用“本聊天”“已完成”替其他 agent 作结论；他人状态不明时登记“待核实”及依据。
7. **执行记录可核对**：按[操作说明](协作执行记录/README.md)为自己的任务执行 read → ack → check。先阅读输出并核对实际改动，确认时使用本次输出的指纹；任务状态、范围或其他上下文变化后重新读取、确认。交付先更新任务和释放范围，再登记 delivery 并检查；过期或失败不自动解除任何任务占用。

任务文件是人工维护的协作记录，**不是系统文件锁**，也不会自动通知已运行的其他会话。不能仅靠时间戳和文档消除竞争；遇到重叠需在已有沟通渠道协调。若当前会话无法联系对方，向用户说明具体冲突并保留独立工作，不替对方撤销认领。

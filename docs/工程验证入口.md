# 工程验证入口

2026-11-21 实现；入口 `tools/verify-unity.mjs`，复用既有协作记录、基础源码检查和 `tools/unity.ps1`，无新增依赖。当前适用于 Windows Unity 2022.3.62f3 保存工程的图形 EditMode / PlayMode，不代表构建、微信转换、AOT、真机或玩法人工验收。

## 默认按变更范围验证

2026-11-24用户明确：前期快速开发、快速修复，后期稳定后同样以模块验证为主。**日常开发和提交推送不默认执行全量EditMode + PlayMode**；先选择能覆盖本次风险的最小范围，只有新的失败、依赖变化或尚未覆盖的风险才扩大验证。

| 场景 | 默认验证范围 |
| --- | --- |
| 纯文档、提交已有已验内容 | 文档/差异/引用检查，核对已有证据与本次内容一致；不因提交动作重跑Unity |
| 局部代码与快速修Bug | 基础源码检查、必要编译、最小复现与受影响用例；按风险选择EditMode或PlayMode，不要求两套都跑 |
| UI、交互、布局修改 | 受影响面板/模块的PlayMode或实际试玩，覆盖改到的状态、适配和输入边界；复用已有截图/助手，不扫全部场景 |
| 稳定期与模块合并 | 默认仍按模块及直接依赖的接口/关键流程回归；合并影响哪里就补验哪里，不因阶段变晚自动扩大到全库 |
| 阶段整体集成、基础设施广泛变化、发版候选或用户明确要求 | 先说明影响面及模块验证不足的原因，再选择全量与必要构建/渠道检查；目标设备要求仍按发布风险执行 |

任务中记录选择的模块、具体过滤器/用例、适用快照、结果与未验边界。已通过且输入未变的检查不无依据重复；缺陷修复的配对回归仍按[测试要求](conventions/topics/delivery.md#s-13-2)执行，不以缩小范围掩盖已知失败。

模块验证可使用既有入口，例如从Windows PowerShell运行地图回归：

```powershell
$mapReportSuffix = "map-" + [Guid]::NewGuid().ToString("N")
powershell -NoProfile -ExecutionPolicy Bypass -File tools/unity.ps1 -Task PlayMode -Isolated -Graphics -TestFilter "CityMap|UiLayoutCompliancePlayTests" -ReportSuffix $mapReportSuffix
```

`-TestFilter`按实际改动选择，报告名每次唯一；这是模块回归，不称全量。可复用自有隔离副本的编译缓存加快反馈，但需核对其保存输入和本次候选内容一致，不操作用户Editor或混入其他会话未完成的改动。并发导致整体输入变化时先区分变化归属，验证本次候选与相关模块，不自动连跑全库追赶活动工作树。

## 按需运行全量入口

先按[协作执行记录](协作执行记录/README.md)登记任务并实际执行 read → 阅读输出 → ack → check。入口只检查已有回执，不会代签或替其他会话补签。任务、范围或共同上下文变化后须重新阅读确认。

从仓库根目录，在 Windows PowerShell 使用 Node >=20.9：

```powershell
node tools/verify-unity.mjs --task docs/协作任务/<自己的任务文件>.md --session <自己的会话ID>
```

可选 `--editor <Unity.exe绝对路径>`、`--powershell <powershell.exe绝对路径>`；Unity 版本仍须与 `ProjectVersion.txt` 一致。WSL 访问本 Windows 工程时使用 Windows Node，保证 Node、PowerShell 和 Unity 使用相同路径语义；无需操作用户已打开的 Editor。

本工具是显式选择的全量入口，顺序固定：检查当前回执 → 保存输入清单 → 基础源码检查 → 新隔离副本全量 EditMode → 新隔离副本全量 PlayMode → 最终核对。始终使用 `-Isolated -Graphics`，不提供过滤测试或跳过步骤的参数。日常模块验证使用上节方式，不把全量工具当每次开工、修Bug或提交的默认动作。

## 可核对的证据

每次使用时间和 UUID 生成唯一运行 ID，不复用报告名。运行目录：`test-results/unity/verify-<运行ID>/`。

- `summary.json`：`running/passed/failed`、起止时间、任务/会话、协作回执、工具脚本哈希、Node/PowerShell/Unity 版本、测试范围、每阶段实际进程退出码、输入指纹和错误。
- `inputs.json`：`Assets/`、`Packages/`、`ProjectSettings/` 全部保存文件的相对路径、原始字节长度、SHA-256 和组合指纹，包含未提交文件及换行差异。可选动作基线 `test-results/pet-motion/baseline-rig.bundle` 的存在性及字节单独记录。
- `source-check.json`：本次独立保存的基础检查输出及哈希；不依赖共享 `source-check.json` 推断运行对应关系。检查范围是格式、namespace、meta 和本地程序集依赖图，不是完整 C# 分析器。
- `EditMode.json` / `PlayMode.json`：旧 PowerShell 工具新增的结构化记录，包含实际隔离路径、启动前输入清单、进程退出码、版本、测试计数、XML 与日志路径/哈希。进程真正退出后才结束记录。
- 每阶段 stdout/stderr 和报告保留原路径；XML/Unity 日志仍在 `test-results/unity/<模式>-isolated-<运行ID>.*`。隔离副本保留以便复查，不复制回源工程。

每个副本启动前的清单及测试结束后的文件都须匹配本次源清单；每阶段前后再核对源工程、验证工具、动作基线和协作上下文。报告必须来自本次唯一名称并与结构化记录的哈希相符。任何步骤缺失、进程非零、无报告/空报告、零测试、失败/跳过/未决测试、版本不符或输入变化都返回非零，`summary.status` 为 `failed`。不要仅看 XML 已出现或某阶段通过就宣布整轮通过。

## 失败与边界

失败证据保留，不自动覆盖上次结果，不隐式重跑。按具体错误处理后重新运行；源文件或回执过期时先修复上下文、重读确认，不能改报告或回执 JSON 消除错误。整轮超过回执 60 分钟有效期也会失败，不能把超时当作已确认。

这仍是保存工程的可复查检查，不是文件锁、用户授权认证、源码签名或 CI。无法捕获其他进程两次取样间改动后恢复的瞬态；未保存的 Editor 修改不在范围内。沿用旧工具复用 `Library/PackageCache`，不复制用户 Editor 数据库/锁文件；第三方缓存内容未逐字节纳入本次清单，其版本依据 `Packages` manifest/lock。构建、渠道、性能、图片预算及人工反馈按相应任务另验。

工具故障回归：

```powershell
node --test tests/unity-verification.test.mjs tests/collaboration.test.mjs
```

这些 Node 测试使用临时工程和模拟 Unity 进程验证失败处理，另包含真实协作回执和进程退出测试；它们不能代替实际 Unity 全量运行。本轮真实全量已通过（EditMode758/758、PlayMode73/73、1079项输入匹配）；运行 ID、指纹及失败修正过程见[交付任务](协作任务/20261121-统一验证与容量续玩-01a1f74d.md#最终验证证据)。

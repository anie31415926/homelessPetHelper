## 本次要验证什么

选项池是否能让玩家在“争取进展、稳住局面、保留后续方法”之间作出有意义的选择；动物意图是否可读、回应是否真正改变局面；锁定与自动刷新能否支持合理处理前提。

退开、等候、放食和接近的基础分工已确认，具体条件、数值及其他候选行动仍待细化；三个选项、使用一个、最多锁定两个已获认可作为首轮试做规格，不是最终平衡，且须为更多选项与多选保留扩展边界。独立于抽取的收尾方向已确认，见下文。文字推演不代表代码测试或好玩结论，也不是现实救助/医疗指导。

## 候选行动池

先用六种方法讨论，不用大量近义选项充数。退开、等候、放食和接近的基础职责已确认，见[确认记录](#已确认四种基础行动的职责)；下表不是完整效果表，玩具与移除现场干扰仍为候选：

| 候选行动 | 可能的作用 | 需要讨论的限制与回应 |
| --- | --- | --- |
| 退开留出空间 | 解除距离压力，为稳定或试探创造前提 | 不直接增加靠近进度；需要多少空间尚未定 |
| 安静等候 | 合适时稳住情绪，前提满足后进入恢复/观察 | 不是无限等待就自动成功；也不是所有情况下都安全 |
| 放下食物 | 创造闻食/进食机会，处理饥饿需求 | 食物消耗与选项消耗分开；动物可叼走后退开，不等于建立足够信任 |
| 展示玩具 | 回应好奇与玩耍倾向，创造互动机会 | 饥饿、疼痛或紧张可能限制适用性，具体条件待确认 |
| 移除现场干扰 | 解除噪声等环境压力 | 只在存在对应可操作对象时进入本轮候选池，不默认每个地点都有噪声 |
| 慢慢接近 | 在合适条件下缩短距离，争取安全转运机会 | 过早接近可使它退缩；具体条件与失败幅度未定 |

“不适合此刻使用”不能仅因为不安全就全部过滤掉，否则失去观察与判断。客观不存在的对象、物资不足和暂缺恢复前提分别如何处理，需要明确，不能混成一种拒绝。

查手册和求援为已确认常驻入口，不占随机池位置；它们的成本与结算未定。每回合安全选择的保证必须在考虑现有锁定项、物资和动物意图后成立，不能只对新抽部分或上一回合状态成立。

## 一轮文字推演

按已认可的首轮规格，用三个选项、每回合用一个举例；最多锁定两个，不据此确定最终数量或回合长度。初始为“饥饿 + 紧张”，健康状态独立存在；本例不假定必须先治病才能互动，也不假定喂食会消除伤病。

1. 动物频繁看向掩体，身体朝后，透露可能退缩。本轮出现退开、食物、接近；玩家锁定食物，使用退开。动物不再继续后退，但还没有愿意跟随。
2. 食物选项保留，其他位置自动刷新。动物开始探头观察；玩家使用此前保留的食物，该选项正常消耗。动物停留并尝试闻食，不立即把饥饿、情绪和信任全改为满足。
3. 动物靠近地上的食物，仍关注玩家。本轮玩家选择合适的等候，动物开始进食；这是需求和行为的变化，不等于救助成功。
4. 后续动物是否主动接近、如何达到可转运条件，要由明确状态与可见反应说明，不假定走完上述三个动作就固定成功。

可替代路径：先选合适的等候维持局面，再退开并提供食物，不因与上例输入串不同就判错。若选择不合适的接近，给出可解释的退缩/警告，仍保留求援；具体恶化与挽回步骤另定。

## 救助收尾方向已确认

用户确认：动物愿意接受救助后，不再等待抽牌，出现独立收尾操作。按钮可暂用“救助成功”，后续可按动物类型改变文案；“邀请进箱”不作为物种通用规则或固定名称。

具体接受条件、伤势分类、转运限制与收尾表现仍待确认；按安全转运需求决定是否先做现场处理的原则已确认。不因为这里已确认就默认候选动作、信任/距离阈值或转运设备也已确定。

## 现场简易医护方向已确认

用户选择：成功接近、已经可以救助时，发现明显伤病可打开简易医护包扎窗口；与后续站内医护同源，现场只给简易处理范围，不做两套系统，不是交涉中再等抽到一张医疗牌。

共用系统需能沿用同一动物的健康与处置结果，避免现场处理完回站后被重置；用户已选择动手包扎，具体状态类型、动作、工具、手势和表现未定。不能因为医护方向已确认就开始制作 UI 或整套医疗系统。

## 现场处理与成功结算已确认

用户认可按安全转运需求决定现场处理是否必要，流程方向如下，具体伤势与判定尚未细化：

```text
成功接近、愿意接受救助
  -> 没有需要现场处理的问题：直接完成救助
  -> 有影响转运、且可简易处理的伤势：现场医护 -> 必要处理完成 -> 救助成功
  -> 超出现场能力：求援，具体交接与结算待定
  -> 回站后由同源医护继续治疗和恢复
```

不是所有明显小伤都强制处理，也不是包扎一次清除全部伤病；影响转运且现场能处理的伤势，必要处理未完成不能走普通成功转运路径。伤势分类与具体前提、窗口关闭/处理中断、物资、失败和求援结算仍待讨论。

## 首轮回合规格已确认

用户认可先试每回合三个选项、使用一个、最多锁定两个，至少留一个位置参与刷新。安全应对需结合现有锁定项、资源与本轮动物倾向保证，不能只保证抽出时安全、动物回应后却继续恶化；留出刷新位置本身不等于已解决保底算法。

### 选项扩展与多选边界

**用户要求已确认**：首轮规格不能写成只能容纳三个选项、只能提交单个选项的固定结构；需要方便接入更多行动内容、更多可选位置及未来每回合选择多个选项。当前仍只开放使用一个，不据此提前定案多选玩法。

按项目规范采用以下最小设计约束，具体类型与字段在实现前按实际需要确定：

- **内容与数量分开**：行动定义通过明确标识加入候选集合；手中选项用集合表达，不使用固定的第一/第二/第三选项字段，也不以位置代表行动种类。复用已有行为的新增内容走定义接入；新行为仍需明确规则和测试，不承诺任意新选项只填表即可。
- **参数与运行态分开**：展示数量、每回合使用上限、锁定上限集中到只读规则参数，通过统一入口提供并校验，不散落在按钮和结算分支中。首轮使用 3/1/2；不修改共享定义来保存某轮选项或锁定状态，也不借此引入尚未选型的配置生成器或远程配置。
- **区分定义与实例**：同一种行动和本轮抽到的某个选项实例分开；锁定、选择及消耗对应实例身份，不绑定数组下标，避免扩容、刷新或以后允许重复抽取时作用到错误选项。
- **选择与执行分开**：选择输入和规则提交边界以选项实例集合表达，当前校验恰好选择一个且不超过使用上限；不只保留一个 `selectedOptionId` 作为唯一可表达的输入。集合边界为后续多选留余地，不表示当前允许一次提交多个选项，也不预先规定顺序或同时生效。
- **校验后提交**：完整校验会话/回合、实例存在性、重复选择、数量、可执行条件与资源，再产生副作用；非法请求不先消耗部分选项。具体资源与效果仍待规则确认。以后加入多选时，还须讨论动作间的前提变化、共享资源、执行顺序及动物回应时机，不能只调大上限就宣称多选完整可用。
- **不提前造框架**：沿用普通类型、集合和显式规则；不为扩展性新增通用卡牌引擎、反射注册、每选项一个策略类或万能效果脚本。

**验证进展**：选项管理的首轮 3/1/2、锁定跨回合、消耗/刷新、扩大展示数、非法参数与过期/重复/超限输入等已测试，证据见[实现记录](选项管理模块实现记录.md)。真实动物安全保底尚未实现；数量调整后仍须验证刷新空间与整回合安全，不默认允许全锁。多选实际结算用例待玩法确认后补充。

## 下一问题：具体行动与动物回应

回合容量和扩展方向已有共识，接下来用候选行动、动物意图与回应补齐正常、误处理和资源耗尽的例子，明确玩家行动与动物回应如何结算，再约定小范围试做。本页部分规则被确认不代表整页提案都成为正式规则。

### 已确认：采用可解释的状态回应

2026-11-17，用户确认采用“状态与前提决定回应、不另加隐藏成功率”的首轮结算方向。**方向已确认，具体规则未实现**；下列行动例子、细化顺序和效果不因此全部获批。

**已确认首轮不增加行动结果的隐藏随机判定**：相同动物状态、现场条件、相关可观察历史、已预告意图与玩家选择，产生一致的规则结果；变化来自初始状态组合、选项供给与玩家造成的局面变化。具体初始生成和抽取分布仍待确认，不因为此方向就实现新随机机制。动物不是每回合掷骰子决定接受或翻脸，也不是每只动物都按同一个固定动作串通关。预告是倾向，玩家改变相关条件后，实际回应可以有原因地改变。

按已确认方向细化的候选回合顺序，具体阶段划分与扣除时机仍待确定：

1. 读取组合状态与现场条件，决定动物本轮倾向，先向玩家展示线索；随后结合意图、现有锁定项和物资供给可选行动。不能先给牌后发现本轮没有安全应对。
2. 玩家提交行动，先校验会话/回合、选项实例和实际可执行条件，再统一处理选项与物资。方法不合适是游戏选择与后果，不一律当作非法请求；暂缺恢复前提但可稳住的方法不判为危险误操作。具体前提和资源扣除仍未定案。
3. 依据玩家动作改变后的条件结算一个主要动物回应；预告意图是倾向而不是不可改变的强制动作。合理操作若改变了意图前提，应以可见原因说明回应的变化，不无缘由换成另一种危险结果。
4. 统一得到本回合状态和反应结果；正确方法但恢复前提不足，整回合至少不恶化，不能在动物步骤追加惩罚。进入可救助状态后走独立收尾/必要医护，不为此继续抽牌；否则再形成下一倾向与刷新。

以下仅为游戏内回应例子，不是行动全量规则或现实救助指导。同一倾向需要多条合理应对，不建立“一个意图只能出一张克制牌”的对应表。

| 候选倾向及线索 | 主动回应示例 | 可产生的选择差别 |
| --- | --- | --- |
| 想躲开：关注掩体、身体后移 | 留出空间后停下观察；不当逼近时退得更远 | 稳定当前局面与强行推进的区别；具体安全方法需结合环境判断 |
| 关注食物：视线追随食物、探头闻 | 条件合适时试吃；仍戒备时可取食后退开 | 缓解饥饿不等于建立足够信任，也不保证距离变近 |
| 好奇试探：关注玩家或合适的玩具 | 自主探头、接近或短暂参与互动 | 创造接近机会；继续等待可维持局面但不保证无限推进 |
| 警告回避：绷紧身体、明确拒绝靠近 | 正确处理可稳住或逐步恢复；继续刺激则加重警告/退缩 | 给玩家纠正与求援机会，不把一次失误直接判为死亡 |

**文字例子**：动物饥饿且紧张，预告关注食物。放食后它可能在安全条件下尝试进食，也可能仍保持戒备；适当退开可让它停留观察，但不把“没靠近玩家”自动算恶化。后续接近机会取决于局面已发生的变化，不额外摇一次接受概率。若误在明确抗拒时继续逼近，给出相应退缩/警告和原因，仍有求援机会；具体幅度和失败边界另定。

**仍待细化**：具体意图清单、优先级、动作前提与效果、接受条件、安全方法及资源耗尽情形。此次仅记录确认与下一组讨论材料，未修改白板、选项规则或动物实现。

### 已确认：四种基础行动的职责

2026-11-17，用户认可“退开、等候、放食、接近”的基础职责与因果关系，以及先退开再放食、先放食再退开均可继续的多路径方向。**分工已确认，具体效果未实现**；玩具、移除现场干扰仍为候选，后续补充，不据此取消扩展。这是游戏规则，不是现实救助指导；距离档数、数值、物资数量及下述资源拒绝示例不因此全部获批。

| 候选行动 | 前提与玩家作用 | 动物回应与不推进的情况 |
| --- | --- | --- |
| 退开留出空间 | 有退让空间时解除距离压力；已有足够空间时不继续累加收益 | 可停止退缩、转为观察；不立即消除饥饿、伤病或全部紧张 |
| 安静等候 | 对适用的紧张情境，留出空间、解除持续干扰后才可逐步恢复 | 恢复前提不足时整回合稳住但不推进；不是无限等待自动获救，也不泛化为所有紧急伤病都能靠等候稳定 |
| 放下食物 | 有可用食物时在现场留下食物，提供取食机会 | 条件允许才闻食或进食；仍受距离压力时可先警戒。实际进食后才缓解饥饿，放食不直接等于情绪恢复或信任达标 |
| 慢慢接近 | 根据动物对当前距离的接受程度推进接近；是否已放松、是否明确抗拒等条件须可观察 | 接受时缩短距离；在明确拒绝时继续逼近则退缩或警告，具体恶化幅度与失败边界另定 |

**正常例子**：在只有距离压力、没有其他持续干扰的“饥饿 + 紧张”情境中，可先退开再放食，也可先放食再退开；后者在留出空间前先得到警戒而非进食回应。两条路径都能继续，不能因动作串不同判错。动物何时从闻食转为进食、何时允许接近仍需明确，不能仅凭本例认定几步后必然成功。

**误处理例子**：动物已明确抗拒靠近，仍选择接近，得到退缩/警告与原因；之后允许按前提纠正或求援，不用隐藏失败率替代解释。警告次数、应激阶段与恢复速度不在本组先定案。

**资源耗尽例子**：食物不足与方法不合适分开处理；建议不足时提示不可执行，非法提交不消耗选项或推进回合。仍须保证本轮有实际可稳住的选择并保留求援，但不承诺不用食物必能完成每次救助。食物库存、扣除量、重复抽取与求援成本留待后续确认。

**确认边界**：本次确认四种行动的职责及上述非唯一操作串，不是一次确认全部状态字段、完整行动池、资源系统、医护或完整救助流程。

### 已确认：允许接近与愿意接受救助

2026-11-17，用户认可区分“允许靠近”与“愿意接受救助”，并特别认可动物在觉得玩家没有威胁后主动靠近的正向反馈。**方向已确认，具体触发与表现未实现**；不把吃过食物、距离变近直接等同于获救，也不强制每只动物先吃饱、完全放松或喜欢玩家。下列为情境区别及线索示例，不要求新增一套混合情绪、距离和健康的状态枚举。

| 情境 | 线索与建议规则 |
| --- | --- |
| 仍抗拒接近 | 明显后缩、躲避或警告；继续逼近可触发已确认的退缩/警告后果 |
| 允许接近，但未接受救助 | 玩家靠近后不再退开、开始主动观察，但仍回避必要操作；可以接近，不把“没有逃走”直接当作救助意愿 |
| 愿意接受救助 | 在可接近范围内，出现接受必要安置/转运操作的明确回应，且不存在使该操作不安全的强烈应激或现场干扰；进入已确认的独立收尾或必要医护分支，不再等收尾选项 |

**主动回应方向已确认**：动物在不再感到玩家威胁、条件合适时可以主动靠近，以实际行动回应玩家建立的安全感，不只显示警惕下降。若已经满足接近条件，不强迫再用一张“接近”走形式；主动来取食或接近不自动等于愿意被带走。不要求受伤或其他不便移动的动物必须主动走来。食物、玩具或等待等方法可创造机会，但具体形成意愿的条件仍要细化，不能靠看不见的好感阈值或额外成功率让玩家猜。上述情境不是每次必经的三个阶段，也不强迫已经愿意接受救助的动物再走一次互动流程。

**与健康分开**：受伤不等于不愿接受帮助，接受帮助也不等于伤病消失；转运前是否必须处理仍按已确认医护边界判断。本组不确定伤势清单，也不增加新的摸头、抱起或运输设备操作。

**确认边界**：接近许可与救助意愿的区分、主动靠近方向已确认；具体线索、触发条件、状态转换、资源与失败边界仍待细化，不据此扩展整套动物或动画实现。

- **普通失误**：例如在明确抗拒时继续接近，动物退缩、情绪转紧张或发出警告，当前接近机会受影响；不默认一次失误立刻进入极端应激，也不把此前已进食、已移除干扰等事实抹掉。

**确认边界**：普通失误与应激分开，挽回不要求重做全部流程；具体应激触发、接近许可损失与恢复程度、恢复速度、不可恢复失败及求援结算仍待细化。状态保留不等于效果永远不变；后续若有新的明确原因影响状态，应按因果更新，而非因一次受惊无条件清零。

## 约束词定义

| 词 | 含义 |
| --- | --- |
| **必须** | 强制。Code Review 不通过则拒绝合入 |
| **禁止** | 强制不允许。出现即视为缺陷，需立即整改 |
| **推荐** | 默认采用；偏离需在提交说明中给出理由 |
| **可** | 允许自行选择，保持同一模块内一致即可 |

**优先级链**：正确性、玩家数据安全与合规是不可突破的底线；满足底线后，在性能/内存预算内优先选择可读、可测试、易维护的方案，最后考虑个人编码习惯。性能优化必须有测量依据，不能以“优化”为由跳过校验或破坏数据一致性。

**例外流程**：确需偏离本规范时，在 Changelist 描述中写明 `例外条款号 + 原因 + 影响范围 + 回退方案`，经模块 Owner 与至少一名 Reviewer 同意；例外仅限单次提交，不自动继承。

## 15.1 术语

| 术语 | 说明 |
| --- | --- |
| UPF | 项目所选 UI 框架的占位名，负责面板栈、Prefab 绑定与生成链；不指任何具体在研工程实现 |
| 生成链 | 从面板描述、Luban schema 到 C# 代码与资源的自动生成流程 |
| 随包表 / 远程覆盖 | 随包表为基础真值，远程配置为带版本号的覆盖层，失败回落随包表 |
| 弹窗栈 | 统一管理面板/弹窗层级与排队顺序的机制 |
| 安全区 | `Screen.safeArea` 定义的可交互区域，需排除刘海、挖孔与底部手势条 |
| 配对测试 | 同一输入在改动前后各执行一次，比对输出差异的验证方式 |
| 静态绑定 | 引用关系在 Prefab 中固化、通过 Inspector 赋值 |
| 契约 | 接口对输入、输出、失败、状态修改及适用的线程/生命周期行为的约定 |
| 幂等 | 同一操作重复执行不重复产生业务效果；资产流程须覆盖持久化、重试与重启恢复 |
| 资源所有权 | 谁创建/租借、谁使用、谁最终释放/归还的明确责任 |
| 圈复杂度 | 对独立控制流路径数量的度量，工具/版本统一后用于识别评审与测试风险 |
| 质量门禁 | 合入/发版必须满足的检查及失败阻断规则；不是代码质量的单一分数 |
| FSM | 有限状态机：用明确状态、迁移条件与入口组织行为；不要求必须拆成一组状态类 |
| 选型记录 | 对真实问题、简单替代、方案边界、成本与验证的轻量决策说明，不是模式名词清单 |
| 配置 / 资源 / 代码更新 | 分别改变受支持的数据、内容资产、可执行托管逻辑；前两者不自动提供新增脚本能力 |
| 底包 | 通过渠道发布的完整客户端，包含引擎/原生代码与启动基线；补丁能做什么取决于其内置能力与契约 |

## 15.4 项目事实与模板落地

本规范是模板，实际选型统一记录在[项目基线](PROJECT_BASELINE.md)的“项目事实与待确认项”，不得把文中的候选或占位当成已接入。

| 占位/待确认项 | 落地需要记录 |
| --- | --- |
| UI 与生成链 | 实际 UI 框架、基类、生成命令、源与产物目录 |
| 配置与资源 | 配置生成器、schema/源表、资源系统、版本与发布入口 |
| 版本管理与构建 | 实际版本管理/分支/锁策略、Owner、渠道、构建与验证命令 |
| 更新能力 | 配置/资源/代码更新的选定范围、框架兼容版本、平台规则、恢复责任，见 [§9.5](topics/updates.md#s-9-5) |

本机绝对路径、个人账号及无关的其他工程细节不写入通用规则。项目事实更新项目基线，通用细则更新所属专题；不要为同步事实复制多份选型清单。

> 线上问题优先止损、恢复与修复；复盘时补齐根因、规则和测试/检查项。

## 约束词定义

| 词 | 含义 |
| --- | --- |
| **必须** | 强制。Code Review 不通过则拒绝合入 |
| **禁止** | 强制不允许。出现即视为缺陷，需立即整改 |
| **推荐** | 默认采用；偏离需在提交说明中给出理由 |
| **可** | 允许自行选择，保持同一模块内一致即可 |

**优先级链**：正确性、玩家数据安全与合规是不可突破的底线；满足底线后，在性能/内存预算内优先选择可读、可测试、易维护的方案，最后考虑个人编码习惯。性能优化必须有测量依据，不能以“优化”为由跳过校验或破坏数据一致性。

**例外流程**：确需偏离本规范时，在 Changelist 描述中写明 `例外条款号 + 原因 + 影响范围 + 回退方案`，经模块 Owner 与至少一名 Reviewer 同意；例外仅限单次提交，不自动继承。

## 0. 一页速查（提交前红线）

1. 生成代码（UPF 面板绑定、Luban 表与产物）**禁止手改**，改动只能回到生成源 / 生成器。
2. 任何 `TryXxx` / `DoXxx` 业务接口，**必须**先校验完整前置状态，禁止靠"调用另一个接口"隐式推进状态。
3. **禁止**提交任何绕过校验的调试开关（含强制广告成功、强制内购成功、强制实验分支），调试能力用编译符号隔离且默认关闭。
4. `Update` / `LateUpdate` / 每帧回调等稳态热路径**必须**达到项目分配预算，默认 0 B；禁止未经评估的引用类型分配、字符串拼接、LINQ、捕获闭包与装箱，见 §4.6。
5. UI **必须**静态 Prefab + Inspector 绑定；**禁止**运行时按名字查找、`new GameObject` 拼界面、`Resources.Load` 加载面板。
6. 竖屏安全区（刘海 / 挖孔 / 底部 Home 条）与多宽高比**必须**适配；**禁止**绝对坐标与整体缩放式"适配"。
7. 弹窗队列、激励广告、内购、切后台回调**必须**处理打断、重入与恢复，奖励只发一次。
8. 事件、协程、定时器、对象池租借、弹窗注册**必须**成对登记与释放。
9. 配置（随包表 + 远程覆盖）**必须**有版本兼容与失败降级，远程失败**禁止**导致白屏或空列表。
10. 资源**必须**带导入设置；`.meta` 同进同出；场景 / Prefab / 图集 / 配置源表**必须**独占加锁编辑。
11. Release 包**禁止**输出隐私、密钥、协议原文，禁止保留可用 GM 指令与临时调试日志。
12. 提交前**必须**完成编译与相关质量检查，并按改动风险执行测试、生成链与真机验证；适用范围和阻断条件见 §13，禁止以无关检查代替关键路径验证。

**代码质量快速入口**：模块职责见 §2.5；函数与复杂度见 §4.9；接口契约见 §4.10；数值/时间/随机见 §4.11；集合与算法见 §4.12；数据封装与序列化见 §4.13；注释与技术债见 §4.14；资源所有权见 §4.15；最小示例见 §4.16；质量门禁见 §13.3–§13.5。

## 1. 总则：竖屏休闲项目的硬约束

手机平台与 PC / 编辑器环境的差异，加上休闲品类的产品形态，是本规范所有条款的根因：

| 约束 | 工程含义 | 对应章节 |
| --- | --- | --- |
| 帧预算刚性 | 60 fps 下每帧仅 16.6 ms，一次 GC 尖峰即可掉帧 | §4.6 §9.1 |
| 内存与发热 | 中低端机可用内存低、无虚拟内存换页，UI 图集与托管堆双高压 | §8 §9.2 |
| 首包与热更 | 休闲品类买量转化对包体、启动耗时极敏感 | §8.4 §9.4 |
| 竖屏适配 | 长屏 20:9 到 4:3 并存，刘海/挖孔/底部手势条，安全区必须处理 | §6.2 |
| 打断频繁 | 激励视频、插屏、内购、切后台、来电随时中断一次会话 | §5 §6.3 §10 |
| 离线可玩 | 核心玩法与启动不依赖网络，配置必须随包 | §7 §10 |
| 迭代节奏 | 小团队、活动与数值高频变更，配置需热更与灰度 | §7 §12 |

**项目基线假设**（落地时按立项评审结果覆盖）：

| 项 | 基线 |
| --- | --- |
| 设计分辨率 | 竖屏 1080×1920（或项目统一基准），CanvasScaler 策略全工程唯一 |
| 屏幕方向 | 锁定 Portrait，禁止运行时横竖屏切换 |
| 场景结构 | 单主场景 + 面板/弹窗栈，避免多场景切换丢状态 |
| 目标帧率 | 60 fps（低端机可降级到 30 fps，需明确降级策略） |
| 网络 | 核心玩法离线可玩，联网仅用于账号、排行榜、活动、广告与内购 |
| 支持机型 | 明确最低 Android / iOS 版本与宽高比范围，范围外给降级布局 |

**必须**：所有性能与适配结论以真机（至少一台中低端 Android + 一台 iOS，且覆盖长屏与小屏）数据为准，禁止以编辑器或单一机型结论代替验收。

## 2. 工程结构与程序集

### 2.1 目录约定

```
Assets/
├── Art/
│   ├── UI/Atlas/            # UI 图集，按面板/弹窗分
│   ├── UI/Frames/           # 九宫格底板、通用边框
│   └── Audio/               # BGM、SFX
├── Scenes/                  # Boot / Main（竖屏单主场景为主）
├── Prefabs/
│   ├── Panels/              # 全屏面板
│   ├── Popups/               # 弹窗：奖励、结算、广告、设置
│   └── Widgets/             # 复用控件：按钮、进度条、红点、商品卡
├── Scripts/
│   ├── Framework/           # UI 栈、事件、资源、网络、音频基础（无业务依赖）
│   ├── Generated/           # 共享配置/协议生成产物，禁止手写
│   ├── Config/              # 配置访问层、远程覆盖与版本兼容
│   ├── Network/             # 协议层、连接管理
│   ├── Modules/             # 业务模块；UI partial 生成文件随所属模块存放
│   └── Editor/              # 编辑器扩展，禁止被运行时程序集引用
├── Settings/                # URP、CanvasScaler、质量、输入配置资产
├── Plugins/                 # 广告/内购/埋点 SDK，保持原始目录结构
└── Resources/               # 原则上禁止新增，见 §8.4
```

**必须**：`Scripts/Generated/` 内文件头部保留生成标记；生成器重跑后被覆盖属预期行为。
**必须**：业务代码不得反向引用 `Editor/` 程序集；编辑器工具不得影响运行时构建产物。
**禁止**：在 `Assets/` 根目录堆放脚本、临时场景、个人测试资源。
**推荐**：竖屏休闲项目以单主场景 + 面板栈为主，避免多场景切换带来的重复加载与状态丢失。

### 2.2 程序集定义（asmdef）

- **必须**按 `Framework` / 共享配置或协议生成层 / `Config` / `Network` / 业务模块 / `Editor` 等职责建立 asmdef，禁止全工程默认 `Assembly-CSharp` 大杂烩。UI 绑定生成的 `partial` 类型与其手写扩展必须在同一程序集/命名空间，禁止把所有生成文件机械隔离到独立 asmdef 导致类型无法合并。
- **必须**单向依赖：`Modules → Framework`，`Framework` 不得反向引用业务模块；跨模块通信走事件/接口。
- **必须**所有 Editor 脚本标记 `Include Platforms: Editor`，防止误打进运行时程序集。
- **必须**广告 / 内购 / 埋点 SDK 封装在独立适配层，业务模块禁止直接引用 SDK 类型（便于换渠道与打桩测试）。
- **推荐**按模块拆包缩短增量编译时间；新增 asmdef 需同步提交 `.asmdef` 与 `.meta`。

### 2.3 命名空间

```csharp
// 命名：项目.层.模块
namespace MyGame.Modules.Daily.UI
{
    public sealed class DailyRewardPopup : PopupBase { }
}
```

- **必须**与目录路径一致；一个文件一个主类型，文件名与主类型同名。
- **禁止**无业务语义的上帝类（`Utils` / `Common` / `Manager` 泛化命名需评审）。

### 2.4 生成代码边界

- `Scripts/Generated/`（或等价目录）下文件**必须**带 `// <auto-generated />` 标记。
- 生成源（UPF 面板描述 / Prefab 描述、Luban schema 与源表、生成模板配置）是唯一可修改对象。
- 生成结果不稳定时**必须**修生成器或模板，禁止在生成文件上打补丁后提交。
- 生成器版本升级**必须**全量重生成 + 编译 + 面板回归，禁止只生成单个文件。
- **禁止**生成产物中出现本机绝对路径、个人账号、本地时间戳；生成流程**必须**可由统一命令或 CI 复现，不依赖某台开发机。

### 2.5 职责划分、依赖与可测试性

- **必须**区分三类职责：UI/组件负责展示和输入；业务逻辑负责规则与状态迁移；基础设施负责存档、网络、资源和 SDK。禁止由按钮回调直接修改多份存档、调用 SDK 并完成发奖。
- **必须**让可独立计算的核心规则（奖励计算、解锁条件、状态迁移、配置校验）脱离场景与 `MonoBehaviour`，能够在 EditMode 中直接构造输入并验证输出。无需为了“纯净”而给每个简单类型增加接口。
- **必须**在启动/装配入口显式传入模块依赖；时间、随机数、存档、网络和 SDK 等非确定性边界须可替换，以便测试。禁止业务逻辑通过全局查找、任意单例链或 Service Locator 隐式取得依赖。
- **必须**保持程序集依赖图无环；数据生成与 UI 绑定生成依赖不同时应拆分程序集，禁止为消除编译错误反向引用业务层。跨模块调用须有明确契约，禁止读取另一模块的内部可变字段。
- **必须**区分命令与通知：需要结果、顺序或错误处理的操作使用显式方法/接口；已发生事实的广播可用事件。禁止把完整业务流程藏在无顺序保证的全局事件链中。
- **推荐**优先组合而非深继承，沿用工程已有服务与扩展点；只有真实重复、稳定边界或外部依赖替换需求出现时再抽象。禁止为尚未出现的需求引入通用框架、万能管理器或多层空转发。

## 3. 命名规范

### 3.1 C# 命名

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 类 / 结构体 / 枚举 / 委托 | PascalCase，名词或名词短语 | `DailyRewardPopup`, `RewardState` |
| 接口 | `I` 前缀 + PascalCase | `IPopupLifecycle` |
| 方法 | PascalCase，动词或动词短语 | `TryClaimReward()`, `LoadConfigAsync()` |
| 属性 / 事件 | PascalCase，属性用名词/状态，事件描述发生的事实 | `RewardCount`, `IsClaimed`, `AdRewarded` |
| 私有字段 | `_camelCase` | `_claimButton`, `_isClaiming` |
| 序列化字段 | `_camelCase` | `[SerializeField] private Button _claimButton;` |
| 常量 / 只读静态 | PascalCase（全工程统一即可） | `MaxRetryCount` |
| 局部变量 / 参数 | camelCase | `levelId`, `popupArgs` |
| 泛型参数 | `T` / 语义前缀 | `TItem`, `TResult` |
| 协程 / 异步方法 | 协程 `XxxRoutine`，异步 `XxxAsync` | `LoadConfigAsync()` |
| 布尔 | `is/has/can/should` 语义前缀，大小写随成员类别；优先肯定式 | `isClaimed`, `_isClaiming`, `IsReady` |

- **禁止**匈牙利命名、拼音命名、无意义缩写（`tmp1`, `obj2`, `mgr`）。
- **推荐**用 `TryXxx` 表示预期内可失败的操作，返回 `bool` + `out` 结果或失败原因；成功时可以修改状态，失败时不得留下未说明的部分修改。只读判定用 `CanXxx` / `IsXxx`，禁止把 `Try` 误解为“成功也无副作用”；业务拒绝不抛异常，见 §4.10。
- **推荐**方法名体现真实行为；命名与实现不一致按缺陷处理。

### 3.2 文件、资源与资产

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 脚本 | `PascalCase.cs` | `DailyRewardPopup.cs` |
| 面板 Prefab | `Panel_<模块>.prefab` | `Panel_Main.prefab` |
| 弹窗 Prefab | `Popup_<用途>.prefab` | `Popup_DailyReward.prefab` |
| 控件 Prefab | `Widget_<用途>.prefab` | `Widget_RewardCard.prefab` |
| 场景 | `SC_PascalCase.unity` | `SC_Main.unity` |
| 贴图 | `T_<模块>_<用途>_<变体>` | `T_UI_BtnClaim_Normal` |
| 图集 | `Atlas_<模块>_<用途>` | `Atlas_Popup_Daily` |
| 九宫格 | `Frame_<用途>` | `Frame_PopupBg` |
| 材质 / Shader | `M_*` / `Sh_*` | `Sh_UI_RoundedMask` |
| 音频 | `SFX_*` / `BGM_*` | `SFX_Popup_Open` |
| 动画 / 控制器 | `Anim_*` / `AC_*` | `AC_Popup_Daily` |

- **禁止**资源名含空格、中文、版本号后缀 `_new` / `_final` / `_bak`；历史版本交给版本库。
- **禁止**同名资源放在不同目录；重命名**必须**在 Unity 内操作以保 `.meta` 与 GUID 一致。

### 3.3 Luban 表与字段

- 表名 `PascalCase` 集合语义：`TbLevel`, `TbShopGoods`, `TbDailyReward`；字段名风格全工程统一。
- ID 字段统一 `id`，引用他表统一 `<表名主键>_id`，禁止 `id1`, `target`, `ref` 等歧义名。
- 枚举字段**必须**定义独立枚举类型，禁止裸 `int` 魔法值。
- 可空/缺省字段**必须**在 schema 中显式声明默认值与注释，禁止靠运行时 `??` 掩盖配表缺失。
- **禁止** `param1..param8` 式万能字段；确有灵活参数需求用显式结构体 / 标签列表表达。

## 4. C# 编码规范

### 4.1 语言级别与格式

- 项目锁定 **Unity 2022.3 LTS；C# 9 为语言上限**，Api Compatibility Level 以 `Project Settings > Player > Other Settings` 实际配置为准。
- **必须**区分语言语法、运行时 API 与 IL2CPP/AOT 支持；本工程基线不启用默认接口方法、`record` / `init`、异步流、模块初始化器、`Reflection.Emit`、`dynamic`。如需放开，须对照目标 Unity 版本支持情况，并完成目标平台构建与真机验证，不能仅凭编辑器可编译认定兼容。
- **禁止**依赖 `System.Reflection` 做热路径调用；反射仅用于启动期/编辑器期并缓存结果。
- 格式：4 空格缩进、UTF-8（无 BOM）、工程统一换行符、Allman 大括号、一行不超过 120 字符、文件末尾保留换行。
- **推荐**启用 `.editorconfig` 与 IDE 自动格式化；格式化变更与逻辑变更**必须**分两个 Changelist。
- **禁止**用 `#region`、`partial` 或机械拆文件掩盖超大类；复杂度评审基线见 §4.9。

### 4.2 类型与成员设计

```csharp
public sealed class DailyRewardPopup : PopupBase
{
    [SerializeField] private Button _claimButton;
    [SerializeField] private RectTransform _cardListRoot;
    [SerializeField] private GameObject _claimedMask;

    private bool _isClaiming;
    private readonly List<RewardCard> _cards = new List<RewardCard>();
}
```

- 类默认 `sealed`；成员可见性按最小原则，禁止无理由 `public`。
- **必须**明确字段的初始状态、可空性与初始化时机；`false` / `0` 等有清晰语义的语言默认值可直接使用。必需的 Inspector 引用通过校验保证，禁止用空对象或无意义默认值掩盖漏绑。
- **必须**用 `[SerializeField] private` 暴露 Inspector 绑定，**禁止**为方便把运行时字段 `public` 化。
- **推荐**用 `[Header]` / `[Tooltip]` / `[Range]` 描述用途，绑定缺失时给出可定位的报错。

（上例为片段示意，`PopupBase` / `RewardCard` 为占位类型，按项目 UI 框架实际基类替换，见 §15.4。）

### 4.3 Unity 对象判空

- **必须**统一使用 `if (target == null)` 判空 Unity 对象，**禁止**混用 `is null`、`?.`、`??`，避免绕过重载造成"已销毁对象仍被使用"。
- 普通 C# 对象与 `UnityEngine.Object` **必须**区分；集合中的 Unity 对象需定期清理已销毁项。
- **必须**在外部数据/接口入口做运行时校验；断言仅表达内部不变量，不能代替 Release 包仍需执行的校验，见 §4.8。

### 4.4 状态校验与接口边界（高风险条款）

- **必须**为每个业务操作定义前置状态集合并在入口统一校验。例：领取奖励需覆盖「不可领 / 可领 / 领取中 / 已领取」；进入关卡需覆盖「未解锁 / 体力不足 / 可进入 / 进行中」。
- **禁止**通过调用其他业务接口隐式满足前置条件（例如为进入关卡而直接触发加体力），状态迁移**必须**走唯一显式入口。
- **必须**方法名、注释、日志三处描述同一行为；实现与命名不一致按缺陷处理。
- **必须**为失败路径提供可识别的结果/原因；预期的业务拒绝由调用方反馈，不要求底层逐次打日志。异常状态与基础设施失败须在统一边界记录关键 ID、当前状态和关联 ID，避免重复上报或日志刷屏。
- **必须**一次领取 / 一次购买全流程只允许一次发奖；入口防重入只保护当前会话，不能代替持久化幂等。重复回调、超时重试与重启补单须复用同一操作/交易 ID，并把到账记录与余额变更纳入同一事务或可恢复日志，见 §10.3。
- **推荐**状态机用枚举 + 显式迁移表，禁止多个散落 `bool` 组合表达状态。
- **推荐**每类状态分支补一组配对测试（改动前 / 改动后同输入对照），见 §13.2。

### 4.5 调试开关与安全旁路

- **禁止**提交 `BypassXxxCheck` / `ForceSuccess` / `SkipVerify` 形式的运行时旁路字段，无论默认为 false；尤其禁止"强制广告完成""强制内购成功""强制命中某实验分支"。
- 调试能力**必须**用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 隔离，**禁止**出现于 Release 程序集。
- 临时验证用本地未提交改动 + 明确 TODO，验证完立即还原；**禁止**把验证开关作为"以后可能用"留在主干。
- GM / 调试指令**必须**有权限校验与审计日志，正式服不可用。

### 4.6 每帧代码与 GC

- **必须**对 `Update` / `FixedUpdate` / `LateUpdate` / `OnGUI` / 高频事件等稳态热路径控制分配，默认预算 0 B；引用类型 `new`、隐式数组/`params`、字符串格式化、捕获闭包、装箱与 LINQ 需重点检查。低频初始化和非热路径按测量结果取舍，不全局禁用可读的语言特性。
- **必须**以目标平台 Profiler 的 `GC.Alloc` 调用栈确认分配来源。值类型 `new` 不等于堆分配；具体 `List<T>` / `Dictionary<TKey, TValue>` 的 `foreach` 通常不分配，转为接口枚举或发生装箱时需另测，禁止仅按关键字定罪或机械改写。
- **必须**避免热路径中的场景查找、反复组件获取与批量返回数组的查询；组件引用在 `Awake` 或显式初始化阶段缓存。持有者结束生命周期时解除外部引用/订阅，单纯给自身字段置空不等于释放资源。
- **推荐**缓存不变文本、仅在值变化时刷新，或使用项目文本组件的低分配格式化 API；`StringBuilder.ToString()` 仍会产生字符串，不得宣称使用 `StringBuilder` 就已零分配。
- **必须**区分受 `timeScale` 影响的玩法时间与不受其影响的 UI/超时计时；连续运动使用匹配的 delta time，禁止按帧 `++` 累加模拟时间。固定步长逻辑使用 `fixedDeltaTime`，业务时钟见 §4.11。
- **推荐**高频逻辑降频或改事件驱动（脏标记 + 一次性刷新）；倒计时、体力显示按显示精度到点刷新，而非每帧重建文本。

### 4.7 异步、协程与生命周期所有者

- **必须**明确每个协程/异步任务的生命周期所有者：面板任务随关闭取消，组件任务随销毁取消，支付/补单/发奖由服务层持有。禁止因面板关闭丢弃已提交交易；不支持取消的外部操作须接管结果或忽略过期 UI 更新，不能假装已撤销业务。
- **禁止**在无 Owner 的静态工具类中启动长期协程；禁止 `async void` 业务方法。UI/SDK 强制要求的 `void` 入口仅作薄包装，须观察内部任务异常并在边界处理；脱离等待的任务也须有明确错误观察者。
- **必须**为 I/O 与可能长期等待的操作定义取消、超时与结束态；取消属于预期控制流，不能统一当 Error。锁、租借对象等在 `finally` 或等价机制中释放，取消令牌按调用链传递，禁止在主线程 `.Wait()` / `.Result` 阻塞等待。
- **必须**保证 UI 与其他要求主线程的 Unity API 在主线程执行；SDK 回调线程未知时，经统一调度层切回主线程，禁止假设所有回调天然在 Unity 线程。
- **必须**在 `await` / 延迟回调后检查对象存活、请求序号/绑定 ID 与会话是否仍有效；旧请求不得覆盖新请求，池化 Cell 的旧图片结果不得写到新条目。业务状态在提交点重新校验，不能只在发起前检查一次。
- **必须**广告 / 内购回调通过 SDK 适配层统一接入，事件订阅成对释放；服务层处理重复、延迟、乱序回调与持久化幂等，面板只消费最终状态，见 §10.3。
- **推荐**全工程采用一种主要异步方案（UniTask / Task / 协程）；SDK 或已有框架需转换时集中适配，禁止同一流程无理由叠加多套调度机制。

### 4.8 异常、断言与防御

- **禁止**空 `catch { }`、仅记录 `e.Message` 后假装成功、用异常做常规流程控制。异常须保留堆栈与上下文；重抛用 `throw;`，禁止用 `throw e;` 重置堆栈。
- **必须**仅在能够恢复、转换错误或统一报告的边界捕获异常；预期失败返回明确结果，调用参数错误/不变量破坏可抛合适异常。禁止逐层重复记录同一个异常。
- **必须**在配置加载、协议解析、存档读取、远程配置合并等边界做运行时校验；只对有产品语义的场景降级，错误须定位到表/行/字段或具体操作。存档/资产失败优先保留原数据和恢复线索，禁止用默认值掩盖数据丢失，见 §10.2。
- **可**用 `Debug.Assert` 表达内部假设，其启用与剔除以 `UNITY_ASSERTIONS` 等实际构建设置为准；断言和日志均不能代替必要的运行时校验及失败处理。

### 4.9 函数设计、可读性与复杂度

- **必须**一个方法完成一个清晰动作，保持同一抽象层次；业务编排与具体计算/序列化分开。复杂条件提取为有业务含义的判定，入口用 Guard Clause 尽早处理非法状态，禁止靠深层嵌套表达正常流程。
- **必须**让副作用可见：修改余额、存档、网络、事件派发的方法名和接口契约须说明行为；属性 getter、资格查询与排序比较器禁止悄悄发奖、落盘或发请求。
- **禁止**复制粘贴已有规则形成第二套实现；稳定的重复规则收敛到一个归属明确的入口。仅外形相似、变化原因不同的代码不强行抽成万能方法。
- **推荐**采用下表作为评审触发线，而非“低于数字就算高质量”。超过时须重构或说明为何更清晰；禁止为达标机械拆成无意义转发方法。

| 指标 | 默认评审触发线 | 处理原则 |
| --- | --- | --- |
| 手写方法有效行数 | > 40 行 | 检查是否混合多个职责，不计空行/独立括号/注释 |
| 手写主类型有效行数 | > 400 行 | 检查职责与依赖；`partial` 文件合计，生成代码不计 |
| 圈复杂度 | > 10 | 检查分支、状态表与测试；统一分析器和计数口径 |
| 控制流嵌套 | > 3 层 | 优先提前返回、提取判定或拆分阶段 |
| 方法参数 | > 4 个 | 检查是否缺少有语义的请求/上下文对象，禁止改成 `object[]` |

- **推荐**避免多个布尔参数控制完全不同的行为，优先拆分命令或使用有语义的枚举；循环临时量可短命名，跨多行使用的业务变量须体现单位和含义。

### 4.10 接口契约、错误结果与一致性

- **必须**公共/跨模块接口明确输入约束、可空性、返回结果、失败原因、状态修改范围，以及适用的线程、生命周期和取消语义。简单且自解释的接口不要求重复堆砌注释，复杂契约须写在声明处。
- **必须**区分业务拒绝（体力不足、未解锁、已领取）、技术失败（超时、损坏）与取消；调用方可据此决定提示、重试或恢复，禁止只返回无法区分原因的 `false` / `null` / 魔法字符串。
- **必须**明确 `TryXxx` 失败时 `out` 值及状态保证；同步操作原则上“校验完整后一次提交”，失败不留下半扣费/半发奖。跨 I/O 操作用显式处理中状态与事务/恢复记录，不承诺无法实现的瞬间原子性。
- **必须**对跨异步阶段的状态重新校验或使用版本检查；先判断后执行不代表无竞态，单线程下 `await`、事件回调也可能导致交错与重入。
- **禁止**为了测试方便公开内部可变状态、跳过关键校验或在 Release 增加旁路；测试通过真实入口和可替换依赖验证契约。

### 4.11 数值、时间与随机数

- **必须**统一金币、数量、价格、概率和时间单位；字段名/类型注明 `Seconds` / `Milliseconds` 等单位，禁止把展示字符串作为计算数据。货币/离散资源使用整数最小单位，容量由上限推导，不能默认 `int` 永不溢出。
- **必须**在加减乘除、类型转换和配表边界处理负值、上下限、除零与溢出；关键资产运算使用 `checked` 或等价预检查。舍入、截断、封顶须有产品规则与边界测试，禁止静默溢出或无依据地 `Clamp` 掩盖错误。
- **必须**按语义比较浮点数，连续计算结果使用合适容差；概率/权重校验范围与总量，禁止未经校验就参与掉落。有限值输入须拦截 `NaN` / `Infinity`。
- **必须**区分持续时间、UTC 时间点与显示时区：超时/耗时使用不受系统校时影响的单调时钟；活动与跨日按约定时区/服务端时间判断；玩法与 UI 暂停语义见 §4.6。离线跨会话计时须定义改系统时间时的处理与补偿上限，不能依赖进程内时钟跨重启续算。
- **必须**让影响玩法结果的随机源可注入/设置测试种子，记录复现所需输入；核心规则测试不得依赖全局随机状态。高价值抽奖结果以明确的权威端为准，客户端随机数不能用作安全凭证。
- **必须**为协议、存档与配置使用稳定的数值/日期格式（如 `InvariantCulture` 或协议规定），禁止因设备语言改变小数点/日期解析；玩家展示再走本地化格式。

### 4.12 集合、算法与数据规模

- **必须**按访问模式与最大规模选择集合：顺序展示用列表，键查找用字典，成员去重用集合。热路径与大列表禁止无依据地嵌套全量扫描、重复排序或重复解析，评审须说明预期数据量。
- **必须**明确空集合、缺键、重复键和迭代中修改的行为；可预期缺键用 `TryGetValue`，禁止用索引异常判存在。修改集合可使用明确的反向索引/延迟变更策略，不能一律靠复制快照制造分配。
- **必须**为缓存/队列/对象池设容量、失效与清理策略；预分配依据真实规模，禁止无限增长或为“零 GC”无上限预热。
- **必须**在需要确定输出时显式排序，不能依赖字典/集合遍历顺序；排序相同时提供稳定的次级键，避免 UI 闪动和测试偶发失败。

### 4.13 数据封装、序列化与兼容

- **必须**由拥有者修改状态，对外提供只读视图或快照；`readonly List<T>` 仅禁止字段重新赋值，不代表集合和元素不可变，禁止把内部可变列表直接暴露给业务随意增删。
- **必须**区分配置对象、运行时状态与存档/协议 DTO；禁止把场景组件或任意服务引用混入持久化数据，禁止直接修改共享配置或共享 `ScriptableObject` 充当单局状态。
- **必须**保持持久化枚举值稳定；已有枚举用作协议/存档后显式赋值，新增不重排旧值，未知值有校验策略，禁止删除后复用旧编号。
- **必须**评估序列化字段重命名/移动影响；Unity 字段可用 `[FormerlySerializedAs]` 保留旧名映射，并验证 Prefab/场景数据；类型迁移及自定义存档另做版本迁移，不能以 C# 编译通过代替兼容测试。
- **推荐**只在确有值语义、大小和复制成本合理时用 `struct`，避免可变大结构体和装箱；`class` 与 `struct` 选择不得只看“是否使用 new”。

### 4.14 注释、死代码与技术债

- **必须**删除已失效实现、注释掉的旧代码、不可达分支和未使用成员；历史交给版本库，不以“以后可能用”保留整段备用实现。
- **推荐**注释解释原因、业务约束和非直观取舍，而非复述赋值/循环；对外复杂接口用 XML 文档说明契约。修改逻辑时同步更新关联注释、测试与文档。
- **必须**临时 `TODO` / `FIXME` 关联负责人、跟踪项和计划处理版本；影响正确性/安全性的已知缺陷不能用 TODO 代替阻断合入，其他例外走既定评审流程。
- **禁止**为消除告警随意加 `#pragma warning disable`、忽略分析器或扩大可见性；必要抑制须最小范围、说明理由并可追踪。
- **推荐**重构由真实修改点或重复缺陷驱动，保持行为并补测试；避免把功能需求夹带成全模块改写，提交边界见 §12.2。

### 4.15 资源所有权与可恢复清理

- **必须**为事件、定时器、取消源、文件流、原生缓冲区、资源加载句柄与池化对象指定唯一释放/归还责任；可用 `using` / `try-finally` / 生命周期登记表保证成功、失败、取消路径均清理。
- **必须**明确池对象租借后的初态与归还后的复位项（回调、数据 ID、动画、显隐和请求版本）；禁止重复归还、归还后访问、旧回调修改已复用对象。
- **必须**让可重复进入的清理方法按契约幂等；资源加载与释放使用管理系统配对 API，禁止只 `Destroy` 实例却遗留加载句柄或在共享资源仍被使用时提前释放。

### 4.16 最小示例：可测试的计算契约

以下为独立普通 C# 示例：只计算、不扣款/发奖；失败时 `totalCost` 为 0、返回明确原因，成功才输出结果。真正购买由服务层按 §4.10 / §10.3 提交，不能把“算出价格”当作“购买成功”。

```csharp
public enum CostFailure
{
    None = 0,
    InvalidUnitPrice = 1,
    InvalidQuantity = 2,
    Overflow = 3
}

public static class PurchaseCostCalculator
{
    public static bool TryCalculate(long unitPrice, int quantity,
        out long totalCost, out CostFailure failure)
    {
        totalCost = 0;
        failure = CostFailure.None;

        if (unitPrice < 0)
        {
            failure = CostFailure.InvalidUnitPrice;
            return false;
        }

        if (quantity <= 0)
        {
            failure = CostFailure.InvalidQuantity;
            return false;
        }

        if (unitPrice > long.MaxValue / quantity)
        {
            failure = CostFailure.Overflow;
            return false;
        }

        totalCost = unitPrice * quantity;
        return true;
    }
}
```

| 单价 | 数量 | 预期 | 验证点 |
| --- | --- | --- | --- |
| `100` | `3` | 成功，`300` / `None` | 正常计算 |
| `0` | `1` | 成功，`0` / `None` | 免费商品不等于非法价格 |
| `-1` | `1` | 失败，`0` / `InvalidUnitPrice` | 非法单价 |
| `100` | `0`、`-1` | 失败，`0` / `InvalidQuantity` | 数量边界 |
| `long.MaxValue` | `1` | 成功，`long.MaxValue` / `None` | 合法上界 |
| `long.MaxValue` | `2` | 失败，`0` / `Overflow` | 乘法溢出 |

（示例合并展示便于阅读，落地时枚举与类按 §2.3 分文件；具体商品限购/价格上限仍须由业务规则校验。）

## 5. Unity 生命周期与组件

| 回调 | 职责 | 禁止 |
| --- | --- | --- |
| `Awake` | 自身引用缓存、内部状态初始化 | 访问其他组件状态、访问配置表 |
| `OnEnable` | 注册事件、订阅广告/网络回调 | 重复注册（须与 OnDisable 严格配对） |
| `Start` | 依赖外部数据的初始化、首屏刷新 | 同步加载大资源、阻塞启动 |
| `Update` | 输入、状态推进 | 分配、查找、IO、协议请求 |
| `LateUpdate` | 布局后置刷新、安全区重算 | 业务逻辑 |
| `OnDisable` | 反注册、停止/取消本次启用周期的任务 | 假设禁用组件会自动停止所有协程或 async 任务 |
| `OnDestroy` | 释放自身拥有的资源、清除外部持有的引用 | 访问已销毁对象、承担无法恢复的唯一存档职责 |

- **必须**事件「注册 / 反注册」成对写在同一文件相邻位置，`+=` 与 `-=` 一一对应。
- **必须**处理 `OnApplicationPause` / `OnApplicationFocus`：暂停计时与音频、记录弹窗栈与进行中状态；回前台**必须**重新校验会话、配置版本与广告/内购结果，禁止假设状态仍有效。
- **必须**在 Player Settings 锁定竖屏方向；**禁止**运行时横竖屏切换，也禁止用整体缩放掩盖方向问题。
- **必须**处理激励视频 / 插屏 / 内购界面打断：打断前保存进度，恢复后重新判定弹窗栈，禁止奖励重复发放或界面叠两层。
- **禁止**在 `Awake` 依赖脚本执行顺序；需要顺序用显式初始化器。
- **必须**对前后台回调去重；移动端进程可能被直接终止，关键进度应在业务检查点持久化，禁止仅依赖 `OnApplicationQuit` / `OnDestroy` 保存。SDK 交易恢复由服务层接管，见 §4.7 / §10.3。
- **禁止**用 `DontDestroyOnLoad` 常驻对象承载业务状态；跨场景数据走明确的服务层/持久化。
- **推荐**组件只做一件事；单一 `MonoBehaviour` 同时管 UI、网络、数据视为需拆分。

## 6. UI / UPF 面板规范（竖屏休闲项目核心）

> 本节以通用 UI 框架为对象。文中 `UPF` 代表项目所选的 UI 框架占位，其基类、生成命令、目录名按 §15.4 替换，不假设任何具体在研工程的实现。

### 6.1 绑定与生成边界

- **必须**采用**静态 Prefab + Inspector 绑定**：结构、引用、初始显隐在 Prefab 里定死，运行时只做数据填充与状态切换。
- **禁止**运行时 `new GameObject` 拼装界面树、`Transform.Find("xxx")` 按名字查找、`Resources.Load` 加载面板。
- 动态生成仅限列表单元（Cell），且**必须**走对象池 + 复用，禁止每条数据新建节点。
- **推荐**绑定代码由 UI 生成链产出，手写逻辑只放 `partial` 扩展文件；二者放同一模块 asmdef 下的不同目录，生成目录禁止手写。若框架采用独立绑定对象而非 `partial`，按其组合契约接入；生成文件被覆盖不算缺陷，改生成器/描述源才是修复。
- Prefab 中**禁止**残留断链引用（Missing Script / 空字段）；提交前用编辑器批量扫描工具校验。
- **禁止**把渠道差异、SDK 差异写进 Prefab；差异由适配层在运行时注入。

### 6.2 竖屏适配与安全区（必须逐项验收）

| 项 | 规则 |
| --- | --- |
| 设计基准 | 全工程唯一：竖屏 1080×1920（或立项基准），CanvasScaler `ScaleWithScreenSize` + 明确 Match 值 |
| 安全区 | 用统一 SafeArea 适配组件读取 `Screen.safeArea`；**交互元素必须在安全区内**，纯背景可延伸到安全区外 |
| 顶部 | 刘海 / 挖孔 / 状态栏遮挡区禁止放可点击控件与关键信息 |
| 底部 | Home 手势条 / 导航栏区域禁止放主操作按钮；主按钮上移并留出安全边距 |
| 宽高比 | 至少覆盖 20:9、19.5:9、18:9、16:9、4:3（或立项范围）；范围外**必须**给降级布局而非裁切 |
| 锚点 | 顶部/底部元素分别锚定，中部用自适应布局；**禁止**绝对坐标与固定高度硬编码 |
| 缩放 | **禁止**整体 Scale 拉伸 UI 来"适配"；禁止为长屏单独切一整张全屏背景大图 |
| 单手操作 | 高频按钮置于屏幕下半部可达区；点击热区不小于项目基准（建议 ≥ 88×88 设计像素） |
| 文本 | 字号随缩放、支持多行与自适应；**必须**用最长语言文案做溢出用例，禁止固定宽度单行硬编码 |

- **必须**为安全区适配提供统一组件/基类，禁止每个面板各写一套 `Screen.safeArea` 计算。
- **必须**在真机长屏、小屏、刘海屏三类机型上核对主界面、结算弹窗、商店页与底部按钮栏。

### 6.3 面板栈与弹窗队列

- **必须**统一 `Open → Refresh → Close` 三段式；`Open` 只负责显示与首刷，`Close` 负责反注册、停止动画/协程、归还池对象。
- **必须**参数用强类型结构体 / 参数对象传递，禁止 `object[]`、全局静态变量、字符串字典传参。
- **必须**弹窗由统一栈管理，业务面板**禁止**自行改 `sortingOrder`、Canvas 排序或射线阻挡。
- **必须**处理同时到达的多个弹窗（登录奖励 / 活动 / 结算 / 广告奖励）：按优先级串行排队弹出，禁止互相覆盖、禁止同时弹两层奖励。
- **必须**面板重开时状态完全复位（滚动位置、选中态、红点、输入、动画进度）。
- **必须**面板关闭后异步回调先判活再刷新；动画播放期间加操作锁，禁止连点重复触发。
- **必须**激励视频 / 插屏 / 内购 / 切后台打断后，弹窗栈可恢复且奖励只发一次（配合 §4.4 幂等）。
- **推荐**弹窗优先级、遮罩规则、关闭策略由框架配置表统一定义，业务只声明优先级。

### 6.4 列表、图集与重建

- **必须**长列表（关卡、排行榜、背包、商品）使用虚拟化/循环复用；容器尺寸、锚点、滑动方向在 Prefab 中固化。
- **必须**只在数据变更或可见区变化时重建 Cell，禁止每帧 `SetActive` / 重建布局。
- **禁止**在 Cell 的 `Update` 做布局计算；禁止嵌套多层 `ContentSizeFitter` + `LayoutGroup` 造成布局重建风暴。
- **必须**按面板/弹窗分图集，通用控件抽公共图集；**禁止**一张全局大图集常驻内存。
- **必须**动静分离 Canvas，透明度变化用 `CanvasGroup`；**禁止**全屏透明遮罩叠多层、多层全屏 Sprite 叠底。
- **推荐**列表数据索引化，滚动回调只更新差异项；改动面板生成逻辑后**必须**全量重生成 + 面板回归。

### 6.5 交互与文案

- **必须**所有可点击控件有明确禁用态表现，网络/广告/内购进行中给出可见状态，禁止仅逻辑拦截无视觉反馈。
- **必须**处理连点与重复点击（防抖 / 操作锁），关键写操作全程只发一次请求。
- **必须**玩家可见文案走本地化 Key，禁止在代码中硬编码中文字符串；数值格式化使用统一工具。
- **推荐**UI 动效时长与可跳过方式统一，禁止因动画阻塞首次可交互时间。

## 7. 配置数据（Luban）

> 定位：竖屏休闲项目表数量少、迭代快、活动与数值需热更或远程覆盖。**随包表是基础真值，远程配置是覆盖层**，两者都受本节约束。

### 7.1 生成与来源

- **必须**以 schema / 源表为唯一真值；生成代码与生成数据**禁止**手工编辑。
- **必须**源表与生成产物同 Changelist 提交，并注明生成器版本；版本升级需全量重生成。
- **必须**生成流程由统一命令或 CI 复现，**禁止**产物中出现本机绝对路径、个人账号或本地时间戳。
- **必须**为配置访问提供统一入口（表管理器 + 远程覆盖层），**禁止**业务代码直接读生成类静态表并各自兜底。
- **禁止**运行时修改配置对象；派生数据请复制或建视图模型。

### 7.2 表设计

- **必须**一表一职责；数值型内容（关卡、奖励、商店、活动、掉落）入表；类型/枚举与程序结构由代码/schema 定义，禁止用任意数字表驱动隐藏的代码分支。UI 初始布局/引用在 Prefab 中固定，弹窗优先级等稳定规则可集中配置，禁止将“UI 参数一律不准配置”与 §6.3 混为一谈。
- **必须**UI 文案走本地化表，**禁止**塞进业务数值表。
- **必须**活动 / 实验配置带生效时间、版本区间、渠道与灰度比例字段，客户端只做展示与判定资格，**最终发奖由服务端确认**。
- **必须**枚举独立类型，ID 规则与外键明确；可空字段显式默认值 + 注释。
- **禁止**把随版本变化的平衡性数值写死在 C# 常量里；禁止 `param1..param8` 万能字段。

### 7.3 校验、热更与离线

- **必须**加载阶段校验：主键唯一、外键存在、枚举合法、数值区间、必填非空、活动时间区间不冲突；开发/测试环境校验失败**必须**报错中断，禁止静默跳过。
- **必须**离线可玩：进入主界面与核心玩法所需配置**全部随包**，**禁止**启动时强依赖网络拉取配置。
- **必须**远程覆盖失败、超时或数据非法时，**静默回落随包表**并上报一次告警；**禁止**白屏、空列表或卡启动。
- **必须**配置与热更带版本号与兼容策略：新增字段定义旧版本可理解的缺省语义，改名/改类型先兼容读取并迁移，删除字段在确认最低支持版本不再依赖后进行；**禁止**直接变更 schema 导致旧包/旧存档崩溃。
- **禁止**热更中途覆盖正在使用的配置文件；覆盖前完成校验，失败可回滚。
- **推荐**为每张表配最小校验用例（含边界行与非法行），随 CI 在每次生成后执行。

### 8.3 Prefab 与场景

- **必须**Prefab 编辑在 Prefab Mode 进行；修改前在版本库独占加锁，禁止并行改同一文件。
- **必须**Prefab 嵌套层级扁平稳定；**禁止**运行时通过名字路径访问嵌套节点。
- **禁止**提交调试用 GameObject、空脚本、断链组件、临时材质；测试场景统一放 `Assets/EditorScenes/` 且不参与打包。
- **推荐**一个面板/弹窗一个明确 Owner，减少多人同时改同一 Prefab 的冲突面。

### 8.4 资源分包与地址

- **必须**通过统一资源管理系统（Addressables / AssetBundle）按路径或标签寻址，**禁止**新增 `Resources/` 目录下资源。

- **必须**多渠道包（Android 渠道 / iOS / 小游戏等）共用同一套资源与配置；渠道包名、签名、密钥由 CI 注入，**禁止**入库。

## 9. 性能、内存与包体

### 9.1 帧预算

| 指标 | 目标（中低端真机） |
| --- | --- |
| 平均帧率 | ≥ 项目目标帧率（60 fps，低端机降级策略明确） |
| 主线程单帧 | 不超过帧预算的 70% |
| 每帧托管堆分配 | 稳态 0 B |
| GC 触发 | 滚动、弹窗动画等连续交互期间 0 次 |
| 启动到主界面可交互 | 按立项基线，逐版本对比不得劣化 |
| 弹窗打开到可点击 | 按立项基线，不得因同步加载或动画阻塞 |

- **必须**新增每帧逻辑同步给出耗时/分配评估；归档设备、场景、样本时长与 Profiler 证据。Deep Profile 仅用于定位，其开销会改变耗时，禁止将深剖面数据直接当作最终性能验收基线。
- **禁止**以"编辑器不卡"或单一机型作为验收结论。

### 9.2 内存

- **必须**建立内存基线（PSS / Unity Profiler 分项：UI 图集、纹理、托管堆、音频）。
- **必须**评估大对象、图片、协议缓冲区的大小、分配频率与存活期；高频分配优先复用/池化，低频对象不强制池化，池容量与清理策略见 §4.12。禁止无业务需要地长期保留大数组，亦禁止为减少分配制造更高的常驻内存。
- **必须**静态集合、事件中心、单例中的对象引用在销毁时移除。
- **禁止**无上限增长的缓存（头像、排行榜快照、日志、历史记录），必须有 LRU / 数量上限。
- **推荐**切后台释放可重建缓存，对低内存回调做降级；休闲项目频繁前后台切换，此项必须验证。

### 9.3 渲染与 UI 重建

- **必须**控制 DrawCall / SetPass 与 Overdraw；移动端禁用非必要实时阴影与全屏后处理。
- **必须**避免 `Canvas` 整体重建：动静分层，禁止频繁改 `Color.alpha`（用 `CanvasGroup`）。
- **禁止**对不可见 Cell 做动画、粒子、逐帧刷新。

### 9.4 启动与热更

- **必须**启动流程分阶段且可观测（SDK 初始化 → 随包配置加载 → 资源校验 → 账号/远程配置（非阻塞）→ 主界面）；首屏前禁止同步加载大资源。
- **必须**广告 / 埋点 SDK 初始化延后或异步，禁止阻塞首次可交互；远程配置拉取**禁止**作为进入主界面的前置条件。
- **推荐**启动期预热高频 Shader / 对象池，避免首次打开弹窗卡顿。
- **必须**热更具备版本号、断点续传、校验与失败回滚。

## 10. 网络、协议、存储与安全

### 10.1 网络与联网权威边界

- **必须**协议层与业务层隔离：协议结构由生成流程产出，业务禁止直接拼字节流或手改协议类。
- **必须**每个请求有超时、重试上限与退避；只对可重试错误自动重试，写操作须有幂等键且重试复用同一键。超时是“结果未知”而非“服务端必然未执行”，禁止直接新建订单重试或仅凭超时回滚已到账资产。
- **必须**明确离线可用范围：本地关卡/进度不依赖网络；云同步、活动领奖、广告与支付按各自联网契约处理，给出不阻断核心玩法的状态反馈。仅支持重放的操作进入有容量、有效期与冲突策略的持久化队列，恢复后按业务顺序同步，禁止把所有失败请求盲目排队重发。
- **必须**处理断线重连与回前台：重连后重新同步状态，禁止沿用旧会话缓存直接下发操作。
- **必须**服务端返回值做范围/合法性校验，禁止未校验数据直接写入 UI 或存档。

### 10.2 存档完整性与迁移

- **必须**本地存档带版本号、完整性校验与可测试的迁移路径；校验和只能帮助发现意外损坏，不等于防作弊。未来版本存档/未知字段须有保留或拒绝策略，禁止旧客户端误读后覆写。
- **必须**使用平台支持的原子替换或“临时文件 + 校验 + 替换/备份”等经验证的可恢复写入方案；不能先删除唯一好档再写新档。业务检查点及时落盘，不能依赖退出回调必定到达。
- **必须**读档失败时保留原文件和诊断线索，优先尝试最近有效备份、迁移恢复或云恢复；恢复未完成时禁止自动保存覆盖坏档。使用默认档须区分真正新用户与恢复失败，并有明确产品确认/隔离写入策略，禁止静默清空玩家进度。
- **必须**迁移在副本/暂存数据上执行、成功后再提交，失败可恢复且重复执行不破坏数据；云同步按数据类型定义版本、冲突与合并规则，禁止一律“最后写入覆盖”导致资产回退或重复领取。
- **禁止**将 `PlayerPrefs` 当作关键资产、交易记录或凭证的唯一安全存储；本地加密也不能让客户端成为支付的可信权威端。

### 10.3 发奖、扣费与补单

- **必须**在产品/服务端契约中明确权威归属：本地关卡奖励可由本地事务提交；联网活动奖励、广告权益与内购发货以服务端验证结果为最终态。离线可玩不等于支付和联网奖励必须离线完成；未配置相应服务端能力时须先评审调整产品范围，不能悄悄用本地回调代替验证。
- **必须**奖励/购买流程有持久化的操作或交易 ID、处理中/已完成状态与恢复入口；到账记录、扣费和奖励变更应原子提交或由可恢复日志保证一致。`_isClaiming`、按钮防抖和进程内 `HashSet` 不能单独保证重启后的幂等。
- **必须**重复回调/重复请求返回已有处理结果，不再次扣费或发奖；失败、取消、超时与“结果待确认”分别处理。补单须覆盖应用被杀、回调丢失、回前台和重复投递，并按 SDK/平台要求完成确认，不能仅绑定在当前面板上。
- **推荐**关键写操作给出“处理中”反馈；乐观展示须可纠正，且不能把未确认资产作为后续可消费余额、生成不可回滚结果或冒充最终成功。

### 10.4 凭证、隐私与发布安全

- **禁止**在代码、配置表、Prefab、日志中硬编码密钥、长期 Token 等秘密；构建签名/服务端凭证由安全的 CI/服务端管理。注入到客户端包中的值仍可被提取，CI 注入不等于保密；公开 API 地址和非秘密 SDK 标识可配置化管理，不应与密钥混淆。
- **禁止**记录玩家隐私（设备标识、手机号、支付信息、聊天内容）到日志与埋点；广告/埋点 SDK 采集范围按上架地区合规要求评审，儿童向内容从严。
- **必须**远程配置、资源与热更经可信传输与完整性校验；涉及信任判定时校验签名/可信元数据及版本约束，普通哈希不能代替来源认证。生产包保持证书校验，禁止保留任意信任证书的调试实现。

## 11. 日志、异常与可观测性

| 级别 | 用途 | Release 行为 |
| --- | --- | --- |
| `Verbose/Debug` | 开发期链路追踪 | 编译剔除或关闭 |
| `Info` | 关键流程节点 | 采样或关闭 |
| `Warning` | 可恢复异常、远程配置回落 | 保留 + 上报 |
| `Error` | 功能失败、数据错误 | 保留 + 上报 |
| `Fatal` | 崩溃前、不可恢复 | 保留 + 上报 |

- **必须**使用统一日志门面，**禁止**业务代码散落 `Debug.Log` 无上下文文本。
- **必须**日志带模块标签 + 关键 ID（关卡 / 奖励 / 配置行 / 交易单号），禁止 `here`, `111`, `test`。
- **必须**为发奖、内购、远程配置回落、广告回调建立可追踪链路，一次操作一个关联 ID。
- **禁止**逐帧/高频打日志；循环内日志**必须**限流或聚合。
- **必须**异常上报携带版本、渠道、设备、场景与最近关键操作；禁止把控制台完整堆栈作为唯一手段。
- **禁止**临时调试日志与 GM 指令留在 Release 主干。

## 12. Perforce (P4) 版本管理

> 面向小团队、高频迭代的竖屏休闲项目。本节不假设任何具体 depot / stream 命名与本机工作流；命名按 §15.4 替换。若项目改用 Git，见 §12.6 映射。

### 12.1 流与分支策略

- **推荐**轻量结构：主干（日常迭代）+ 发版分支（提审/灰度）+ 紧急修复分支；每次提审包打标签（Label），便于回溯与回滚。
- **禁止**长期存在的个人分支；**必须**至少每日同步一次主干，避免大合并。
- **必须**发版分支只收缺陷修复，新功能只进主干；禁止在发版分支直接改配置 schema 或面板生成逻辑。

### 12.2 Changelist 规范

```
[模块][类型] 一句话描述（≤ 50 字）

问题/需求：<原因或需求单号>
方案：<关键实现与取舍>
验证：<格式与分析器 / 编译 / 自动化测试 / 按风险补充生成链、面板、真机证据；不适用项说明原因>
影响：<受影响模块、是否需重新生成 / 配表 / 资源 / 热更版本>
例外：<条款号 + 原因，无则填 无>
```

- **必须**一个 CL 对应一个可独立回滚的逻辑变更；**禁止**格式化、重构、功能修复混提。
- **必须**同时提交脚本 + `.meta` + 相关 Prefab / 场景 / 配置源表 / 生成产物，禁止拆成多个 CL 造成中间版本编译失败。
- **禁止**提交 `Library/`、`Temp/`、`Logs/`、`obj/`、IDE 用户配置、个人临时文件；忽略规则由工程统一维护。
- **禁止**提交二进制资源时未标注来源与导入设置变更。
- **推荐**活动/数值类高频改动单独 CL，便于灰度与回滚。

### 12.3 锁、冲突与 UI 协作

- **必须**对场景/Prefab/图集/配置源表按团队锁策略独占编辑，二进制及不宜语义合并的资产启用文件锁；`.asmdef` 为 JSON，`.asset` 等可能为 YAML，不能一概视为不可文本合并。可合并文件经人工复核并验证依赖/引用，策略由版本库配置明确。
- **必须**一个面板/弹窗一个明确 Owner，UI 改动提前在协作频道通告；**禁止**并行改同一 Prefab。
- **必须**冲突时先与对方确认语义再合并，禁止 `Accept Theirs` / 覆盖式强制解决。
- **必须**合并后重新生成 + 编译 + 面板回归，禁止"能编译就提交"。
- **推荐**大范围重构（改生成器、批量重命名、目录调整）选低峰期提交并提前通告。

### 12.4 提交前动作

1. `p4 sync` 到最新，确认无待解决冲突。
2. 手写代码变更执行编译、格式与静态分析（0 Error，无未获批准的新增 Warning）；涉及绑定/schema/源表/生成器时重跑对应生成链，确认源与产物一致；纯文档变更执行文档结构/引用检查。
3. 涉及 UI 时打开并关闭受影响面板/弹窗，检查断链引用、安全区、状态复位与弹窗队列；涉及资源导入/生命周期/SDK/性能时补目标平台验证。
4. 按 §13 执行单测、回归、必要的配对测试与风险对应的真机验证，记录结果，不适用项须说明原因。
5. 用 `p4 opened` / diff 逐文件复核，**必须**确认无调试开关、临时日志、本机路径、渠道密钥夹带。
6. 涉及热更资源或配置时，**必须**在 CL 中记录版本号。

### 12.5 多渠道构建

- **必须**构建参数（包名、签名、渠道 ID、SDK 开关）由 CI 注入，禁止写入仓库或 Prefab。
- **必须**各渠道共用同一套资源、配置与代码；差异只允许存在于隔离的适配层配置。
- **推荐**提审包与灰度包的资源/配置版本可回溯到 CL 与 Label。

### 12.6 若项目改用 Git（选型替换映射）

| P4 条款 | Git 等价做法 |
| --- | --- |
| 独占锁 | Git LFS 文件锁 + `CODEOWNERS`，同一 Prefab 禁止并行改 |
| Changelist | 单个 PR / Commit，沿用 §12.2 描述模板 |
| Stream / Label | 主干 + 发版分支 + Tag |
| `.p4ignore` | `.gitignore` + `.gitattributes`（二进制标记 LFS） |
| `p4 opened` / diff | `git status` / `git diff --cached` |

**说明**：选型由立项评审决定，本规范只约束"怎么做"，不锁定工具。切换工具时以上映射逐条落地，其余条款不变。

## 13. Code Review 与测试验证

### 13.1 Review 要求

- **必须**每个 CL 至少 1 名 Reviewer；涉及 UI 框架、生成器、协议、配表 schema、发奖链路、性能热路径的变更需模块 Owner 复核。
- **必须**Review 覆盖适用项：职责/依赖方向、接口契约与可读性、复杂度与重复规则、状态校验、数据一致性/幂等、异步竞态、资源所有权、数值/时间边界、测试有效性，以及 UI/生成/性能/发布相关约束。
- **推荐**Reviewer 用 §14 清单逐项打勾；涉及适配或打断的改动附真机录屏 / Profiler 证据。
- **禁止**以「能跑就行」「先合再改」放行含 §0 红线的改动。
- **必须**Review 结论区分阻断缺陷、需说明的风险和个人风格建议；已有格式/命名工具可检查的问题不反复人工争论。阻断项须解决并复核，超阈值例外须附原因、Owner 与补偿性测试/监测措施。

### 13.2 测试

- **必须**新增/修改核心规则时提供 EditMode 单测（配置校验、状态迁移、发奖幂等、数值计算、远程覆盖回落）；面板栈、组件生命周期与场景交互使用 PlayMode 或等价自动化；SDK/IL2CPP/原生差异补目标平台测试。测试范围随风险变化，纯文档修改不强制跑全量真机。
- **必须**重构状态机或替换算法时保留行为基线并做同输入配对测试；新增功能按需求定义期望结果，修复缺陷须证明旧版本错误、新版本正确，禁止把旧缺陷当作必须保持的正确基线。
- **必须**覆盖受影响规则的正常/拒绝/异常路径，以及适用的空数据、上下界/溢出、重复调用、取消、超时、关闭后回调、乱序响应、断网恢复和读写失败；发奖/购买须验证重启补单仍不重发，不能只测按钮防抖。
- **必须**测试断言可观察结果及关键副作用（状态、余额、事件次数、持久化次数），而非仅“未抛异常”或照抄实现；测试彼此独立，时间/随机/网络可控，禁止用任意 `Sleep` 等待和反复重跑掩盖不稳定用例。
- **必须**可自动化的缺陷修复补充“修复前失败、修复后通过”的回归用例；平台/人工条件限制无法自动化时，记录可复现步骤、原因与替代验证证据。
- **必须**UI/适配改动及发版回归执行竖屏真机矩阵：长屏（≥19.5:9）、刘海/挖孔屏、小屏（16:9 或 4:3）、中低端 Android 一台、iOS 一台；生命周期/SDK/网络改动补弱网/离线、切后台、广告打断与回前台。平台范围以立项支持清单为准。
- **必须**UI/本地化改动核对受影响页面的安全区和文本溢出；发版覆盖主界面、结算、商店、底部按钮栏与最长语言文案。

### 13.3 质量检查与 CI 门禁

**必须**执行基础质量检查；CI 用于自动阻断，不代表没有 CI 就可以免检。暂未自动化的检查由责任人提供可复核结果，并登记自动化落地计划。禁止声称“工具通过”却不记录执行命令/工具版本、结果与报告位置。

| 阶段 | 检查项 | 不通过时 |
| --- | --- | --- |
| 提交/合入：手写代码 | 目标配置编译、格式、静态分析、相关自动化测试、敏感信息扫描 | 编译错误/测试失败/未批准的新增诊断阻断；超复杂度触发线须重构或批准例外 |
| 合入：配置/绑定/资源 | 重生成与源/产物一致性、表校验、Prefab 断链/漏绑扫描、资源导入检查 | 非法配置、断链、产物不可复现阻断 |
| 合入：构建/SDK/平台 | 受影响平台或渠道的构建；发布宏与调试能力剔除验证 | 构建失败、生产包含可用安全旁路阻断；关键词扫描仅作辅助，不能替代构建验证 |
| 每日/定期构建 | PlayMode/机型冒烟、内存/帧率、包体增量、适配截图比对 | 超预算或回归失败必须排查，确认风险前不得进入发版候选 |
| 发版前 | 支持平台 IL2CPP/AOT 构建与真机、离线启动、存档迁移/恢复、广告/内购沙箱与补单、隐私合规、回滚预案 | 关键链路失败或未验证阻断发版 |
| 纯文档 | Markdown 结构、章节引用、示例及变更记录检查 | 无效引用/错误示例修正后合入，不要求无关的全量客户端回归 |

### 13.4 静态分析、指标与基线

- **必须**将 `.editorconfig`、分析器/规则版本、严重级别、构建配置和忽略范围纳入版本控制；选用兼容当前 Unity 编译链的工具，不以个人 IDE 告警代替统一检查结果。
- **必须**把编译错误、程序集循环依赖、明确的安全/正确性错误与未处理资源泄漏作为阻断项；格式/命名可由工具修正。分析器发现的问题需结合语义复核，规则抑制按 §4.14 执行。
- **必须**对存量问题建带 Owner 的基线，新增/修改的手写代码不得无批准地增加同类问题；禁止反复刷新基线掩盖新增问题。生成代码、SDK 与第三方代码可排除风格/复杂度统计，但不能排除构建、安全和真实运行错误。
- **推荐**对新增/修改的纯业务规则，以行覆盖率 ≥ 80%、分支覆盖率 ≥ 70% 作为初始观察目标，落地时按工具能力与风险调整；核心资产/状态迁移的关键路径须逐项测试，不能用覆盖率均值抵消漏测。生成/第三方代码不计分母，禁止为达标写无有效断言的测试。
- **必须**联合看待测试结果、复杂度（§4.9）、重复规则、诊断增量和运行预算；任何单一数字达标都不等于代码正确。达成指标优先改善设计和测试，禁止只移动代码、改统计范围或降低门槛。

### 13.5 小团队落地顺序

| 优先级 | 最小落地内容 | 完成证据 |
| --- | --- | --- |
| 首批：立即执行 | 统一格式/编译规则、职责边界、基础单测、人工 Review、缺陷回归 | 仓库内规则文件、统一执行命令、首批测试与评审记录 |
| 次批：自动化阻断 | CI 编译/单测/分析器、生成一致性、配置/Prefab 校验 | 失败提交能被阻断；存量诊断有基线与 Owner |
| 持续：风险量化 | 覆盖率趋势、复杂度、真机性能/包体、补单与坏档恢复演练 | 可对比的报告、预算、回滚/恢复记录 |

**必须**在项目补充约定中为每项门禁写明负责人、适用范围、工具版本、执行命令、失败判定、报告位置与计划日期；分阶段的是自动化能力，不是正确性/数据安全底线。

## 14. 自检清单

## 15. 附录

### 15.1 术语

| 术语 | 说明 |
| --- | --- |
| UPF | 项目所选 UI 框架的占位名，负责面板栈、Prefab 绑定与生成链；不指任何具体在研工程实现 |
| 生成链 | 从面板描述、Luban schema 到 C# 代码与资源的自动生成流程 |
| 随包表 / 远程覆盖 | 随包表为基础真值，远程配置为带版本号的覆盖层，失败回落随包表 |
| 弹窗栈 | 统一管理面板/弹窗层级与排队顺序的机制 |
| 安全区 | `Screen.safeArea` 定义的可交互区域，需排除刘海、挖孔与底部手势条 |
| 配对测试 | 同一输入在改动前后各执行一次，比对输出差异的验证方式 |
| 静态绑定 | 引用关系在 Prefab 中固化、通过 Inspector 赋值 |
| 契约 | 接口对输入、输出、失败、状态修改及适用的线程/生命周期行为的约定 |
| 幂等 | 同一操作重复执行不重复产生业务效果；资产流程须覆盖持久化、重试与重启恢复 |
| 资源所有权 | 谁创建/租借、谁使用、谁最终释放/归还的明确责任 |
| 圈复杂度 | 对独立控制流路径数量的度量，工具/版本统一后用于识别评审与测试风险 |
| 质量门禁 | 合入/发版必须满足的检查及失败阻断规则；不是代码质量的单一分数 |

### 15.4 落地时的三处占位替换

本文件刻意不绑定任何具体工程。新项目落地需替换以下三类占位，并在项目补充约定中确认性能预算、联网权威边界与质量门禁的工具/阈值，不能只替换框架名字就视为完成：

| # | 占位 | 需替换为 | 影响章节 |
| --- | --- | --- | --- |
| 1 | `UPF` / `PanelBase` / `PopupBase` / `Scripts/Generated/` | 项目实际 UI 框架名、面板基类、绑定生成命令与产物目录 | §2 §6 §12.4 |
| 2 | `TbLevel` 等表名 / schema 目录 / 生成器版本 / 远程配置地址 | 项目实际 Luban schema 目录、表清单、生成器版本、覆盖层接口 | §3.3 §7 §12 |
| 3 | 主干 / 发版分支 / depot / stream / 渠道清单 | 项目实际版本库命名、分支策略、渠道与 CI 参数 | §12 §8.4 |

**禁止**把本机路径、个人账号、具体在研工程的模块名或缺陷单号写进本文件；项目特有约定请放工程内的补充约定文件，并在本文件版本记录中登记引用。

> 本规范是活的文档：线上问题优先止损、恢复与修复；复盘时补齐「根因 → 条款 → 测试/检查项」，避免为补文档延误处理，也避免只加禁令、不补验证。

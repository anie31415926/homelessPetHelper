## 约束词定义

| 词 | 含义 |
| --- | --- |
| **必须** | 强制。Code Review 不通过则拒绝合入 |
| **禁止** | 强制不允许。出现即视为缺陷，需立即整改 |
| **推荐** | 默认采用；偏离需在提交说明中给出理由 |
| **可** | 允许自行选择，保持同一模块内一致即可 |

**优先级链**：崩溃/数据错误 > 线上安全与合规 > 性能与内存 > 可读性与一致性 > 个人编码习惯。冲突时按此链取舍。

**例外流程**：确需偏离本规范时，在 Changelist 描述中写明 `例外条款号 + 原因 + 影响范围 + 回退方案`，经模块 Owner 与至少一名 Reviewer 同意；例外仅限单次提交，不自动继承。

## 0. 一页速查（提交前红线）

1. 生成代码（UPF 面板绑定、Luban 表与产物）**禁止手改**，改动只能回到生成源 / 生成器。
2. 任何 `TryXxx` / `DoXxx` 业务接口，**必须**先校验完整前置状态，禁止靠"调用另一个接口"隐式推进状态。
3. **禁止**提交任何绕过校验的调试开关（含强制广告成功、强制内购成功、强制实验分支），调试能力用编译符号隔离且默认关闭。
4. `Update` / `LateUpdate` / 每帧回调中**禁止**托管堆分配：无 `new`、无字符串拼接、无 LINQ、无闭包、无装箱。
5. UI **必须**静态 Prefab + Inspector 绑定；**禁止**运行时按名字查找、`new GameObject` 拼界面、`Resources.Load` 加载面板。
6. 竖屏安全区（刘海 / 挖孔 / 底部 Home 条）与多宽高比**必须**适配；**禁止**绝对坐标与整体缩放式"适配"。
7. 弹窗队列、激励广告、内购、切后台回调**必须**处理打断、重入与恢复，奖励只发一次。
8. 事件、协程、定时器、对象池租借、弹窗注册**必须**成对登记与释放。
9. 配置（随包表 + 远程覆盖）**必须**有版本兼容与失败降级，远程失败**禁止**导致白屏或空列表。
10. 资源**必须**带导入设置；`.meta` 同进同出；场景 / Prefab / 图集 / 配置源表**必须**独占加锁编辑。
11. Release 包**禁止**输出隐私、密钥、协议原文，禁止保留可用 GM 指令与临时调试日志。
12. 提交前**必须**完成编译 0 Error、面板开关、生成链重跑、配对测试、竖屏真机核对。

## 1. 总则：竖屏休闲项目的硬约束

手机平台与 PC / 编辑器环境的差异，加上休闲品类的产品形态，是本规范所有条款的根因：

| 约束 | 工程含义 | 对应章节 |
| --- | --- | --- |
| 帧预算刚性 | 60 fps 下每帧仅 16.6 ms，一次 GC 尖峰即可掉帧 | §4.6 §9.1 |
| 内存与发热 | 中低端机可用内存低、无虚拟内存换页，UI 图集与托管堆双高压 | §8 §9.2 |
| 首包与热更 | 休闲品类买量转化对包体、启动耗时极敏感 | §8.4 §9.4 |
| 竖屏适配 | 长屏 20:9 到 4:3 并存，刘海/挖孔/底部手势条，安全区必须处理 | §6.2 |
| 打断频繁 | 激励视频、插屏、内购、切后台、来电随时中断一次会话 | §5 §6.3 §10 |
| 离线可玩 | 核心玩法与启动不依赖网络，配置必须随包 | §7 §10 |
| 迭代节奏 | 小团队、活动与数值高频变更，配置需热更与灰度 | §7 §12 |

**项目基线假设**（落地时按立项评审结果覆盖）：

| 项 | 基线 |
| --- | --- |
| 设计分辨率 | 竖屏 1080×1920（或项目统一基准），CanvasScaler 策略全工程唯一 |
| 屏幕方向 | 锁定 Portrait，禁止运行时横竖屏切换 |
| 场景结构 | 单主场景 + 面板/弹窗栈，避免多场景切换丢状态 |
| 目标帧率 | 60 fps（低端机可降级到 30 fps，需明确降级策略） |
| 网络 | 核心玩法离线可玩，联网仅用于账号、排行榜、活动、广告与内购 |
| 支持机型 | 明确最低 Android / iOS 版本与宽高比范围，范围外给降级布局 |

**必须**：所有性能与适配结论以真机（至少一台中低端 Android + 一台 iOS，且覆盖长屏与小屏）数据为准，禁止以编辑器或单一机型结论代替验收。

## 2. 工程结构与程序集

### 2.1 目录约定

```
Assets/
├── Art/
│   ├── UI/Atlas/            # UI 图集，按面板/弹窗分
│   ├── UI/Frames/           # 九宫格底板、通用边框
│   └── Audio/               # BGM、SFX
├── Scenes/                  # Boot / Main（竖屏单主场景为主）
├── Prefabs/
│   ├── Panels/              # 全屏面板
│   ├── Popups/               # 弹窗：奖励、结算、广告、设置
│   └── Widgets/             # 复用控件：按钮、进度条、红点、商品卡
├── Scripts/
│   ├── Framework/           # UI 栈、事件、资源、网络、音频基础（无业务依赖）
│   ├── Generated/           # UPF 绑定 + Luban 产物，禁止手写
│   ├── Config/              # 配置访问层、远程覆盖与版本兼容
│   ├── Network/             # 协议层、连接管理
│   ├── Modules/             # Main / Level / Shop / Daily / Ad / IAP 等
│   └── Editor/              # 编辑器扩展，禁止被运行时程序集引用
├── Settings/                # URP、CanvasScaler、质量、输入配置资产
├── Plugins/                 # 广告/内购/埋点 SDK，保持原始目录结构
└── Resources/               # 原则上禁止新增，见 §8.4
```

**必须**：`Scripts/Generated/` 内文件头部保留生成标记；生成器重跑后被覆盖属预期行为。
**必须**：业务代码不得反向引用 `Editor/` 程序集；编辑器工具不得影响运行时构建产物。
**禁止**：在 `Assets/` 根目录堆放脚本、临时场景、个人测试资源。
**推荐**：竖屏休闲项目以单主场景 + 面板栈为主，避免多场景切换带来的重复加载与状态丢失。

### 2.2 程序集定义（asmdef）

- **必须**为 `Framework` / `Generated` / `Config` / `Network` / 每个业务模块 / `Editor` 建立独立 asmdef，禁止全工程默认 `Assembly-CSharp` 大杂烩。
- **必须**单向依赖：`Modules → Framework`，`Framework` 不得反向引用业务模块；跨模块通信走事件/接口。
- **必须**所有 Editor 脚本标记 `Include Platforms: Editor`，防止误打进运行时程序集。
- **必须**广告 / 内购 / 埋点 SDK 封装在独立适配层，业务模块禁止直接引用 SDK 类型（便于换渠道与打桩测试）。
- **推荐**按模块拆包缩短增量编译时间；新增 asmdef 需同步提交 `.asmdef` 与 `.meta`。

### 2.3 命名空间

```csharp
// 命名：项目.层.模块
namespace MyGame.Modules.Daily.UI
{
    public sealed class DailyRewardPopup : PopupBase { }
}
```

- **必须**与目录路径一致；一个文件一个主类型，文件名与主类型同名。
- **禁止**无业务语义的上帝类（`Utils` / `Common` / `Manager` 泛化命名需评审）。

### 2.4 生成代码边界

- `Scripts/Generated/`（或等价目录）下文件**必须**带 `// <auto-generated />` 标记。
- 生成源（UPF 面板描述 / Prefab 描述、Luban schema 与源表、生成模板配置）是唯一可修改对象。
- 生成结果不稳定时**必须**修生成器或模板，禁止在生成文件上打补丁后提交。
- 生成器版本升级**必须**全量重生成 + 编译 + 面板回归，禁止只生成单个文件。
- **禁止**生成产物中出现本机绝对路径、个人账号、本地时间戳；生成流程**必须**可由统一命令或 CI 复现，不依赖某台开发机。

## 3. 命名规范

### 3.1 C# 命名

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 类 / 结构体 / 枚举 / 委托 | PascalCase，名词或名词短语 | `DailyRewardPopup`, `RewardState` |
| 接口 | `I` 前缀 + PascalCase | `IPopupLifecycle` |
| 方法 / 属性 / 事件 | PascalCase，动词开头 | `TryClaimReward()`, `OnAdRewarded` |
| 私有字段 | `_camelCase` | `_claimButton`, `_isClaiming` |
| 序列化字段 | `_camelCase` | `[SerializeField] private Button _claimButton;` |
| 常量 / 只读静态 | PascalCase（全工程统一即可） | `MaxRetryCount` |
| 局部变量 / 参数 | camelCase | `levelId`, `popupArgs` |
| 泛型参数 | `T` / 语义前缀 | `TItem`, `TResult` |
| 协程 / 异步方法 | 协程 `XxxRoutine`，异步 `XxxAsync` | `LoadConfigAsync()` |
| 布尔 | `is/has/can/should` 前缀，禁止否定式 | `isClaimed`, 禁止 `isNotReady` |

- **禁止**匈牙利命名、拼音命名、无意义缩写（`tmp1`, `obj2`, `mgr`）。
- **推荐**用 `TryXxx` 表示可失败、无副作用的操作，返回 `bool` + `out` 结果；`Try` 方法**禁止**抛业务异常。
- **推荐**方法名体现真实行为；命名与实现不一致按缺陷处理。

### 3.2 文件、资源与资产

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 脚本 | `PascalCase.cs` | `DailyRewardPopup.cs` |
| 面板 Prefab | `Panel_<模块>.prefab` | `Panel_Main.prefab` |
| 弹窗 Prefab | `Popup_<用途>.prefab` | `Popup_DailyReward.prefab` |
| 控件 Prefab | `Widget_<用途>.prefab` | `Widget_RewardCard.prefab` |
| 场景 | `SC_PascalCase.unity` | `SC_Main.unity` |
| 贴图 | `T_<模块>_<用途>_<变体>` | `T_UI_BtnClaim_Normal` |
| 图集 | `Atlas_<模块>_<用途>` | `Atlas_Popup_Daily` |
| 九宫格 | `Frame_<用途>` | `Frame_PopupBg` |
| 材质 / Shader | `M_*` / `Sh_*` | `Sh_UI_RoundedMask` |
| 音频 | `SFX_*` / `BGM_*` | `SFX_Popup_Open` |
| 动画 / 控制器 | `Anim_*` / `AC_*` | `AC_Popup_Daily` |

- **禁止**资源名含空格、中文、版本号后缀 `_new` / `_final` / `_bak`；历史版本交给版本库。
- **禁止**同名资源放在不同目录；重命名**必须**在 Unity 内操作以保 `.meta` 与 GUID 一致。

### 3.3 Luban 表与字段

- 表名 `PascalCase` 集合语义：`TbLevel`, `TbShopGoods`, `TbDailyReward`；字段名风格全工程统一。
- ID 字段统一 `id`，引用他表统一 `<表名主键>_id`，禁止 `id1`, `target`, `ref` 等歧义名。
- 枚举字段**必须**定义独立枚举类型，禁止裸 `int` 魔法值。
- 可空/缺省字段**必须**在 schema 中显式声明默认值与注释，禁止靠运行时 `??` 掩盖配表缺失。
- **禁止** `param1..param8` 式万能字段；确有灵活参数需求用显式结构体 / 标签列表表达。

## 4. C# 编码规范

### 4.1 语言级别与格式

- 项目锁定 **Unity 2022.3 LTS；C# 9 为语言上限**，Api Compatibility Level 以 `Project Settings > Player > Other Settings` 实际配置为准。
- **禁止**使用 IL2CPP / AOT 支持不完整的特性：默认接口方法、`record` / `init` 访问器、异步流、模块初始化器、`Reflection.Emit`、`dynamic`。
- **禁止**依赖 `System.Reflection` 做热路径调用；反射仅用于启动期/编辑器期并缓存结果。
- 格式：4 空格缩进、UTF-8（无 BOM）、工程统一换行符、Allman 大括号、一行不超过 120 字符、文件末尾保留换行。
- **推荐**启用 `.editorconfig` 与 IDE 自动格式化；格式化变更与逻辑变更**必须**分两个 Changelist。
- **禁止**用 `#region` 掩盖超大类；单类超过 500 行或单方法超过 60 行需拆分或说明。

### 4.2 类型与成员设计

```csharp
public sealed class DailyRewardPopup : PopupBase
{
    [SerializeField] private Button _claimButton;
    [SerializeField] private RectTransform _cardListRoot;
    [SerializeField] private GameObject _claimedMask;

    private bool _isClaiming;
    private readonly List<RewardCard> _cards = new List<RewardCard>();
}
```

- 类默认 `sealed`；成员可见性按最小原则，禁止无理由 `public`。
- **必须**字段显式初始化或明确可空，禁止依赖默认值的隐式语义。
- **必须**用 `[SerializeField] private` 暴露 Inspector 绑定，**禁止**为方便把运行时字段 `public` 化。
- **推荐**用 `[Header]` / `[Tooltip]` / `[Range]` 描述用途，绑定缺失时给出可定位的报错。

（上例为片段示意，`PopupBase` / `RewardCard` 为占位类型，按项目 UI 框架实际基类替换，见 §15.4。）

### 4.3 Unity 对象判空

- **必须**统一使用 `if (target == null)` 判空 Unity 对象，**禁止**混用 `is null`、`?.`、`??`，避免绕过重载造成"已销毁对象仍被使用"。
- 普通 C# 对象与 `UnityEngine.Object` **必须**区分；集合中的 Unity 对象需定期清理已销毁项。
- **推荐**外部入参在方法入口断言，把错误暴露在链路起点而非深层。

### 4.4 状态校验与接口边界（高风险条款）

- **必须**为每个业务操作定义前置状态集合并在入口统一校验。例：领取奖励需覆盖「不可领 / 可领 / 领取中 / 已领取」；进入关卡需覆盖「未解锁 / 体力不足 / 可进入 / 进行中」。
- **禁止**通过调用其他业务接口隐式满足前置条件（例如为进入关卡而直接触发加体力），状态迁移**必须**走唯一显式入口。
- **必须**方法名、注释、日志三处描述同一行为；实现与命名不一致按缺陷处理。
- **必须**失败路径给出可诊断日志（含关键 ID 与当前状态），禁止静默 `return false`。
- **必须**一次领取 / 一次购买全流程只允许一次发奖，领奖中状态**必须**能防重入，回调可重复到达时按幂等处理。
- **推荐**状态机用枚举 + 显式迁移表，禁止多个散落 `bool` 组合表达状态。
- **推荐**每类状态分支补一组配对测试（改动前 / 改动后同输入对照），见 §13.2。

### 4.5 调试开关与安全旁路

- **禁止**提交 `BypassXxxCheck` / `ForceSuccess` / `SkipVerify` 形式的运行时旁路字段，无论默认为 false；尤其禁止"强制广告完成""强制内购成功""强制命中某实验分支"。
- 调试能力**必须**用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 隔离，**禁止**出现于 Release 程序集。
- 临时验证用本地未提交改动 + 明确 TODO，验证完立即还原；**禁止**把验证开关作为"以后可能用"留在主干。
- GM / 调试指令**必须**有权限校验与审计日志，正式服不可用。

### 4.6 每帧代码与 GC

- **禁止**在 `Update` / `FixedUpdate` / `LateUpdate` / `OnGUI` / 每帧事件回调中出现：
  - `new` 引用类型（含隐式数组、`params`、`ToList()`、闭包捕获）；
  - 字符串拼接 / `string.Format` / 插值字符串（改用预分配 `StringBuilder` 或缓存文本）；
  - LINQ、`IEnumerable` 上的 `foreach` 装箱、字典遍历枚举器分配（用索引 `for` 或缓存列表）；
  - 值类型装箱（枚举作 `object` 键、格式化函数传值类型）；
  - `GameObject.Find` / `FindObjectOfType` / `GetComponentsInChildren` / `Camera.main` 等查找调用。
- **必须**在 `Awake` 缓存 `GetComponent` / `RectTransform` 结果；随组件销毁释放或在 `OnDestroy` 置空。
- **推荐**用 `Time.deltaTime` 驱动，禁止依赖帧率的 `++` 累加；高频逻辑降频或改事件驱动（`IsDirty` + 一次性刷新）。
- **推荐**倒计时、进度条、体力恢复等显示用"到点刷新"而非每帧重建文本。

### 4.7 异步、协程与生命周期所有者

- **必须**明确每个协程 / 异步任务的 Owner 组件；销毁时**必须**停止其持有的全部协程与任务。
- **禁止**在无 Owner 的静态工具类中启动长期协程；禁止 `async void` 业务方法（UI 事件入口除外）。
- **必须**为异步操作处理取消与超时；面板关闭后回调**必须**先判活再刷新 UI。
- **必须**广告 / 内购回调以事件订阅方式接入，订阅与反订阅成对；回调可能在数秒后、面板已关闭或应用已回前台时到达，需按幂等处理。
- **推荐**全工程统一一种异步方案（UniTask / Task / 协程），禁止同模块混用三套。

### 4.8 异常、断言与防御

- **禁止**空 `catch { }`、仅 `Debug.Log(e.Message)` 后继续跑、用异常做常规流程控制。
- **必须**在配置加载、协议解析、存档读取、远程配置合并等边界做显式校验与降级（默认值 + 一次告警），错误可定位到表/行/字段。
- **推荐**用 `Debug.Assert` 表达内部假设；Development 包开启，Release 关闭但保留校验日志。

## 5. Unity 生命周期与组件

| 回调 | 职责 | 禁止 |
| --- | --- | --- |
| `Awake` | 自身引用缓存、内部状态初始化 | 访问其他组件状态、访问配置表 |
| `OnEnable` | 注册事件、订阅广告/网络回调 | 重复注册（须与 OnDisable 严格配对） |
| `Start` | 依赖外部数据的初始化、首屏刷新 | 同步加载大资源、阻塞启动 |
| `Update` | 输入、状态推进 | 分配、查找、IO、协议请求 |
| `LateUpdate` | 布局后置刷新、安全区重算 | 业务逻辑 |
| `OnDisable` | 反注册、停止协程 | 遗漏导致重复注册 / 内存泄漏 |
| `OnDestroy` | 清空静态引用、归还对象池 | 访问已销毁对象 |

- **必须**事件「注册 / 反注册」成对写在同一文件相邻位置，`+=` 与 `-=` 一一对应。
- **必须**处理 `OnApplicationPause` / `OnApplicationFocus`：暂停计时与音频、记录弹窗栈与进行中状态；回前台**必须**重新校验会话、配置版本与广告/内购结果，禁止假设状态仍有效。
- **必须**在 Player Settings 锁定竖屏方向；**禁止**运行时横竖屏切换，也禁止用整体缩放掩盖方向问题。
- **必须**处理激励视频 / 插屏 / 内购界面打断：打断前保存进度，恢复后重新判定弹窗栈，禁止奖励重复发放或界面叠两层。
- **禁止**在 `Awake` 依赖脚本执行顺序；需要顺序用显式初始化器。
- **禁止**用 `DontDestroyOnLoad` 常驻对象承载业务状态；跨场景数据走明确的服务层/持久化。
- **推荐**组件只做一件事；单一 `MonoBehaviour` 同时管 UI、网络、数据视为需拆分。

## 6. UI / UPF 面板规范（竖屏休闲项目核心）

> 本节以通用 UI 框架为对象。文中 `UPF` 代表项目所选的 UI 框架占位，其基类、生成命令、目录名按 §15.4 替换，不假设任何具体在研工程的实现。

### 6.1 绑定与生成边界

- **必须**采用**静态 Prefab + Inspector 绑定**：结构、引用、初始显隐在 Prefab 里定死，运行时只做数据填充与状态切换。
- **禁止**运行时 `new GameObject` 拼装界面树、`Transform.Find("xxx")` 按名字查找、`Resources.Load` 加载面板。
- 动态生成仅限列表单元（Cell），且**必须**走对象池 + 复用，禁止每条数据新建节点。
- **推荐**绑定代码由 UI 生成链产出，手写逻辑只放 `partial` 扩展文件；生成文件被覆盖不算缺陷，改生成器/描述源才是修复。
- Prefab 中**禁止**残留断链引用（Missing Script / 空字段）；提交前用编辑器批量扫描工具校验。
- **禁止**把渠道差异、SDK 差异写进 Prefab；差异由适配层在运行时注入。

### 6.2 竖屏适配与安全区（必须逐项验收）

| 项 | 规则 |
| --- | --- |
| 设计基准 | 全工程唯一：竖屏 1080×1920（或立项基准），CanvasScaler `ScaleWithScreenSize` + 明确 Match 值 |
| 安全区 | 用统一 SafeArea 适配组件读取 `Screen.safeArea`；**交互元素必须在安全区内**，纯背景可延伸到安全区外 |
| 顶部 | 刘海 / 挖孔 / 状态栏遮挡区禁止放可点击控件与关键信息 |
| 底部 | Home 手势条 / 导航栏区域禁止放主操作按钮；主按钮上移并留出安全边距 |
| 宽高比 | 至少覆盖 20:9、19.5:9、18:9、16:9、4:3（或立项范围）；范围外**必须**给降级布局而非裁切 |
| 锚点 | 顶部/底部元素分别锚定，中部用自适应布局；**禁止**绝对坐标与固定高度硬编码 |
| 缩放 | **禁止**整体 Scale 拉伸 UI 来"适配"；禁止为长屏单独切一整张全屏背景大图 |
| 单手操作 | 高频按钮置于屏幕下半部可达区；点击热区不小于项目基准（建议 ≥ 88×88 设计像素） |
| 文本 | 字号随缩放、支持多行与自适应；**必须**用最长语言文案做溢出用例，禁止固定宽度单行硬编码 |

- **必须**为安全区适配提供统一组件/基类，禁止每个面板各写一套 `Screen.safeArea` 计算。
- **必须**在真机长屏、小屏、刘海屏三类机型上核对主界面、结算弹窗、商店页与底部按钮栏。

### 6.3 面板栈与弹窗队列

- **必须**统一 `Open → Refresh → Close` 三段式；`Open` 只负责显示与首刷，`Close` 负责反注册、停止动画/协程、归还池对象。
- **必须**参数用强类型结构体 / 参数对象传递，禁止 `object[]`、全局静态变量、字符串字典传参。
- **必须**弹窗由统一栈管理，业务面板**禁止**自行改 `sortingOrder`、Canvas 排序或射线阻挡。
- **必须**处理同时到达的多个弹窗（登录奖励 / 活动 / 结算 / 广告奖励）：按优先级串行排队弹出，禁止互相覆盖、禁止同时弹两层奖励。
- **必须**面板重开时状态完全复位（滚动位置、选中态、红点、输入、动画进度）。
- **必须**面板关闭后异步回调先判活再刷新；动画播放期间加操作锁，禁止连点重复触发。
- **必须**激励视频 / 插屏 / 内购 / 切后台打断后，弹窗栈可恢复且奖励只发一次（配合 §4.4 幂等）。
- **推荐**弹窗优先级、遮罩规则、关闭策略由框架配置表统一定义，业务只声明优先级。

### 6.4 列表、图集与重建

- **必须**长列表（关卡、排行榜、背包、商品）使用虚拟化/循环复用；容器尺寸、锚点、滑动方向在 Prefab 中固化。
- **必须**只在数据变更或可见区变化时重建 Cell，禁止每帧 `SetActive` / 重建布局。
- **禁止**在 Cell 的 `Update` 做布局计算；禁止嵌套多层 `ContentSizeFitter` + `LayoutGroup` 造成布局重建风暴。
- **必须**按面板/弹窗分图集，通用控件抽公共图集；**禁止**一张全局大图集常驻内存。
- **必须**动静分离 Canvas，透明度变化用 `CanvasGroup`；**禁止**全屏透明遮罩叠多层、多层全屏 Sprite 叠底。
- **推荐**列表数据索引化，滚动回调只更新差异项；改动面板生成逻辑后**必须**全量重生成 + 面板回归。

### 6.5 交互与文案

- **必须**所有可点击控件有明确禁用态表现，网络/广告/内购进行中给出可见状态，禁止仅逻辑拦截无视觉反馈。
- **必须**处理连点与重复点击（防抖 / 操作锁），关键写操作全程只发一次请求。
- **必须**玩家可见文案走本地化 Key，禁止在代码中硬编码中文字符串；数值格式化使用统一工具。
- **推荐**UI 动效时长与可跳过方式统一，禁止因动画阻塞首次可交互时间。

## 7. 配置数据（Luban）

> 定位：竖屏休闲项目表数量少、迭代快、活动与数值需热更或远程覆盖。**随包表是基础真值，远程配置是覆盖层**，两者都受本节约束。

### 7.1 生成与来源

- **必须**以 schema / 源表为唯一真值；生成代码与生成数据**禁止**手工编辑。
- **必须**源表与生成产物同 Changelist 提交，并注明生成器版本；版本升级需全量重生成。
- **必须**生成流程由统一命令或 CI 复现，**禁止**产物中出现本机绝对路径、个人账号或本地时间戳。
- **必须**为配置访问提供统一入口（表管理器 + 远程覆盖层），**禁止**业务代码直接读生成类静态表并各自兜底。
- **禁止**运行时修改配置对象；派生数据请复制或建视图模型。

### 7.2 表设计

- **必须**一表一职责；数值型内容（关卡、奖励、商店、活动、掉落）入表，结构性常量（层级、枚举、UI 参数）**禁止**入表。
- **必须**UI 文案走本地化表，**禁止**塞进业务数值表。
- **必须**活动 / 实验配置带生效时间、版本区间、渠道与灰度比例字段，客户端只做展示与判定资格，**最终发奖由服务端确认**。
- **必须**枚举独立类型，ID 规则与外键明确；可空字段显式默认值 + 注释。
- **禁止**把随版本变化的平衡性数值写死在 C# 常量里；禁止 `param1..param8` 万能字段。

### 7.3 校验、热更与离线

- **必须**加载阶段校验：主键唯一、外键存在、枚举合法、数值区间、必填非空、活动时间区间不冲突；开发/测试环境校验失败**必须**报错中断，禁止静默跳过。
- **必须**离线可玩：进入主界面与核心玩法所需配置**全部随包**，**禁止**启动时强依赖网络拉取配置。
- **必须**远程覆盖失败、超时或数据非法时，**静默回落随包表**并上报一次告警；**禁止**白屏、空列表或卡启动。
- **必须**配置与热更带版本号与兼容策略：新增字段给默认值、删除字段先双写过渡；**禁止**直接改字段类型导致旧包/旧存档崩溃。
- **禁止**热更中途覆盖正在使用的配置文件；覆盖前完成校验，失败可回滚。
- **推荐**为每张表配最小校验用例（含边界行与非法行），随 CI 在每次生成后执行。

## 8. 资源与资产规范

### 8.1 导入设置（必须逐项确认，不接受默认值）

| 资源 | 关键项 | 移动端基线 |
| --- | --- | --- |
| 贴图 | 压缩格式 | Android ASTC / ETC2 兜底，iOS ASTC |
| 贴图 | `Read/Write Enabled` | 关闭（需运行时读像素时单独申请） |
| 贴图 | `Mipmap` | UI/2D 关闭；3D 场景按需 |
| 贴图 | `Max Size` | 按实际显示尺寸设定，禁止 2048 用在 64px 图标 |
| Sprite | 九宫格 Border | 底板/边框**必须**用九宫格，禁止为每个弹窗尺寸切多张整图 |
| Sprite | 图集 | 同面板进同一图集，禁止散图导致合批失败 |
| 音频 | `Load Type` / 压缩 | 短音效 Decompress On Load，BGM Streaming + Vorbis/ADPCM |
| 动画 | 精度 / 曲线 | 去除无用曲线，UI 动效优先用代码补间而非大序列帧 |

### 8.2 竖屏 UI 资源

- **必须**背景用纯色 / 九宫格 / 可平铺元素延伸到安全区外；**禁止**按 1080×1920 切死整屏背景图。
- **必须**按面板/弹窗分图集，跨模块共用需评审；**禁止**一张全局大图集常驻。
- **禁止**多层全屏半透明 Sprite 叠底造成 Overdraw；**必须**纳入真机验收。
- **推荐**长文本按钮、多语言标签使用自适应容器，避免为每种语言单独切图。

### 8.3 Prefab 与场景

- **必须**Prefab 编辑在 Prefab Mode 进行；修改前在版本库独占加锁，禁止并行改同一文件。
- **必须**Prefab 嵌套层级扁平稳定；**禁止**运行时通过名字路径访问嵌套节点。
- **禁止**提交调试用 GameObject、空脚本、断链组件、临时材质；测试场景统一放 `Assets/EditorScenes/` 且不参与打包。
- **推荐**一个面板/弹窗一个明确 Owner，减少多人同时改同一 Prefab 的冲突面。

### 8.4 资源分包与地址

- **必须**通过统一资源管理系统（Addressables / AssetBundle）按路径或标签寻址，**禁止**新增 `Resources/` 目录下资源。
- **必须**资源路径常量化或由生成代码提供，禁止硬编码字符串路径散落各处。
- **必须**同一资源只属于一个主包，共享依赖抽公共包，禁止重复打包。
- **必须**首包 / 延后下载 / 按需下载清单与体积上限由立项评审确定，CI 逐版本校验增量；休闲项目**推荐**把非核心玩法资源延后下载。
- **必须**多渠道包（Android 渠道 / iOS / 小游戏等）共用同一套资源与配置；渠道包名、签名、密钥由 CI 注入，**禁止**入库。

## 9. 性能、内存与包体

### 9.1 帧预算

| 指标 | 目标（中低端真机） |
| --- | --- |
| 平均帧率 | ≥ 项目目标帧率（60 fps，低端机降级策略明确） |
| 主线程单帧 | 不超过帧预算的 70% |
| 每帧托管堆分配 | 稳态 0 B |
| GC 触发 | 滚动、弹窗动画等连续交互期间 0 次 |
| 启动到主界面可交互 | 按立项基线，逐版本对比不得劣化 |
| 弹窗打开到可点击 | 按立项基线，不得因同步加载或动画阻塞 |

- **必须**新增每帧逻辑同步给出耗时/分配评估；**推荐**附 Profiler 深剖面截图随提交说明归档。
- **禁止**以"编辑器不卡"或单一机型作为验收结论。

### 9.2 内存

- **必须**建立内存基线（PSS / Unity Profiler 分项：UI 图集、纹理、托管堆、音频）。
- **必须**大对象、图片、协议缓冲区池化或复用，禁止一次性分配大数组并长期持有。
- **必须**静态集合、事件中心、单例中的对象引用在销毁时移除。
- **禁止**无上限增长的缓存（头像、排行榜快照、日志、历史记录），必须有 LRU / 数量上限。
- **推荐**切后台释放可重建缓存，对低内存回调做降级；休闲项目频繁前后台切换，此项必须验证。

### 9.3 渲染与 UI 重建

- **必须**控制 DrawCall / SetPass 与 Overdraw；移动端禁用非必要实时阴影与全屏后处理。
- **必须**避免 `Canvas` 整体重建：动静分层，禁止频繁改 `Color.alpha`（用 `CanvasGroup`）。
- **禁止**对不可见 Cell 做动画、粒子、逐帧刷新。

### 9.4 启动与热更

- **必须**启动流程分阶段且可观测（SDK 初始化 → 随包配置加载 → 资源校验 → 账号/远程配置（非阻塞）→ 主界面）；首屏前禁止同步加载大资源。
- **必须**广告 / 埋点 SDK 初始化延后或异步，禁止阻塞首次可交互；远程配置拉取**禁止**作为进入主界面的前置条件。
- **推荐**启动期预热高频 Shader / 对象池，避免首次打开弹窗卡顿。
- **必须**热更具备版本号、断点续传、校验与失败回滚。

## 10. 网络、协议、存储与安全

- **必须**协议层与业务层隔离：协议结构由生成流程产出，业务禁止直接拼字节流或手改协议类。
- **必须**每个请求有超时、重试上限与退避；**禁止**无限重试、并发重复提交同一写操作。
- **必须**离线可玩：核心玩法不依赖网络；联网失败走本地队列并在恢复后按序同步，**禁止**阻塞主界面或弹错误框打断玩法。
- **必须**处理断线重连与回前台：重连后重新同步状态，禁止沿用旧会话缓存直接下发操作。
- **必须**服务端返回值做范围/合法性校验，禁止未校验数据直接写入 UI 或存档。
- **必须**激励广告奖励与内购发货以服务端确认为最终态，客户端幂等去重、支持补单；**禁止**仅凭本地广告完成回调直接发奖。
- **必须**本地存档带版本号与迁移路径；读档失败降级（默认档 + 上报），禁止崩溃或白屏；云同步冲突有明确覆盖策略。
- **禁止**在代码、配置表、Prefab、日志中硬编码密钥、Token、后台地址；渠道密钥由 CI 注入。
- **禁止**记录玩家隐私（设备标识、手机号、支付信息、聊天内容）到日志与埋点；广告/埋点 SDK 采集范围按上架地区合规要求评审，儿童向内容从严。
- **推荐**关键写操作（购买、领取、消耗）乐观展示但以服务端回包为准，避免状态分叉。

## 11. 日志、异常与可观测性

| 级别 | 用途 | Release 行为 |
| --- | --- | --- |
| `Verbose/Debug` | 开发期链路追踪 | 编译剔除或关闭 |
| `Info` | 关键流程节点 | 采样或关闭 |
| `Warning` | 可恢复异常、远程配置回落 | 保留 + 上报 |
| `Error` | 功能失败、数据错误 | 保留 + 上报 |
| `Fatal` | 崩溃前、不可恢复 | 保留 + 上报 |

- **必须**使用统一日志门面，**禁止**业务代码散落 `Debug.Log` 无上下文文本。
- **必须**日志带模块标签 + 关键 ID（关卡 / 奖励 / 配置行 / 交易单号），禁止 `here`, `111`, `test`。
- **必须**为发奖、内购、远程配置回落、广告回调建立可追踪链路，一次操作一个关联 ID。
- **禁止**逐帧/高频打日志；循环内日志**必须**限流或聚合。
- **必须**异常上报携带版本、渠道、设备、场景与最近关键操作；禁止把控制台完整堆栈作为唯一手段。
- **禁止**临时调试日志与 GM 指令留在 Release 主干。

## 12. Perforce (P4) 版本管理

> 面向小团队、高频迭代的竖屏休闲项目。本节不假设任何具体 depot / stream 命名与本机工作流；命名按 §15.4 替换。若项目改用 Git，见 §12.6 映射。

### 12.1 流与分支策略

- **推荐**轻量结构：主干（日常迭代）+ 发版分支（提审/灰度）+ 紧急修复分支；每次提审包打标签（Label），便于回溯与回滚。
- **禁止**长期存在的个人分支；**必须**至少每日同步一次主干，避免大合并。
- **必须**发版分支只收缺陷修复，新功能只进主干；禁止在发版分支直接改配置 schema 或面板生成逻辑。

### 12.2 Changelist 规范

```
[模块][类型] 一句话描述（≤ 50 字）

问题/需求：<原因或需求单号>
方案：<关键实现与取舍>
验证：<编译 / 生成链 / 面板开关 / 配对测试 / 竖屏真机>
影响：<受影响模块、是否需重新生成 / 配表 / 资源 / 热更版本>
例外：<条款号 + 原因，无则填 无>
```

- **必须**一个 CL 对应一个可独立回滚的逻辑变更；**禁止**格式化、重构、功能修复混提。
- **必须**同时提交脚本 + `.meta` + 相关 Prefab / 场景 / 配置源表 / 生成产物，禁止拆成多个 CL 造成中间版本编译失败。
- **禁止**提交 `Library/`、`Temp/`、`Logs/`、`obj/`、IDE 用户配置、个人临时文件；忽略规则由工程统一维护。
- **禁止**提交二进制资源时未标注来源与导入设置变更。
- **推荐**活动/数值类高频改动单独 CL，便于灰度与回滚。

### 12.3 锁、冲突与 UI 协作

- **必须**对 `.unity`、`.prefab`、`.asset`、`.asmdef`、图集源文件、Luban 源表等不可文本合并文件启用独占锁；修改前 `p4 edit` 并确认无他人占用。
- **必须**一个面板/弹窗一个明确 Owner，UI 改动提前在协作频道通告；**禁止**并行改同一 Prefab。
- **必须**冲突时先与对方确认语义再合并，禁止 `Accept Theirs` / 覆盖式强制解决。
- **必须**合并后重新生成 + 编译 + 面板回归，禁止"能编译就提交"。
- **推荐**大范围重构（改生成器、批量重命名、目录调整）选低峰期提交并提前通告。

### 12.4 提交前动作

1. `p4 sync` 到最新，确认无待解决冲突。
2. Unity 编辑器完整编译（Console 0 Error，Warning 不新增）；重跑 UI 绑定与配置生成链，确认产物与源一致。
3. 打开并关闭受影响面板/弹窗，检查断链引用、安全区、状态复位与弹窗队列。
4. 跑配对测试与相关单元测试（§13）。
5. 用 `p4 opened` / diff 逐文件复核，**必须**确认无调试开关、临时日志、本机路径、渠道密钥夹带。
6. 涉及热更资源或配置时，**必须**在 CL 中记录版本号。

### 12.5 多渠道构建

- **必须**构建参数（包名、签名、渠道 ID、SDK 开关）由 CI 注入，禁止写入仓库或 Prefab。
- **必须**各渠道共用同一套资源、配置与代码；差异只允许存在于隔离的适配层配置。
- **推荐**提审包与灰度包的资源/配置版本可回溯到 CL 与 Label。

### 12.6 若项目改用 Git（选型替换映射）

| P4 条款 | Git 等价做法 |
| --- | --- |
| 独占锁 | Git LFS 文件锁 + `CODEOWNERS`，同一 Prefab 禁止并行改 |
| Changelist | 单个 PR / Commit，沿用 §12.2 描述模板 |
| Stream / Label | 主干 + 发版分支 + Tag |
| `.p4ignore` | `.gitignore` + `.gitattributes`（二进制标记 LFS） |
| `p4 opened` / diff | `git status` / `git diff --cached` |

**说明**：选型由立项评审决定，本规范只约束"怎么做"，不锁定工具。切换工具时以上映射逐条落地，其余条款不变。

## 13. Code Review 与测试验证

### 13.1 Review 要求

- **必须**每个 CL 至少 1 名 Reviewer；涉及 UI 框架、生成器、协议、配表 schema、发奖链路、性能热路径的变更需模块 Owner 复核。
- **必须**Review 覆盖：状态校验完整性、发奖幂等、生命周期配对、生成代码边界、GC/分配、竖屏安全区、资源导入设置、版本库文件完整性、调试残留。
- **推荐**Reviewer 用 §14 清单逐项打勾；涉及适配或打断的改动附真机录屏 / Profiler 证据。
- **禁止**以「能跑就行」「先合再改」放行含 §0 红线的改动。

### 13.2 测试

- **必须**为状态机类改动写配对测试：同一输入在改动前后各跑一次，输出差异需可解释；改动前基线留档。
- **必须**核心逻辑（配置校验、状态迁移、发奖幂等、数值计算、远程覆盖回落）有 EditMode 单测；面板栈与弹窗开关有 PlayMode 或等价自动化用例。
- **必须**分支覆盖：正常路径 + 每个失败分支 + 空数据 + 重复调用 + 打断/关闭时回调 + 远程配置失败。
- **必须**竖屏真机矩阵至少覆盖：长屏（≥19.5:9）、刘海/挖孔屏、小屏（16:9 或 4:3）、中低端 Android 一台、iOS 一台、弱网/离线、切后台恢复、广告打断与回前台。
- **必须**对主界面、结算弹窗、商店页、底部按钮栏做安全区与文本溢出核对，并用最长语言文案跑一遍。
- **推荐**缺陷修复同时补一条能复现该缺陷的回归用例（根因修复 + 链路闭环）。

### 13.3 CI（推荐门槛，逐步落地）

| 阶段 | 检查项 |
| --- | --- |
| 提交前 | 编译 0 Error、格式检查、生成产物与源一致性 |
| 合入 | 单测、配置表校验、Prefab 断链扫描、调试开关关键字扫描 |
| 每日构建 | 竖屏机型冒烟、内存/帧率基线对比、首包与热更包体积、安全区截图比对 |
| 发版前 | 全量回归 + 离线启动 + 广告/内购沙箱 + 隐私合规检查 + 回滚预案 |

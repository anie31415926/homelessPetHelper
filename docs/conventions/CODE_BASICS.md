# 代码基础（编码必读）

适用于编码、代码 Review 和架构任务。详细规则由 [入口](../../CODE_CONVENTIONS.md) 按需路由；本文件只保留高频底线。

## 正确性与职责

1. 正确性、玩家数据安全与合规是底线。在性能预算内优先选择可读、可测试的简单方案；不为模式数量或假设的需求堆框架。
2. UI 负责展示/输入，业务负责规则/状态，基础设施负责网络/存储/SDK。核心规则应能脱离场景测试；外部依赖显式传入，依赖无环，避免全局单例链。
3. 一个函数完成一个清晰动作；使用有业务含义的名称、提前校验与明确分支。稳定规则只有一个归属，避免复制实现和无意义抽象。

## 最小编码约定

- 类型/方法/属性用 `PascalCase`，参数/局部变量用 `camelCase`，私有字段用 `_camelCase`，异步方法以 `Async` 结尾；文件与主类型同名。已有工程遵循统一格式和语言兼容配置。
- 模板格式为 4 空格、UTF-8 无 BOM、Allman 大括号；实际工程按统一规则执行，不为局部功能顺带全库格式化。
- 最小可见性，封装可变状态；只读字段不代表集合不可变。禁止属性查询暗中扣费、落盘或发请求。
- 接口明确输入约束、返回值、失败原因和副作用。`TryXxx` 成功可以改状态，失败不得留下未说明的部分修改；业务拒绝、技术失败和取消要区分。
- 先校验完整状态再提交，异步返回后重新核对状态/会话/请求版本。入口防连点不能代替资产事务和持久化幂等。
- 数量、货币与时间明确单位及范围，处理负值、除零、溢出、空值和缺键；测试中的时钟/随机/外部服务可控。持久化字段/枚举变更须兼容旧数据。
- 方法 > 40 有效行、类型 > 400 有效行、嵌套 > 3 层或圈复杂度 > 10 时，读取详细复杂度规则并评审；这些是触发线，不以机械拆函数达标。

## 生命周期与资源

- 异步、协程、订阅、计时器、加载句柄和池对象有明确所有者及结束/释放路径。覆盖失败、取消和销毁；不使用已归还对象，旧回调不覆盖新状态。
- 不阻塞主线程等待异步结果；异常须有人观察，禁止空 catch、吞错后报成功。必要校验在正式包执行，不能仅靠断言。
- 热路径按实测分配与耗时预算实现，避免反复查找、无界缓存和无依据的全量扫描；不凭 `new` / `foreach` 关键字判断性能。

## 安全与数据

- 生成文件从生成源修改；禁止手改后提交。代码、配置、资源及生成产物保持一致。
- 禁止生产安全旁路、可用 GM 和强制支付/广告成功开关；调试工具隔离于正式构建。禁止提交秘密或输出隐私。
- 扣费/发奖须防重复并可恢复；超时可能结果未知。坏档先保留和恢复，禁止默认档自动覆盖玩家进度。

## 验证与改动范围

- 先读相关实现，沿用工程约定，只改任务范围；不覆盖用户已有改动，不夹带无关格式化或大重构。
- 代码改动执行适用的编译/静态检查与测试；核心规则验证正常、拒绝、边界和副作用，缺陷修复补回归。UI、SDK、生命周期、性能等按风险加目标平台验证。
- 交付说明改了什么、验证结果及未验证项；无法运行的检查注明原因，不声称通过。例外须记录条款、原因、影响与恢复方案，按工程评审流程处理。

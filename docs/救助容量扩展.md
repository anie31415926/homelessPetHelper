# 救助容量扩展

2026-11-21 工程契约；用户确认名额应可动态扩展。当前样例初始 2 名不等于正式容量上限，普通求助仍只有配置中的猫狗两单；扩容不会自动生成新动物或刷新请求。

## 状态与接口

- `CityMapPreviewConfig.InitialCapacity` 仅初始化新档。
- `RescueStation.TemporaryCapacity` 是当前站点实际总名额，`AvailableTemporaryPlaces` 是总名额减入住数。
- 沿用既有 `TryExpandTemporaryCapacity(stationSessionId, newCapacity, out failure)`。参数为扩建后的**绝对总容量**，只允许增加；重复提交同一总容量返回 `CapacityNotIncreased`，不会重复加名额。负值、错误会话、暂停及关闭均拒绝，失败不改变容量。
- 扩建玩法未来负责校验权限、费用与升级条件，再调用该接口，在稳定站内检查点显式保存。当前没有扩建按钮、价格、等级或额外运行时调试入口；不能把底层扩容接口当作已完成资产交易。

## 持久化与展示

Main 的 schema v1 原本已有 `Capacity` 字段，捕获也已取当前总容量。本轮修复恢复时强制等于初始配置的约束：保存容量须非负且不小于居民数量，恢复使用存档实际值。以后修改新档初始配置不会自动增减已有容量；零容量和 int 范围内的扩容均由现有接口支持，不臆定玩法最大等级。

不改变既有存档 schema，也不绕过请求、居民、护理和时间的其他语义校验；非法容量或其他坏档仍保留原数据并阻止覆盖。

地图展示、规划/出发预检和入站重检使用实际剩余名额；站内状态显示实际入住数/总容量。现有面板刷新或重开时读取新值，本轮不新增自动扩建通知机制。住户列表沿用既有动态 Cell 复用，不按总容量预创建空位。大规模动物数量的交互与性能尚未验收。

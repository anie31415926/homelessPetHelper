# 脑内过招：HTML 耐玩性实验

2026-11-19。用户反馈救助几局后趋向固定套路，希望增加对局不确定性、消除爽感和救援成功的成就感，并明确要求先在 HTML 原型里试。

## 比较的方向

| 方案 | 决策变化从哪里来 | 本轮处理 |
| --- | --- | --- |
| 读招交锋 | 动物当前倾向、默契主动技、留牌准备；偏宝可梦的读招而非攻击动物 | 可玩独立模式，顺意额外 +2，不做暗骰 |
| 顺势连锁 | 随机初盘、重力补入、组形与连锁；要不要先用牌接一大片 | 可玩，默认推荐先试；真实五连自动接消 |
| 现场变局 | 预告下一事件，决定先消、先留牌还是先应对干扰 | 可玩独立模式，每两手一次变化 |
| 局内选装备/路线 | 开场带不同工具，途中二选一，形成流派 | 留作下一轮候选；本轮不叠加养成、经济或牌组升级 |
| 假动作/对手记忆 | 动物记住重复方法，对玩家行为作反应 | 留作下一轮候选；需要先验证可读性，不能用随机拒绝伪装智慧 |

前三种共用一个小棋盘和行动机制，切换模式会明确确认重开同一编号，可对比“多了这条规则是否真的更有趣”。没有把三种规则全部叠成复杂正式系统，也没有承诺无限耐玩。

## 当前临时规则

### 棋盘与结算

- 5 列 × 4 行；食物、空间、玩具、安置四类，另有不可单点的干扰。
- 点上下左右相连的同类机会，两个起消。使用已有 `pathfinding` 的四向 A* 核心判定同类可达组，不新增拼图依赖、不跨行或斜连。
- 消除后同列上方落下，顶部按局内种子补入。邻接干扰一同消除，每个安心 +1，特定个体 +2。
- 基础推进等于组大小；符合当前倾向额外 +1，“读招”额外 +2；偏好类别至少四连再 +1。所有推进只计入尚未满足的本局目标并封顶。
- “连锁”模式：首次消除/补入后，实际存在的五连及以上组同时接消，最多四段。每段保存真实棋盘快照；演出依次显示这些快照，不拿假连击数字冒充消除。
- 没有合法二连时确定性补一组，不加分、不无限洗盘。每局初始两个干扰，事件最多保留五个干扰。

### 个体、倾向与收尾

六种个体不仅目标不同，规则也不同：饭点巡逻员食物四连后下次空间 +2；纸箱调查员提前熟悉入口后接受 +3；球先归我顺意玩具四连默契 +2；保持一点距离带走干扰每个安心 +2；路过也要看看交替类别 +2；今天走了很远顺意二到三连 +2。

- 目标按个体生成，每项加 0～2 作为临时变体。两项需要满足后开放接受安置；提前消安置只记一次熟悉，开放时接受 +2（纸箱个体 +3），重复不叠加。
- 顺意消除每手结算一次默契，通常 +1（球个体可 +2），上限 3。满后可主动接出当前倾向的四格，并立即消除该类最大组；使用后允许这次回应重新获得默契。
- 连续三次不顺意消除后，当前倾向转为空间并补两格空间；不倒扣成果、没有伤害或死亡。不是强制失败系统。
- 倾向由剩余需要、偏好和空间池决定。干扰、洗牌或非目标消除可以整理局面，但不冒充目标进展。
- 接受值满足后出现独立完成按钮，不再等抽到一张牌。完成演出、真实行动/消除/连锁回顾、同局重试与新相遇均可用。
- 允许主动结束相遇；明确记为未完成，不显示救助成功。无现实倒计时、资源收费或隐藏成功率。

### 行动与现场变化

- 三张行动牌，最多保留两张，每手后自动补足并换掉未保留牌；使用的保留牌也消耗，实例 ID 与当前手数双重防重复。
- 食物/空间/玩具/安置和顺势牌改造棋盘，不直接加目标值；改变的格子接在该类最大组旁。无该类别时先创建相连组。清静牌把干扰变空间并挡下次推车；换位牌重排当前机会。
- 每手至多一个趣味项（包括保留），回消息/拍照只给短回应且各一次后退出；它们占用一次选择、可能推进预告时机，不增加专属动物效果或额外惩罚。
- “变局”模式每两次行动触发队列首项，前两项可见：路人散去、推车经过、风吹一行、玩具出现、安置处空下来。已预备的清静应对只在推车时消耗。
- 局内 PRNG 保存在状态内，预览/保留/无效或过期提交不消耗随机数。同一编号、玩法和操作顺序可重现；新相遇使用新的 uint32 编号。不同模式保证同一初盘，后续因规则/操作不同而分流。

## 数据与技术归属

- `src/duel/content.json`：个体、目标、特性提示、行动定义与中文内容。`content.js` 只导出 JSON；无需数据库或新配表框架。
- `board.js`：随机、分组、重力、改造与无解保护。`engine.js`：唯一局内状态和纯提交入口；拒绝提交返回原对象。
- `DuelApp.jsx` / `duel.css`：显示和交互。复用 B 页取消式约 400ms 长按 hook，不修改共享 hook；棋盘直接点，图钉独立。
- 运行状态/牌实例/最近 40 条回顾在会话内存。URL 只存编号和模式；刷新会重开，不存当前进度，不读写旧原型 localStorage。
- Web 试验沿用其他 HTML 原型的 UI 文本写法；玩法内容已进 JSON，界面短标签/规则说明仍有组件内文本，**不是正式本地化交付**。移植前按正式文案键与配置校验规范整理。
- 复用原临时猫/狗 PNG 和停车棚 JPG，已补唯一资源清单用途；不复制资源、不改变 temporary / preview-only 及许可待审状态。动物位移和跳动是表现，不是新表情帧或真实路径规划。

## 验证

- 规则测试 `npm run test:duel`：15 项，包括连通边界、重力身份、确定性/纯预览、失效提交、无解修复、保留/趣味限制、默契、个体特性、接受收尾、真实连锁、预告与退出。
- 36 编号 × 3 模式 × 2 策略，共 216 次模拟均完成；观察目标/用默契/必要时改盘的启发式，与只点最大组对照：

| 模式 | 应对式平均行动 | 只点最大平均行动 | 应对式范围 |
| --- | --- | --- | --- |
| 读招 | 9.7 | 13.6 | 5～16 |
| 连锁 | 8.2 | 11.4 | 4～18 |
| 变局 | 10.8 | 13.6 | 5～20 |

两策略在连锁模式均有 33/36 局出现真实连锁。这只证明不同局面及决策有可测差别、不易卡死，**不证明人类长期策略已不收敛，更不证明三个模式已平衡**。

- 浏览器脚本 `npm run test:duel:browser`：六个视口 320×568、360×640、390×844、430×932、768×1024、1440×1000；另测小屏变局与正常变局，无横溢出/文字裁切/格子重叠，实际图片解码正常。短屏以行动抽屉保证一屏棋盘可操作，不把手牌藏到屏幕外。
- 覆盖短点/提前松手取消、保留独立、长按一次、键盘移动和长按、暂停不推进、编号校验、同局重开、切换玩法、完整真实救助和结算；开启动画时检查实际快照消除。截图与 JSON 证据在忽略的 `test-results/duel/`。
- 另验 740/780 高临界视口、47px 顶/34px 底模拟安全区、猫狗两图、触摸打开预告说明及三个模式完整 UI 收尾。基础 Web 与资源规则回归 58/58，原 B 长按浏览器回归通过，Vite 构建通过（既有 3D 大包提示仍在）。台账无缺失/漏登记；正式首批范围仍未确认，微信实际下载未测，不能以此称首包验收通过。
- 原型尚未做微信/真机测试、正式字体/最长语言、音效、完整动物动作、关卡难度曲线、真实运输/医护/回站及长期重复体验。当前偏轻松无损尝试，最优策略仍可能逐渐收敛；先收集连锁是否爽、看反应是否值得、需不需要更明确的取舍三个反馈，再考虑局内分支或有限工具。

## 接下来怎么试

优先默认连锁模式玩 5 局，刻意各试“眼下最大”“先留牌攒组”“顺着反应攒默契”。喜欢的一局可用相同编号换模式重玩。优先观察是否想再来一局，而不是先追加更多文字选项或把救助变成打掉一条血条。

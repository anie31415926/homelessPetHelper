# 轻量图片资源检查工具

日期：2026-11-17。状态：v1 已实现，只读 Editor 工具；不是运行时资源框架或性能达标证明。

## 目标与取舍

用户确认微信小游戏图片规模有限，工具以帮助后续加载流畅和运行效率为目的，不做大规模资源平台。
当前正式图片尚未批量入库，先让尺寸、导入设置和引用关系可见；发现候选问题后再结合实际画面、微信导出与真机测量决定优化。

- 复用 Unity `TextureImporter`、`AssetDatabase.GetDependencies` 和 SpriteAtlas API，不解析 YAML 猜依赖，不维护第二份手工依赖表。
- 手动按需扫描，结果只写入忽略的 `Library` 或 `test-results`；没有 Update、自动导入钩子、长期缓存或新增包依赖。
- 不修改导入设置，不移动、重命名或删除图片，不改 Prefab 绑定，不创建或重新打包图集，不接入下载、分包、热更或 Addressables。
- 复用已有 Editor 程序集；运行时程序集不引用工具。新增 EditMode 测试引用 Editor 程序集，不改变生产依赖方向。

独立打包器和完整资源框架当前不能带来已证实收益，反而增加微信兼容性和生命周期维护成本，因此本轮不做。正式资源加载选型仍按项目基线另行评审。

## 使用入口

Unity 空闲 Edit Mode 下运行：

1. `Homeless Pet Helper > Tools > Check Image Resources`：生成 JSON 和 Markdown 报告，Console 显示摘要与路径。
2. `Homeless Pet Helper > Tools > Reveal Image Resource Report`：在系统文件管理器中定位 Markdown 报告。

默认报告位于 Unity 工程内 `Library/ResourceAudit/image-resources.json` 和同名 `.md`。不会自动打开外部应用或切换当前场景；菜单在 Play、编译、导入时禁用。扫描以 Unity 当前已导入的资产为准，未保存场景中的引用变化不算已保存依赖；隔离命令只检查磁盘上的已保存文件。

仓库根目录也可执行，不占用用户正在打开的工程：

```powershell
powershell.exe -NoProfile -File tools/unity.ps1 -Task ResourceAudit -Isolated -ReportSuffix MyRun
```

报告复制到 `test-results/unity/ResourceAudit-isolated-MyRun.json` 及同名 `.md`；日志为同名 `.log`。当前 Windows PowerShell 5.1 已验证可用，也可沿用 `pwsh`。没有失败候选强制阻断构建的钩子；扫描异常会失败，不能用旧报告冒充本次结果。报告候选本身只提示人工复核，不自动判构建失败。

## 扫描内容

范围是 `Assets/` 中由 `TextureImporter` 导入的 `Texture2D`，不扫描 Packages，也不覆盖自定义图片导入器。报告按路径和规则码稳定排序，无时间戳或本机绝对路径。

| 内容 | 报告含义 |
| --- | --- |
| 图片属性 | GUID、源尺寸、当前导入尺寸/格式、Read/Write、Mipmap、默认最大尺寸和压缩模式 |
| WebGL 设置 | 是否覆盖、最大尺寸、格式和压缩模式；未覆盖时展示默认值，不据此断言微信实际格式 |
| 直接引用 | 哪些已保存资产直接依赖该图，包括 Prefab；不等于完整反向传递路径 |
| 构建场景依赖 | 是否在当前启用场景的递归依赖中；不是最终包清单，不含动态加载/预加载等所有入口 |
| 图集声明 | 支持 `.spriteatlas` 和 `.spriteatlasv2`，展开文件夹、Sprite/纹理输入，报告主图集、变体及 Include In Build |

图集成员以源贴图为粒度；同一源图的不同切片可能有意分配到不同图集。单图集内重叠文件夹与直接输入会去重，主图集加自身变体不当作两个独立主图集。不会实际 Pack，不测页数、利用率、构建重复字节或合批效果。

| 规则码 | 级别与建议 |
| --- | --- |
| `TextureReadWrite` | Review：确认是否需要 CPU 像素访问；不能机械关闭遮罩或特殊贴图的读写 |
| `SpriteMipmaps` | Review：确认是否是屏幕 UI；世界空间 Sprite 可能需要 Mipmap |
| `LargeImportedTexture` | Review：当前导入任一边超过 2048 px 时复核显示尺寸；这是工具观察阈值，不是产品预算或硬上限 |
| `UncompressedDefault` | Review：默认压缩模式未压缩，须结合显式格式及平台覆盖判断；不自动修改 |
| `MultipleMasterAtlases` | Review：同一源图声明进入多个主图集，检查是否有意；不是重复打包已证实 |
| `AtlasMissingMaster` | Review：变体没有主图集，未能索引继承成员 |
| `NoIndexedReference` | Info：没有索引到静态引用或图集输入；动态字符串加载无法识别，不等于未使用，更不是删除建议 |
| `NonTexture2DImporter` | Info：有 TextureImporter 但没有 Texture2D，未执行尺寸/导入复核，不静默当作已覆盖 |

不根据目录名猜 UI、动物或背景，不强制所有 Sprite 入图集，不报“没有图集就是性能问题”，不自动修改共享依赖和分包。正式分组应结合共同显示、加载和释放时机确认。

## 当前扫描结果

- 两张临时图片，均 600×640，当前 Windows 导入为 RGBA32；Read/Write、Mipmap 均关闭，无图集。
- 两张默认压缩模式为 Uncompressed，产生两条 Review，保留白板现状，未擅自压缩。
- 猫图被站内 Prefab 直接引用；狗图通过 Editor 样例代码动态设置，静态索引找不到，产生一条 Info。这正是不能据扫描结果删除资源的例子。
- 两图均不在当前 Main 启用场景的依赖中；不代表工具已核实所有未来资源包。

这些是白板阶段的观察结果，不是正式美术缺陷或微信内存结论。

# 精灵树屋关卡设计

2026-11-25。用户认可[楼梯版树屋](../art-source/treehouse-field-20261125/room-stairs/candidate.jpg)，不要求固定三路。以下为用户确认后的首个可试玩题面。复用已有清理、挪箱、出牌和现场存档。

## 空间与目标

进门后正前方是能摆东西和部署的底层，左侧是楼梯。楼梯脚到门口有一条直接但较窄的通道；穿过右侧地板、再折回楼梯脚是较长的绕行。两条都从门内空地出发，最终到同一个楼梯口；只有清开的通道才可供战斗单位使用。绕行应在汇合前能躲开近路的一处塔位，不能只多走路，也不让同一座塔从开局就封死两个选择。上层书架旁放可覆盖的小篮，揭露后是同一只小猫。

```text
上层书架旁：盖毯藤篮／找到小猫
                  ↑ 玩家清开后上楼
左侧楼梯口：战斗送达点
   ↑                     ╲
短而窄的直路          右侧绕路（可选清理）
   ↑                     ╱
门内空地：起点／部署区
```

## 清理关：楼上有动静

1. 刚进屋时只听见楼上传来一声猫叫或看到篮毯轻动。清掉门口散纸后能接触下一圈的书堆和挡住楼梯脚的木凳；远处物件不能隔着阻挡直接清。
2. 清开通往楼梯的基本通道后上楼，移开书架旁散书，再揭开藤篮盖毯，小猫才出现。楼上也有一次清理推进，救助入口不会在清完门口后立刻弹出。两层需要能分别看清和点到；楼梯口可用现有短过渡切换操作焦点，不要求可自由走动的角色。
3. 找到猫、楼梯口可达即可手动开始救助。玩家也能先下楼清右侧书堆，把绕路带进战斗。剩下的杂物保留。提前接战与再花一点时间清绕路都合法，不需要清完所有物件。

## 解谜关：让开楼梯口

同地点另一张完整题面，使用两只可沿直线滑动的矮收纳箱和可撤回操作，不在清理中途强插第二套规则。左箱占着通向楼梯的窄口，右箱占着左箱可滑入的凹位。先把右箱滑进墙边收纳位，再把左箱推入腾出的凹位，就露出通往楼梯的通道。错误摆位可以撤回。如同时制作绕路解法，须证明它会留下不同的战场通道，并实际可解；首测先做一套必过、可复原的摆法。箱子位置带入逆塔防。箱子形象可复用项目已有木箱作为试玩素材。

## 逆塔防：把安抚道具送到楼梯脚

镜头和残局留在原房间。底层出兵、造塔和战斗，单位抵达楼梯脚计救助进度，用一小段送达反馈表现道具到达小猫身边。上层是小猫的安全位置，不给楼梯做格子、跨层攻击、高低差数值或单位逐阶移动。第一次先验证平面战斗中“短路抢时间 / 绕路避塔”的取舍，再决定要不要扩展楼梯参与逆塔防。

手牌上方显示当前资源，救助完成度用动物头顶的短进度条呈现（2026-11-25 后续用户确认，替代首测左上角的爪印到爱心条）。沿用有资源就可在部署区即时落位、守方用资源在合法空格建塔的规则。走向按落点和清出的通道决定；未开的绕路仍由对应障碍留在场上。单路线也必须可通关，绕路是策略收益，不能成为隐形必做条件。纸团盒可以压近路，线轴架可以卡拐角，两个区段需留不同的布防面；不要让左侧楼梯挡住手牌或塔的落点。

## 回访与试玩边界

中断回来原地续玩，不新增障碍。结束外出、经过配置的游戏时间再回来时，只从入口与侧边的轻杂物候选恢复少量，首测可用一处；不补关键楼梯阻挡、不重盖已找到的同一只猫、不恢复已移动的箱子。新求助可重新配置藏身物。以既有地点记录和本轮现场快照为准，加载界面或重复进入不重掷。

首测做两组对照：一组只走直路也能完成救助；一组多清出绕路，能绕开一个具体塔位并改变部署选择。另验上楼揭露前后中断、直接接战与清绕路后接战、箱子撤回、开战续玩及回访重复进场。本轮未定杂物工作量、收费或战斗数值。既有三路关卡沿用原规则，树屋在自身配置中声明必开近路、可选绕路。素材走现有 Sprite 和图集，不加单位造型组件。

## Unity 试玩入口和验证

- 大地图右上方，橡树小屋下方的「精灵树屋」标签，可从小猫求助出发。首次使用完整清理；本次救助完成后，新求助进入两箱题面。回访同一求助以保存结果为准，经过约定的 120 游戏分钟后至多补回一件轻杂物；中断读档不会补刷。
- 近路和绕路都把道具送到楼梯脚，开局抓板只覆盖近路的一段。楼上篮子揭开后，战斗仍显示同一只猫与剩余杂物。资源移到手牌旁，救助进度以爪印到爱心的图形条表示。
- [EditMode 结果](../test-results/unity/EditMode-isolated-treehouse-delivery.xml)：72 项通过，含单路线实时胜利、绕路避开实际塔位、推箱撤回、战斗回放，以及旧场地和地图绑定回归。[PlayMode 结果](../test-results/unity/PlayMode-isolated-treehouse-visual-check.xml)：9 项通过，含实景出发、手动接战、楼上小猫、读档和回访补刷。[战斗截图](../test-results/forest-edge-screenshots/Treehouse-siege.png)为 Unity 的 540×960 台架截帧。
- 扩展回归另有两项旧版战斗存档用例失败；在改动前的 `9448265` [复跑](../test-results/unity/PlayMode-treehouse-legacy-baseline.xml)，两项均以相同断言失败。
- 已运行 `npm run assets:check`。室内底图和单页运行图集按临时静态依赖登记，合计约 644 KiB 源文件；和微信首下大小不是同一口径。尚未做微信真机的帧率、首下和手感验收。


## 2026-11-25 用户确认：紧凑操作区、头顶进度与无冷却出兵

- 实时出兵不设置卡牌或单位部署冷却；可连续出兵，只在现有合法落位、资源费用、场上单位安全上限等规则满足时提交。玩家与守方分别按配置恢复资源。单位费用、属性、合体/辅助交互与恢复速度是平衡入口；单位自身技能频率仍由其数据决定，不把技能冷却当成部署冷却。本轮不改数值、牌组抽取、战斗时间或存档。
- 手牌使用共享纸卡、圆体、单位图和费用图标，实时现场卡高从 312 U 收为 168 U，仍保留至少 144 U 的标准目标。资源条和余额放在手牌上方，显示真实余额和分数恢复进度；满资源保持满条。资源不足的卡保持名称、费用可读，按纸面状态区分可用性；触摸选中可查看不足提示。长按约 0.5 秒松手查看已有道具说明，不触发出兵；拖动从开始拖拽时即取消长按。构筑允许携带的种类与场上手牌容量是两个概念，现有容量布局按宽度换行，不为五种可携带单位改抽牌规则。
- 动物头顶使用现有 `Progress / Target` 救助完成度，跟随实际动物投影，单独静态绑定且不拦截射线，绘制层在房间栏杆之上。推进完成度平滑填充，初始与存档恢复按实际进度显示。当前玩法没有动物实时扣血变量，用户称“血条”的视觉条不新增 HP、伤害或败北逻辑。实时顶栏保留倒计时、动向、暂停及目标入口，旧顶部双行动条隐藏；回合预览保留旧展示。
- 清理现场按可用工具实时收口底部操作组，保持标准热区；清除工作量以当前剩余工作和总工作计算短进度条。找到动物、满足进入救助条件即可推进，进度条未填满不代表必须清完可选物件。解谜题面不显示清理工作条。
- 资产复用已有控件及房间栏杆分层，不重新生成图片、不增加单位 GameObject。运行时手牌继续复用池，资源条按既有展示快照刷新，头顶条跟随场景坐标。第一轮隔离图形 PlayMode 测试 9/10；树屋、实时战斗及同一时刻连续部署 90 单位压力用例通过，综合布局检查仅报大地图 Treehouse 地标在 768×1024 尺寸越界。最终回归及实际截图见本轮任务记录。

### 本轮实施与验收

- 树屋固定在上层的动物与其头顶条共用房间归一化布局锚点，消除初次进入时场景布局更新导致的条位置偏移。场景其他动物继续按投影跟随；栏杆仍覆盖动物而不覆盖进度条。
- [最终树屋集成验证](../test-results/unity/PlayMode-isolated-realtime-compact-verified.xml) 3/3；[扩展回归](../test-results/unity/PlayMode-isolated-realtime-compact-final.xml) 中实时战斗四项、教学拖拽、实时设置和其他 UI 项通过。扩展回归剩余两项为地图平板地标边界和旧样本 yard 绑定（均在进入战斗前发生），暂留单独处理。90 单位压力用例通过；微信真机帧率、触控待验。

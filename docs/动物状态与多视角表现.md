# 动物状态与多视角表现

2026-11-24。按用户要求：1秒顺势坐下，不额外缓冲；烦躁甩尾，开心翘尾；以后正面互动用同一动物状态驱动面部、耳朵和头部。

## 数据归属

`AnimalIndividual.Current` / `AnimalSnapshot` 是同一个体的唯一事实来源。沿用既有结构：

| 维度 | 现有归属 | 表现方式 |
| --- | --- | --- |
| 情绪、应激、行为、饥饿 | `AnimalDisposition` | 侧面与正面分别映射动作，不能自行改善情绪 |
| 脏污、浮毛 | `AnimalCoatCondition` | 同一个体跨地图、回站及互动视图保持一致 |
| 健康、护理意愿 | `Health` / `CarePermissions` | 仍由已有业务规则决定权限与结果 |
| 站、坐、走及动作时间 | 站内表现 `StationHabitatMotion` | 可与任一情绪组合，不写进持久业务情绪 |
| 混合权重与摆尾相位 | 视图实例 | 可重建的临时表现，不写档、不推进业务时钟 |

不能把“开心、坐着、脏污”合成互斥的大枚举；它们可以同时成立。不同画面展示不同部位，并不新建一份动物情绪。

## 本轮已实现

- 在 `AnimalEmotion` 末尾追加 `Irritated = 4`、`Happy = 5`，保留旧值0～3。没有修改默认动物情绪、护理权限、清洁奖励或互动数值规则；现有业务的 `Relaxed` 判定也未扩大。
- `Animals.UI/AnimalExpression.From(snapshot)` 是只读投影：烦躁→摆尾，开心→抬尾，原有情绪→保持原动作。急性应激优先压住开心表现，进入摆尾通道；`null`旧预览不猜情绪。
- 正式站内 `StationSceneResident.Snapshot` → `StationResidentView` → `StationCatPlayer/StationCatTail` 已接线。同ID重绑更新目标，0.2秒混合，不重播坐下；暂停、详情、切后台共同冻结表现时钟与混合，关闭释放renderer。
- `StationCatTail` 在坐下/起身/踏步原生clip采样后叠加情绪，围绕作者数据里的尾根转动。烦躁周期0.8秒、往返摆动；开心保持抬尾。尾巴仍是原分层图的刚性骨，没有新增贴图、网格或SDK。
- 参数现以 `src/pet-sit-chibi/appearances/` 中各形象profile的`tail`字段为作者源（原先在`tail.js`），经 `tools/pet-sit-unity.mjs` 导出 `tailMotion`，写入actor的显式绑定。运行时不按名字查节点、不修改sharedMesh。
- 坐下删除独立的0.86接触关键段及肩部二次下压，1秒连续进入最终坐姿；定长腿、接地、尾根连接与1.6秒原地起身保留。

正式Main只在真实快照进入对应状态时展示这些动作，不擅自把已救助或已清洁的猫都变成开心。尾巴表达已具备，但“哪些互动触发/结束烦躁或开心”仍由后续玩法确认；目前可在专项渲染证据中对照两种状态。

## 正面互动的下一步

沿用上述 `AnimalSnapshot`。正面视图可直接读取同一 `Disposition`，通过自己的表现映射驱动头、双耳、眼睛、嘴与身体；需要共用的通道再扩展只读 `AnimalExpression`，不增加平行的情绪存档。当前投影只包含已使用的两条尾巴通道，没有提前搭通用动作框架。

资源建议按一个角色拆：身体、头、左右耳、眼睑/眼睛、嘴、尾巴；保留遮挡补画和可旋转余量，绑定稳定锚点。正面可表达开心时柔和抬头/竖耳、烦躁时耳位变化/避开注视，幅度与具体设计在资源试做时确认。头脸目前是一整层，不能宣称已能独立眨眼或动耳。

短期可沿用原生分层网格/骨骼，达到类似Live2D的轻量表现；是否采用Live2D SDK需在正面资源和变形需求明确后评估。此轮没有安装SDK、生成正面资源或制作正面互动界面。触摸目标/反馈可作为临时输入传给表现适配器，持久情绪变化仍由业务先校验再更新快照。

# 动物同骨架过渡：调研与制作试验

2026-11-23。用户授权记录调研，并试做 Spine 式制作；需要的补画可使用本机 ComfyUI。当前只验证原橘猫站立→坐下→站起，不等于安装 Spine/Live2D 或批准替换 Main。

本文保留初期试验和当时问题，不是当前推荐坐法。最终已接受版本见[短腿萌系与臀尾触地](猫坐下萌系比例.md)，总结见[制作经验](动物同骨架过渡经验.md)；后续调研→无贴图骨架→原图比例重定向已替代文末的历史“下一步”。

## 当前工程事实

`PetMotionPlayer.cs` 现有同姿态姿势缓冲混合和跨姿态透明交叉淡入，已不是早期文档中的直接切图。站/坐/卧仍是不同网格/绑定组；透明淡入不是同一身体真实坐下。

原站图 `public/pet-mesh/cat-side.png` 为452×512。坐图的眼形、头身比例与围巾结构有差异；侧卧又改变脸部视角。这些来自当前图像目视，不是通过统一缩放就能消除的偏移。原资源及历史动作不覆盖。

## 素材与动画契约

- 头脸、耳形、眼睛、围巾与可复用花纹优先保留原像素，不分别生成各姿势完整猫后强行交叉淡入。
- 同一坐标系/角色单位；固定脚底与头部尺度，不按每个姿态外接框重新自动放大。
- 头/围巾、躯干、前后腿、尾巴按真实遮挡拆件，补足被遮区域；接缝放在覆盖层下面，不让两个可见描边重叠。
- 骨骼处理平移/旋转和主要动作；局部网格/少量修形控制腹部、髋部等轮廓。线条粗细、花纹拉伸和半透明叠深要单独看，不以更多骨骼代替补画。
- 视角/可见表面改变时允许局部附件或关键图；不许从一张侧图凭空扯出胸腹另一面。
- 第一条只做站→坐→站。微动、快速反向、暂停/拖动、深浅背景与手机尺寸都要验；侧卧另做。
- 用户本轮明确否定“靠压扁大腿坐下”：不能在动作中缩短骨长、改Scale或用髋到脚的宽区混权代替折腿。绑定前按原图标定短腿骨长与此不同，最终萌系版已采用这种比例适配。大腿先保体积旋转，膝与跗关节产生真实位移，脚掌支撑；关节露出的缺面另补，不再回到整片压缩。

## 本轮流程

1. 冻结原猫与参数，保留SHA256。
2. ComfyUI做局部躯干补画候选，使用原图为身份/画风参考；最终合成限制使用区域，生成器不得重画共享脸。
3. 原像素拆件与补画放在同一原坐标，记录每个mask/裁边offset/挂点；保留母图和未选结果。
4. 一套Three.js骨架和共享图集，连续可采样的站坐轨迹；不在运行时重新生成图。
5. 固定seed重复生图与机械重建哈希分别验；相邻seed对照为后续项目，本轮未做。固定seed只是可复现条件之一，不能承诺所有模型版本/设备一致。
6. 只有观感合格的补画才冻结选图与派生链；重复生成不合格则保留实验，不自动批量推广。

## 验收与接续

本轮独立试验已可看，入口：`http://127.0.0.1:5193/pet-transition.html`。默认静止，可播放、逐帧、拖进度、切站/坐、显骨架/网格与深浅底。实际动作轨迹为站立→1.2秒坐下→坐姿停留→1.5秒站起，5.6秒循环；数值是观感样例，不是正式规则。

- 当前修正版为11附件/21骨，同一Three.js Skeleton与340×740图集217327bytes（约212.2KiB）。后腿为髋→膝→跗→脚的父子链；髋下降55原图像素、向后26像素，大腿旋转约37度；膝/跗使用已有Three.js官方`CCDIKSolver`追踪固定足端。每次从静置姿态重置求解，不依赖上一帧。它是针对这张Q版图的运动学近似，不是生物力学仿真。
- 大腿、跗部与脚掌分成重叠附件。大腿整片100%绑定髋/股骨，脚掌100%绑定地面目标；骨长和Scale均不变，不再使用髋到脚的宽区混权。大腿隐藏末端用同列邻近原毛色闭合，跗部裁去会形成尖角的脚趾残片；路径、远侧偏移和填色规则保存在process脚本及derivation.json，无新生图、无覆盖原件。原头脸围巾、全程不透明度仍保持，未引入完整姿态淡入。
- ComfyUI两次独立作业成功；固定模型/参考/提示/seed2026112301、24步Euler/simple/CFG4。两张896×672母图的解码RGBA完全一致，PNG文件哈希因元数据不同而不同；模型三文件SHA256和运行环境实测保存在[复现证据](../art-source/pet-transition-20261123/reproducibility.json)。不是跨设备/模型版本/seed/服务重启稳定性证明。

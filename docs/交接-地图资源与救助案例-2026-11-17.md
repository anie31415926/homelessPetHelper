## 3. 本聊天确认的方向

- **地图**：保留城市背景，入口为“救助站 -> 城市地图 -> 救助现场”；区域与小地点可在同一地图呈现，不增加必须进入的区域中转页，不做城市自由移动。
- **外出来源**：求助为主、主动发现为辅，地图承载求助地点。电话/留言的具体形式与主动发现方式仍待定；现场保留寻找、清理或解谜。
- **节奏**：避免求助堆积、快速满员卡住循环。频率、并行数量、容量和奖励量可以试玩调试，不要求现在定死。暂缓/失败/满员后果不是纯数值，仍需确认。
- **补给**：救助途中顺带获得，适合融入清理通道，不另做专程采集。安全通道连通即可，不要求全清，不逐次拾取推进世界时间。
- **建设支持**：救助记录、照护或领养成果可带来社区/政府/个人或系统支持，用于建设；不自动确定两种货币、兑换、合成或多个支持系统。
- **建设内容**：扩建照护空间、新增设施、升级已有设施；具体清单、效果、条件、消耗与外观变化未定。固定区域、固定设施是建议，不把自由摆放或施工倒计时当已确认。

共享文档还记录了有限临时安置容量、扩建增容、满员出发前提醒和主动快进领养机会等同期确认；不将其与长期陪伴名额混用。世界时间仍由完整行动推动，不按现实挂机/离线流逝。新增惩罚、强制送养和健康安全后果须先确认。

## 4. 当前可体验内容

Unity 菜单 `Homeless Pet Helper > Preview > Open Rescue Case`，然后 Play。

同期已新增 `Homeless Pet Helper > Preview > Open Stress Recovery Case`，用于已有应激、已经进食的恢复起点；复用同一场景和面板。普通选项白板 `Open Option Whiteboard` 保留原样。

案例流程：

```text
停车棚现场，观察状态与意图
  -> 选一个行动，可保留其他选项
  -> 显示动物回应，再继续下一回合
  -> 允许接近／动物主动靠近
  -> 准备安置，观察本样本接受回应
  -> 独立完成救助
  -> 只读总结
  -> 站内单只动物轻量互动
```

- 三个选项、用一个、最多保留两个；复用已有 `RescueOptionHand`，没有重写卡牌框架。
- 需求、情绪、行为分开；同期已增加独立应激状态。普通受惊不自动等于极端应激，已进食、已有地上食物等事实不会因退缩清空。
- 一个 `CaseAnimal` 持有本次动物的最新状态；回应、换轮、恢复、总结、回站不重建动物，快照不可变。只有显式重开/切起点创建新会话。
- 允许接近不等于愿意接受救助；合适等候可得到主动靠近，不强制再抽接近选项。
- 暂停/失焦拒绝操作，旧回合或旧会话不能推进新会话；重复成功、重复互动被规则拒绝。
- 手册自由查看；求援只结束试做，不算成功、不入站、不发奖，不代表正式求援交接已定。

### 暂定而非正式规则

两份食物、有种子且当前不重复的供给、安全选项补位算法、玩具效果、恢复速度、放松与接近条件、准备安置必然被此样本接受、点击继续观察、单次抚摸回应，均只用于此次验证。尤其不能把“所有动物必须吃饱再救”“必然可恢复”推广为正式规则。

本案例没有地图、开路、伤病医护、资源收益、建设、领养、存档或正式失败/死亡/结局。回站是案例内部延续，**尚未与 ST-01 或正式 Main 集成**。同期站内白板属于另一项工作，不是此处简单回站页面的替换实现。

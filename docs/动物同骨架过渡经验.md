# 动物同骨架过渡制作经验

2026-11-23。用户已认可[短腿萌系坐下与臀尾触地版](猫坐下萌系比例.md)，本记录总结这次实际试做，不是多品种自动绑定或正式Unity接入结论。

## 最重要的结论

让骨架适应原图，而不是拉长原图去适应写实骨架。正确关节连接、正确折叠分支、原图头身比例和接地轮廓必须同时成立。技术测试只检查各自覆盖的约束，不能代替动作与美术观感。

## 走过的弯路

| 问题 | 原因 | 本次有效处理 |
| --- | --- | --- |
| 大腿像被压扁 | 跨髋到脚的大区域混权代替折腿 | 大腿刚性绑定，固定骨长，通过髋/膝/跗/趾旋转折叠；缺面另补 |
| 骨长不变但坐法仍错 | 只验IK可达，没有验膝/跗方向和重心 | 先查真实猫解剖与连续实拍，做无贴图五姿态，结构认可后再蒙皮 |
| 结构正确却不像原猫 | 用写实长腿比例拉伸原萌系图 | 按原图坐标标定骨长、头身和脚底；短骨后重算目标与骨盆/胸腰轨迹 |
| 只证明脸像素不变 | 忽略头部缩放、身长、腿高和整体轮廓 | 原头身1:1绑定，同镜头原PNG对照，颜色/轮廓统计与实际看图分开 |
| 臀部悬空 | 固定上抬只防穿地，没有落坐接触目标 | 后躯美术锚点按可见轮廓平滑下降，保留圆臀，不下移整猫或压大腿 |
| 尾巴触地后断根 | 用整条尾巴上移补偿地面碰撞 | 尾根固定随臀连接，只围绕根部调整角度，尾巴保持刚性 |
| 接件反折或透明框误判 | 权重过窄、把透明矩形当轮廓 | 扩大局部平滑区，依据可见alpha边界检查，深浅底逐帧复核 |

“缩短骨骼”要区分两个阶段：绑定前按萌系原图标定短骨是正确的比例适配；动作中不断缩骨或Scale来伪装坐下仍然不可取。

## 后续制作顺序

1. 冻结同一动物身份、画风、头身比、镜头、原坐标和地面基准，保留源图SHA256。不按不同姿态外接框各自放大。
2. 先查结构和真实动作。区分可靠解剖、装配姿态与毛皮遮挡下的观察，不把手工曲线称为动捕或生物力学仿真。
3. 先做无贴图骨架五关键姿态：站立、预备、下降、接触、坐稳。确认髋→膝→跗→趾连接、折叠方向和前爪支撑。
4. 以原图反标骨长与绑定姿态，再重算足端目标、骨盆和胸腰。保留大头、圆躯干和粗短腿，不能只整体缩放。
5. 同源拆件，记录mask、原尺寸、裁切offset和挂点。优先保留原脸/围巾/花纹；补画只处理隐藏面与缺面，不分别重画整只猫再淡入。
6. 分离运动骨与美术覆盖控制。关节链固定长度，大腿/脚掌等保体积；臀部被毛可用独立锚点柔和变形，但不声称是物理肌肉。
7. 接触约束同时检查前爪、后爪、臀部和尾巴。先看整体承重，再处理alpha轮廓；尾根必须连着臀部，不能靠整体上抬遮问题。
8. 观感与专项均通过后冻结选图、参数、派生与输入清单。先让一只动物的一条转换成立，再扩品种/姿势，不先批量生成。

## 验证分层

- 几何：骨长/Scale、IK目标、关节分支、刚性区域边长/面积、三角正向、权重归一化、任意拖动确定性、连续采样。
- 原图：头身绑定坐标、脸RGBA、同镜头完整原PNG对照。屏幕轮廓IoU只是当前阈值统计，不是“美术保真率”。
- 接触：可见alpha采样不穿地、臀部靠地、尾根同点；仍不是完整像素碰撞或动力学。
- 实际渲染：桌面/手机/横屏、深浅底、骨线可见、首尾/中间/慢放与控制状态，检查真实像素而非只看DOM。
- 人工观感：原图气质、线条/条纹、体积、遮挡和坐法。用户接受的范围单独记录，自动测试不能代签。
- 交付：源/生成物逐字节重建、冻结输入、实际提交blob与依赖核对。Unity/微信/AOT/真机另验，不从HTML通过推导。

## ComfyUI工作流经验

最终短腿/臀尾优化复用原图与已有供体，没有重新生图。需要补画时沿用[API制作链](../art-source/pet-transition-20261123/README.md)，保留参考、完整正负提示、模型三件套及哈希、seed、步数/CFG/采样器、提交ID、历史和后处理mask；不能只留seed。

本次两次独立同参数作业解码RGBA一致，PNG因元数据而哈希不同。这只证明本机/当前模型与该补画条件可重复，不能推导跨设备、相邻seed或新动物稳定。生成成功后仍须逐张检查肢体/身份/轮廓，选图不会自动替换运行图；机械重建优先复用已审母图，不必反复耗GPU。

# 图片资源台账与入库流程

2026-11-18。现在起管理 ComfyUI 基础图、既有样例及正式资源计划；不安装运行时资源框架，不触发生图，不改变当前玩法或图片绑定。

## 只维护一份清单

- **人工事实与计划**：[resource-catalog.json](resource-catalog.json)。维护唯一 ID、用途、模块、制作状态、加载时机、内容开放说明、单图计划字节、文件位置、生成来源及审核状态；预算数值也在此统一维护。
- **自动观察结果**：在仓库根运行 `npm run assets:check`（或 `node tools/resource-catalog.mjs`），生成 `test-results/resource-catalog/report.json` 和 `report.md`。文件字节及 SHA256 自动读取，不在台账重复手填；报告在忽略目录，不手改、不当历史主档。
- **Unity 导入/引用**：沿用[轻量图片检查](../docs/轻量资源检查工具.md)。本台账不替代 Unity API，也不声称已经建立实际分包/下载关系。
- **规格与判断依据**：[图片规格与首包预算](../docs/图片资源规格与首包预算.md)。调整预算时同时更新其中的说明快照，不能只改报告。

AI 接到生图、选图、替图或正式导入任务时按需读本页，再读涉及的台账条目与规格；不需要读全部工作流/历史。每批图完成后同一任务更新台账并运行检查，不能只写聊天总结。

## 内容开放和加载时机分开

`availability` 写什么时候允许使用该内容，例如“进入此地点即可使用”“某设施开放后使用”；没有确认的条件明确写未确认，不能自行补等级或章节。当前地图首版点位全部可用的共识不因资源管理而改变。

`loadTiming` 只描述资源计划，不是运行时加载已实现：

| 值 | 含义 |
| --- | --- |
| `preview-only` | 当前仅用于 Editor/临时试做，不计正式首批；仍须由构建依赖验证实际不入包 |
| `first-play` | 启动到首个可玩内容必需；包括首包外仍必须先下的图片，不靠 CDN 名义排除 |
| `on-demand` | 首个可玩内容之后，进入相应场景/动物近景/已确认扩展内容时再加载；不一定要玩法锁定 |
| `unassigned` | 尚未确认加载边界，报告会提示，不能默默按“延后”算省下了空间 |

CommonUI / CityMap / Rescue / Station / ArchiveHandbook 是用途归属，不是强制下载顺序或已建物理包。共享图只登记一个归属，其他用途写在 `use`；不同尺寸的真实派生图分别登记 ID，并注明复用关系。把一条标成 `on-demand` 不会自动切断 Prefab 依赖。

**1.4 MiB 只是上一轮静态容量示例，不是前期资源承诺。**首个可玩入口和必需清单未确认，因此 `firstPlayableScope.status` 当前为 `draft`，首批登记为 0 也不能宣称达标。2 MiB 是转换后首次必需图片下载的暂行目标，1.5 MiB 是早期源文件规划参考；两种口径不可直接等同，修改文件压缩也未必减少 Unity 输出。

## 从 ComfyUI 到正式入库

| 状态 | 使用边界 |
| --- | --- |
| `planned` | 尚无当前成图，可先记预算、用途与工作流；不把计划字节当实测 |
| `candidate` | 已生成待选，当前图可留 Unity 外；不自动视为正式资产 |
| `temporary` | 明确允许临时试用，正式美术/商用来源/目标链路仍未验收 |
| `approved` | 当前运行图的观感、来源许可与目标交付验证已接受，记录审核哈希及证据后才可使用此状态 |
| `retired` | 不再使用；保留条目追溯，不因此自动删除文件或解除引用 |

1. **生成前登记计划**：确定 ID、用途/最大显示尺寸、模块、`plannedBytes` 与加载时机。正式内容未讨论时，只标临时或未确认，不借台账批准玩法。尺寸以[规格表](../docs/图片资源规格与首包预算.md#2-尺寸根据实际显示分档)为起点。
2. **保存生成依据**：母图和可复现的 ComfyUI 工作流放 Unity 外；工作流保留正/负提示、模型/LoRA/ControlNet 名称与版本、seed、采样器/步数/CFG、参考图及后处理。生成历史可保留，不能只留 seed 冒充完整复现。旧图资料缺失就如实写缺失，不伪造补全。
3. **挑选候选与派生运行图**：台账 `files` 中只保留一个当前 `candidate` 或 `runtime` 图，其余母图/工作流按角色关联。裁切、缩放、抠图和 alpha 修正要留依据，已有交互图先核对 pivot、遮罩与热点。不要把母图直接复制进 Assets，也不因登记而覆盖现有 PNG/Prefab。
4. **正式导入前复核**：同尺寸 A/B、深浅背景边缘、清洁遮罩/点击区、画风、模型及参考素材使用条件；标明证据路径。生成图片不自动等于商用许可通过；旧临时图不因尺寸合适自动升为正式。
5. **导入与更新**：在获准任务里用 Unity 保持 `.meta`/GUID，更新台账当前路径。运行台账检查和 Unity 只读审计；确认当前图片属于首批还是进入内容后加载，再核实真实依赖。批量正式资源前仍须确定微信兼容的统一加载入口。
6. **验证后冻结当前审核**：`review.visual/rights/target` 分别填 `accepted`，在条目里写清验收依据/审核人/日期，复制报告中当前运行文件的 SHA256 到 `reviewedSha256`，才改 `approved`。替图或生成参数改变后先回到 `candidate/temporary`、重置受影响审核并清除旧审核哈希，不能仅更新哈希冒充复核。旧版本由 Git 追溯。

### 文件位置与版本管理

`art-source/<批次或主题>/` 已用于保存母图/工作流；沿用，不搬动同期文件。新任务可在其下按 ID 分目录保存 `master.png`、`workflow.json`、`history.json` 和候选图；母图、候选图、工作流都在 `files` 标明角色，参考图记来源和许可。模型权重、大量失败候选、凭证/服务密钥不得入库；工作流和历史 JSON 提交前检查敏感字段。

目录在 Assets 外只说明不被 Unity 默认导入，不说明 Git 已备份；当前文件是否已提交须单独核对。大母图/大量候选进入 Git 前另行决定 LFS 或外部归档策略，本工具不会自动提交、推送、安装 LFS 或扫描整个 ComfyUI 输出盘。

最小计划条目示例，按需加入 `assets`；这是字段示例，不是新增资源任务：

```json
{
  "id": "animal.example.care",
  "name": "示例动物近景",
  "module": "Station",
  "status": "planned",
  "loadTiming": "unassigned",
  "availability": "具体出现条件未确认",
  "use": "近景交互，512 档起比，需记录最大显示像素及遮罩要求",
  "plannedBytes": 153600,
  "files": [],
  "generation": { "tool": "ComfyUI", "notes": "生成后补工作流、模型与参考图信息" },
  "review": { "visual": "pending", "rights": "pending", "target": "pending" }
}
```

文件角色：`runtime` 当前运行图、`candidate` 当前候选图、`master` 母图、`workflow` 工作流、`generation-record` 历史、`reference` 参考文件。路径相对仓库根、使用 `/`；仓库外旧素材只在 `generation.notes` 记录现有线索，未归档文件不伪装成仓库已备份。当前脚本不解析图片尺寸，尺寸/导入设置继续由 Unity 审计或图像工具验证。

## 报告如何使用

自动汇总每模块、首批、临时图的字节；当前运行/候选图用实际文件大小，尚无成图的计划用 `plannedBytes`。母图、工作流、历史和参考文件不计运行图预算。模块汇总排除 `preview-only` 与 `retired`，临时图另列；按源图统计不代表已去除构建重复。

| 提示 | 处理 |
| --- | --- |
| `UnregisteredImage` | Unity Assets 或 art-source 中有图未登记：确认用途后登记，或明确淘汰/归档；不自动猜分类或删除 |
| `MissingFile` / `ReviewedFileChanged` | 登记文件不存在或审核过的文件内容改变；命令非零退出，核对路径/版本和受影响审核 |
| `ImageOverPlan` / `ModuleOverPlan` / `FirstPlaySourceOverPlan` | 单图或源文件规划超额，提供对比后评审，不自动压图或静默涨预算 |
| `IdenticalImage` | 不同条目的当前图内容相同，复核是否可共用；不是实际重复打包已证实 |
| `FirstPlayableScopeIncomplete` / `UnassignedDeliveryTiming` | 首批范围/加载时机尚未确认，不能据低统计量宣称通过 |
| `NotApprovedForDelivery` | 首批/按需计划中还有未批准条目；可用于提前规划，不可视为发布验收完成 |

Review 提示不阻断构建；schema/路径错误、缺失文件和审核内容变化使该命令失败，但没有安装构建钩子。工具只读取登记文件并枚举上述两个目录中的图片，不访问外部服务、不跟随目录符号链接、不改原图或台账，只写忽略的报告。

命令失败时不要把上次保留的报告当本次成功结果。报告反映运行时的文件快照；同期聊天可能继续生图/替图，交付前再运行一次，不自动将新产物设为已批准。

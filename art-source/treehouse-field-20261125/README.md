# 精灵树屋 · 清理与逆塔防素材候选

[楼梯版空场景](room-stairs/candidate.jpg) · [楼梯版清理 / 开战预览](room-stairs/field-preview.jpg) · [透明图集](treehouse-atlas.png)

用户已认可楼梯版，作为[树屋关卡设计](../../docs/精灵树屋关卡设计.md)的美术基准。楼梯版按上下层的树屋室内重新构图，不预画三条路线。楼梯和上层平台属于固定场景，书堆、盖毯藤篮和战斗物件仍是独立 Sprite。预览仅表现两阶段，楼梯是否参与清理或战斗寻路未定。

[旧平层预览](field-preview.jpg) · [旧平层空场景](room/candidate.jpg)（留作对照）

旧平层对照中，左图用书堆、木凳、卷轴和盖毯藤篮展示清理层；右图沿用同一张背景，以留下的两处轻杂物和战斗单位展示大小与对比。这是静态摆件图，未模拟动画、寻路、手牌或动物揭露。以 384 像素宽展示时，普通杂物约 38–52 像素、基础单位约 61–64 像素、重车约 89 像素。单位、机关保持更强的色彩区分，藤篮是清理阶段的重点。

- **底图** 640×1152。楼梯版以同一参考目录中的 `(29).png` 为建筑参考。旧平层图参考用户提供的 `精灵树屋/游戏界面地图图标设计 (30).png` 的圆窗、木梁和植物；裁去参考图页脚后仅作条件输入。成图重排了屋内构造：圆窗和壁龛在后墙、两侧木梁沿墙支撑、门槛后为同高连续木地板；没有烘焙可清物、动物、文字或水印。
- **清理物** 书堆、低木凳、盖毯藤篮、卷轴杂物。藤篮单独一层，可在清理时遮藏动物；收走摆件不改变地板。入关时需要为每个物件另外配置占格、工作量和恢复资格，不能从图像推导。
- **战斗物件** 鱼干、毛线球、羽毛、木夹、围巾、重车，另有 3 个机关和 3 种进阶造型候选。沿用既有猫侧普通单位及五卡试做身份；新增绘图不更改费用、碰撞、射程、合体、构筑和正式阵容。初稿给单位带了木地板垫，`units-clean` 重绘去掉底垫后才用于派生。
- **图集** 512×512 RGBA，16 个透明 Sprite；每个都有留边，`derivation.json` 按左下坐标记录切片和贴地锚点。保留左下纯白像素供现有合批绘图采样。预览的软接地影仅用于构图对照。圆润感来自原画，接入时可以继续复用 `OutingFieldGraphic` 和现有战斗 Sprite 绘制，不需要给单个单位增加组件。

本机 ComfyUI 串行任务；Qwen Image 2.1 INT8 ConvRot、Qwen3VL 8B INT8 ConvRot 和 Qwen 2.1 VAE。各文件夹的 `workflow.json` 包含模型、参考文件、seed、采样参数；`history.json` 保留本机任务结果；`master.png` 为原始生成图。在同一 Windows ComfyUI Python 环境、本地实例监听 `8197` 时可用 `python -B art-source/treehouse-field-20261125/generate.py` 生成或取回未完成任务，`python -B art-source/treehouse-field-20261125/derive.py` 重新派生。派生对近白底抠取 alpha、剔除小噪点、清理白边和保留轮廓孔洞；用源文件 SHA-256 追溯。

目前 `Treehouse` 是地图已有视觉地标；正式地图点、求助模板、内外场转场绑定、树屋清理/解谜、逆塔防 HUD 与回访存档均未接入。图已逐张初筛并按候选登记；楼梯版视觉已获认可，来源许可、Unity 导入和微信真机验证仍待对应阶段。
